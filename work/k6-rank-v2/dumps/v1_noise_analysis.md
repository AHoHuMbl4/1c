# Разбор шума меры v1 (почему gold lead 2→1 / «покупают» 5→1)

Снято на okna 27.08; данные — alias/corpus/refcols (чтение).

## 1. Alias-дыра (главный шум набора)

«сколько продали вчера?» → `alias_idx` hits = **0**. Большинство sum/name
вопросов gold не имеют эталона в top-24 alias. Мера v1 переставляет только
то, что уже в пуле → на 15/23 etalon «не найден» в приборе K6 v1
(`docs/K6_ENTITY_RANK.md` §4). Сдвиг 2→1 — не «мера вредит продажам», а
мера на sum **молчит**, а на единственном card-count («всего клиентов»)
**роняет** лидера.

## 2. Fit=2 выше карточек (v1)

`answer_fit`: держатель с `0 < DISTINCT(axis) < n_cards` → fit=2, каталог → 1.
На «сколько у нас всего клиентов?» (эталон каталог) регистр поднимается
выше → place 1→2 в K6 v1 / 1→4 в приборе v2 при расширенном пуле.
Нет сигнала «вопрос про карточки, а не про движения» без period/form.

## 3. Нет вида объекта

Метка без вида (PATH_AND_FAILURE §1): `Реализация ТМЦ` — и документ, и
регистр. v1 не смотрит OData-префикс / `search_entity_class`.

## 4. Нет doc_date как признака

Каталоги: 0 дат / N NULL. Регистры: все строки с датой. v1 использует дату
только внутри окна DISTINCT, не как ранг «есть ли живые ячейки».

## 5. Kind угадан криво

«позиций в прайсе» → alias top = строки документов `*_номенклатура` и
`catalog_типыцен*`, не `catalog_номенклатура`. Expand holders не тащит
эталон → miss/out8.

## 6. Служебные

`search_entity_class=service` в мере v1 не режется (ask режет позже).

## Вывод для v2

Live + вид объекта + popularity(`n_dated`) первичны; лексика — последний
ключ. Пул расширять stem-пересечением и live canon registers, иначе мера
не на чем работать.
