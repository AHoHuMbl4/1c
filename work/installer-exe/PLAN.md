# План: Windows-установщик (`setup-1c-odata.exe`)

Заведён 2026-07-29. Рабочая папка: `work/installer-exe/`.  
Параллельные агенты трогают другой контур — **правки боевого кода** (`windows/odata-setup/`)
только после явного слова; до этого черновики и план живут здесь.

Опора: `TARGET.md` п. 14, `docs/PLAN_AUTONOMY.md` Фаза 1, `windows/odata-setup/`,
`docs/RUNBOOK_DEPLOY.md` §5, `docs/TEST_SECOND_BASE.md` (Н-3).

---

## 0. Цель

Со стороны **Windows** клиент настраивает канал `1С → IIS → OData (только чтение)`
одним exe. Руками по контракту (п. 14) остаются:

1. создать пользователя-читателя (`ai_reader`) и выдать ему только то, что собственник
   разрешил искать;
2. при необходимости — пользователь Windows.

Всё остальное на Windows-стороне — установщик. Ubuntu (шлюз, SereneDB, конвейер) —
**не** этот exe (Фаза 2 `PLAN_AUTONOMY`).

Критерий «готово» (Фаза 1): публикация → **проверка `enable="true"`** → пул → состав
OData (или ручной путь) → проверка, что `$metadata` / OData отвечает. Ни одного шага
«потом поправить руками».

## 2. Решение владельца (сессия 29.07): два явных варианта состава OData

В установщике — **выбор**, не один скрытый путь:

| # | Вариант | Что делает exe | Пароль админа 1С |
|---|---|---|---|
| **1** | «Задать состав автоматически» | после бэкапа пишет состав OData через COM | ввод **локально**, скрыто; один раз |
| **2** | «Задам состав сам» | состав **не трогает**; IIS/публикация/`enable` уже сделаны | **не спрашивает** |

### Тексты (смысл, не дословная вёрстка)

**Вариант 1 — коротко и честно, без «верьте на слово» как главного аргумента:**

- пароль нужен платформе 1С один раз, чтобы записать список объектов в составе OData;
- вводится локально (звёздочки), нам по сети не передаётся, в лог как `***`;
- кому этого мало для ИБ — берите вариант 2: пароль в программу не вводится вообще.

**Вариант 2 — точные слова:**

- не «опубликую базу сам» (публикацию в IIS exe уже сделал);
- а «задаю **состав OData** сам» + подробный туториал: Конфигуратор → бэкап .dt →
  «Состав стандартного интерфейса OData…» → какие разделы отметить → проверка в
  браузере / повторный запуск exe с `--skip-scope`.

Заголовок диалога: **«Два способа задать состав OData»**.

## 3. Нет веб-модуля (`wsisapi.dll`): не «переустановить всю 1С»

Без `wsisapi.dll` канал IIS/OData **невозможен**. Базы при этом **не** трогаем.

### Предпочтительный способ (владелец, 29.07) — способ 1

**Изменить установку платформы** (не снос 1С):

1. Панель управления → Программы и компоненты → платформа «1С:Предприятие 8» нужной версии.
2. **Изменить** → включить **«Модули расширения веб-сервера»**.
3. При необходимости там же — «Модули расширения COM» (нужны для варианта 1 состава).
4. Готово → снова запустить наш exe.

Это **не** удаление платформы и **не** пересоздание баз/пользователей/лицензий.

### Другие способы (запасные, в туториале вторично)

| # | Способ | Когда |
|---|---|---|
| 2 | Тихий MSI: `msiexec … WEBSERVEREXT=1` | есть дистрибутив той же версии, без GUI |
| 3 | Поставить рядом другую версию платформы **с** веб-модулем | exe сам берёт новейшую с `wsisapi`; или `--platform-version` / `--platform-dir` |

**В текстах exe запрещено** писать «переустановите всю 1С». Только: «добавьте компонент /
Изменить установку».

### Туториал — полный, подробный, на диск

Если префлайт находит платформу **без** веб-модуля (или без COM при выборе автосостава):

- остановиться с кодом 3 **сразу**, до IIS/публикации;
- напечатать **полный пошаговый туториал** (клики, названия пунктов меню, что галка
  означает, что базы не затрагиваются, как проверить появление `wsisapi.dll`);
- сохранить тот же текст в файл, напр.
  `C:\1c\logs\1c-odata-добавить-веб-модуль.txt` — чтобы можно было переслать админу.

Отдельный полный туториал уже нужен для варианта 2 состава (`…-ручная-настройка.txt`).
Тот же стандарт подробности — и для веб-модуля.

## 4. Префлайт с самого начала (до любых изменений)

Сейчас часть проверок размазана (место — у бэкапа, веб-модуль — на шаге 2 после
выбора базы). **Нужен явный блок в начале** (после прав админа, до установки IIS и
до публикации): «проверка системы и предусловий». В `--check` — тот же блок, только
без изменений.

### 4.1. Платформа и компоненты 1С

| Проверка | Если плохо |
|---|---|
| Платформа найдена | код 3 + как указать `--platform-dir` |
| Есть `wsisapi.dll` (веб-модуль) | код 3 + **туториал «Изменить установку»** (способ 1) |
| Есть `comcntr.dll` | предупреждение: без COM возможен только вариант 2 состава; для варианта 1 — туториал добавить COM |
| Несколько версий | показать список; выбрать новейшую **с** веб-модулем |

### 4.2. Система (машина)

| Проверка | Зачем | Поведение |
|---|---|---|
| Свободное место на диске базы, публикации (`inetpub`), логов и бэкапа | бэкап ≈ размер базы; IIS; логи | не хватает → **стоп** с цифрами (сколько нужно / сколько есть), до любой записи |
| Ожидание перезагрузки Windows | иначе фичи IIS не применятся | уже есть warn; усилить: не продолжать установку IIS, пока pending reboot (кроме явного override) |
| Нагрузка ПК (CPU / память) | тяжёлые шаги (IIS, COM, бэкап большой базы) на «задыхающейся» машине дают таймауты и ложные поломки | снять замер; при высокой загрузке — **предупреждение** + совет закрыть лишнее / повторить позже; порог и «стоп vs warn» — зафиксировать замером на стенде, не гадать в коде |
| Версия/редакция Windows | IIS на урезанных SKU | уже частично; в префлайте явно |
| База указана / `1Cv8.1CD` на месте | иначе нечего публиковать | код 3 |

Место считать **в начале** (оценка: размер базы + запас под бэкап + запас под логи),
а не только перед zip. Если `--no-backup` — запас под бэкап не требовать, остальное да.

Нагрузка («загрузка компа»): читать текущие CPU% и доступную RAM (WMI/PDH). Точные
пороги — в замер при реализации; в плане зафиксировано само требование проверки.

## 5. Что сказать клиенту (согласовано с периметром)

Текст, который уже дали клиенту — в целом верный:

> Создать читателя (`ai_reader`), профиль «Только просмотр» / доступ только к разрешённому
> собственником; пароль запомнить. Остальное установщик сделает сам.

Уточнения, которые нельзя потерять:

1. **Два рычага:** состав OData (что в API) и права `ai_reader` (что реально читается).
   Периметр поиска для AI — в первую очередь **права читателя**.
2. «Только просмотр» ≠ узкий список. Если нужен узкий периметр — права режут явно.
3. Пароль **админа** нам не нужен; рабочий для Ubuntu — пароль **`ai_reader`**.
4. Пароль админа в exe — только вариант 1 состава; вариант 2 — без него.
5. Если нет веб-модуля — не переустановка 1С, а **Изменить** + галка (туториал из exe).

## 6. Объём работ (когда скажут «делай»)

Порядок: черновики здесь → перенос в `windows/odata-setup/`.

| # | Задача | Где | Статус |
|---|---|---|---|

| Q | Туториал **«добавить веб-модуль»** (способ 1 подробно) + файл на диск; MSI/вторая версия — вторично | новый текст + `Steps` | план |
| A | Диалог: «два способа» состава, тексты 1/2, без упора на «верьте» | `AskScopeChoice` | план |
| B | Туториал состава: слово «состав», не «публикация»; файл на диск | `ManualScopeInstructions` | план |
| C | README exe + кусок для клиента | `windows/odata-setup/README.md` | план |

- создание `ai_reader` из exe;

## 7. Критерий приёмки (замер, не рассуждение)

1. Запуск на машине **без** `wsisapi.dll`: сразу код 3, **до** изменений IIS; на диске
   полный туториал «Изменить установку»; в тексте нет «переустановите всю 1С».
2. Запуск при нехватке места под бэкап/базу: стоп в префлайте, с цифрами.
3. Высокая нагрузка CPU/RAM: предупреждение (или стоп — по порогу после замера), без
   «тихого» таймаута на COM/бэкапе без объяснения.
4. `--check --base …` — префлайт + план двух вариантов состава, ничего не меняет.
5. Вариант 2 / `--skip-scope`: IIS/`enable`/пул ок; состав не тронут; туториал состава на диске.
6. Вариант 1: состав непустой; пароль в логе как `***`; повторный запуск — ПРОПУСК.
7. В `default.vrd` после успеха — `standardOdata enable="true"`, иначе ошибка, не успех с 404.
8. С `--reader-user` + пароль читателя: финальная проверка под читателем.

## 8. Инвариант безопасности (не размывать)

- 1С только читаем: слой 1 = права `ai_reader`, слой 2 = шлюз GET-only (Ubuntu).
- Админский пароль — разовый, только состав; в работе его нет.
- Для ИБ клиента главный ответ — **вариант 2 состава**, а не обещания про маскирование лога.
