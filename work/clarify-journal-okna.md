## Чего журналу не хватает

Список пробелов, из‑за которых кучи A / B-птичий и слой 2 нельзя разметить по журналу:

1. **Текст вопроса** — колонки нет (только `q_hash` / `q_len`); фраза везде «текста нет».
2. **Варианты clarify (слой 2)** — подписи/вопросы человеку, `src`, меры, сущности опций не пишутся; `fork_keys` на clarify всегда `[]`.
3. **Числа / атомы веток** — `atoms` на всех clarify пуст (`[]`); сходимость A не проверить.
4. **Признак сомнения модели** — колонки нет.
5. **Связь clarify → клик по конкретному варианту** — есть только `ticket_used` (булево) и `ticket_error`; нет id выбранного варианта / label.
6. **Стык с `ask_scope` / `ask_choice_memory`** — нет ключа на строку журнала; choice_memory не подтягивался автоматически.
7. **Пустой `user_hash`** — 64 clarify (из разметки «невидимо… пустой user_hash» / канал без пользователя): исход «бросил/второй круг» по user+channel не определить.
8. **Содержимое `intent_json`** — не варианты UI, а урезанный intent; для B-птичий по вариантам недостаточно.

Отклонения дословно: `\d ask_journal` на живой SereneDB падает (`pg_partition_ancestors` отсутствует) — схема снята через `information_schema.columns`.
