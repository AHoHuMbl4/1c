# Compound Ask (К8)

Слой **снаружи** `serene_ask`: составной вопрос раскладывается на **простые**
подвопросы, каждый уходит в MCP `ask_1c`, ответы складываются в таблицу атомов,
итог для человека собирается **из строк таблицы** — без разности, процентов и
других чисел, которых не было в ответах атомов.

Счёт, развилки A/B/C, люк и `decision_id` — внутри `serene_ask` / моста
`ask_1c`; этот скилл их не дублирует.

Справка: `{baseDir}/references/composite-vs-simple.md`,
`{baseDir}/references/atom-table.md`, `{baseDir}/references/ask-response-fields.md`.
Примеры планов: `{baseDir}/examples/`. Установка: `{baseDir}/INSTALL.md`.

## Когда этот скилл

Достаточно одного признака:

- два или больше **независимых срезов** («и …, и …», два периода, две сущности);
- сравнение периодов или величин («больше, чем …», «лучше прошлого»);
- **топ-N и число по каждой** позиции;
- перечисление нескольких однотипных подсчётов одним предложением.

Один период, одна мера, без сравнения и без списка позиций — **один** вызов
`ask_1c`, скилл не включается.

## Конвейер (четыре шага)

### 1. Разбитие на атомы

Каждый атом — **отдельный простой вопрос** для `ask_1c`, без местоимений на
соседей («там», «в прошлом» без явного периода).

Разбитие делает **агент** по смыслу фразы. Списки ключевых слов, имена таблиц
и полей 1С в скилл не входят.

План (внутренний):

| поле | смысл |
|------|--------|
| `composite` | `true` — дальше; `false` — один `ask_1c` |
| `synthesis` | `compare` \| `top_n` \| `table` |
| `atoms[]` | `id`, `question`, `label` |
| `compare` | при `compare`: `left_id`, `right_id`, `relation` |

### 2. Вызов `ask_1c` по каждому атому

```
ask_1c(question=<текст атома>, …)
```

Параллельные вызовы допустимы. На атом **не** переносится разбор сущности /
меры / периода из соседних атомов.

`focus`, `measure`, `decision_id` — только если их вернул предыдущий ответ
**этого же** атома (clarify того же подвопроса), по протоколу моста.

### 3. Таблица атомов

Шаблон — `{baseDir}/references/atom-table.md`:

| id | label | question | kind | body (фрагмент ответа ask_1c) |

- `kind` — из ответа (`answer`, `figures`, `clarify`, `no_data`, …).
- Числа и формулировки — **дословно** из текста / ATOM_JSON, без новых сумм.

### 4. Ответ человеку

Сборка **только** из строк таблицы:

- **`table`** — подпись + то, что вернул `ask_1c` по каждому атому;
- **`compare`** — обе пары «подпись + число/текст»; вердикт «больше / меньше /
  равно» по **двум готовым числам**; разность и процент **не** вводятся;
- **`top_n`** — таблица или список: позиция, подпись, значение из ответа.

Служебные id атомов и JSON плана — не в ответ человеку.

## Границы

| Внутри скилла | Снаружи (serene_ask) |
|---------------|----------------------|
| разбить фразу на простые вопросы | сущность, мера, период |
| N вызовов `ask_1c` | счёт в базе, гейт |
| таблица + prose из ответов | A/B/C, люк, options |

Не второй проход «понимания» поверх атомов.

## Опционально: проверка сборки (тесты, не бой)

Оффлайн-движок `{baseDir}/table.py` — только для замков и оркестрации: заполнить
таблицу из моков / ответов и собрать текст **без пересчёта**. В живом чате
агент следует шагам 1–4; CLI не обязателен.

```bash
python3 {baseDir}/test_table.py
```
