# Compound Ask (К8, черновик)

Слой **снаружи** `serene_ask`: составной вопрос человека раскладывается на
**простые** подвопросы, каждый уходит в MCP `ask_1c`, ответы складываются в
таблицу атомов, итог для человека собирается **из строк таблицы**.

Счёт, развилки A/B/C, люк и `decision_id` — внутри `serene_ask` / моста
`ask_1c`; этот скилл их не дублирует и не подменяет.

Подробнее: `{baseDir}/references/composite-vs-simple.md`,
`{baseDir}/references/atom-table.md`,
`{baseDir}/references/ask-response-fields.md`.

## Когда этот скилл

Признаки составного вопроса (достаточно одного):

- два или больше **независимых срезов** в одной фразе (два периода, две
  сущности, «и …, и …»);
- сравнение периодов или величин («больше, чем …», «лучше прошлого»);
- **топ-N и число по каждой** позиции («топ-3 и сколько у каждого»);
- перечисление нескольких однотипных подсчётов одним предложением.

Если вопрос — один период, одна мера, без сравнения и без списка позиций —
**один** вызов `ask_1c`, этот скилл не включается.

## Конвейер (четыре шага)

### 1. Разбитие на атомы

Каждый атом — **отдельный простой вопрос**, который можно отправить в
`ask_1c` без ссылок на соседей («там», «в прошлом» без явного периода,
«у него» без имени).

Разбитие делает агент по смыслу фразы человека. Списки ключевых слов,
имена таблиц и полей 1С в скилл не входят — завтра другая база.

Запиши план (для себя, не для человека):

| поле | смысл |
|------|--------|
| `composite` | `true` — идём дальше; `false` — шаг 1 завершён, один `ask_1c` |
| `synthesis` | `compare` \| `top_n` \| `table` — как собирать итог |
| `atoms[]` | `id`, `question`, `label` (короткая подпись строки) |
| `compare` | только при `synthesis=compare`: `left_id`, `right_id`, `relation` |

Примеры планов: `{baseDir}/examples/`.

### 2. Вызов `ask_1c` по каждому атому

Для каждой строки `atoms[]`:

```
ask_1c(question=<текст атома>, …)
```

Параллельные вызовы допустимы. На атом **не** переносится разбор сущности /
меры / периода из соседних атомов — это работа `serene_ask` на простом
вопросе.

`focus`, `measure`, `decision_id` — только если их вернул предыдущий ответ
**этого же** атома (clarify того же подвопроса), по протоколу моста.

### 3. Таблица атомов

После всех вызовов заполни таблицу (шаблон —
`{baseDir}/references/atom-table.md`):

| id | label | question | kind | ответ ask_1c (фрагмент) |
|----|-------|----------|------|-------------------------|

- `kind` — из ответа (`answer`, `figures`, `clarify`, `no_data`,
  `unavailable`, …).
- Числа и формулировки — **дословно** из текста / блока ATOM_JSON ответа
  `ask_1c`, без новых сумм, разностей и процентов.

Если атом вернул `clarify` — в ячейке видно уточнение и опции; итог для
человека **не** маскирует это под «нет данных».

Если атом вернул `no_data` / `unavailable` — строка таблицы это показывает;
частичный итог помечается явно (сколько атомов без числа).

### 4. Ответ человеку

Сборка **только** из строк таблицы:

- **`table`** — связный текст или markdown-таблица: подпись + то, что вернул
  `ask_1c` по каждому атому;
- **`compare`** — обе пары «подпись + число/текст» из двух атомов; вердикт
  «больше / меньше / равно» даётся по этим двум цитатам; новые числа
  (разность, процент, отношение) не вычисляются;
- **`top_n`** — нумерованный список или таблица: позиция, подпись атома,
  значение из ответа; пропуски и уточнения по строкам видны.

Служебные имена инструментов, JSON плана, внутренние id атомов — не в ответ
человеку.

## Границы (что скилл не делает)

| Внутри скилла | Снаружи (serene_ask / мост) |
|---------------|----------------------------|
| разбить составную фразу на простые вопросы | выбор сущности, меры, периода |
| N вызовов `ask_1c` | счёт в базе, гейт чисел |
| таблица + prose из ответов | исходы A/B/C, люк, `options`, билеты |
| передача clarify/no_data как есть | контракт ответа (PLAN_ANSWER_CONTRACT) |

Не второй проход «понимания» поверх атомов: атом уже простой вопрос для
`serene_ask`.
