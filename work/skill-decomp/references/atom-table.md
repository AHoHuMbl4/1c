# Таблица атомов

Рабочая структура между шагами 2 и 4 скилла. Не уходит человеку целиком.

## Колонки

| колонка | источник |
|---------|----------|
| `id` | из плана разбития |
| `label` | короткая подпись для итога («этот месяц», «поз. 2») |
| `question` | текст, ушедший в `ask_1c` |
| `kind` | тип ответа serene_ask (через текст моста) |
| `body` | фрагмент ответа `ask_1c`: готовая пара подпись+число или текст clarify |

## kind и видимость человеку

| kind | что попадает в `body` | в итоге человеку |
|------|----------------------|------------------|
| `answer` / `figures` | текст ответа или FIGURES-блок, числа дословно | подпись + значение |
| `clarify` | вопрос уточнения + перечень OPTIONS (без decision_id в prose) | «по [label]: нужно уточнение — …» |
| `no_data` | «нет таких данных» или эквивалент из ответа | явно, без подмены нулём |
| `unavailable` / ошибка | текст сбоя | явно, не скрывать за другими атомами |

## Правила сборки

1. **Ни одного числа**, которого нет в `body` какого-либо атома.
2. **Ни одного атома**, пропущенного в итоге, если по нему был вызов.
3. При `synthesis=compare` и `clarify` / `no_data` у одного из двух атомов —
   итог называет сравнение неполным и показывает обе строки таблицы.
4. При `synthesis=top_n` порядок строк = порядок атомов в плане (или порядок
   rank из единственного rank-атома, если декомпозиция не дробила топ).

## Шаблон markdown (для человека)

```markdown
| Подпись | Результат |
|---------|-----------|
| этот месяц | <из body mtd> |
| прошлый месяц | <из body prev> |
```

Для compare после таблицы — одно предложение, **цитирующее** обе ячейки, без
арифметики разности.

## Шаблон (внутренний, черновик)

```
id= mtd | label= этот месяц | kind= answer | body= …
id= prev | label= прошлый месяц | kind= answer | body= …
synthesis= compare | complete= partial|full
```

`complete=partial`, если хотя бы один атом без готового числа/ответа и не
`clarify`, ожидающий выбор человека в рамках того же turn.
