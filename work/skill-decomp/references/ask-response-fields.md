# Поля ответа ask_1c (для строк таблицы)

Мост `mcp_ask.py` возвращает **строку**. Скилл кладёт в `body` то, что нужно
человеку, без разбора JSON serene_ask снаружи моста.

## Что читать из текста ответа

| маркер в тексте | смысл для таблицы |
|-----------------|-------------------|
| обычный текст с числом | `kind` ≈ answer; `body` = фрагмент с парой подпись+число |
| `CLARIFY` / блок OPTIONS | `kind=clarify`; `body` = вопрос + варианты (без служебных id в финале) |
| FIGURES / несколько пар | `kind=figures`; каждая пара — как вернул мост; не склеивать в новое число |
| ATOM_JSON | опора для подписи/единицы; значения не переписывать |
| PRESENTATION_JSON | для канала (кнопки); в prose человеку — текст OPTIONS |
| «нет таких данных» | `kind=no_data` |
| сообщение о сбое / HTTP | `kind=unavailable` |

## Чего не делать

- не парсить prose regex-ом ради «удобного» числа, если структурированный
  блок уже дал значение;
- не суммировать несколько чисел из одного ответа в новое;
- не отбрасывать `partial` / oговорки свежести, если они есть в `body`;
- не подменять `clarify` ответом «0» или «нет данных».

## Параллельные атомы

Каждый вызов `ask_1c` — отдельная строка таблицы. Pending/clarify-lock моста
привязан к `(user, channel)` и тексту **конкретного** атома; смешивать
варианты разных атомов в одном `decision_id` нельзя.
