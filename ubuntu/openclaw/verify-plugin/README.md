# braine-verify — анти-галлюцинационный гейт слоя OpenClaw

Плагин OpenClaw (нативный, `definePluginEntry` + хуки `api.on`). Гарантирует
**кодом, а не промтом**, что бот-оболочка не «дорисовывает» факты поверх ответа нашего
braine («второго мозга»). Это требование владельца: «промты не держат».

## Идея
мозги уже отдают обоснованный ответ (гейты + цитаты). Риск — LLM бота (DeepSeek),
«оживляя тон», добавит/исказит число (ИНН, сумму, дату, цену, код). Плагин детерминированно
сверяет **жёсткие числовые токены** исходящего сообщения с эталоном инструмента за этот же ход.
Заземляет ОБА инструмента: факты `ask_1c` (braine) и числа `report_1c` (отчёты SereneDB).

## Как работает (четыре хука)
1. **`after_tool_call`** — когда бот зовёт MCP-инструмент (`ask_1c` **или** `report_1c`), захватываем
   его ответ как эталон хода. Ключ — **`ctx.sessionKey`** (у `message_sending` нет `runId`, а доставка
   идёт ПОСЛЕ `agent_end` → эталон нельзя терять; сбрасываем на новом `runId`, вызовы хода сливаются).
2. **`message_received`** — запоминаем числа из ввода пользователя (если он сам назвал номер
   заказа/ИНН, эхо этого числа — не галлюцинация).
3. **`message_sending`** — из исходящего текста берём числовые токены (≥ `minDigits` цифр,
   с учётом группировки `7 727 406 020`, `1 234,56`). Каждый обязан быть обоснован эталоном
   инструмента или вводом пользователя. Решение:
   - все обоснованы → **allow** (отдаём «живой» ответ);
   - есть необоснованные, эталон был и с данными → **replace** на дословный ответ инструмента;
   - эталон был, но **инструмент упал** (`serviceErrorMarker`) → **replace** на строку про сбой.
     Это НЕ «нет данных» (п. 18 контракта): сказать «таких данных нет» при неотвечающем сервисе —
     худший из возможных ответов, потому что звучит уверенно;
   - эталон был, но инструмент сказал «нет данных» → **replace** на безопасную строку;
   - эталона не было и есть выдуманное длинное число (ИНН/счёт/телефон, ≥ `highRiskDigits`) →
     **replace** на строку «не могу подтвердить это число».
     🔴 Раньше здесь был **cancel** — доставка отменялась, и взамен не уходило НИЧЕГО: человек
     видел молчание бота. Контракт (п. 21) требует, чтобы ответ дошёл, а п. 12 — чтобы выдумка не
     ушла; честная строка выполняет оба, тишина не выполняла ни одного.
   Плюс `stripInternal` (если включён) режет из текста внутреннее (SQL/пути/маркеры).
4. **`reply_payload_sending`** — **подпись к медиа проходит ТОТ ЖЕ числовой гейт** и ту же
   зачистку (у фото caption идёт мимо `content` хука `message_sending`). До 02.08 здесь звался
   только `stripInternal`, то есть подпись к графику — место, где числа и живут, — не сверялась
   с эталоном вообще.

Чистая логика — в `verify-core.js` (без зависимостей, тест `test-verify.mjs`).
`index.js` — только подключение к хукам и состояние хода в памяти процесса.

## Конфиг (конфиг-нейтрально, дефолты в коде `verify-core.js`)
`plugins.entries.braine-verify.config` (всё опционально — дефолты в коде):
- `toolNames` (`["ask_1c","report_1c"]`) — имена MCP-инструментов, чьи ответы = эталон (матч по суффиксу
  `<server>__<tool>`). (`toolName` — устаревший одиночный ключ, оставлен для совместимости.)
- `minDigits` (`4`) — минимальная длина числа для сверки, когда эталона НЕТ. `3` — строже (ловит
  3-значные цены), но чаще трогает риторические числа (проценты, «100%»).
- `minDigitsWithRef` (`1`) — когда эталон ЕСТЬ, сверяются все числа: количества и штуки — такие же
  факты. Нумерация пунктов списка (`1.`, `2.` в начале строки) снимается до сверки — это разметка.
- `highRiskDigits` (`5`) — длина числа, которое без эталона считаем выдумкой.
- `noDataMarker` (`[NO DATA`), `clarifyMarker` (`[CLARIFICATION NEEDED`),
  `serviceErrorMarker` (`[SERVICE ERROR`) — 🔴 **протокол между кодом и кодом**: те же строки шлёт
  `ubuntu/openclaw/mcp_ask.py`. Менять только с обеими сторонами разом, иначе правило молча
  отключается, а служебная пометка уходит клиенту.
- `noDataReply` / `serviceErrorReply` / `unverifiedReply` — строки клиенту: данных нет / сервис
  данных не отвечает / число не подтверждено. ⚠ Умолчания русские — см. `docs/BOXED_BLOCKERS.md`.
- `refTtlMs` — TTL эталона хода в памяти.
- `stripInternal` (`true`) — детерминированно резать внутреннее (SQL/серверные пути/наши маркеры).
- `debug` (`false`) — лог решений гейта через штатный `api.logger` (смотреть: `openclaw logs`).

## Границы (честно)
- Сверяются **числа**. Подмена имени/текста без числа не ловится детерминированно
  (имена — нечёткие; для них работает связка «braine = источник» + замена на эталон при любом
  необоснованном числе). Числовые факты (ИНН/суммы/даты/цены) — самый опасный класс — закрыты.
- 3-значные факты при `minDigits=4` пропускаются (компромисс против ложных срабатываний на
  процентах/годах). Владелец может выставить `minDigits=3`.

## Тест и установка
```bash
node test-verify.mjs                 # оффлайн-юниты чистой логики (83 кейса, без базы и сети)
npm pack --pack-destination /tmp     # собрать tgz
openclaw plugins install npm-pack:/tmp/openclaw-braine-verify-1.1.2.tgz --force
openclaw plugins inspect braine-verify --runtime --json   # проверить, что хуки зарегистрированы
# включить: plugins.allow += "braine-verify"; plugins.entries.braine-verify.enabled = true
```
