# «Второй мозг» на данных 1С

AI-ассистент компании по данным из 1С — **строго на чтение**, ничего в 1С не меняя. Отвечает
в Telegram живым языком на вопросы по данным: кто, что, сколько, когда.

> **Перед началом работы — [`docs/HOW_NOT_TO.md`](docs/HOW_NOT_TO.md).** Каждый пункт
> там оплачен потерянным днём, упавшим сервером или неверным числом у клиента.
>
> **Чем этот продукт обязан быть — [`TARGET.md`](TARGET.md).** Что менялось и чем
> доказано — [`CHANGELOG.md`](CHANGELOG.md).
> Это утверждённый владельцем
> контракт из 19 пунктов. При расхождении любого документа с ним прав он.

**Статус: работает на стенде (Бухгалтерия 3.0), до продакшена не доведён.** Пишешь боту в
Telegram → он отвечает по реальным данным 1С, приёмочный набор проходит 8 из 8. Открыто
несколько пунктов `TARGET.md`, они перечислены в [`docs/STATE_2026-07-26.md`](docs/STATE_2026-07-26.md).

> 🚀 **Развернуть на новом сервере / подключить новую 1С-базу → [`docs/RUNBOOK_DEPLOY.md`](docs/RUNBOOK_DEPLOY.md)**
> (пошагово, воспроизводимо; §10 — слой аналитики и подключение новой базы без хардкода).

## Как это работает

Всё строится вокруг SereneDB: она и хранит, и ищет. Модель не считает и не ищет —
она нужна только для смысла (п. 19 `TARGET.md`).

```
Windows (1С)              Ubuntu LXC (весь наш контроль)
┌────────────┐  по IP   ┌───────────────────────────────────────────────────────────────┐
│ 1С:база    │ (роутер  │ OData-шлюз :6011 ── только GET (read-only)                     │
│ └ IIS      │  .1)     │   └ serene_sync ──► витрина SereneDB :7890                     │
│   └ OData ─┼─────────►│        └ serene_search_build ──► корпус + инвертированный      │
│  (ai_reader│          │                                   индекс (BM25 + вектор)       │
│  read-only)│          │                                                                │
└────────────┘          │  Вопрос: человек → Telegram @бот → OpenClaw (тон, DeepSeek)     │
                        │     └ serene_ask :8091 — ВЕСЬ ответ строится здесь:            │
                        │         1. модель понимает вопрос (маленький контекст)         │
                        │         2. ИНДЕКС SereneDB отбирает строки                     │
                        │         3. БАЗА считает суммы/количества по всем строкам       │
                        │         4. модель формулирует фразу из посчитанного            │
                        │         неоднозначно → уточняющий вопрос, а не догадка         │
                        │     → verify-плагин (ГЕЙТ КОДОМ: числа сверяет, внутреннее режет)│
                        │  1c-bot-monitor: алерт в Telegram, если что-то упало            │
                        └───────────────────────────────────────────────────────────────┘
```

⚠ **Слой braine (RAG на OWUI/pgvector) и инструмент `report_1c` (NL→SQL) выведены из контура**
(решение владельца 26.07). Графики по данным вернутся позже — как дополнение ПОСЛЕ ответа,
а не как способ его получить.

- **Канал чтения — штатный OData 1С на IIS** (служба Windows): авто-старт, многопоточно, переживает
  ребут. Не встроенный MCP-тулкит — он для прода не годится (`docs/TOOLKIT_TRANSPORT_ROOTCAUSE.md`).
- **Read-only 1С — два слоя:** пользователь `ai_reader` (нет прав записи) + шлюз (режет всё, кроме GET).
- **Один движок — SereneDB.** Инвертированный индекс на IResearch несёт и словесный поиск (BM25,
  фразы, префикс, опечатки), и вектор. Считает база, по всем строкам, а не по выборке.
  Эмбеддинги — **только Qwen `text-embedding-v4` @ 1536** (DashScope).
- **Контекст модели не растёт с базой.** Схема базы и перечень колонок в модель не уходят —
  ограничение держится кодом (символьные бюджеты), а не просьбой в промте.
- **OpenClaw** — диалоговая оболочка тона (нативно, `@test1c_mcp_bot`). Отвечает живо, но
  факты берёт только из инструментов.
- **Анти-галлюцинации — КОДОМ, не промтом** (правило владельца): гейт `verify-плагин` детерминированно
  сверяет числа ответа с данными и режет внутреннее (SQL/пути). Промт держит только тон.
- **Zero-touch:** настроил один раз → работает само, переживает перезагрузки; мониторинг алертит при сбое.

Полная картина — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Правила проекта
- 🔴🔴 Вся работа — **только внутри этой папки `1c/`** (в соседние папки воркспейса не смотреть).
  Каждое изменение — коммит + push в `origin/main`.
- 🔴 **1С только читаем** — инвариант. Ни один запрос не меняет данные 1С (2 слоя + read-only роль SereneDB).
- 🔴 **Правила/ограничения — КОДОМ, не промтом** (промт не держит): анти-галлюцинации, анти-слив,
  read-only — детерминированным кодом/гейтом/ролью, персона — только тон.
- 🔴 **Без хардкода.** Настройка, которую человек может заполнить, только зная конкретную базу, —
  такой же дефект, как имя в коде.
- 🔴 **Модель не считает и не ищет** (п. 19 `TARGET.md`). Считает база, отбирает индекс.
- Эмбеддинги — **только Qwen** (как braine), ollama не используем.
- На серверах (LXC/Windows) состояние меняем только по явной инструкции владельца.
- Перед любым изменением базы 1С — бэкап (`windows/scripts/backup-1c.ps1`).
- Секреты — в `credentials/` (вне git); на серверах — в `/etc/*.env` (chmod 600).
