# setup-1c-odata.exe — автонастройка Windows-стороны одним файлом

Готовит Windows к работе «второго мозга»: **1С → IIS → OData (только чтение)**, чтобы сервер Ubuntu
мог забирать данные. **Руками остаётся ровно одно — создать в 1С пользователя-читателя** (это
осознанно не автоматизируется, см. «Почему»).

Версия **1.2.0**: добавлен **блок 2 — агент пакетного транспорта** (Windows → Ubuntu,
ТЗ `work/installer-exe/AGENT_TZ.md`): активен, когда рядом с exe лежит комплект
(`packet-setup.json` + `packet-agent.exe` + `age.exe` + `zstd.exe`). Без комплекта
поведение идентично 1.1.0. Раньше: префлайт системы и платформы в начале, два явных
варианта состава OData, туториал «добавить веб-модуль» без сноса 1С, проверка связи
с Ubuntu (`--ubuntu-host`), перечитывание `enable="true"` после публикации.

- Пошагово вручную (если нужно понять, что происходит) — `docs/RUNBOOK_DEPLOY.md` §1-6.
- Состояние Windows-стороны и адреса — `windows/README.md`.
- Рабочий план доводок — `work/installer-exe/PLAN.md`.

## Быстрый старт

```bat
:: 1) посмотреть, что будет сделано — НИЧЕГО не меняет (+ проверка связи с Ubuntu)
setup-1c-odata.exe --check --base "C:\1c\bases\ваша_база" --ubuntu-host 192.168.56.42 ^
                   --external-url http://192.168.56.1:6003/1c/odata/standard.odata/

:: 2) настроить (перед составом OData — выбор: пароль админа ИЛИ ручной туториал)
setup-1c-odata.exe --base "C:\1c\bases\ваша_база" --ubuntu-host 192.168.56.42 ^
                   --external-url http://192.168.56.1:6003/1c/odata/standard.odata/ ^
                   --scope analytics --reader-user ai_reader

:: 3) без пароля админа 1С (состав зададите в Конфигураторе по туториалу)
setup-1c-odata.exe --base "C:\1c\bases\ваша_база" --skip-scope --ubuntu-host 192.168.56.42
```

Запускать **от имени администратора** (файл сам попросит повышение прав). Полная справка — `--help`.

## Что делает (13 шагов, все повторно безопасны)

| # | Шаг | Что именно |
|---|---|---|
| 1 | Окружение | права администратора, версия Windows, ожидание перезагрузки |
| 2 | Платформа 1С | ищет версии, выбирает новейшую **с веб-модулем**; проверяет `wsisapi.dll` и `comcntr.dll`; определяет разрядность по PE-заголовку |
| 3 | База | файловая (проверяет `1Cv8.1CD`) или клиент-серверная (`Srvr/Ref`) |
| 4 | Компоненты IIS | доустанавливает недостающие; понимает «нужна перезагрузка» и умеет продолжить |
| 5 | Служба W3SVC | автозапуск + запуск |
| 6 | Публикация | `webinst -publish -iis`; если уже опубликовано — не трогает |
| 7 | OData | `standardOdata enable="true"` в `default.vrd` (с резервной копией файла) |
| 8 | Пул приложений | создаёт **отдельный** пул нужной разрядности, отключает выгрузку по простою |
| 9 | ISAPI | разрешает модуль 1С в ограничениях IIS |
| 10 | Права | выдаёт IIS доступ к каталогу базы (по SID — не зависит от языка Windows) |
| 11 | Бэкап | zip-копия базы **перед** единственным изменением в ней |
| 12 | Состав OData | через COM задаёт, какие объекты отдавать (`--scope`) |
| 13 | Проверка | без пароля → ожидает **401**, с паролем → **200** и список сущностей |

Итогом печатает и сохраняет в файл готовый блок для сервера Ubuntu (`ODG_UPSTREAM/ODG_USER/ODG_PASS`).

## Блок 2 — агент пакетного транспорта (с версии 1.2.0)

Активен **только когда рядом с exe лежит комплект** от сервера Ubuntu:
`packet-setup.json` (base_id, токен, pubkey, адрес приёмника) + `packet-agent.exe` +
`age.exe` + `zstd.exe`. Без комплекта установщик работает ровно как 1.1.0.

Что делает блок (после успешной проверки OData, шаги 1–13 не меняются):

| # | Подшаг | Что именно |
|---|---|---|
| 1 | Комплект | валидирует `packet-setup.json` (base_id, `age1…`, https), проверяет наличие и запуск `age.exe`/`zstd.exe` |
| 2 | Префлайт | исходящий HTTPS на приёмник (`GET /health` → `packet-server-ok`; входящие порты на Windows не нужны), место под данные агента (≈ база/4 + индекс версий) |
| 3 | Установка | копирует exe в `C:\1c\packet\`, пишет `agent.ini` (токен и пароль читателя — в лог `***`), права на ini — **только Administrators и SYSTEM** |
| 4 | Автозапуск | задачи планировщика «1C Packet Agent» (при старте системы, SYSTEM) и сторож (каждые 5 мин) |
| 5 | Пробная посылка | `packet-agent.exe --smoke`: тестовый пакет до `verified` от приёмника; код выхода exe — **0 только при подтверждённой доставке** |

Ключи: `--packet-setup <файл>`, `--packet-kit <каталог>`, `--packet-dir <путь>`,
`--skip-packet`. Ошибки приёмника переводятся в понятные строки («токен отклонён»,
«комплект уже использовался», «приёмник в карантине — звоните нам»).

## 🔑 Пароль администратора 1С: клиент его НЕ отдаёт

Пароль администратора 1С нужен **ровно один раз и ровно для одного шага** — задать состав OData
(шаг 12): «какие объекты вообще видны через OData». Это административная операция в базе, без прав
её не сделать. **Но передавать нам пароль клиенту не нужно** — есть три рабочие модели:

| Модель | Как | Пароль |
|---|---|---|
| **1. Клиент запускает exe сам** (штатная) | отдаём файл, их админ запускает и вводит пароль в скрытый запрос | не покидает их машину: не пишется в лог, не хранится, никуда не отправляется |
| **2. Админ клиента задаёт состав сам** | в Конфигураторе: Администрирование → Состав стандартного интерфейса OData; мы запускаем exe с `--skip-scope` | нам не нужен вообще |
| **3. Совместный сеанс** | мы ведём установку, пароль вводит их администратор | нам не нужен |

⚠ **В работе пароль администратора не нужен вообще.** После настройки система живёт под
пользователем-читателем (`ai_reader`) — только чтение. Админский пароль — исключительно разовый,
на этапе установки, и только для шага 12.

### Программа сама предлагает выбор

Если пароль не передан ключами, перед шагом 12 (и **до** резервного копирования, чтобы не тратить
время зря) программа останавливается и объясняет администратору: что осталось сделать, зачем нужен
пароль, **что именно она с ним сделает** (скрытый ввод → окружение дочернего процесса → не на диск,
не в лог, не в сеть, использовать один раз) и **что именно изменится в базе** (только список видимых
через OData объектов; документы/справочники/проводки не трогаются). Дальше — два варианта:

```
ВАШ ВЫБОР:
    1) Ввести пароль — программа сделает всё сама (несколько секунд).
    2) НЕ вводить — программа не тронет базу и напечатает точную пошаговую
       инструкцию, как сделать это руками в Конфигураторе.
```

При выборе **2** база не изменяется, а в конце печатается и сохраняется в файл
`C:\1c\logs\1c-odata-ручная-настройка.txt` пошаговая инструкция: копия базы → Конфигуратор →
Администрирование → «Состав стандартного интерфейса OData…» → какие разделы отметить (списком, на
русском) → как проверить результат. Этот файл можно переслать тому, у кого есть пароль.

Для скриптов: `--unattended` без `--admin-user` не «падает молча», а сразу говорит, что нужно либо
передать учётные данные, либо запускать с `--skip-scope`.

Если состав OData уже задан (например, база переезжает, а публикацию поднимают заново) — пароль не
нужен и подавно: состав хранится **в самой базе** и переживает перепубликацию, запускайте с `--skip-scope`.

## Почему пользователь-читатель — руками

Это **граница безопасности** всей системы: именно права этого пользователя гарантируют, что 1С только
читают. Набор ролей зависит от конфигурации (в типовых на БСП это профиль **«Только просмотр»**), и
создавать его программно — значит рисковать выдать лишнее. Поэтому инструмент его **не создаёт**, но
умеет **проверить**: с `--reader-user` он скажет, существует ли пользователь, покажет его роли и
**предупредит, если у него есть административная роль**.

Как создать: 1С:Предприятие → Администрирование → Настройки пользователей и прав → Пользователи →
сначала администратор с полными правами, затем `ai_reader` с профилем «Только просмотр».

## Что происходит, если чего-то не хватает

Инструмент не падает с непонятной ошибкой — он объясняет причину и что делать.

| Ситуация | Поведение |
|---|---|
| Запущен без прав администратора | манифест сам запросит повышение; если отказано — код 2 и подсказка |
| Платформа 1С не установлена | код 3 + как установить / ключ `--platform-dir` |
| Платформа **без веб-модуля** (частая причина «OData не работает») | код 3 + **полный туториал** «Изменить установку» (НЕ снос 1С) → файл `1c-odata-добавить-веб-модуль.txt` |
| Несколько версий платформы | берёт новейшую **с веб-модулем**, все найденные печатает; выбор — `--platform-version` |
| Платформа x86 против x64 | сам ставит разрядность пула IIS и вызывает PowerShell нужной разрядности для COM |
| Компоненты IIS отсутствуют | доустанавливает; если нужна перезагрузка — код 10, сохраняет команду для повтора (`--auto-resume` продолжит сам) |
| Windows Server вместо Windows 10/11 | если `Get-WindowsOptionalFeature` недоступен — переходит на `Install-WindowsFeature` |
| Каталог публикации занят другой базой | останавливается и объясняет; перезапись — только явным `--force` |
| Уже всё настроено | шаги помечаются ПРОПУСК, изменений нет (можно запускать сколько угодно раз) |
| COM-коннектор не зарегистрирован | сам выполняет `regsvr32` нужной разрядности из каталога `bin` и повторяет |
| Неверный пароль администратора 1С | распознаёт ошибку 1С и говорит по-русски, что именно не так |
| База открыта в конфигураторе / заблокирована | распознаёт и просит закрыть сеансы |
| Нет лицензии 1С | распознаёт и просит активировать |
| База восстановлена из копии и ждёт вопроса «Это копия ИБ?» | COM не зависает навсегда — таймаут и точная подсказка «зайдите в базу один раз вручную» |
| Мало места под бэкап | считает размер базы и свободное место, останавливается заранее |
| Бэкап не удался | **состав OData не меняет** (правило: перед изменением базы — всегда бэкап) |
| В базе нет пользователей | видит `200` без пароля и предупреждает: OData открыт всем в сети |
| Состав OData пуст | проверка это ловит и говорит, каким ключом починить |
| Пул остановлен / 404 / 500 | по коду HTTP выдаёт конкретную причину и команду |
| Разделы (регистры и т.п.) отсутствуют в конфигурации | не ошибка — пропускает и пишет в лог |
| Объект опубликован, но пользователю не положен | нормально: права 1С действуют ПОВЕРХ состава — такой объект отдаёт «Доступ запрещен» (код 20). Это защита, а не сбой настройки |

## Состав OData (`--scope`)

| Значение | Что публикуется |
|---|---|
| `default` (по умолчанию) | справочники + документы |
| `analytics` | + регистры накопления/сведений/бухгалтерии, планы счетов, перечисления — **нужно для оборотов и остатков** |
| `all` | все поддерживаемые разделы |
| список | например `catalogs,documents,accumulation-registers` |

Полный список ключей разделов — в `--help`.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 2 | нет прав администратора |
| 3 | не выполнены предусловия (нет платформы / веб-модуля / базы) |
| 4 | ошибка на шаге настройки |
| 5 | ошибка в аргументах |
| 10 | компоненты IIS установлены — **нужна перезагрузка**, затем запустить снова |
| 20 | настроено, но итоговая проверка не прошла |
| 30 | агент пакетного транспорта: установка или пробная посылка не подтверждена |

## Безопасность

- **Ничего не пишет в данные 1С.** Единственное изменение в базе — *состав* интерфейса OData
  (какие объекты отдавать), и только после успешного бэкапа.
- **`--check`** — полностью read-only режим: показывает план, не меняя ничего (проверено на живом стенде).
- **Пароли не попадают ни в командную строку, ни в лог**: спрашиваются скрытно либо берутся из
  переменной окружения (`--admin-password-env`), в COM передаются через окружение процесса, в логе — `***`.
- Отдельный пул приложений — чтобы настройки 1С (разрядность, время жизни) **не ломали другие сайты** IIS.
- `--open-firewall <сеть>` открывает входящий 80/TCP **только для указанной подсети**, а не всему миру.

## Сборка из исходников

Зависимостей нет: компилятор входит в состав .NET Framework, который есть на любой современной Windows.

```bat
build.cmd
:: -> build\setup-1c-odata.exe
```

Файлы: `src\Sys.cs` (лог, запуск процессов, PowerShell, системные проверки), `src\Steps.cs` (шаги),
`src\Packet.cs` (блок 2 — агент пакетного транспорта), `src\Program.cs` (сценарий, аргументы, отчёт),
`src\app.manifest` (запрос прав администратора).

⚠ **Два разных каталога — намеренно:**
- `dist\setup-1c-odata.exe` — **готовый** бинарь из репозитория, можно запускать сразу;
- `build\` — локальная сборка, **в `.gitignore`**.

Так сделано, потому что иначе `git pull` на машине, где уже собирали локально, падает с
`untracked working tree files would be overwritten by merge` — и репозиторий молча остаётся старым.

## Лог и результат

- Лог каждого запуска: `C:\1c\logs\setup-1c-odata_<дата>.log` (полные команды и их вывод).
- Данные для Ubuntu: `C:\1c\logs\1c-odata-connection.txt`.
