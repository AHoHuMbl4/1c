## Простота (решение №10)

v2 длиннее v1 за счёт обязательных правок C1–C4 (гейт покрытия, oversize-хвост, бэкап векторов, сухой такт, уточнение контракта §0) — это не расползание механизма, а фиксация границ приёмки и fail-closed.

| Кандидат «убрать» | Можно без потери контракта? |
|---|---|
| Этап 1 или этап 2 | **Нет** — уже разобрано в C2; §8 фиксирует |
| §1.3 memory_limit | Спорно: unmatched-резка — главный фикс OOM; session limit — страховка cookbook. Дешёвый SET, не новый механизм. Оставить. |
| §2.1 (б) oversize-хвост | **Нет** для живучести: без него V5 на базе с >50% коллизий = огромный батч; молчаливый 5-часовой монолит без следа тоже запрещён |
| §2.1 (г) гейт order∪tail | **Нет** — п.13 |
| §3.4 сухой такт | Не продукт; слой приёмки. Убрать = слабее доказательство до merge. Оставить. |
| §3.3 бэкап | **Нет** при допуске потери векторов = 0 (§0.3) |
| CHECKLIST_SEARCH_FIX (из C2 «желательно») | В v2 **не добавлен** — правильно; не раздувает |

Лишнего пункта, который можно снять без потери контракта «минуты + из коробки + 0 векторов / 0 молчаливых дыр», **нет**.
