## 2. Правка 2 — гейт хвоста ↔ `chunk_cells`

### Внесена?

§2.1(б): `tail_rows × ncols > chunk_cells` (экв. `tail_rows > chunk_rows`); при любом
исходе — `tail_rows`/`nrows`/`ncols` в `search_quality`. M2 (§2.5) — тот же порог → mono.

### Корректна ли привязка к коду `:1389-1463`?

**Да.**

| Код | Смысл |
|---|---|
| `:1387-1406` | `chunk_cells` = floor(memory_limit×0.25 / ws_bytes_per_cell) — бюджет ячеек порции |
| `:1454-1456` | `chunk_rows = floor(chunk_cells / ncols)` |
| `:1465-1469` | порции режутся по `chunk_rows` |

Эквивалентность для целых `tail_rows`:
`tail_rows × ncols > chunk_cells` ⇔ `tail_rows > floor(chunk_cells/ncols)` —
порог на одном и том же целом (floor-арифметика). Смысл гейта: хвост больше одной
разрешённой порции → тот же класс workload, что монолит. Доля «½ nrows» убрана.

На окне realiz (якорь C4): ~2776×~126 ≈ 350k < `chunk_cells`≈627k → V5 проходит;
катастрофа «хвост ≈ таблица» и кейс «хвост > одной порции» ловятся; 40%-видимость —
через обязательную запись quality.

**Вердикт П2:** закрыта; привязка верная.

## 3. Правка 3 — атомарный tail+маркер

### Внесена?

§2.3: одна строка `\gexec`
`'BEGIN; EXECUTE p_doc_tail(...); INSERT INTO tmp3_pdoc_tail_done ...; COMMIT'`;
жизненный цикл `_done` = progress/stage; finalize без маркёра при непустом tail → `error()`.

### Закрывает окно «tail есть, маркёра нет»?

**Да, при условии что вся строка уходит на сервер одним multi-statement вызовом.**

Доки SereneDB (*Multi-Statement Transactions*): несколько операторов через `;` в одном
батче — одна (неявная) транзакция; ошибка любого → откат предшествующих. Явный
`BEGIN…COMMIT` внутри той же строки усиливает тот же контракт: обрыв/`ON_ERROR_STOP`
до `COMMIT` не оставляет stage без маркёра. Повтор после отката чист — раздувания нет.
Файл уже `\set ON_ERROR_STOP on` в шапке `corpus_build.sql:2` — падение statement валит
скрипт; до finalize с «вечным STOP» из-за хвоста без маркёра этот путь не должен доходить.

### Риск многооператорной строки в `\gexec`

| Риск | Оценка |
|---|---|
| psql `\gexec` шлёт ячейку целиком (PQexec / simple query) | ожидаемо; иначе паттерн мёртв — **обязан** поймать M2 до выката |
| неявная транзакция батча + явный `BEGIN` | теоретический конфликт вложенности; доки разрешают и multi-statement, и `BEGIN TRANSACTION`. Смягчение: даже `EXECUTE; INSERT _done;` **без** BEGIN уже атомарны по тому же разделу доков |
| `ON_ERROR_STOP` mid-batch | fail → предшествующее откатывается; маркер не пишется — окно D4-Н2 не открывается |
| нет прецедента `BEGIN;…;COMMIT` в `\gexec` в дереве | новый паттерн; замок — M2 resume «не раздувает stage» |

**Вердикт П3:** окно D4-Н2 **закрыто спецификацией**. Остаточный риск — механика
первого внедрения multi-stmt в `\gexec` (не дыра плана): закрывается M2 до выката;
при странностях с `BEGIN` — упростить до двух операторов без явного BEGIN (доки уже
дают атомарность батча). Не требует нового круга правок плана.

## 5. Если всё равно сломается — первый зелёный прогон v3

**Самый вероятный отказ:** сухой №0 (§3.4) — **multiset
`(content_hash, row_key)` финального `tmp3_corpus` после V5+finalize ≠ эталону
монолита v10** (74 982 / `57ad85de…`) на `document_реализациятмц`.

Почему именно это:
- этап 2 меняет путь сборки (dup→хвост, новый `p_doc_tail`, гейт покрытия,
  stage_gate fold=`nrows`); семантика ключей «не меняется» — утверждение плана, не
  замер на новом коде;
- класс расхождений (NULL/«|», DISTINCT keyvals, QUALIFY/fold, порядок агрегатов)
  уже горел в аудитах A/D; живой замер «витрина=74982» закрыл fold-гипотезу, но не
  тождество **нового** SQL хвоста монолиту;
- merge/OOM после резки unmatched — второй эшелон и ловится позже; №0 merge не зовёт.

**Где план ловит:** §3.4 — mismatch → **merge не зовём**, разбор; векторы боевого
корпуса не трогаются; бэкап §3.3 ещё не нужен для отката данных. M2 обязан поймать
раньше на фикстуре — если M2 зелёный, а №0 красный, это дрейф окна/формулы, не «тихий»
провал.

Второй по вероятности (оркестратор): пропуск предусловия → realiz ∉ build → V5 не
исполняется / эталон бессмыслен — ловится §0.1/§3.4 **до** долгого прогона, если
процедуру не сократят.
