## 3. C4 — норм-функция имён: SPANS на входе probe (и только probe)

ЕДИНАЯ span-функция: spans = непрерывные многословные фрагменты вопроса (>=2 токенов по
порядку слов, в т.ч. через границы term-групп); норм-склейка (lower без пробелов,
`_homonym_norm` z21:831). 🔴 Алгоритм при >=2 spans: перебираются ВСЕ spans длины >=2;
hit = любой с d <= допуск; SUPERSEDE — OR всех hit-exprs (приоритет shortest-hit; norm-тег ставится ТОЛЬКО после живого count(*)>0 hit-expr — иначе группа остаётся unmatched);
замок на тройке токенов Q5 («регистре», «реализации», «ТМЦ»). 🔴 ГАРД exclude-only:
src известен ∧ span DL-хитит хвост/label src → группа ИСКЛЮЧАЕТСЯ (понятие (iii)),
SUPERSEDE/match-expr для неё ЗАПРЕЩЁН (сужение строк по имени сущности = п.13). В probe (z06:43–145), ДО resolve_values; триггер: (>=1
UNMATCHED) ∨ (у покрытой группы hit только fuzzy/part). 🔴 SUPERSEDE: span перезаписывает
exprs покрытых групп с hit ∈ {unmatched, fuzzy, part}; exact/slop НЕ трогаются
(фикстура «обе группы exact» — span не применяется; ложный fuzzy — вытесняется) + diag-
тег «norm» каждой покрытой. R-C assert: matched == n_groups ∧ kind/expr == norm (для
fuzzy-фикстуры). Предикаты разведены: wiki — скалярный DL к хвосту src (закрытый набор ~1.5k); probe —
index-backed термовый ts_levenshtein(склейка, допуск) на doc (штатный путь z06:74–75;
hit-expr SUPERSEDE = doc @@ ts_levenshtein(...)); ts_like — только точная склейка. Гардины:
мин-длина 8; допуск 1 (2 при len>=16); синтетика коротких пар у порога + НЕГАТИВЫ «похожий хвост другого src» (DL=1 на чужой базе — не sole, меню). CamelCase-
однотокенник — штатный exact (граница). Граница: честный no_data для отсутствующих
значений.
