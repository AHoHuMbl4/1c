сущностей и мер → меню прочтений при >1 → ответ). Режим: ТОЛЬКО ЧТЕНИЕ кода. Ничего

## Контекст дефекта

Контракт «один путь»: любое >1 прочтение → меню (readings_menu), ровно одно → сразу
ответ; отказ законен ТОЛЬКО если данных реально нет; молчаливый выбор при >1
прочтении — дефект. Прогон 67: 6 вопросов умерли отказом при живых данных. Твоя
зона — ступень выбора сущности (wiki choice) и меры (clarify memory): где верный
кандидат теряется ДО меню, где один кандидат забирается молча, где провал верификации
убивает вопрос вместо меню.

2. z21: `_homonym_norm` — точное место, что нормализует (регистр/пробелы/склейка?),

   post_verify) — как устроен сейчас.
3. z14: выбор меры — measure_choice, _word_hits_text (exact/alias хиты), ветка
   len==1 → 'single' без проверки слова; proven (measure_already_proven,
   choice_levels_proven); где мера выбирается молча при неоднозначности; где вопрос

4. Оба файла: ВСЕ ветки, где результат — пустота/None без меню и без ответа

   доступен ЦЕЛИКОМ — чтобы его можно было отдать LLM-резолверу «где что» до
   среза/выбора лидера.

## Формат реестра c-lens3-choice.md

- §1 пайплайн z21 (пул → лидер → верификация → меню/leader; константы отсечения);
- §2 пайплайн z14 (мера: хиты, single-шорткорт, proven, тикеты/decision_id);
- §3 таблица «точек смерти»: file:line → механизм → условие → чем грозит;
- §4 _homonym_norm и прочая нормализация: что есть, сигнатура, call-site'ы;
- §5 точки отдачи полного пула в резолвер (до среза).

Только измеримое: каждая строка реестра обязана иметь file:line. Мнений «наверное» —
не писать; если что-то не нашёл — так и написать «не найдено».
