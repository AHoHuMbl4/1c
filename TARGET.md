# Каким должен быть результат

Утверждено владельцем. **Изменять и дописывать этот файл без его явного указания
запрещено.** Всё остальное в проекте — доки, планы, код — подчинено этому документу;
при расхождении прав он.

---

## Требования

1. **Полноценный продакшен.** Не MVP, не прототип — продукт.

2. **Бот отвечает на основе данных из 1С.**

3. **Ответы без ошибок, без галлюцинаций, детерминированно на данных.**

4. **На Windows стоит 1С. Там же ставим PostgreSQL.**

5. **Эмбеддинг — через API Alibaba Qwen.**

6. **На сервере Ubuntu стоит SereneDB, через неё идёт поиск в базе.**

7. **Поиск — ТОЛЬКО нативными средствами SereneDB.**

8. **Всё строится вокруг SereneDB — это главное преимущество системы.**

9. **Без хардкода и подстройки под конкретную базу.** Работает из коробки на базе с
   любыми данными и любой размерностью.

10. **Это бизнес-решение: любые ошибки в ответах бота запрещены.** Числовые и
    смысловые.

11. **Оставлять любой пункт нерешённым запрещено.** Только полное соответствие этому
    файлу.

12. **Отказ и уточнение — не ошибка. Догадка — ошибка.**
    Ошибок быть не должно вообще. Если что-то непонятно или данных не хватает — бот
    задаёт уточняющий вопрос либо честно говорит, что данных нет. Выбор наугад между
    правдоподобными вариантами запрещён.

13. **Полнота данных.** Всё, что есть в 1С, доступно поиску. То, что недоступно —
    закрыто правами, не загрузилось, не попало в индекс — видно владельцу.
    Молчаливая потеря данных приравнивается к неверному ответу (см. п. 10): если
    из-за неё возможен неверный ответ, система обязана уточнить или отказать, а не
    ответить по неполным данным.

14. **Инсталлятор.** Ставится сам. Ручных действий два: создать читателя в 1С и, если
    требуется, пользователя Windows. Всё остальное — из коробки.
    **Делается в конце, когда закрыто всё остальное.** Правила те же, что для всей
    системы: без хардкода, на любой базе.

15. **Проверка независимыми агентами.** Соответствие проверяют агенты, которые
    контекста не знают или знают поверхностно. Приёмочный набор вопросов строится
    из самой базы клиента при установке, а не пишется под конкретные данные.

16. **Размещение данных и периметр.**
    - база — на Windows рядом с 1С;
    - индекс, поиск и бот — на нашем сервере;
    - сейчас данные уходят в API Alibaba и DeepSeek — **это временно, для тестов**;
    - целевое состояние: модели внутри нашего контура, наружу не уходит ничего.

17. **Свежесть.** Ответ отражает изменения в 1С **не позднее 20 минут**, лучше меньше.
    При этом обновление не должно создавать заметной нагрузки.

18. **При отказах — честный отказ, а не ответ на неполных данных.** Недоступна 1С,
    не отвечает модель, перезагружается движок — бот сообщает об этом. Ответ по
    частично собранным данным запрещён.

19. **Моделью не считаем и не ищем.** Модель нужна ТОЛЬКО для смысла: понять, о чём
    спросили, сопоставить слово человека с названием в базе, сформулировать фразу.
    - **считает код** — суммы, количества, минимумы, максимумы, средние, группировки:
      всё в базе, по всему множеству;
    - **ищет код** — отбор строк ведёт индекс SereneDB, а не модель;
    - **большой контекст в модель запрещён.** Схема базы, перечень колонок, выгрузки
      данных в модель не отправляются. То, что уходит, ограничено сверху и не растёт
      с размером базы.

20. **ЗАПРЕЩЕНО ПИСАТЬ СВОИ СКРИПТЫ ДЛЯ РАБОТЫ С БАЗОЙ ДАННЫХ.**
    Указание владельца 27.07: «твои скрипты не нужны, а из-за них вся беда».

    Данные лежат в SereneDB — значит и работа с ними делается **внутри** SereneDB, её
    штатными средствами. Вычитывать данные наружу, обрабатывать в Python и заливать
    обратно — запрещено.

    Конкретно **запрещено**:
    - читать таблицы в память процесса, чтобы что-то с ними сделать и записать обратно;
    - собирать тексты, считать отпечатки, сравнивать состояния, дедуплицировать,
      агрегировать, сортировать, фильтровать — вне базы;
    - выполнять один запрос на таблицу, на колонку или на строку там, где движок
      делает это одним запросом;
    - запускать процесс `psql` (или иной клиент) в цикле.

    Своим кодом остаётся **только то, чего у движка нет**:
    - поход в 1С за метаданными и данными по OData;
    - вызов языковой модели и решения, требующие смысла;
    - отрисовка изображений;
    - проверка ответа модели (гейт чисел и дат) — это проверка ЛЛМ, а не работа с данными.

    Этот перечень — **исчерпывающий**. Всё, что в него не входит, делается движком.
    Прежде чем написать хоть строку своего кода поверх базы, требуется ответ агента
    `serenedb-native`, что штатного средства нет. Обычный SQL и приёмы PostgreSQL
    штатным средством SereneDB **не считаются** (см. п. 7).

    Восемь дефектов проекта — холостой такт на 86 % времени, тысяча с лишним запусков
    процесса за такт, стена argv, падение на 4 % корпуса, тихая потеря пачек
    эмбеддинга, 37 ГБ памяти, 21 час на поиск владельца строки, полторы минуты на
    вопрос — оказались следствиями **одной** этой причины. Разбор:
    `docs/HOW_NOT_TO.md §0`.

## Как проверяется соответствие

| Пункт | Чем доказывается |
|---|---|
| 3, 10 | цифра в ответе сверена с независимым SQL по источнику; расхождение = отказ |
| 7, 8 | по каждому механизму поиска есть ответ агента `serenedb-native`: это штатное средство движка. Обычный SQL и приёмы PostgreSQL не засчитываются |
| 9 | на чужой базе — другой язык, другая конфигурация, другой масштаб — работает без правки кода |
| 11 | пункт закрыт, только если проверен замером на живых данных, а не рассуждением |
| 12, 18 | на вопрос без однозначного ответа система уточняет или отказывает; проверяется вопросами, у которых нет одного верного прочтения |
| 13 | число строк и колонок, дошедших до поиска, сверено с 1С; расхождение видно владельцу |
| 14 | установка на чистую машину: ручных действий не больше двух |
| 15 | приёмочный набор построен из базы клиента; проверку ведут агенты без контекста |
| 16 | что уходит за периметр — перечислено поимённо и подтверждено замером |
| 17 | задержка от изменения в 1С до ответа бота измерена, не больше 20 минут |
| 19 | каждый вызов модели измерен в символах: размер не зависит от числа таблиц, строк и колонок. Ни одна цифра в ответе не вычислена моделью — только скопирована из посчитанного базой |
| 20 | за такт сборки посчитано число запусков процесса `psql` и объём данных, покинувших движок. Норма — единицы запусков и ноль строк наружу. Любой цикл «прочитал из базы → обработал у себя → записал обратно» = нарушение, независимо от того, быстро он работает или нет |
