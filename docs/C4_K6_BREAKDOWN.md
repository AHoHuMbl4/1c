## 4. Эталонный SQL (снят заново 27.08)

Якорь даты: `timezone('Europe/Chisinau', now())::date` = **2026-08-27**.
Источник формулировок: `ubuntu/serenedb/ab-gold-okna.tsv`.

### 4.1. Клиенты реально покупают → **141**

```sql
WITH today AS (SELECT timezone('Europe/Chisinau', now())::date AS d)
SELECT count(DISTINCT map_extract_value(refs_map,'Контрагент'))
FROM search_corpus, today
WHERE src_table='accumulationregister_реализациятмц'
  AND doc_date >= today.d - INTERVAL 12 month;
-- [замер] 141
```

### 4.2. Позиции совсем не продаётся (MTD) → **1891**

```sql
WITH today AS (SELECT timezone('Europe/Chisinau', now())::date AS d)
SELECT
  (SELECT count(*) FROM search_corpus
   WHERE src_table='catalog_номенклатура'
     AND NOT coalesce(map_extract_value(flags,'IsFolder'), false))
  -
  (SELECT count(DISTINCT map_extract_value(refs_map,'ТМЦ'))
   FROM search_corpus, today
   WHERE src_table='accumulationregister_реализациятмц'
     AND doc_date >= date_trunc('month', today.d));
-- [замер] 1891
```

Эталоны **всё ещё верны**. Бот к ним не приблизился (clarify / 353 / 2376).

## 5. Проект починки (патч текстом; код здесь не вносить)

Уже написано и замкнуто офлайн: `ASK_ENTITY_FORM`, формы `distinct_axis` /
`complement`, catalog-скан без date-pred — `docs/SCORER_CLASSES_2026-08-25.md`
§K6; код `ubuntu/serenedb/serene_ask.py` зона entity-form
(~`1996–2562`, вызовы ~`12794–12811`, ~`13465–13480`, `fork_scan_readings`
~`4179–4221`). На бое `:8091` флаг **выключен** (нет в
`/etc/1c-serene-ask*.env`; умолч. `"0"` на `:1432`).

### 5.1. Q1 «реально покупают» → `distinct_axis`

Целевое поведение при `ASK_ENTITY_FORM=1` (уже в коде):

1. `entity_form_applicable` (`:2268`) — want=count, в пуле catalog+sales.
2. Без явного period: для не-товарного catalog →
   `entity_form_rolling_year` (`:2255`) = 12 мес.
3. `entity_form_structs` (`:2430`) → `("distinct_axis", {catalog, sales, axis, period})`.
4. `entity_form_compute` (`:2504`) → `aggregate_distinct_axis(sales, …, axis)` —
   тот же смысл, что эталон DISTINCT `Контрагент` на
   `accumulationregister_реализациятмц`.
5. `try_entity_form_answer` (`:2531`) до/после выбора моделью
   (`:12794`, `:13465`) отдаёт `kind=answer` с числом.

**Что сделать оркестратору (без правки логики, если замок зелёный):**

1. Выкат того же бинаря ask, что уже содержит entity-form (если бой
   отстаёт — `deploy-okna-serene-ask.sh`).
2. На стейджинг `:8092` / probe: `ASK_ENTITY_FORM=1` (+ уже принятые Ф6
   по чеклисту). Прогон двух K6 + полный scorer / AB_PROBE.
3. Если на probe **141** сходится — выкат флага на бой по Ф6.5.
4. Если не сходится — смотреть журнал: сработала ли F (`diag.entity_form`),
   какой `sales_src`/`axis`; чинить `entity_form_axis_on_sales` /
   `holders_of_target` / гейт `entity_form_pre_entity_ok` при `classes>1`
   (сейчас pre_entity при многих классах форму **не** отдаёт — тогда
   обязателен путь **после** arb_pool, `:13465`).

Патч-набросок (только если живой probe покажет дыру в гейте pre_entity при
16 классах — **не вносить вслепую**):

```text
# serene_ask.py, try_entity_form_answer / entity_form_pre_entity_ok
# Симптом: pre_entity отказал (classes>1), post-arb тоже не взял F,
# модель снова выбрала catalog_*.
# Направление: для want=count + entity_form_applicable и единственной
# struct distinct_axis/complement — не отдавать выбор модели, пока F
# не посчитан (или сузить early_classes-гейт только когда form_n>1).
# Файл/функции: entity_form_pre_entity_ok ~2319; вызов ~12797–12811.
```

### 5.2. Q2 «совсем не продаётся» → `complement`

Целевое поведение при `ASK_ENTITY_FORM=1`:

1. Есть period (MTD) + product catalog → `entity_form_structs` кладёт
   `("complement", {catalog_номенклатура, sales_src, axis ТМЦ, period})`.
2. `fork_scan_readings` с флагом: catalog без date-pred → нет ложного
   `no_live_cells` (`:4182–4207`).
3. `entity_form_compute` complement = `aggregate(catalog) − aggregate_distinct_axis(sales)`
   ≈ эталон **1891**.
4. Sales-держатель обязан быть **канон** `accumulationregister_реализациятмц`,
   не `книгапродаж` (`sales_noncanon_focus` / `entity_form_axis_on_sales`
   `:2398`).

**Что сделать:**

1. Тот же выкат `ASK_ENTITY_FORM=1` на probe.
2. Проверить, что в `diag` после ответа: `entity_form=complement`,
   `entity_form_sales=accumulationregister_реализациятмц`, число **1891**.
3. Если F не сработала и снова C на книге продаж — патч направления:

```text
# 1) В круг арбитра / expand_pool для product-count с period всегда
#    тащить holders_of_target(catalog_номенклатура) → реализациятмц
#    (entity_form_expand_pool уже делает holders; убедиться, что arb_pool
#    для исхода C/B строится из expand_pool, а не из урезанной тройки
#    «номенклатура + книга + журнал»).
#    Место: сборка arb_pool / stop2 ~13353–13458; entity_form_expand_pool :2232.
#
# 2) Не считать книгу продаж соперником «позиций» при want=count+period
#    на товарном catalog (not_for / sales_noncanon), иначе signals_disagree
#    тянет НДС-регистр.
#
# 3) При ASK_ENTITY_FORM=1 не гасить catalog no_live_cells в исходе C,
#    если открыта complement (уже частично в fork_scan_readings).
```

### 5.3. Чего не делать

- Не подгонять эталон и не писать питон-счёт поверх корпуса (п. 20).
- Не чинить K6 одним только словарём синонимов: для Q1 словарь указывает
  на catalog, эталон — на sales×DISTINCT; для Q2 словарь не собирает
  разность множеств.
- Не править `serene_ask.py` из этой сессии — патч оркестратору после
  живого probe с `ASK_ENTITY_FORM=1`.
