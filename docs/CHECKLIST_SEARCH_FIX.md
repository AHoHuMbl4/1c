# §4-бис. Правка 3-бис — включить `refs` в отбор с весом

**Заведено 27.07 вечером. Меняет ОТВЕТ. Индекс и корпус не трогает — только `serene_ask.py`.**

**[замер]** Поле `refs` строится сборщиком и лежит в индексе, но в `serene_ask.py` в
отборе **не участвует ни разу** — только в подсчёте значимых термов. При этом
`doc @@ q AND NOT refs @@ q` = 0 и обратное = 0, то есть `refs ⊂ doc`: полноты поле не
добавляет и добавить не может. Оно существует ровно ради того, ради чего заводилось, —
**веса и адресности**: чтобы «Контрагент: Ромашка» весил больше, чем «Склад: Ромашка».

**[замер]** `WHERE doc @@ q OR refs @@ (q ^ 8.0)` на запросе «ромашка»:

| | топ-1 … топ-4 | с пятой позиции |
|---|---|---|
| без буста | состоянияконтрагентов 13,01 … документыпотребованиюфнс 11,79 | — |
| `refs ^ 8.0` | те же четыре, 109,97 … 97,40 | **состав меняется**: книгаучетадоходовирасходов 94,05 обгоняет документыпотребованиюфнс |

- [ ] `probe()` / `match_expr()` (`serene_ask.py:244-335`) — добавить ветку по `refs`
      с весом; вес выбрать A/B из {2, 5, 8} на приёмочном наборе;
- [ ] заодно: `ts_compound(NULL, NULL, [...], k)` (`:325`) использует **один бакет из
      трёх**. Имя собственное обязано идти в `must`, остальное — в `should`. Оба бакета
      в сборке работают ([замер] `must` = 14 строк; `must_not` режет 29 → 6);
- [ ] §0 полностью.
