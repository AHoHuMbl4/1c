# Регрессия первой базы: что проверено после каждой правки

**Заведён 29.07 по вопросу владельца:** «все правки не поломают например работу с первой
базой или любой другой? там ведь работало всё».

Вопрос правильный, и ответ на него не может быть «вроде не должно». Здесь фиксируется,
**какой правкой** и **каким замером** доказано, что первая база цела. Без замера строка в
таблицу не попадает.

---

## 0. Чем именно проверяется «не сломано»

Три уровня, от дешёвого к дорогому. Все три обязательны — первый проходит и на сломанной
базе, если поломка тихая.

| # | Проверка | Что ловит | Как запустить |
|---|---|---|---|
| 1 | такт конвейера доходит до конца | падение сборки, слияния, векторов | `systemctl start 1c-serene-pipeline.service` |
| 2 | перепись полноты и `search_quality` | молчаливую потерю строк (п. 13) | внутри такта, шаг 7 |
| 3 | **приёмочный набор** | ухудшение ОТВЕТОВ при исправной сборке | `python3 ab_scorer.py` в `/opt/1c-mcp-reports` |

🔴 Третий уровень — единственный, который ловит ухудшение качества ответа. Первые два
могут быть зелёными, а бот при этом отвечать хуже: сборка не знает, что такое «верный
ответ».

## 1. Правки 29.07 и чем каждая проверена на первой базе

| Правка | Риск для первой базы | Замер |
|---|---|---|
| разметка сущностей моделью (`classify_entities.py`) | новый шаг в такте; при отказе модели такт мог бы падать | шаг не `fail`, а предупреждение. [замер] на первой базе 231/231 размечено, ноль неразобранных |
| очерёдность векторов двумя проходами | второй проход мог бы не покрыть остаток → строки без вектора навсегда | [замер] такт зелёный, `осталось: 0` на всех трёх целях |
| замок по `current_database()` | неверное имя → такт не стартует вовсе | [замер] обе формы DSN (с `dbname=` и без) дают `postgres`, замок один |
| рабочие таблицы по базам (`emb_<база>_<таблица>`) | потеря уже посчитанных векторов при смене имени | [замер] докатка из прежних имён: `ut_test` 632 683 → 630 562, то есть 2 121 оплаченный вектор перенесён, не потерян |
| фильтр `database_name` в досчёте | — (только сужает) | [замер] без фильтра видно 5 чужих таблиц, с фильтром 0 |
| `deploy.sh` + вызов из конвейера | раскладка поверх идущего такта могла бы порвать его | подмена атомарная (`mv`), [замер] такт с раскладкой прошёл |
| порядок «метки → резолвер → корпус» | на первой базе порядок не влияет (всё считается за секунды) | [замер] такт зелёный, 0 без вектора |
| потолок разметки `CLASSIFY_MAX_PER_RUN` | частичная разметка могла бы отправить новое во второй проход | условие первого прохода изменено на «НЕ служебное»; [замер] см. таблицу ниже |
| погашен `nightly-eval` | к первой базе отношения не имеет (чужой слой) | [замер] `timer: inactive/disabled` |

## 3. «А любая другая база?»

Первая база — не доказательство универсальности, а только доказательство отсутствия
регрессии. Универсальность проверяется на **второй** базе (УТ 11.4.9), протокол —
[`TEST_SECOND_BASE.md`](TEST_SECOND_BASE.md). Именно она вскрыла все находки 28-29.07,
невидимые на одной базе.

**Правило, из этого следующее:** правка, сделанная ради второй базы, не считается
законченной, пока на первой не сняты замеры 1-3 из §0. И наоборот. Одна база всегда
врёт — тем, что молчит про случай, которого в ней нет.
