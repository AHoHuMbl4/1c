## 2. Модель исходов (строгая форма A/B/C)

Каждый вопрос заканчивается ровно одним исходом из шести:

| Исход | Условие | Человеку |
|---|---|---|
| **единственность** | один класс эквивалентности атомов в полном пространстве, один src | ответ; паспорт набора |
| **A** | один класс, src несколько — полный `AnswerAtom` совпал у всех веток | ответ источник-нейтрально; ничего не запоминать о src |
| **B** | классов несколько, все ветки посчитаны и у каждой проверенная человеческая подпись | условные пары «подпись + число», собранные кодом; порядок — не выбор; «свой вариант» рядом |
| **C** | есть неподсчитанная, скрытая или неподписанная ветка | `clarify` свободным текстом + варианты из данных |
| **no_data** | все ячейки пространства пусты | честное «нет таких данных» |
| **unavailable** | сбой контура, неполнота источника | видимое сообщение о сбое/неполноте; после восстановления ответ обязан вернуться |

Ключевое определение (аудит §0): ответ существует, только когда существует
**единственный полный ответ, одинаковый при всех ещё допустимых прочтениях**.
Безусловного числа лидера при разных атомах нет ни в одном исходе. Молчание
человека (ненажатие) не считается выбором нигде.

## 3. Ядро: детектор из данных, always-on

**Что меняется принципиально.** Сегодня развилка обнаруживается по сигналам
(расхождение выбора модели с вектором/словарём → сомнение → круг ≤ `ARBITER_MAX=3`).
Это хрупко: верная сущность не дошла до круга → сомнения нет → уверенный неверный
ответ (три ошибки прогона 03.08, все `сомнение=False`). Детектор из данных убирает
зависимость от сомнения: развилка доказывается или опровергается самим счётом.

**Пространство прочтений R = E × P × M × W — конечно и перечислимо:**

- **E** — сущности, достигнутые хотя бы одной поверхностью (буквальный отбор любого
  уровня, синонимы, вектор, карточка) — полный охват, не топ-N;
- **P** — различные разборы вопроса из согласия прогонов (шаг 1 уже их производит;
  берутся все, влияющие на счёт, не только победитель);
- **M** — величины, относящиеся к слову вопроса (`measures_of` + `search_measure_alias`);
- **W** — окна периода (явное, prior, assumed, без окна).

**Счёт.** На каждый разбор — один SQL: `GROUP BY src_table` по общему WHERE
(match + preds) со счётом, суммами относящихся величин и дискриминаторами
(вид записи у `_RecordType`-сестёр, папки). Частные предикаты кандидатов
(`kid_pred`, `via_partial`) — фильтрами в том же запросе или точечными добавлениями;
разнородные WHERE — `query`/`query_table` (§1). Замер: миллисекунды, один запрос на
разбор (§1). Модель в этом не участвует вовсе (п. 19); в модель уходят только
различные атомы в фиксированном количестве.

**Схлопывание.** Ячейки сводятся в классы эквивалентности по полному
`AnswerAtom` (§5) без внутреннего src. Один непустой класс — единственность
ответа доказана **теоремой о данных**, а не отсутствием сомнения. Несколько
классов — развилка существует и видна кодом: B или C. Пусто — `no_data`.

**Статусы ячеек (аудит §7.3).** Каждая ячейка имеет явный статус: посчитана /
доказанно не относится / не посчитана (ошибка, права, неполнота). Третий статус
запрещает терминальный A/B и виден клиенту.

**Место в конвейере.** Детектор стоит после сборки `match`/`preds` (шаг 2) и до
формулировки. Существующие сигнальные защиты (стоп 2, `writer_pair`, вето по
синонимам) **не сносятся**: на переходный период детектор работает рядом, а их
роль сужается до подбора кандидатов в перечень модели. Снятие — только по замеру
shadow (шаг 5), отдельным решением. Выбирающий модельный арбитр (`arbitrate`)
в новой модели не нужен: при расходящихся атомах выбирать не из чего (B/C), при
сошедшихся — нечего выбирать (A).

**Ограничение, названное честно.** Полнота детектора = полнота пространства E.
Сущность, недостигнутая всеми поверхностями, в круг не попадёт. Размер этой дыры
перестаёт быть туманом — он измеряется самопроверкой (§4).

## 4. Состязательная самопроверка из данных (мерило слепого пятна)

Ответ на «закрыть пробел необнаруженной развилки»: невозможное доказать
отсутствие неизвестного — но можно **считать его числом** с другой стороны, из
данных.

- **Генератор.** На каждую сущность и величину базы строятся вопросы из самой
  базы (метки, алиасы, величины — без значений данных, п. 19). Фаза 4
  `PLAN_AUTONOMY.md` это уже предусматривает.
- **Прогон** через боевой `/ask` (или через детектор напрямую — дешевле) — на
  дев-базах и **на прод-базе после пересборки корпуса**: слепое пятно меряется и
  на реальных данных, его число на полигоне само по себе не доказательство.
- **Проверка:** породившая сущность вошла в пространство детектора? атом сошёлся
  с прямым счётом? Каждый промах — адрес настоящего слепого пятна.
- **Метрика на базу:** доля сущностей/величин, недостижимых детектором. Цель — 0;
  число вносится в приёмку и регрессирует. Каждый промах чинится (поверхность,
  словарь, классификация service, случай приёмки).
- **Петля:** реальные вопросы пользователей из журнала пополняют набор
  самопроверки — разница между «что генерирует проверка» и «что спрашивают люди»
  убывает со временем.

Уверенный неверный ответ после §3+§4 требует одновременного сбоя независимых
механизмов: сущность недостижима всеми поверхностями **и** самопроверка её не
поймала **и** проверки полноты молчат. Это конъюнкция измеренных событий с
владельцами, а не невидимый класс.

## 5. `AnswerAtom` и детерминированный renderer

Структура атома — по аудиту §17 (operation, exact/display value, measure_id +
measure_label, единица, период, фильтры, зерно/ось/форма, полнота, свежесть,
отброшенное, proof_status). Поля — деталь реализации; семантика явная.

Правила рендера:

- пара «подпись + число + единица + оговорка» подставляется **одним кодовым
  местом**; модель не видит значений и не пишет подписи;
- одиночные числовые места при нескольких парах запрещены структурно;
- тест до выката: перепутанные подписи → фраза не собирается (невозможность по
  построению, не гейт постфактум);
- `kind=figures` несёт те же атомы (мост не разворачивает их в плоский текст для
  переназначения ролей);
- гейт и зачистка покрывают и текст, и presentation кнопок.

## 6. Доказуемый выбор: одноразовый `decision_id`

- Выбор — короткий одноразовый билет: ссылка на серверную запись (вопрос,
  разбор, src/measure/зерно/ось, база, пользователь, версия набора, TTL, nonce,
  «использован»).
- **Сырой `focus` от модели — подсказка, а не выбор**: он больше не отключает
  проверку достаточности, стоп 2 и финальную проверку поддержки источника.
  Сегодня эти защиты гаснут самим фактом непустого `focus` (аудит §10).
- Нажатие снимает **конкретную** неоднозначность; оставшиеся (величина, ось,
  период) уточняются — второй круг терминален.
- Просроченный/чужой/повторный билет виден клиенту как ошибка выбора, а не молча
  возвращает общий путь.
- Каналы: Telegram — штатные кнопки presentation (callback ≤ 64 байт = id
  билета); WebUI — детерминированный текст пар + чипы/свободный ввод (выбор
  возвращается текстом, сводится `resolve_focus`; это уже работает, §1).
  Возможности каналов не приравниваются (замок §19.11 аудита).

## 7. Словарь развилок (человеческие подписи веток)

Проблема B: подпись «Реализация ТМЦ (документ)» не говорит человеку «это
отгрузки, а не оплаты». Ручная разметка отвергнута аудитом (§12: третье ручное
действие, не существует на холодном старте). Решение — третий словарь, на уровне
пар, тем же штатным контуром, что словарь сущностей (`wiki_alias.sh`):

- **Ключ:** отпечаток класса развилки (множество src + контекст величины).
  Классы структурны (документ ↔ его регистр, шапка ↔ табчасть, одноимённые
  источники) — их мало, и они не растут с языком.
- **Наполнение:** детектор зафиксировал новый класс → класс в очередь → штатный
  агент OpenClaw один раз пишет подписи веток (видит только имена и величины,
  п. 19) → подписи в базе.
- **Применение:** B рендерит пары кодом из словаря; класса нет — честный C.
- **Качество:** неверная подпись детерминирована, одна на класс, чинится один
  раз; доля переключений с ветки — телеметрия вводящих в заблуждение подписей.
- **Критерий отсева:** словарь пуст через месяц журнала → гипотеза «развилок
  мало» неверна → контур выключается. Затрат до проверки: один промт.

| **18** (честный отказ, не ответ на неполных данных) | `unavailable` при сбое; неполнота источника — видимый отказ; после восстановления ответ обязан вернуться |
| **19** (модель не считает и не ищет; объём ограничен) | Детектор — SQL в движке, модель не участвует; в модель уходят только различные атомы в фиксированном числе; подписи из базы; объём не растёт с базой (замер 4,6 мс на 1502 сущности) |
| **20** (свои скрипты поверх базы запрещены) | Детектор — один SQL на разбор; самопроверка читает через `/ask`; словари наполняются штатным агентом OpenClaw (как `wiki_alias.sh`); перед реализацией — раздел доков назван в коммите (гейт `check-sql-docs`) |
| **21** (отдать правильный ответ; отказ при наличии данных — дефект) | A отвечает там, где сегодня clarify; B отдаёт все посчитанные ветки сразу вместо круга вопросов; вторая попытка формулировки сохранена; положительная метрика «доля ответов при наличии данных» обязательна в приёмке — ноль ошибок молчанием не считается |
| **7, 8** (только штатные средства SereneDB) | Детектор — штатный SQL (GROUP BY, map_extract, DECIMAL, query/query_table); всё найденное проверяется на живой сборке 26.07.3 до выката |
| **9** (без хардкода, коробка) | Ноль имён конфигурации; словарь развилок строится агентом из данных; холодный старт = честный C; самопроверка работает на любой базе; замок «новая база — ноль ручных подписей» |
| **15** (независимая проверка из базы клиента) | Самопроверка генерирует набор из самой базы (§4); приёмка агентами без контекста — как сейчас |

Пункты 14 (инсталлятор — в конце), 16 (периметр), 17 (свежесть) планом не
меняются: контур свежести и выкат продолжают работать как сейчас; план добавляет
к ним только требование, чтобы словарь развилок наполнялся в такт, как и словарь
сущностей.

## 10. Сводные замки приёмки

Наследуются из аудита §19 без ослабления:

1. `wrong_numeric = 0`. 2. `wrong_semantic = 0`. 3. Ответов при различающихся
атомах без явных условий — 0. 4. Ответов при непосчитанной допустимой ячейке — 0.
5. Ответов по известному неполному снимку — 0. 6. Потерь кандидатов без видимой
пометки — 0. 7. Перестановок label↔value во всём E2E — 0 по построению.
8. Сырой/чужой/просроченный/повторный билет не отключает защиту. 9. Одинаковый
вопрос на одном снимке — детерминированно. 10. `partial`, freshness, excluded
доходят на всех `kind`. 11. Telegram и WebUI проверяются отдельно. 12. Новая база
— ноль ручных подписей. 13. Приёмка содержит все виды исходов и клики. 14. Смена
лидера не брак; брак — смена проверенного ответа на неверный. 15. Clarify-rate —
диагностика, не замок против безопасной правки.

Добавляются этим планом:

16. **Детектор всегда включён:** на эталонных развилках обе ветки видны без
сомнения модели (замер, не рассуждение).
17. **Слепое пятно — число:** метрика недостижимых сущностей/величин на каждой
базе в приёмке; рост — брак.
18. **Доля ответов при наличии данных растёт** (п. 21) на одном и том же наборе:
A и B переводят clarify в ответы; падение доли без причины — брак.

## 11. Чего план не обещает

- Не «любой вопрос — сразу одно число». При двух неразличимых намерениях ответ —
  ветки или вопрос; это контракт (п. 12), а не недоделка.
- Не мгновенный рост доли ответов: она растёт через A/B и через сокращение ложных
  clarify после починки прибора; на переходном периоде clarify-rate может вырасти
  (A3 оживёт) — это диагностируется замком 18.
- Не доказательство нуля слепых пятен вне измеренного пространства: пространство
  конечно, перечислимо и фасуется самопроверкой; остаток — измеренное число с
  адресами, а не невидимый класс.
- Не чинит выбор сущности как таковой: если прочтение одно, отвечает выбор
  модели с существующими защитами; детектор гарантирует, что ВТОРАЯ ветка не
  останется невидимой.
