## Дев (`/srv/1c`, lxc-claude-1c)

Роль: разработка, тесты, сборка установщика. Прод-данных нет.

1. **Установщик, часть А** — правка `Steps.cs` + `ai-ext.ps1` (клиент-серверные
   базы), см. `PLAN_EXT_CLIENT_SERVER.md §А`. Код пишется здесь; сборка exe —
   на стенде `192.168.56.1` (ключ у владельца, сессия стенд не читает).
2. **Проверка части А требует сервера 1С на стенде** — установка сервера и
   создание клиент-серверной базы — 🔴 шаг владельца. До этого правка лежит в
   репозитории с пометкой «не проверено на клиент-серверной» и в S3 НЕ уезжает.
3. **Паритет приёмника**: на юнитах `a023c360` (правка соседней сессии
   «пофайловый предел»), сверить с HEAD репозитория; расхождение доносить
   выкатом, эталонную сумму держать в `activeContext`.
4. **Прогоны после любой правки приёмника**: `test_packet_apply` (полный,
   против живого движка дева) + `test_packet_server`.
5. Эмбеддер дева указывает на мёртвый хост — решение владельца 13.08
   «дев потом»; не трогать до его слова.

## okna (`167.233.249.110`, бот в бою)

Роль: первый живой клиент, витрина восстановлена 15.08 полностью.

1. **Дождаться нуля очереди векторов** (15.08 было 972 551, оценка ~15 ч) —
   проверить факт, не предполагать.
2. **Вернуть ручки памяти** (ставились временно под пересборку, запись
   CHANGELOG 15.08): `SET memory_limit='6GB'`; `swapoff /swapfile-1c-build`
   и удалить файл (в fstab не вписан); удалить дозор-cron (раз в час, :23).
3. **Сверить эталоны** после пересборки корпуса: книга продаж, реализациятмц —
   числа из `PLAN_KEY_DEDUP_RECOVERY §0` (74 705 / 77 179).
4. **Опись полноты okna** — тем же способом, что для klient-1 (баланс
   контур = доехало + skipped + пустые, до единицы). У okna тоже есть
   пропуски по правам (заметка 13.08: «401 права/RLS у части сущностей»);
   масштаб измерить, не оценивать на глаз.
5. **Права okna** — в отличие от klient-1, доступ к Windows okna у владельца
   есть. После готовности части А установщика — тот же одноразовый заход:
   команда с числом отказов до/после. 🔴 Решение и время — владельца.
6. **Приёмка** — линейка п. 21 по свежепересобранному корпусу (прошлые замеры
   шли по корпусу, собранному до восстановления витрины).

## klient-1 (`10.1.1.7`, только через релей `89.23.101.22`)

Роль: второй клиент, первая полная загрузка завершена 17.08 12:06 UTC
(61 ч, 33 порции), агент в режиме дельт. 🔴 Захода на Windows нет и не будет
до планового визита админа (~полгода).

1. **Опись полноты** → `docs/COMPLETENESS_KLIENT1.md`: баланс уже сведён
   (9151 = 1519 доехали + 6298 закрыты + 1372 пустые − 38 дочитанных),
   осталось оформить с поимёнными списками и закоммитить. Списки сняты
   17.08, лежат в скретчпаде сессии (`k1-contour/arrived/skipped`).
2. **Корпус + векторы** — 🔴 ждёт слова владельца. Путь okna 15.08; уроки
   в коде (`§3.77`), ловушка `p_doc_plain` записана. Память юнита 9,3 ГиБ —
   ручки и их возврат описаны в `PLAN_KEY_DEDUP_RECOVERY §0`. Оценка объёма:
   витрина 14,6 млн строк (корпусных строк будет больше — считать после
   слияния).
3. **Словарь на регистры закрытых доменов**: 35 закрытых типов документов
   держат 3 021 572 движения в витрине (амортизация, производство, зарплата,
   ввод остатков). `selftest_surfaces` → `wiki_alias` → живые вопросы по
   доменам; в ответе источник «по движениям» — формой кода, не промтом.
4. **Приёмка** — линейка п. 21, в наборе отдельные вопросы по закрытым
   доменам, чтобы хвост был виден процентом.
5. **Хвосты env**: `PACKET_MAX_CHUNKS_PER_PACKAGE=20000` в `/etc/1c-packet.env`
   больше не нужен (предел снят в коде приёмника 14.08) — снять при следующем
   заходе на юнит. `PACKET_APPLY_THREADS` снят 15.08; `threads` движка
   возвращён рестартом 15.08 (~13:50 EEST).
6. **Мониторинг без участия**: дельты каждый час; сверка контура
   (`_check_contour_arrived`) пишет расхождения в журнал приёмника; пустые
   перечитываются агентом каждый такт.
7. **Заход админа (~полгода)**: одна команда из части А (обновлённый
   установщик, уже проверенный на стенде с сервером 1С) → права → агент
   дочитывает 6228 сущностей сам, без переустановки (механика проверена
   на 38). До того дня закрытые домены отвечают по регистрам (п. 3).
