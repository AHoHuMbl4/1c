## 4. Провалы → причина в коде → проект патча

### P1. Compare считается, rank перетирает (Q5, вероятно Q6)

**Причина.** После успешного `aggregate_compare_sales` ранний return атома — только под `ASK_ENTITY_FORM` (`14490–14509`). Замок `_cmp_form_locked` (`14725–14731`) тоже требует флаг. В бою флаг выкл. → `rank_deterministic_answer` забирает поток; в тексте MTD/лидер договора, не diff.

**Патч (текст).**  
1. При успешном `_cagg` всегда фиксировать ответ compare (ранний return), **не** только под `ASK_ENTITY_FORM`; **или**  
2. `_cmp_form_locked = bool(diag.get("compare_sales") or (agg or {}).get("form") == "compare" or …)` без требования флага.  
3. Атом: `exact_value = diff`; в `period`/`filters` или отдельном поле — оба окна; `figures` — `compare_base`, `compare_other`, `diff`.  
4. Замок оффлайн: вопрос F3 → text/figures содержат **1049991.33** (или актуальный diff при сдвиге `today`), `form=compare`, нет `form=rank`.

### P2. Узкий лексический вход (Q1, Q3, Q4, Q7, Q8)

**Причина.** `sales_compare_intent` (`2055–2057`) принимает только  
`лучше|хуже|больше чем|меньше чем|больше, чем|меньше, чем`.  
Нет: `сравни`, `сравнение`, `против`, `по сравнению`, `насколько … больше` без «чем», follow-up «год назад».  
`_vs` (`против`/`vs`) лишь ослабляет блок rank, сам compare не включает.

**Патч.** Расширить вход **структурно**, не списком «красивых» слов где можно:  
- `period2` из разбора уже заполнен → compare;  
- иначе маркеры пары окон: `сравни`/`против`/`vs`/`по сравнению`/`на сколько`/`насколько` + (продажи) + два периода;  
- «больше/меньше» + «прошл*»/имя месяца без обязательного «чем».  
Оффлайн-кейсы на Q1/Q4/Q7/Q8.

### P3. Нет окна «год назад» (Q2)

**Причина.** `sales_compare_windows` умеет только `wtd` / `mtd` / `explicit` с готовым `period2`. Сдвига на −1 year нет. Follow-up без контекста продаж уходит в курсы валют.

**Патч.** Форма `yoy`: cur = текущее окно вопроса (MTD/месяц/явное), prior = те же границы `− INTERVAL 1 year` (доки: interval arithmetic). Follow-up «а год назад?» — от prior dialog period, не новый entity search. Без продаж в контексте — уточнение «сравнить какие продажи?», не курсы.

### P4. Два месяца склеиваются в одно окно (Q4, Q7)

**Причина.** Без `sales_compare_intent` разбор даёт один `period` июль…август → один `sum`, иногда с текстом «сравнить нельзя».

**Патч.** При маркере пары месяцев (`против`/`сравни` + два месяца) принудительно `period`/`period2` = полные календарные месяцы, затем `aggregate_compare_sales`. Не `UNION` дат в один preds.

### P5. В ответе не видно пару окон (все Q)

**Причина.** `atom_from_agg(..., period=_p1)` (`14495`) — только первое окно; `compare_base`/`compare_other` из agg в атом/`render_atom_pair` не попадают.

**Патч.** Расширить атом/render:  
«Всего: {diff} · {p1_human} ({base}) против {p2_human} ({other})»;  
если `form_id in (mtd,wtd)` — явная оговорка «текущий период неполный, прошлый — полный месяц/неделя» (п.13). Не промтом — кодом сборки строки.

### P6. Исторический «не тот diff» (1755883.45 в логах K5b)

В старых логах атом compare = **1 755 883,45** ≠ золото. На сегодняшнем корпусе SQL-пара MTD−июль = золото. После P1 перепроверить: если diff снова ≠ 1 049 991,33 — искать второй `src`/меру/обрез prior по дню `today` (сужение prior запрещено комментарием 2064–2066; регрессия = баг окна).

## 5. Вывод: что мешает закрыть К2

1. **В бою compare не терминален:** флаг `ASK_ENTITY_FORM=0` → diff считается (`diag.compare_sales`) и **стирается rank** — якорь F3/K5b не может сойтись с **1 049 991,33**, даже когда SQL эталон на месте.  
2. **Вход в compare слишком узкий** — человеческие «сравни / против / насколько / год назад» не доходят до `aggregate_compare_sales`.  
3. **Нет YoY-окон и нет пары в тексте ответа** — даже после починки замка форма останется невидимой человеку и сломает follow-up.

Закрытие К2 = патчи P1+P2 (+P5 для п.13) в `serene_ask.py` оркестратором, выкат, повтор Q1–Q8: Q5 обязан показать **1 049 991,33** (или актуальный SQL-diff при новых проводках), с двумя окнами словами; Q6 — около **−792 128,74**.

`serene_ask.py` изменён (P1–P5 + дожим окон/rank); см. §Результат.
