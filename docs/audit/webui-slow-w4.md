## Вердикт в одну строку

Клиент ждёт **2,5–5 мин** до clarify/ошибки там, где контракт требует **clarify за ≤15–20 с** или **число за ≤10–15 с**; доминирует стенка `ask_1c` (153801 / 300080 мс), не DeepSeek (~6,4 с суммарно на 15 вызовов). Утечка английского рассуждения в чат — **критический дефект доверия**, чинится кодом плагина, не промтом.

## Целевой UX-контракт (как ДОЛЖНО)

Опора: TARGET п.21 (ответ → уточнение → отказ), п.12 (догадка = ошибка), п.19 (модель не считает/не ищет), п.13 (молчаливая потеря = дефект), решение владельца №9 в activeContext («простые вопросы — верные ответы»). Здравый смысл ассистента: clarify без 2-минутного «думанья» — иначе п.21 формально соблюдён, продукт мёртв.

| Класс вопроса | Целевой E2E (браузер → Open WebUI → OpenClaw → ask → ответ в чат) | Что допустимо | Что дефект |
|---|---|---|---|
| **A. Простой числовой** («сколько продали вчера»), однозначный источник | **≤ 10–15 с** до числа с паспортом | 1× `ask_1c` → `kind=answer`; агент пересказывает эталон без цифр от себя | >30 с; ответ без инструмента; догадка источника |
| **B. Составной → clarify** («…и чего… полный отчёт») | **≤ 15–20 с** до **первого** уточнения с 2–4 опциями | Ранний `kind=clarify` (п.21.2), без полного пула/отчёта | 153 с до clarify; clarify после 5 мин таймаута; EN-thinking в чате |
| **C. Полный отчёт после выбора опции** | **≤ 25–40 с** до сводки (суммы из базы) | Один выбранный `decision_id` → один проход ask | Повторный полный шторм rerank; второй LLM «пересчитывает» |
| **D. Нет данных / недоступно** | **≤ 10 с** честный отказ (п.18) | `no_data` / `unavailable` видимы клиенту | Тихий обрыв; TimeoutError без русского отказа |

**Калибровка по замеру этого же окна:** третий вызов уже дал `ask_reply 15272 kind=clarify` — **целевой коридор B достижим на текущем железе**. Путь на 153801 мс — не «физика базы», а лишний путь до того же clarify.

**Анти-цель:** «полторы минуты на вопрос» уже числится в TARGET п.20 как исторический дефект самописных скриптов. Держать 2,5–5 мин как норму нельзя.

## Утечка thinking — критичность и где чинить

**Факт (не гипотеза):** в `gateway.log` / extract в `effective_params` следующего `ask_1c` попал английский внутренний текст:

> `The wiki tools are returning a verification message rather than actual results. Let me proceed with the data tool…`

затем сразу русский clarify. Клиент видит (или видел) чужой «мозг» агента.

| | |
|---|---|
| **Критичность** | **Критическая для доверия** (бизнес п.10/п.3): выглядит как сломанный/иностранный бот; смешивает протокол с ответом; раздувает вопрос → хуже разбор (п.19: в модель только смысл, не протокол) |
| **Не промт** | Правило проекта: запреты в AGENTS.md/персоне **не держатся**. `thinkingDefault: off` уже стоит в web-профиле — **не помогло** (это не thinking-токены, а обычная EN-проза модели) |
| **Где чинить** | **1) код `braine-verify`** (strip + finalize block / revise) — первично; тесты на EN reasoning уже есть. **2) OpenClaw stream/UI** — не отдавать reasoning/partial tool-thought в chat Completions. **3) Модель** — смена может снизить частоту, но не закрывает дыру |
| **Не чинить** | Дописыванием «никогда не пиши по-английски» в персону |

## Что НЕ трогать (жёсткий запрет на фоне живого прод)

Пока снапшот снят, такт зелёный, ждём живую дельту, пакет B ждёт стоп-точки владельца:

1. **Такт / packet_apply / писатели A / Speed-II / flip / 6a0 / hash_kill** — не «оптимизация ответов».
2. **Вектора корпуса / `embed_bulk` / смена эмбеддера / rehash** — закрыто армией ×4; риск повтора потери 09.09.
3. **`store.db`, холодный бэкап, restore-инстанс** — не полигон для web-latency.
4. **Прод-сборка полной B / row-фильтр / SKIP** — по плану v2 после стоп-точки, не из этой жалобы.
5. **Массовая смена `content_hash` / витрин lowercase** — вне темы; гейт hash_kill свят.
6. **Промт-правила в персоне** про скорость/язык — запрещены проектом.
7. **Смена ask-модели на облако DeepSeek** без явного слова владельца.

Разрешённый периметр правок под эту жалобу: **web-профиль OpenClaw, verify-плагин, MCP timeout, ключ memorySearch, точечный ask-путь clarify/rerank** — и то последние два только с армией/замером L-среза.

## Итог приоритетов (что чинить ПЕРВЫМ)

1. **Ранний clarify + потолок 90 с** — прямой ответ на «очень долго».  
2. **Strip EN-leak в verify** — прямой ответ на утечку раздумья.  
3. **Ключ вики** — убрать ложный контур.  
4. **Не трогать такт/вектора/B.**  
5. **Rerank/кэш/одна модель** — только пакетом после замера, с армией.

Критерий закрытия эпизода (не «кажется быстрее»): на вопросе «Сколько продали вчера и чего продали. Полный отчет» — **первый** `ask_reply kind=clarify < 20000 мс`, в чате **нет** EN-reasoning, нет `TimeoutError` 300 с; на «Сколько продали вчера» (после одной опции или однозначном источнике) — **answer < 15000 мс** с числом из эталона.
