## Новые атаки на v2 (чего не было / не акцентировалось в v1)

### Атака C4-1: STOP пост-xfer / L-mid после DELETE — emb уже дырявый

v2 §5.3 ставит зеркало гейта **после** DELETE+xfer. Если гейт сработал
(`error()`) или процесс убит **после** anti-join, **до** конца xfer:
`ON_ERROR_STOP` рвёт такт, ts не двигаем (§5.6) — но `search_corpus` уже с
дырами; следующий «полный rebuild» **не** возвращает emb из 6a0 сам.
P4 требовал второй гейт (ловим тишину) — поймали; **восстановление** после
срабатывания в v2 не проговорено (quater §4 — про откат SQL, не про mid-flight
STOP). Риск №1 векторов закрыт бэкапом **если** оператор знает, что делать.

**Минимальная правка (если ужесточать):** одна строка в §5 / quater:
«L-mid или пост-xfer STOP → pipeline STOP; до следующего merge — сверка/
restore emb из 6a0-lite; не считать следующий такт самолечением».

### Атака C4-2: обрыв / перестановка до снимка `tmp3_merge_pre_emb`

§5.1: снимок **до** :1290 обязателен, иначе L-mid не отличит hash_kill от
старого NULL. Обрыв **до** снимка при верном порядке (снимок → packs) —
emb ещё цел, безопасно. Опасность новая относительно акцента v1: если
исполнитель/склейка поставит packs **раньше** снимка, L-mid и пост-xfer
слепы к дырам MERGE. Замок `test_merge_mid_abort_lock.py` (§6.4) обязан
якорить порядок; в тексте B6.4 — модель ord/COMMIT, **явного** assert
«pre_emb выше :1290» нет.

**Минимальная правка:** в B6.4 / G-замок одна проверка: grep/порядок
`tmp3_merge_pre_emb` появляется до первого MERGE-пакета `:1290`.

### Атака C4-3: остаточный A1 после снятия cap-STOP (новый акцент v2)

§3.9 фиксирует: маркер-фальшивка на коротком префиксе при пустой mart →
expand «легитимен» по свидетелю (в) → массовая объяснённая смерть; стопор
= бэклог (б) вне окна B. В v1 числовой `|expand|>cap` был тавтологией и
тоже не стопил — семантика runtime та же; но v2 **явно снимает** (б) и
оставляет A1 без стопора внутри B. На flip=0 тела B3 мертвы — для окна
выката B при текущем флаге **не стреляет**. Для показа владельцу плана
стопы не ломает; в §9 A1 не упомянут (только в §3.9).

**Не блокер показа** при flip=0. Для честности экрана владельца — полстроки
в §9: «A1 (фальшивый маркер) — бэклог вне B; на flip=0 мёртв».
