# СНОС-15 / K1: полнота и порядок (красная линза, 2026-09-11)

Линза K1 «полнота и порядок». Входы: `snos15-PLAN.md` (канон 9 волн),
`snos15-MERGE.md` §1–§2, `snos15-P1-waves.md`, `snos15-P2-cuts.md` (§е пар),
`snos15-P3-accept.md`, карты M1/M2/M3; сверка grep по `ubuntu/serenedb/ask/`.
Код/серверы/коммиты не трогались — только этот отчёт. Задача: дыры плана, не
согласие.

Формула №15: вопрос → вики-интерпретация → БД → меню с вики-описаниями при >1 →
выбор человека → ответ. Снос сплошной; 1 волна = 1 коммит = 1 выкат = замер;
Δwrong>0 = откат.

### 2.2. Где тракт дольше всего — «полу-выбиратель»

Худший разрыв относительно P1 (там судьи+fork = одна волна):

1. **После W5 до W6 (1 полный выкат):** арбитр и alias сняты, **fork A/unique/mute/collapse ещё отвечают без человека** (`PLAN` W5 «остаются A-ранний…»; авто-исходы только в W6). Это ровно предупреждение P2 §е цели 5: «снос #5 без #7 оставляет A/mute». Меню early-A есть не на всех ветках → **молчаливый ответ при classes>1** ещё возможен.  
   **Правильнее:** слить W5+W6 (как P1 W4: цели 5+6+7 + builder) **или** поставить цель 7 **перед/вместе** с 5.

2. **После W2 до W4 (2 выката):** sales/prefer сняты, **K6 + emb-сито** всё ещё выбирают порядок сущности. P1/P2-B+C держали до-вики перестановщики компактно.  
   **Правильнее:** вернуть 4+14a в волну с 1+2 (P1 W2) **или** сделать K6+14a немедленной W3, меру сдвинуть на W4.

3. **После W3 до W8 (4 выката):** общий авто-measure срезан, **`try_entity_form_answer` / rolling_year`** ещё могут отдать ответ. Самый длинный полу-тракт пакета.  
   **Правильнее:** подтянуть цель 11 сразу после 3 (или сразу после 5+7), не в W8.

4. **После W4 до W9:** parent-before-child + not_for фильтры режут пул до вики, пока «хвост». Менее критично, чем fork/z05, но противоречит «снос порядка до вики».

Сравнение с альтернативой P2 (A…J) и P1 (7 волн): PLAN дробит «до-вики» и «вторые судьи+fork» сильнее P1 → **больше промежуточных выкатов с живым выбирателем**. Выигрыш проверяемости волн 4/5/6 не окупает дыру §2.2.1.
