## 2. Что калибровали

Симуляция «руками по паспортам/термам» для каждого из **32 match** и **2 wrong**:
взяли фактического лидера из текста ответа onepath-final и поля
`label|aliases|best_used_for|not_enough_for|axes|measures|src_table` с окна.

Покрытие словаря на окне `[замер SELECT]`: **258** строк `search_entity_alias`,
из них **257** с непустым `not_enough_for` (~99.6%). Качество для целевых кейсов
слабое: у `accumulationregister_реализациятмц` в nef **нет** «склад/остат»;
у `catalog_номенклатура` в nef **нет** «прайс» (прайс живёт у
`informationregister_ценыноменклатуры` aliases=`прайс-лист`).

Стоп-слова калибровки (не требуют подтверждения): сколько/записей/движений/
регистре/справочнике/всего/период/дни/… — иначе все «Сколько движений в …»
ломаются на слове «движений».

Именованная сущность: токен в «ёлочках»/кавычках совпал со stem `src_table`
после `_` или с label → подтверждение (named-exempt).

## 5. Рекомендуемая формулировка порога (Б4)

**Где:** код после `wiki_outcome_from_verify`, исход `outcome=leader`
(до SQL / до числа). Промт (в) — только усиление входа модели, **не** единственная защита.

**Правило утверждения лидера L по вопросу Q:**

1. Если в Q есть кавычечное/«ёлочное» имя и оно совпало со stem `L.src_table`
   или `L.label` → **утвердить** (именованный запрос).
2. Иначе если `L.label` (нормализованный) явным куском входит в Q → **утвердить**.
3. Иначе извлечь content-термы Q (минус стоп: сколько/записей/движений/регистре/…);
   domain-термы = корни склад/прайс/остат/цен/клиент/постав/сотруд/валют/орган/…
4. Если есть domain-термы → каждый должен найтись в положительном мешке
   `label|aliases|best_used_for|measures|имена осей (левая часть до →)|src_table`.
   Цель FK (`catalog_местахранения` у оси МестоХранения) **не** считать
   подтверждением слова «склад».
5. Если domain-термов нет → каждый content-терм должен подтвердиться тем же мешком.
6. Если после стоп-слов не осталось ни named, ни content → **не утверждать**
   (no_data или меню пула) — размытый вопрос без темы.
7. Опционально позже: А′ как дополнительный veto, когда `not_enough_for`
   реально перечисляет чужие темы (сейчас на wrong не опираться).

**Исход при отказе:** `no_data` или wiki-clarify по оставшимся yes/unsure —
не число. Не подгонять под «склад»/«прайс» отдельными if.

**Почему не А и не один В:** А режет 2 уверенных match и не ловит склад-wrong;
В уже «проигран» на проде (fit=yes при нерелевантном лидере). Б4 = 0 match /
2 wrong на полном L67 и закрывает «операций в системе».
