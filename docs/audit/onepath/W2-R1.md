## 1. «Мёртвое» — точно мёртво?

### 1.1 Bootstrap / import-побочки

`_bootstrap.load_all` для каждой зоны в `_ZONE_FILES`:

- срезает `apply_bindings(...)` / шапку и хвостовой `register_zone(...)`;
- **`exec` всего остального тела** в общий `ns` (все `def`/`class`/константы
  создаются при загрузке);
- патч `_patch_z20_wiki_primary` — **только** к `z20_ask_main_http_legacy.py`.

Побочки на load: чтение `os.environ`, компиляция regex, `threading.Lock` /
`ContextVar` (z01). **SQL/HTTP на уровне модуля при load не исполняются** —
`psql`/`urlopen` живут внутри функций. Снос файла из `_ZONE_FILES` без правки
списка роняет любой `import serene_ask` / `load_all` (это X3 уже сказал).

`apply_bindings` / `register_zone` **не** спасают «мёртвые» символы: рантайм ask
живёт голыми именами в одном `ns`, не через реестр `_wire`.

### 1.2 Ложные «мёртвые» / ложные «только-legacy» (обязательные правки)

### 1.3 Что действительно мёртво (атака не отменила)

- Весь файл `z20_ask_main_http_legacy.py` при `ASK_ONEPATH=1` не грузится.
- `fork_detector_scan` / `resolve_fork_outcome` / `pick_measure` / почти весь
  veto-arbiter z16 — **нет** reach из нового входа (совпадает с зонными картами).
- Stubs `fork_outcome_a/b/unique`, `fork_label_siblings`, whitelist/arbiter
  z16 без прод-звонов — мёртвы для runtime; **живы замкам** (см. §4).

### 1.4 Динамика / env

- `getattr(fork_classes, "_meta_by_fp")` — legacy z20 + z09/z13 на fork-цепи;
  в новый `answer` **не** входит.
- `globals().get("entity_form_catalogs_for_kind")` в `z21` — **живой** люк:
  wiki post-verify может тянуть z05 → `meaning_candidates`. X1 (только Load z20)
  этот путь **не видит**; зонные карты частично учитывают.
- Env (`ASK_ENTITY_FORM`, `FORK_DETECT`, `ASK_SALES_RANK_CANON`, …) читаются при
  load зон; новый `answer` **не** ветвится на `FORK_DETECT`/`pick_measure`. Флаги
  не воскрешают снесённый legacy-код без вызова.

## 5. Скрытые выбиратели нового тракта

Критерий контракта «один путь»: при **>1** кандидате — меню человеку; авто
допустимо лишь при **ровно одном** (или разбор уже выбранного билета).

| Зона / символ (по W1-z*) | Заявление карты | Проверка кода | Вердикт атаки |
|---|---|---|---|
| **z14 `measure_choice`** | молчаливый выбор меры | При >1 именах: `exact`/`alias`/`base`/`substring` возвращают **одну** без меню; `ask` только при неустранимой неоднозначности. `_settle_measure` при `_got` сразу `return _got` | **Подтвердить:** выбирает при >1 (нарушение духа контракта на silent-ветках). |
| **z10 `rank_axis_resolve`** | скрытый осевой выбиратель | При `len(picked)>1` → `(None, picked)` → меню; авто только `len==1` | **Смягчить карту:** не меню-bypass при ≥2; риск — **схлопывание** rerank/model к одному среди многих входов. |
| **z12 `stock_net_register_pair`** | кодовый выбор регистров | Среди `siblings≥2` молча назначает receipt/expense (+ noise-фильтр) | **Подтвердить:** выбирает при >1. |
| **z13 `stock_balance_is_sales_noise`** | скрытый отсев src | Подстроки имени → отсев в паре регистров | **Подтвердить** (фильтр-выбиратель). |
| **z03 `repair_period_from_question`** | скрытый период | Пишет `intent["period"]` до меню readings | **Подтвердить** (до меню окон). |
| **z05 `live_axis_col_for_count` / `sales_compare_windows`** | скрытые ось/окна | Код выбирает колонку/пару окон | **Подтвердить.** |
| **z06 `keep_empty_period_opts`** | отбор в clarify | Режет пустые в меню; при ≥2 оставшихся меню остаётся | **Не** silent-pick src; карта z06 слегка переоценивает «выбиратель». |
| **z09** | «скрытых нет» | Сами label-функции не выбирают src; но **живы** на new | Заявление про выбиратели **ок**; заявление про мёртвость covering — **нет** (§1). |
| **z04 / z04b prefer-*** | не в new | `prefer=None` / mismatch → options | **Подтвердить.** |
| **z16 pick_measure / …** | не в new | Reach нет | **Подтвердить.** |
| **z18 `axis_clarify_options`** | меню при clarify | Строит options → `readings_menu` при >1 | **Не** silent; карта ок. |
| **z21 wiki** | фильтры пула + verify | При >1 карточках: pick/verify; `wiki_outcome_from_verify` даёт leader при **ровно одном** `yes` | Фильтры — сужение пула; leader при 1×yes — **по контракту «ровно один»**. Clarify при tied → `mk_opts` (≥2). Карта z21 в целом **ок**. |

## 6. Вердикт: что НЕОБХОДИМО скорректировать в реестре сноса

До любой волны выреза:

### P0 — блокер сноса (сломает onepath)

1. **Снять с «выреза целиком»:** `z09_fork_detector.py`, `z13_fork_outcomes.py`,
   `z16_veto_pick_entity.py` (X4 консервативный слой B; X3 «мёртвая z16»).
2. **Перевести в ЖИВА НОВОМУ (сохранить до точечного выноса):**
   - z09: `fork_labels_of`, `fork_labels_covering` (+ зависимость `mk_opts`);
   - z13: `atom_terminal_gate_text`, `stock_balance_is_sales_noise`;
   - z16: `pair_slots_only`, `question_expects_accounting_data`, `_NON_DATA_MARKERS`;
   - z21: `wiki_menu_captions`, `wiki_captions_map_from_cards`, `wiki_passport_enrich`
     (убрать из X2 legacy-корзины сноса);
   - z06: `keep_empty_period_opts` (через wiki-clarify);
   - z20: сам `mk_opts` (+ `live_src_counts` / `disambiguate_labels` / `opts_hints`
     на этой цепи).
3. **Исправить W1-z09** §про mk_opts / `fork_labels_covering` = L — иначе реестр
   исполнителей волны повторит ошибку.

### P1 — обязательная правка метода реестра

4. **Транзитив до сноса:** не сносить символ, пока есть reach от
   `answer`/`wiki_primary_entity_cascade`/`compose` (не только Load в z20).
5. **X2 soft ≠ «оставить насовсем»:** `holders_of_target` и аналоги на
   только-legacy цепях — кандидаты в мёртвое **после** проверки замков.
6. **X4:** «почти мёртвые зоны» = метрика строк, **не** разрешение `rm` файла;
   консервативный вырез пересчитать: legacy файл + **тела** fork/veto **минус**
   щели P0 (не 2568 целиком).
7. **Перекрытие имён z02↔z16** для `question_expects_accounting_data` —
   явный пункт миграции при частичном сносе z16.

### P2 — замки / документация сноса

8. План волны: синхронно править замки на stubs/«мёртвых» символах
   (`test_step4_guards`, `test_answer_atom`, fork-stubs) — иначе «снос мёртвого»
   красный при зелёном проде.
9. Добавить в чеклист сноса: **wiki-clarify ≥2** обязан сохранять
   `mk_opts`→`fork_labels_covering` (замок/проба, которых X3 не требует).
10. Любой файловый снос ↔ правка `_bootstrap._ZONE_FILES` +
    `test_zone_names_resolvable`.

### Не блокер (можно не трогать до исполнения)

- Расхождение счётчиков X1 «149» vs X2 «155» — косметика метода.
- Скрытые выбиратели P0-контракта (`measure_choice`, stock-net, …) — **продуктовый**
  долг onepath, не ошибка реестра сноса мёртвого груза; в снос «как мёртвое»
  их класть нельзя.
