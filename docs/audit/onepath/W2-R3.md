## 0. Метод атаки

| Приём | Что ловит |
|---|---|
| Reachability AST внутри нового `z20` | Load/Call в **мёртвых** локалах файла (не из `answer`/`answer_checked`/`Handler.do_*`/`main`) |
| Транзитивный BFS по голым `Name`-вызовам зон | «Soft» X2: зона читает символ, но **корни только-legacy** |
| `getattr` / `globals().get` / env | Скрытые зовы и мягкая деградация |
| `_bootstrap.load_all` | Что реально exec’ится; срезы `apply_bindings`/`register_zone` |
| Замки по **символу**, не только по зоне | Падения при сносе «мёртвых» def внутри живой зоны |
| Поведение при `len(candidates)>1` | Нарушение контракта «меню, не silent pick» |

Ограничение: ветвление внутри живой функции (редко вызываемый `elif`) не
размечалось — занижает «мёртвое», не завышает «живое».

## 1. «Мёртвое» — точно мёртво?

### 1.1. `_bootstrap.load_all` — побочные эффекты на import

- В общий `ns` **exec**ится тело каждой зоны из `_ZONE_FILES` (включая z16 и
  активный z20). `apply_bindings` / `from ask.*` / `register_zone` **срезаются**
  (`_body_start_line` / `_body_end_line`) — в runtime bootstrap они не
  исполняются.
- На уровне модуля остаются: `os.environ.get(...)`, константы, пустые кэши,
  `threading.Lock()`. **SQL/сети при load нет** (кроме косвенно, если когда-то
  добавят top-level Call — сейчас нет).
- Следствие: «символ определён» ≠ «символ жив тракту». Определение появляется
  у всех замков с `serene_ask` / `load_all` даже у мёртвых для `answer` функций.
  X3 это уже отмечает; зонные карты иногда путают «есть в ns» с «зов из тракта».

### 1.2. Косвенные зовы (getattr / globals / строки)

| Механизм | Где | Для нового тракта |
|---|---|---|
| `getattr(fork_classes, "_meta_by_fp")` | legacy z20; z13 `ordered_fork_classes`; z09 | Только legacy-цепь fork. **Не** воскрешает z09/z13 целиком |
| `globals().get("…")` | z10/z11/z12/z05/z16/z21/z13 | Мягкая опция: отсутствие символа → `None`/False, **не** NameError. Снос «мёртвого» имени может **тихо деградировать** путь (пример: `_is_product_catalog` в z12 net-pair), а не упасть |
| Строковый dispatch / `eval` по именам зон | в ask/ **не найден** | — |
| Env-флаги (`ASK_*`) | много | Включают ветки **внутри уже живых** функций; не поднимают legacy-only символы |

**Атака на «жёсткое мёртвое» X2 §3.2:** часть имён без чужих Load в зонах
действительно мертва для runtime ask. Но **замки** их зовут напрямую
(`test_step4_guards` → `alias_supported` / `arbiter_figures` / …) — см. §4.
Вердикт «можно снести без правки тестов» для этих символов **ложный**.

### 1.3. Ложные «жива новому» у X1 (мертвы достижимостью)

X1 считает любой Name-Load в файле нового z20. Reachability от входов тракта:

| Символ (X1 «жив») | Факт |
|---|---|
| `fork_labels_covering` | Только в **`mk_opts`**. `mk_opts` **недостижим** из `answer`/`Handler` (0 call-site). W1-z09 верно: **L / мёртв для onepath**. X1 **ошибся** |
| `keep_empty_period_opts` | То же: только `mk_opts` → **не жив новому** |
| `RESOLVER_DSN` | Только в `_ensure_ask_scope_table`, а её **никто не зовёт** (в т.ч. не `main`). `_persist_ask_scope` жив и ходит в `_resolver_psql` без проверки DSN |

Карта z09 здесь **сильнее** поперечника X1. Реестр сноса, если копирует X1,
оставит мёртвый `mk_opts`+covering как «нужное» или наоборот посчитает z09
нужной из‑за covering — оба риска.

### 1.4. Что карты верно держат мёртвым (атака не пробила)

- Целый fork-скан z09 (`fork_detector_scan`, `_fork_*`, `fork_classes` как
  рантайм-мета) — только legacy + getattr.
- z13 outcomes A/B/C / `resolve_fork_outcome` — только legacy; stubs
  `fork_outcome_a/b` — мёртвы и для legacy runtime.
- z16 `pick_measure` и большая часть veto — только legacy; в `test_one_path`
  `B4_FORBIDDEN`.
- `_patch_z20_wiki_primary` и инжект `entity_form_gate_open` /
  `stock_asks_named_product` в **новый** z20 не применяются
  (`_bootstrap`: патч только legacy-файла).

## 2. «Жива новому» — точно жива?

### 2.1. X1: Load ≠ достижимость

Метод X1 завышает живость на **мёртвых локалах** нового z20 (§1.3). Исправлять
реестр: внешний символ «жив новому» только если Load из **достижимой** функции
(или module-level, реально исполняемого при старте).

`BaseHTTPRequestHandler` в X1 «nowhere in funcs» — ложная тревога: жив через
`class Handler(BaseHTTPRequestHandler)`.

### 2.2. Символы, которые X2 кладёт в «только legacy / soft», но они REACH из new

Транзитивный граф от `answer` / `_settle_*` / `_onepath_compose_gate` /
wiki-каскада (голые Call по зонам). Ниже — **опровержение** «умрёт со сносом
legacy» для soft-списка X2 §3.3:

| Символ | Цепочка до new (сокр.) |

| `period_preds` | `aggregate_compare_sales` ← `answer` |
| `calendar_axis_open` | `expand_readings_calendar_axis` ← `answer` |
| `currency_axis_open` | `currency_mismatch_blocks_answer` ← compose_gate |
| `emb_ready` / `_vec` | `resolve_values` ← `probe` ← `answer` |
| `_stem_set` | `same_concept_groups` ← `parse_intent` |

вырезать после flip» без транзитивной проверки.

### 2.3. Ложное «целиком жива зона / целиком мертва»

- **z09:** X4 «почти мёртвая, вырезать целиком» — **ложно**. Нужен
  `fork_labels_of` (currency mismatch → меню amount_basis). Covering — нет.
- **z13:** X4 «вырезать целиком» — **ложно**. Нужны
  `atom_terminal_gate_text` + `stock_balance_is_sales_noise` (через z12
  net-pair). Outcomes A/B/C — да, legacy-only.
- **z16:** X3/X4 «мёртвая зона» — **ложно как файл**. Живы новому:
  `pair_slots_only`, `question_expects_accounting_data` (+ константа
  `_NON_DATA_MARKERS` внутри неё). Остальное — legacy/замки.
  Перекрытие имён: z02 тоже определяет `question_expects_*` /
  `_NON_DATA_MARKERS`; при `load_all` **побеждает z16** (грузится позже).
  Снос z16 подменит поведение на z02-версию — не «noop».

### 2.4. Мёртвые ветки внутри «живого» нового z20

Кроме `mk_opts`: `ambiguous_labels`, `disambiguate_labels`, `label_with_kind`,
`live_src_counts`, `opts_hints`, `_ensure_ask_scope_table` — локально
недостижимы. X4 «B2 почти вся достижима» **завышена**: есть мёртвые острова
инфры внутри нового файла (~сотни строк вместе с `mk_opts`).

`live_src_counts` при этом в `test_one_path.SQL_CALLS` — имя в контракте
замка, даже если call-site мёртв.

## 3. Транзитивность (зона A → B)

### 3.1. Где карты потеряли цепочку «A только-legacy ⇒ B мертва»

X2 soft явно предупреждает, что Load в файле-владельце ≠ нужность new, но
**не разворачивает** граф. Красная атака:

**DEAD_TRANSITIVE** (читаются зонами, но корни только legacy / orphan) —
кандидаты на снос **вместе** с legacy-caller, не «оставить как soft»:

- `_fork_atom_of`, `_fork_figures_of`, `_measures_by_src`, `fork_classes`,
  `fork_clarify_from_wiki_pool`, `calendar_day_basis_prefer`,
  `currency_amount_basis_prefer`, `entity_form_gate_open`,
  `entity_form_applicable`, `event_count_period_option_readings`,
  `holders_of_target`, `measure_ambiguous`, `prefer_window_leader`,
  `render_window_label`, `wiki_leader_alive`, `warehouse_axis_values`,
  `src_supports_question`, `kind_has_corpus_support`, …

Зонные карты z09/z13 в основном это учли. **X2 soft и X4 «смешанные зоны»**
могут оставить мёртвый груз под видом «ещё кто-то читает».

### 3.2. Обратная ошибка: цепочка жива, карта — «только legacy»

См. §2.2. Особенно опасно для wiki/stock/period soft-имён: снос «как
legacy-only» сломает onepath.

### 3.3. Эталон правильной транзитивности

W1-z09: `fork_labels_covering` в new z20 есть, но через мёртвый `mk_opts` →
**L**. Это эталон, которому X1/X4 не следовали.

X3 силён на **зонах** и path/text legacy. Слаб на **символах внутри** зоны,
которую new ещё трогает, и на «мёртвых» def с прямыми assert’ами.

### 4.1. Уже в X3, но недооценены как блокер «тонкого» сноса

| Зона / слой | Замки | Риск |
|---|---|---|
| z16 «мёртвые» def | `test_step4_guards` (десятки assert на `alias_supported`, `figures_numbers`, `same_number`, `mute_measure_blocks`, `pair_unanswered`, `single_is_rival`, `veto_top_without`, `arbiter_figures`), `test_answer_atom` (whitelist), `test_gate` | Снос символов с вердиктом МЁРТВА **без** правки замков → красный suite. | z13 stubs / orphan | `test_fork_outcomes`, `test_leader_hatch`, `test_atom_terminal`, `test_action_class`, `test_one_path` (имена в запретах) | Снос stub-имён ломает замки, даже если runtime их не зовёт |

| z10 мёртвые | `count_theme_code_pick_applies`, `rank_leader_*` → entity_form / rank_leader / unit_from_data | X3 зону z10 считает живой; символьный снос не размечен |

### 4.2. Слепые зоны X3

1. **Снос def внутри живой зоны** (не файла) — X3 не даёт реестра.
2. **Двойники new/legacy** (`gate`, journal, health) — X3 оговаривает; при
   сносе legacy path/text замки (§В X3) всё равно красные, пока path не
   перенацелен.
3. **`test_zone_names_resolvable` + `_ZONE_FILES`:** любой файл, вычеркнутый
   с диска, но оставленный в bootstrap — валит **все** `serene_ask`-замки.
4. **`globals().get`:** снос не валит тест «callable», но может снять
   поведение, которое замок не проверяет.

## 5. Скрытые выбиратели нового тракта (опровержение / подтверждение)

Контракт: при **>1** кандидате прочтения/меры/оси/источника — меню человеку,
не silent code-pick. Ниже — зонные заявки vs код.

| Заявка карты | Вердикт атаки | Поведение при >1 |
|---|---|---|
| z09: в new нет выбирателей; только `fork_labels_of` (лейблы) | **Подтверждено** | `fork_labels_of` не выбирает; covering мёртв |
| z13: `stock_balance_is_sales_noise` — скрытый отсев источника | **Подтверждено** | Фильтр/классификатор имени в `stock_net_register_pair`; при нескольких siblings **код** выбирает receipt/expense (`_sort_stock_pool`, `max` по counts) — **silent pair-pick**, не меню |
| z14: `measure_choice` — silent при exact/alias/base/substring | **Подтверждено, контрактный риск** | При `len(names)>1` и `how≠ask` возвращает одну меру без меню. `_settle_measure` это принимает. Меню только при `how=='ask'` |
| z14: `hold_settled_entity` — выбор src по билету | **Подтверждено как память выбора** | Не меню; задумано как settle билета. Риск one-path — если билет неоднозначен |
| z10: `rank_axis_resolve` → меню при ≥2 | **Подтверждено (ок)** | `len(picked)>1` → `(None, picked)`. Авто только при ровно одной |
| z10: skips axis без вопроса | **Подтверждено** | Гейт «не спрашивать ось», не выбор между осями |
| z05: `live_axis_col_for_count` / `_pick_kind_axis_col` | **Усилено** | При нескольких hits: `reranked[0] if reranked else hits[0]` — **явный silent pick при >1** |
| z04: expand calendar → меню при len>1 | **Подтверждено (ок)** | Размножает readings; лидер day_basis в new не проводён |
| z03: `repair_period_from_question` | **Подтверждено** | Пишет period в intent до меню readings — оркестратор периода |
| z21: filter/verify/knn gap | **Частично ок** | `len(cards)==1` → verify; иначе pick+verify; clarify при tie. `filter_pool_by_named_type` режет пул кодом (не меню типов). Leader post_verify может отвергнуть — не silent best-of-bad |
| z12: `stock_net_register_pair` / qty/axis helpers | **Подтверждено** | Кодовый выбор регистра/меры/оси без wiki-меню |
| z16: «выбирателей в new нет» | **Подтверждено** для veto/pick; `question_expects_*` — классификатор, не меню |
| z15/z18 form/slot/axis_clarify_options | **Уточнить** | `axis_clarify_options` → меню; `answer_slot_mode` / atom ops — форма ответа, не src |
| z07 `resolve_values` | **Подтверждено** | Молчаливое значение фильтра (не ось/мера), но code-pick |

**Итог по контракту:** среди «скрытых» на new есть и безопасные (меню при >1:
`rank_axis_resolve`, calendar expand, wiki clarify), и **нарушители**
(`measure_choice` silent-ветки, `_pick_kind_axis_col`, `stock_net_register_pair`).
Зонные карты в целом честны; преуменьшают тяжесть z05/z12/z14.

## 6. Вердикт: что НЕОБХОДИМО скорректировать до исполнения сноса

Обязательные правки реестра (без них этап сноса сломает onepath и/или suite):

### P0 — блокер

1. **X4 / любой план «вырезать z09+z13+z16 целиком»** → заменить на
   **хирургию**:
   - z09: оставить `fork_labels_of` (+ минимум зависимостей лейблов);
   - z13: оставить `atom_terminal_gate_text`, `stock_balance_is_sales_noise`;
   - z16: оставить `pair_slots_only`, `question_expects_accounting_data`,
     `_NON_DATA_MARKERS` (или перенести в z02/z21 **тем же** коммитом с
     проверкой перекрытия имён).
2. **X1:** снять с «живых внешних» `fork_labels_covering`,
   `keep_empty_period_opts` (и не строить на них keep-z09); пометить
   reachability-метод обязательным для реестра.
3. **X2 soft §3.3:** переклассифицировать по транзитивности — **не сносить**
   имена из §2.2; soft DEAD_TRANSITIVE из §3.1 можно сносить только вместе с
   legacy-caller / после вычищения внутренних зовов.
4. **Снос z16 как «мёртвой зоны» (X3)** → запрещён без пункта 1; иначе wiki
   empty-pool / compose slot-mode меняют семантику.

### P1 — до первой волны выреза

5. **Реестр замков символьного уровня** (дополнение X3): минимум
   `test_step4_guards`, `test_compose` (`_ask_back`), `test_answer_atom`,
   z14 diverge/reset, z10 orphan rank-*, z13 stubs — либо правка замков в той
   же волне, либо keep-list «мертвых для прод / живых для suite».
6. **Новый z20 мёртвые локалы** (`mk_opts`, label helpers,
   `_ensure_ask_scope_table`, …) — в умеренный вырез; не считать B2 100% живым.
7. **Скрытые выбиратели-нарушители** (`measure_choice` silent, `_pick_kind_axis_col`,
   `stock_net_register_pair`) — не «баг карт», но **нельзя** молча оставить в
   «супер-простом» тракте без решения владельца (меню vs оставить как расчёт).
   В реестр сноса: не маскировать их под «не выбиратель».

### P2 — уточнения (не блокер flip, блокер агрессивного выреза)

8. X2 «39 hard-dead» — ок как «вход не Load’ит»; перед delete сверить замки
   (§4) и `globals().get` потребителей.
9. `kind_axis_rerank` жив транзитивно через `rank_axis_resolve`; запрет
   `B4_FORBIDDEN` в `test_one_path` — про прямой вызов из `answer`, не про
   отсутствие символа. Снос символа сломает settle оси.
10. Оценка строк X4 (~7.7k консервативно) **завышена**, пока z09/z13/z16
    режутся целиком; после P0 консервативный вырез ближе к
