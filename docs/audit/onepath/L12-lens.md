Дата: 12.09.2026. Режим: только чтение `ubuntu/serenedb/ask/*.py` + этот файл.
Чужие отчёты `docs/audit/onepath/*` не читались. Модель и БД не звались.

Аспект: **полный аудит без специализации** — качество, лишнее, недостающее,
опасное; тяжесть по влиянию на контракт (TARGET п.12/19/21) и на «один путь».

## 0. Метод (свой)

1. Grep по `ask/` на `*_SYS` / `*_PROMPT` / `*_HINT`, `role": "system"`, `ds_chat(`.
2. AST-проход по `z*.py` — константы и длины.
3. Обход вызовов символов (кто реально зовёт, кто только в `OUR_PROMPTS`/комментариях).
4. Чтение каждого system-текста целиком + соседней user-сборки + разбора ответа.
5. Bootstrap: живой runtime грузит `z20_ask_main_http_legacy.py` (новый `z20` — скелет
   до flip, compose/SQL — заглушка B4).

Единая точка LLM-чата: `ds_chat` / `ds_chat_post` в `z01_infra_trace_llm.py`
(`POST …/v1/chat/completions`). Отдельно: эмбеддер и rerank — не промпты чата, в реестр
не входят.

## 2. Анализ по аспекту (промпт за промптом)

### 2.1. INTENT_SYS — оставить ядро; точечные дыры схемы

**Качество.** Хороший контракт формата: язык-агностичный JSON, разделение
`terms` vs `kind`, `about` data/coverage, `action_class`, `search_form` (нужен вики-пулу).
Разбор и согласие прогонов — в коде (правильно по правилу 03.08).

**Лишнее / опасное (правила в промте):**
- блок `Rules:` с `NEVER` / `ALWAYS` — часть дублирует то, что уже чинит код
  (вынос kind/measure из terms, нормализация want/about). Сами по себе не «новые
  запреты продукта», но плотность долженствований высокая; чистить без замера —
  риск регрессии разбора (известно: разброс kind/terms на temperature=0).

**Недостающее (схема vs код):**
1. Код принимает `amount.op = "="` (`_AMOUNT_OPS`, комментарий про нулевые суммы),
   в промте перечень: `">"|"<"|"|>="|"|<="|"between"` — **без `"="`**.
   Дословная строка промта:
   `"amount": {"op": ">"|"<"|">="|"<="|"between"|null, ...}`
2. Код читает и стабилизирует **`period2`**, в JSON-схеме промта поля **нет**.
   Модель не инструктирована → поле почти всегда пустое, кроме случайной выдумки.

**Вердикт:** ядро **не трогать**. Кандидаты: добавить `"="` и (если dual-period
нужен продукту) `period2` в схему — **низкий/средний риск**, только с прогоном
intent-bench. Массово вырезать Rules — **высокий риск** живых ответов.

### 2.2. ARBITRATE_SYS — снести (мёртвый код)

Комментарий z01 честно описывает замысел «выбрать номер, не пересказывать» и
удержание кодом. Но функция не вызывается; тест фиксирует 0 вызовов в z20.

**Вердикт:** **снести** вместе с `arbitrate` при отдельном коммите уборки.
Риск для живых ответов: **нулевой** (путь мёртв). В `OUR_PROMPTS` и так нет.

### 2.3. CLARIFY_SYS — снести / вывести из hot-path

Меню давно строит **код** (`clarify_say`: «не проза модели»). `clarify_text` —
orphan. Промпт всё ещё в `OUR_PROMPTS` (польза только для leak-детекта мёртвого текста).

Дословно лишнее (правило вместо механизма меню):
`Never show table names, codes or internal identifiers.` —
для живого меню это уже `label_has_meta_src` / `human_table_label` в z20.

**Вердикт:** **снести** вызов/константу после подтверждения grep=0 callers.
Риск: **нулевой** для ответов. Не путать с живым `REFUSE_SYS` в том же файле.

### 2.4. REFUSE_SYS — не трогать

Короткий, ролевой, без данных; цифры режет код. Согласован с п.18/языком.

**Вердикт:** **оставить как есть.**

### 2.5. AXIS_PICK_SYS — оставить; риск user-части

Промпт короткий, формат индексный — хорошо (модель не изобретает имена осей в
ответе, который читает код).

**Опасное рядом:** `rank_axis_label_rows` может отдать `«метка (col)»` → в модель
уходит **имя колонки** (напряжение с п.19 «колонки в модель не отправляются»).
Это не строка system-промпта, но часть контракта вызова.

**Вердикт:** system — **оставить**. Кандидат чистки user-меток (без `(col)` если
есть человеческая метка) — средний риск для качества выбора оси; только с замером
rank.

### 2.6. ANSWER_SYS — чистить контракт `ask`; ядро плейсхолдеров не трогать

**Сильное:** запрет писать вычисленные числа держится **устройством** user-части
(плейсхолдеры без значений) + гейтом; комментарии в z18 это прямо замерили.
`claims` объявлены ignored — честно.

**Лишнее / конфликт с «одним путём»:**
Дословно:
`"ask" is the middle road between answering and giving up. Fill it ONLY when…`
и далее правила когда спрашивать / не спрашивать.

В legacy после compose: `_ask_back` → fill → **всегда**
`diag["ask_back_dropped"] = "bare_clarify_forbidden"`. Поле живёт в промпте,
сжигает токены и внимание модели, наружу не доезжает. В новом тракте ask_back
запрещён контрактом эпизода.

Также: `🔴 NEVER WRITE A COMPUTED FIGURE…` — дубль механизма; оставлять можно
как подсказку формата, но это именно rule-in-prompt (защищён гейтом).

**Вердикт:**
- механизм placeholders / язык / short businesslike — **не трогать**;
- блок `"ask"` + инструкция middle road — **чистить** при B4/one-path
  (убрать поле из схемы JSON или зафиксировать `"ask": null` always), риск
  **средний** (регрессия формулировок, если модель цеплялась за ask-ветку);
- не выкидывать `NEVER WRITE FIGURE` без замера — **высокий** риск цифр в тексте.

### 2.7. COVERAGE_SYS — оставить; мелкие противоречия паттерну

Дубликат в new/legacy идентичен. Зовётся после wiki в новом скелете — ок по
порядку «один путь».

Паттерн слабее ANSWER: просит **цифры в тексте** и в `claims`, а не плейсхолдеры.
Защита — белый список переписи + `gate` (в коде прямо отмечен был дырявый путь
«claims пустые → ничего не проверялось» — сейчас gate есть).

User: имена `entity` из `search_coverage` — риск «метаданные» в смысле имён
источников; для coverage это сами данные переписи.

**Вердикт:** **оставить как есть** до замера coverage-вопросов. Унификация под
плейсхолдеры — кандидат низкой приоритетности, риск среднего (другой стиль ответов).

### 2.8. WIKI_PICK_SYS / WIKI_VERIFY_SYS — не трогать (ядро одного пути)

Оба короткие, JSON-only, без морали/запретов продукта. Код: индексы, fit-map,
salvage обрезанного JSON, исход leader/clarify/none. `separable` модели не
перебивает kNN-gap.

**Недостающее не в промпте, а в leak-списке:** WIKI_* нет в `OUR_PROMPTS` →
утечка куска инструкции wiki в клиентский текст формально не ловится
`prompt_leak`.

User verify тяжёлый (до 1500×8) — осознанный бюджет; резать промпт ради этого
нельзя, только budget-константы (вне scope «правка промпта»).

**Вердикт:** **оставить как есть.** Кандидат: добавить в `OUR_PROMPTS` —
риск **нулевой** для смысла ответов.

## 3. Ранжирование проблем по тяжести

| # | Тяжесть | Проблема | Где |
|---|---|---|---|
| 1 | **Высокая (контракт one-path)** | В живом ANSWER_SYS всё ещё контракт модельного `ask` / ask_back, хотя код всегда дропает и новый тракт запрещает | ANSWER_SYS + legacy compose |
| 2 | **Средняя (п.19 / схема)** | INTENT: код знает `=` и `period2`, промпт — нет | INTENT_SYS vs z01/z02 |
| 3 | **Средняя (п.19)** | В AXIS user уходят имена колонок `(col)` | z10 `rank_axis_label_rows` |
| 4 | **Средняя (гигиена/защита)** | Мёртвые CLARIFY + ARBITRATE; CLARIFY ещё в OUR_PROMPTS; WIKI нет в OUR_PROMPTS | z07/z01/z20 |
| 5 | **Низкая** | COVERAGE пишет цифры сам, не плейсхолдерами; дубль константы new/legacy | COVERAGE_SYS |
| 6 | **Низкая (техдолг)** | Плотность NEVER/ALWAYS в INTENT/ANSWER при том, что удержание уже кодом | INTENT/ANSWER |
| 7 | **Инфо** | Новый z20 пока не зовёт ANSWER/AXIS compose-путь (stub B4) — правки ANSWER бьют **legacy/прод** до flip | bootstrap |

Не найдено: отдельных `*_PROMPT` / `*_HINT` констант; второго чат-клиента;
скрытых system-ролей вне таблицы выше.

## 4. Итог

### 4.1. Правки-кандидаты

| Промпт | Строка / фрагмент | Действие | Риск для живых ответов |
|---|---|---|---|
| ANSWER_SYS | блок `"ask"` / middle road (примерно строки схемы JSON + абзац Fill it ONLY…) | Убрать поле `ask` из контракта JSON **или** явно: всегда null; синхронно с B4 one-path | **Средний** — меняет форму ответа модели; нужен compose/acceptance замер |
| INTENT_SYS | строка `amount.op` | Добавить `"="` в перечень | **Низкий** — код уже принимает; снижает lost/угадывание |
| INTENT_SYS | JSON schema | Добавить `period2` **только если** dual-window — продуктовая нужда; иначе не учить модель | **Средний**, если поле начнут заполнять ошибочно |
| CLARIFY_SYS + `clarify_text` | z07:285–311 | Снести мёртвый путь; убрать из OUR_PROMPTS | **Нулевой** |
| ARBITRATE inline + `arbitrate` | z01:602–628 | Снести мёртвый путь | **Нулевой** |
| OUR_PROMPTS | z20 / legacy ~755 | Добавить `WIKI_PICK_SYS`, `WIKI_VERIFY_SYS` | **Нулевой** (только leak-детект) |
| AXIS user labels | z10:169–171 | Не слать сырой `col`, если есть человеческая метка | **Средний** — качество axis-pick |
| COVERAGE_SYS | «State figures in DIGITS» | Опционально позже: плейсхолдеры как у ANSWER | **Средний**; не в первой волне |

### 4.2. Не трогать

| Что | Почему |
|---|---|
| REFUSE_SYS | Короткий, живой, цифры режет код |
| WIKI_PICK_SYS / WIKI_VERIFY_SYS (текст) | Ядро wiki-каскада «одного пути»; формат достаточный |
| INTENT_SYS целиком / Rules-блок целиком | Приёмочно чувствителен; чистить «лишние NEVER» без intent-bench нельзя |
| ANSWER_SYS: плейсхолдеры, язык ответа, запрет выдумки имён из rows | Держится замерами; гейт + fill |
| Механизм `compose` user-body (COMPUTED без значений) | Главная защита п.19 по числам — не промпт-словами |
| `clarify_say` / меню без LLM | Уже правильный путь; не возвращать CLARIFY_SYS |
| Живой `ds_chat` / temperature=0 / intent multi-sample | Не промпт; менять отдельно |

### 4.3. Одна фраза вердикта линзы

Живых чат-промптов **семь логических** (INTENT, REFUSE, AXIS, ANSWER, COVERAGE,
WIKI_PICK, WIKI_VERIFY) + **два мёртвых** (ARBITRATE, CLARIFY); главная содержательная
грязь для «одного пути» — **контракт `ask` в ANSWER_SYS при гарантированном drop в
коде**; главные схемные дыры — **`=` и `period2` в INTENT**; остальное ядро лучше
не трогать без замера.
