Дата среза: 12.09.2026. Только чтение `ubuntu/serenedb/test_*.py` + `ask/z*.py`.
Чужие отчёты `onepath/` не читались.

## Метод

1. Инвентарь top-level `def`/`class`/констант в `ask/z*.py`; уникальные символы → зона.
2. По каждому `test_*.py` (141 файл) — доказательства зависимости:
   - **path/text** — путь к `zNN_*.py` / чтение текста;
   - **exec** — `exec` тела зоны;
   - **load_all()** — вызов (не строка «не load_all»);
   - **import** — `from ask.z…`;
   - **runtime-call** — вызов уникального символа зоны при `import serene_ask` / exec;
   - **name-mention** — только имя в строке/множестве (запреты, якоря) без вызова.
3. **Судьба:** сильная зависимость → **упадёт** при сносе этой зоны; только name-mention → **переживёт**.
4. Мёртвые зоны (независимо): символы, которые есть в `z20_ask_main_http_legacy.py`
   и **нет** в новом `z20_ask_main_http.py`, плюс сам файл legacy.
   Находка: `z16_veto_pick_entity.py`, `z20_ask_main_http_legacy.py`.

### Важно про `import serene_ask`

`serene_ask` тянет `_bootstrap.load_all` → исполняются **все** файлы из `_ZONE_FILES`.
Если зону снесли с диска, но не убрали из `_ZONE_FILES`, упадут **все** замки с `serene_ask`.
В таблице ниже — **субъектные** зоны (что замок реально читает/вызывает).
Загрузочная зависимость «весь bootstrap» отмечена колонкой `serene_ask`/`load_all`.
