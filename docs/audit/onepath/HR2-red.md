## 1. Не режет ли уверенные (матрица классов)

Морфология (`_wiki_topic_stem_match`, z21:1401–1417): общий префикс ≥4, хвост ≤3
**или** подстрока. Проверено: `склад/склада/складу/складом/складе/склады/складов/складах/складам`
→ root `склад`. Не «проспект» для этих форм.

`_wiki_topic_domain_root` (1318–1325): `startswith(root)` или `root.startswith(tok)`
при `len(tok)≥3`. Словарь (1284–1285):
`склад прайс остат цен клиент постав сотруд валют орган`.

| Класс | Ветка кода | Вердикт |
|---|---|---|
| Named в «ёлочках»/кавычках | `named_exempt` → OK (`1487–1498`) | **пройдёт** |
| Label куском в вопросе | `label_in_question` (`1453–1461`, exact/без пробелов) | **пройдёт** при именительном; родительный label («реализации тмц») → не label, но часто **пройдёт** через `topic_ok:content` (stem к «реализация») |
| Alias / `best_used_for` | positive bag (`1386–1398`) + `term_in_text` | **пройдёт**, если терм в мешке |
| Count + domain («на складе») | `required=domain` → все корни в bag | **пройдёт** у носителя; **зарежет** чужого без корня |
| Count без темы («сколько всего записей») | `empty_topic` (`1502–1508`) | **зарежет** |
| Пустой / короткие токены (`q`, `ок`) | `empty_question` / fail-open `no_topic_stems` | пустой — reject; шум без substantive — **пропустит** (G2 fail-open) |
| Compare («сравни продажи …») | content-AND всех термов (`1509–1511`) | **зарежет** лидера продаж: в required остаются `сравни/продажи/этого/прошлого`; даже с alias «продажи» падают глагол и указатели. Wiki-каскад идёт **до** compare-SQL (`z20:1951` → `1996`) → риск `no_data` вместо сравнения |
| Оси/меры без domain | content-AND | **зарежет**, если в вопросе есть термы вне bag (напр. «номенклатуре»), и нет label-hit |
| Alias «поставщики» | domain `постав` | **пройдёт** у контрагентов; продажи — **зарежет** |

**Итог §1:** уверенные named/label/короткие domain — не режет (живое ниже).
Опасная перерезка: **многословный content-AND** (compare и оси без имени сущности).

## 2. Пересчёт пула / меню / homonym

Порядок в hybrid (`1183–1208`): `post_verify` → `wiki_leader_topic_gate` →
repick+`post_verify` / `_wiki_topic_clarify_menu` / `none`.
Homonym (`wiki_homonym_kind_peers`, `909–918`) срабатывает **раньше**, в
`wiki_outcome_from_verify`, до гейта. Конфликта/цикла «меню→гейт→меню» нет:
один clarify за заход; topic-меню с `reason=wiki_topic`.

### Почему «Реализация» может выжить после гейта

Живой SELECT (`ut`/okna, `search_wiki_entity_card` + `search_entity_alias` +
`wiki_pages`):

| src | «склад» в positive bag? | Почему |
|---|---|---|
| `accumulationregister_реализациятмц` | **нет** | оси: `МестоХранения → …` (имя оси ≠ склад; FK цель гейтом не считается — верно) |
| `document_реализациятмц` | **да** | `best_used_for`: «…списанию стоимости товаров **со склада**…» |

Симуляция гейта на живых поверхностях:

- лидер = регистр, пул = регистр+документ+МестаХранения → reject регистра,
  **clarify** `[document_реализациятмц, catalog_местахранения]` (оба score=1);
- лидер = документ один / sole-yes → **ok, leader=document** (молчит в число
  по документу на вопрос про склад).

Именно так Реализация попадает в меню после гейта: не через оси регистра, а через
**случайное «склад» в `best_used_for` документа**. Alias документа «склады» нет;
регистр для «склад» честно `topic_miss:domain`.

Прайс: `informationregister_ценыноменклатуры` aliases содержат «прайс-лист» →
repick с номенклатуры работает (замок + симуляция).

Двойного меню от гейта нет. Homonym и topic не накладываются.

   clarify не должен включать такой паспорт рядом с Местами Хранения.

   «сравни продажи этого и прошлого» при лидере продаж → не `topic_none`.
