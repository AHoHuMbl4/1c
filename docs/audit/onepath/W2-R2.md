## 1. «Мёртвое» — точно мёртво?

### 1.1 Механика загрузки (побочные эффекты)

`_bootstrap.load_all` → `_exec_zone`: AST-срез между `_body_start_line` и
`_body_end_line` (отрезает `apply_bindings` / `register_zone`), затем `exec` в общий `ns`.

- Исполняется **всё тело зоны** в срезе: `def`/`class` + top-level присваивания
  (`os.environ.get`, `re.compile`, locks). Это не «вызов» мёртвой функции, но
  константы вроде `TERMS_FOR` / `TERMS_TOP` **читаются из env при каждом load**,
  даже если никто их дальше не зовёт.
- `register_zone` / `apply_bindings` в рантайме bootstrap **не исполняются**
  (срезаны); косвенная живость через них — нет.
- Строковый диспетчер / `__dict__[name](` / `eval` по именам зон — **не найден**.
- Косвенные вызовы, которые чистый AST Name-Call **может пропустить**:
  `globals().get("…")` в z05/z10/z11/z12/z13/z16/z21; `getattr(fork_classes, "_meta_by_fp")`
  (только fork-цепь, к новому тракту не тянет).

## 2. «Жива новому» — точно жива?

### 2.1 Ложные тревоги почти не всплыли

Сверка «карта = ЖИВА НОВОМУ» vs BFS: из функций спорны по сути только мелочи
(`peek_decision` — в карте как живая инфраструктура памяти без call из `answer`;
не блокер сноса тракта). Крупные входы (`parse_intent`, `period_readings`,
`readings_menu`, `rank_axis_resolve`, wiki-каскад, compose/gate) — **реально** на пути.

### 2.2 «Вызов есть в файле нового z20, но в мёртвой ветке»

- `fork_labels_covering` внутри `mk_opts` в **новом** z20: определение `mk_opts`
  живёт в файле; **прямой** call из `answer` — нет. Живость — **только** через z21
  (см. §1.3). Карта, смотрящая лишь «есть строка в z20», завысила бы; карта z09,
  отрицающая mk_opts, **занизила**.
- Инфра B2 в новом z20 (health/journal/HTTP) достижима из `Handler`/`answer_checked`,
  не из линейного B4 — X4 «почти вся достижима» для B2 **подтверждается**, это не
  мёртвые ветки `answer`.

### 2.3 Затенение имён (не путать с живостью имени)

## 3. Транзитивность

Правило атаки: если A только-legacy, то B, зовущийся **только** из A, тоже legacy;
если B зовётся из живого C — B жив, даже когда legacy тоже звал B.

### 3.1 Где карты/X2 потеряли ребро

```
answer
  └─ wiki_primary_entity_cascade
       └─ try_wiki_hybrid_entity_pick
            ├─ question_expects_accounting_data (z16)  ← X3 «z16 мёртв» ложно
            │    └─ stock_question_engaged / sales_sum_intent / …
            ├─ mk_opts (z20) → fork_labels_covering (z09)  ← W1-z09 L ложно
            └─ wiki_menu_captions / wiki_captions_map_from_cards
  └─ _onepath_compose_gate
       ├─ atom_terminal_gate_text (z13) → render_atom_pair (z15)
       ├─ currency_mismatch_blocks_answer → fork_labels_of (z09)
       └─ _unit_for_measure → _measure_dimension → sales_money_measure
            └─ _fork_sum_headline_pool (z09)  ← W1-z09 L ложно
  └─ aggregate_stock_net_distinct → stock_net_register_pair
       └─ stock_balance_is_sales_noise (z13)
```

### 3.2 Где «soft X2» правильно = не вход z20, но нельзя сносить

X2 честно пометил «новый z20 не Load». Для **сноса** этого мало: после flip
символ может остаться нужен зонам на пути wiki/compose. Ошибочно класть в
«жёсткие кандидаты в мёртвое» (или в вырез зоны целиком) всё из soft-списка без
BFS от `answer`.

### 3.3 Верные обрывы цепочки (не оживлять)

- `fork_detector_scan` / `resolve_fork_outcome` / `pick_measure` / `try_entity_form_answer`
  — только legacy (+замки). Транзитив legacy→z09/z13/z16 **не** делает весь файл живым.
- `currency_sum_for_basis` / `currency_patch_fork_scan` / `calendar_day_basis_prefer`
  — UNREACH из нового `answer` (только fork_scan / legacy prefer).

## 7. Метод / границы этой атаки

- Не строился полный динамический trace на живой базе; только статический граф
  + `globals().get`.
- Name-Load констант (`MEANING_TOP` как аргумент) в BFS по Call не входят —
  константы живых callee считать живыми отдельно.
- Чужие W2-* не читались; сходимость с ними — на сводной волне.
