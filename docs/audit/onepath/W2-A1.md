## Метод и нормализация чисел

| Источник | Что взято |
|---|---|
| `wc -l` файла | колонка «строк всего» (канон объёма на диске) |
| Итог зоны W1 | колонки «жива новому / только-legacy / мёртва» = **строки тел** top-level символов (AST span) |
| X4 | структура z20 (B2/B3–B4), оценки выреза 7.7k/9.6k |
| X1/X2 | внешние имена нового/legacy входа; патч `_patch_z20_wiki_primary` |
| X3 | замки ↔ зоны при сносе |
| AST на диске | сверка span поимённого списка при расхождении «номер строки vs длина» |

**Важно:** сумма «жива+legacy+мёртва» ≠ «строк файла» (шапка, пустые, `register_zone`,
комменты между символами). После посимвольного выреза файл худеет примерно на
сумму тел вырезанных символов, не на 100% «мёртвой доли файла».

**Поправка к X4:** фраза «17730−7671 ≈ 10.0k» смешивает набор ONEPATH (уже без
legacy) с вырезом, куда входит сам legacy. Корректно:

| База | Минус | Остаток |
|---|---:|---:|
| диск всех `z*` = **22833** | conservative 5103+2568 = **7671** | **15162** |
| ONEPATH-load = **17730** | только z09+z13+z16 = **2568** | **15162** |
| умеренный (тела L+D зон + legacy) | **≈9555** тел/файлов-кандидатов | см. §3 |
