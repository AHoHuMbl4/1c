## Метод

| Что | Как |
|---|---|
| Строки | `len(splitlines())` по файлу |
| Определения | top-level `def` / `async def` / `class` (AST) |
| Комментарии | строки с `#` в начале (после strip) **+** строки docstring (AST) |
| Секции нового z20 | по границам функций и комментариям файла (B2 / B4 в шапке и в `answer`) |
| Живое / мёртвое | статический граф вызовов по голым именам от входов `answer` → `answer_checked` → `Handler`/`main` (+ `health_tick`); зоны грузятся в общее пространство имён |

Ограничение метода: вызовы через `getattr` / строковый диспетчер / косвенные ссылки не видны. Оценка «мёртвого» — нижняя граница кандидатов на вырез, не приговор без замка/`test_one_path`.

## 4. Мёртвый груз и оценка «сколько вырежется»

| слой | строк | комментарий |
|---|---:|---|
| **A. Только-legacy** | **5103** | `z20_ask_main_http_legacy.py` — после flip B6 файл уходит целиком |
| **B. Почти мёртвые зоны (файлы)** | **2568** | z09+z13+z16; в графе остаются крохи |
| **C. Недостижимые def в смешанных** | **≈1925** | куски z05/z06/z10/z11/z12/… без вызова из `answer` |
| **D. Мелочь в живых зонах** | **≈345** | единичные helpers |

### Оценки выреза (после flip ONEPATH, без учёта тестов/замков)

| сценарий | ≈ строк с диска | состав |
|---|---:|---|
| **Консервативный** | **~7.7k** | A + B (legacy + три fork/veto-зоны целиком) |
| **Умеренный** | **~9.6k** | A + B + C (ещё недостижимые куски смешанных) |
| **Агрессивный** | **~9.6k** | A + все 4471 недостижимых тел def (близко к умеренному; B уже покрывает большую часть) |

От загружаемого набора 17730:

- консервативно остаётся ≈ **10.0k** строк файлов зон (17730−7671);
- умеренно ≈ **8.1k**.

От полного диска 22833 (оба z20): вырез **~34–42%**.

Новый z20 сам по себе уже «тонкий» относительно legacy (**2953** vs **5103**); основной резерв выреза — **legacy-файл** и **fork/veto-слой** (z09/z13/z16), не инфра B2 внутри нового z20 (она ~70% файла и почти вся достижима: gate, HTTP, journal).
