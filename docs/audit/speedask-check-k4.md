## 3. Новые дыры v2 (≤2)

### Дыра 1 (блокер): §2 «L67/тайминги на /tmp/probe_root» — ложный контур

**Утверждение плана:** до стоп-точки всё «оффлайн»; L67 и тайминги — на «выкате-кандидате `/tmp/probe_root`»; scp на прод — только после стоп-точки; §0.2 обещает L67 после A / C / D **до** стоп-точки.

**Механика (activeContext + код):**
- `probe_root` = `cp -r /opt/1c-mcp-reports` + **`diag_ask2p.py`** — **одиночные** диагностические вопросы по дереву кандидата, не L67.
- L67 = `i2_runner … --path engine` → **HTTP POST** на `I2_ASK_URL` / умолч. `:8091/ask` (`i2_runner.py:895–901`). Раннер **не** импортирует код из `/tmp/probe_root`.
- Сейчас на окне слушает только `:8091`; `/tmp/probe_root` нет. Исторический кандидат-контур — отдельный ask на **`:8092`**, не «оффлайн probe_root».

**Следствие:** либо §0.2 врёт (L67 до стоп-точки без живого `/ask` кандидата невозможно), либо «оффлайн /tmp/probe_root» врёт (нужен подъём кандидата: порт/процесс + `I2_ASK_URL`, по сути мини-выкат). Смешение diag-пробы и L67 делает протокол **неисполняемым как написан**.

**Мини-правка:** один абзац в §2: кандидат = дерево probe_root **+** слушающий ask (явный порт, напр. `:8092`) + `I2_ASK_URL` на него; L67/тайминги §0.2–0.4 — туда; прод `:8091` не трогать до стоп-точки. Либо честно: групповые L67 — только после scp (тогда вычеркнуть «L67 до стоп-точки» из §0.2 и сменить смысл стоп-точки).

### Дыра 2 (не блокер одна, усиливает (1)): deadline@rerank раньше A

§1.B чек-пойнт «вход в `rerank()`» + §1.A вставка у `3613` → при тяжёлом отборе deadline может отдать `unavailable` **до** раннего clarify. §0.5 не говорит «сформированное меню не режется» и не двигает A выше дорогих HTTP. Одна строка приоритета + запрет deadline-abort после готовности options — закрывает вместе с (1).
