## 6. Вердикт

**B4 — готово.** Copy-paste SQL совпадает с P3 буквально (аргументы, `greatest`, `tmp3_key`, `string_split`); горячий путь и #-срез — сверх P3, не мешают.

**B5 — готово.** pre_emb до :1290, скоуп killed∩tmp3, гейт :1366→:1371, зеркало пост-xfer, ord-обёртка xfer — все требования P3 закрыты (полные SQL — отсылкой на p3 §B5.1/§B5.2; для контроля достаточно).

**B6 — почти готово.** L2, ORDER BY/committed, suite, «не /opt», mid-gexec≠замок — внесены. **Остаток вне чистого B4/B5, но из списка P3:**

### Остатки

1. **L4(а) runtime SQL** («урезанный стейдж у `mode=full` → STOP», критерий без «корпус⊃tmp3») — в v2 **не специфицирован**; §1.4 / B6.2 подписывают L4(а) то, что по b3/P3 есть **L4(б)**.
2. **Переименование в B6.2:** §1.4 → явно **L4(б)**; для L4(а) — либо отдельный SQL-якорь в B1/B2 + ветка замка, либо явное решение «L4(а) вне окна B / бэклог» (сейчас ни то ни другое).
3. (косметика) Полные SQL B5.1/B5.2 и пост-xfer живут в p3 по отсылке — при желании встроить в §5 перед показом владельцу, не блокер контроля.

**Итог C3:** части **B4 и B5 плана v2 готовы** к показу по линзе P3; **B6 готов по L2/L-mid/suite**, блокер P3 по скоупу дыр **снят**. Единственный содержательный хвост из списка P3 — **путаница/дыра L4(а) vs L4(б)** (п.2 и п.6 «Упущенного»), не формула bridge и не merge_emb_holes.
