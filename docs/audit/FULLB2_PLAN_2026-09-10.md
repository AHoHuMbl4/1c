## 3. B3 = 1c: gone_expand (Q1 = (в): два свидетеля; cap — не STOP)

🔴 Решение Q1 (линза P2, кандидат-А отвергнут как само-ссылка):
`fanout_cap` **не является порогом STOP** — это кардинальность raw per-marker
для search_quality и замков. Защита = пара независимых свидетелей: мост ∧
свежий deleted_gone ∧ **строки нет в mart**. Числовой STOP |expand|≤cap из
v1 — СНЯТ (кандидат-А: expand ⊆ raw ⇒ cap ≥ expand всегда — тавтология;
post-apply mart COUNT = 0 для честного gone — ложный STOP).

Канонические имена CTE (grep-замок G0): `gone_markers`, `gone_expand_raw`,
`fanout_cap`, `gone_expand`. Место: внутри vec-budget (:890-1073), все
error() ДО MERGE (:1290) и DELETE (:1371). SQL-формы — p2 §«Ответ Q1» и
§«Формула EXCEPT» (взяты дословно):

1. `gone_markers`: op='deleted_gone' ∧ `epoch(ts)::BIGINT > corpus_built_ts`
   ∧ патология key_text ('*', '*|', '*#') — FAIL-closed.
2. `gone_expand_raw`: old_full ⋈ bridge_row_matches(row_key, key_text, n_seg);
   n_seg>0; патология row_key — FAIL-closed; **скоуп: src_table IN
   (gone_markers)** (не весь rebuilt).
3. `fanout_cap`: count(*) raw per-marker → quality/замки, НЕ STOP.
4. `gone_expand` = raw ∩ предок-маркер ∩ **свидетель витрины: строки нет в
   mart** (row-level, через тот же мир, что deleted_delta_rows; предикат
   ключа по key_cols).
5. error() до записи: (а) кандидат expand без предка-маркера → STOP;
   (в) expand-строка жива в mart → STOP. Пункт (б) |expand|>cap — снят (Q1).
6. **unexpected ≡ `векторов_умрёт`:** цепочка `unmatched_emb_rows` →
   `die_unexplained_base` (текущие свидетели; partial — замена на row-level
   gone_expand по §2.3) → `xfer_old_keys` → `die_unexplained_new = base EXCEPT
   gone_expand EXCEPT xfer_old_keys` — МНОЖЕСТВОМ; die_unexplained =
   count(*) GROUP BY. Колонка `векторов_умрёт` :1047 ← du из
   die_unexplained_new; алиас unexpected — в quality-детали.
   **Единственное применение gone_expand** — в EXCEPT-цепочке §3.6; §2.3
   описывает замену свидетеля ВНУТРИ die_unexplained_base (тот же CTE,
   другая роль: до вычитания), второй раз gone_expand не применяется —
   двойного вычитания нет.
   `xfer_old_keys` — полный CTE (стиль p2):

```sql
xfer_old_keys AS (
  SELECT u.src_table, u.row_key
  FROM unmatched_emb_rows u
  WHERE EXISTS (
    SELECT 1
    FROM tmp3_merge_emb_xfer x
    INNER JOIN new_full n
            ON n.src_table = x.src_table AND n.row_key = x.row_key
    WHERE n.src_table = u.src_table
      AND n.ch IS NOT DISTINCT FROM u.ch
    -- узкий мир: только rewrite_wave сущности (как emb_old :805-816);
    -- refs+bmap-ветка — OR с corpus_bmap_common_eq по образцу :850-853
  )
)
```
7. При `partial_rebuild=0` тела B3 мертвы; горячий путь unexplained ≡ текущему
   (доказывается B7).
8. **Perf-скоуп (урок :866, 21 ГиБ tmp):** не строить expand при пустых
   gone_markers; reuse old_full (не второй скан корпуса); запрет
   коррелированного EXISTS по всему search_corpus вне old_full.
9. **Остаточный риск A1 (зафиксирован):** маркер-фальшивка на коротком
   префиксе при уже пустой mart (реальная массовая смерть) — expand легитимен
   по (в); числовой стопор — бэклог (б): persist `fanout_at_apply` при

## 7. B7 = приёмка flip=0 + откат + порядок

**До scp:** 0.1-0.3; все замки B6 PASS; SQL-срез '#' (§4).
**Оффлайн-фикстуры partial без flip (в B6, прогон до scp):** (i) partial
стейдж + anti-join выключен → count emb соседей бит-в-байт; (ii) count-eq
partial по expect; (iii) empty+gone-only PASS; (iv) empty без маркеров STOP;
(v) mixed full+partial: shrink/repost full зелёные; (vi) parent gone /
child partial → срабатывает механизм C.
**Контрольный полный такт после scp (то же окно дельты, что baseline):**
1. count(*) / count(emb IS NOT NULL) / count(emb IS NULL) ≡ baseline;
2. multiset корпуса — одним SQL: `EXCEPT` двух снимков (content_hash‖row_key)
   по всему корпусу или data-driven top-3 `ORDER BY count(*) DESC LIMIT 3`
   (выбор формулой, не именами; top-3 + один hash-агрегат «прочие») — без
   Python-цикла (п.20);
3. rehash_gate=0; STOP-классы quality ≡ baseline; allowlist: новые ключи
   замков B6 + прирост entity_repost_delta ≤ числу из #-среза;
4. wall merge-секции и пик `.tmp` ≤ baseline;
5. SKIP-такт приёмкой НЕ является.
Расхождение вне allowlist = откат. **STOP после DELETE не самолечит emb**
(гейт мог упасть уже после записи) — при любом STOP/обрыве в merge-секции
сверка с 6a0-lite бэкапом обязательна до перезапуска такта.

**Откат — RUNBOOK §10.9-quater (8 пунктов, тем же коммитом что выкат):**
(1) scp pre-B corpus_merge.sql + md5; build/init не трогать; (2) запрет
полуотката и BYPASS как «отката»; (3) один контрольный полный такт flip=0;
