## 2. Новые атаки на план (≥4)

### (1) A+B вместе: early clarify готов, deadline уже истёк

**Сценарий:** составной вопрос; пул `picked>1` собран поздно (после тяжёлого отбора/реранка до точки A); на чек-пойнте арбитра срабатывает B → `unavailable`; либо A возвращает clarify, но мост уже на 90 с отдал отказ.

**Что видит клиент?** План не задаёт **приоритет исходов**:
- clarify (меню) vs unavailable (русский отказ) — порядок проверки в `answer` / перед z20:3613 **не описан**;
- если deadline чекается «вход в цикл арбитра», а early clarify — «перед арбитром», при `now≥deadline` **после** сборки меню клиент может получить отказ вместо меню, хотя неоднозначность уже доказана и дешёвый ответ готов;
- обратное: A срабатывает, отдаёт clarify за 18 с — ок; но если A запрещён fail-closed и путь идёт в арбитр×N при уже горящем бюджете — клиент получает отказ, хотя ранний путь мог бы отдать меню **до** дедлайна, если бы запреты были ужесточены иначе.

**Требование к v2:** явный порядок: *(i)* если меню clarify уже сформировано → отдать clarify даже при `deadline_left≤0` (исход дешевле отказа и соответствует п.21.2); *(ii)* deadline режет только **продолжения** (rerank/LLM/arbiter×N), не готовый ответ/clarify; *(iii)* замер A+B на одном rid: diag `early_clarify_path` vs `deadline_aborts` взаимно исключают на успехе clarify.

### (2) Один L67 после всего пакета vs «каждое ослабление доказывается»

**Факт плана:** §0.3 — «wrong=0 … **для каждого** ослабления»; §2 — «после A+B+C+D — stability + **L67 (один полный)**»; «перед каждым шагом — замки»; scp на прод — только после стоп-точки.

**Противоречие:**
- На **дереве кандидата** без промежуточного L: C3 (кэш) или C1 могут дать wrong; финальный L67 скажет «пакет красный», но **не** какой пункт виноват → откат всего vs точечный revert угадыванием.
- «Каждое ослабление доказывается прогоном» (S4 / п.10) при одном L67 **не выполняется**, если C1..C5 и D2 — ослабления качества входа.
- Замки между шагами **не** заменяют L: `test_intent` 162/0 не ловит порядок пула/меру после урезания rerank (S4 A1/A2).

**Не путать с scp:** запрет промежуточного выката на прод совместим с **промежуточными L67 на стенде/дереве** после каждого C/D. План смешивает «нет scp» с «нет L».

**Требование к v2:** либо L67 (или L-срез с wrong-гейтом) **после каждого** пункта, меняющего отбор/разбор (A, C1–C5, D1, D2); либо явный бюджет: «мини-L / эталон-в-голове на C*, полный L67 только на границах A, после C-пакета, после D2» — и снять формулировку «для каждого ослабления» из §0, если оставляют один прогон (тогда честно: **риск атрибуции**).

### (3) `ASK_DEADLINE_SEC=88` vs `ASK_TIMEOUT` — кто держит `<`?

План: дефолт 88 **«< ASK_TIMEOUT моста 90»**. Живое: мост env=90 (CHANGELOG 11.09 (4)); **код** `mcp_ask.py:50` default всё ещё **300**. План §4: «не трогаем мост… env уже готов».

**Дыры:**
- Инвариант «deadline < timeout» — **только комментарий**, не код, не гейт, не парный env-файл.
- Смена одним из двух: `ASK_TIMEOUT=60` при DEADLINE=88 → сервер продолжает после отказа моста (старая болезнь orphan); `ASK_DEADLINE_SEC=95` при TIMEOUT=90 → мост рвёт раньше, deadline бесполезен для честности клиенту.
- Шлюз `requestTimeoutMs` (сейчас ~100) в план не входит — цепочка из S3 (gateway ≥ bridge ≥ ask-budget) **не воспроизведена**.
- Ссылка на `bak-20260911-timeout` в откате — ок для Q2, но не страхует будущий тюнинг.

**Требование к v2:** одна строка инварианта + где живёт (assert при старте ask **или** док+скрипт выката env парой); явно: менять `ASK_DEADLINE_SEC` / `ASK_TIMEOUT` / `requestTimeoutMs` **только тройкой**; дефолт в коде моста 300 не считать «готовым» без env.

### (4) W4: flash vs pro агент + 30k-промпт — вне скоупа?

План скоуп: `ask/*.py` + serene_ask + env. W4 Q/S: агент `deepseek-v4-pro` vs setup-flash; двойной LLM; стоимость/хвост агента; 30k-промпт — **не** ask-стенка 154 с.

**Атака на решение владельца:** стоп-точка по Speed-Ask без явного «вне скоупа» читается как «webui-slow закрыт». Владелец может ждать flash/pro и ужатие промпта в том же пакете.

**Вердикт атаки:** принять **как вне скоупа — да**, но **обязана** явная полка в плане (§4 или §5 «соседняя очередь»): flash↔pro и политика агентного промпта — отдельный трек + слово владельца (W4 S5 / конфликт моделей); Speed-Ask **не** закрывает п.16/стоимость агента. Иначе стоп-точка по ask даёт ложное «эпизод закрыт».

### Доп. атака (5, короткая): A «подписи известны» без контракта mk_opts

Если `search_tables.label + mk_opts` частично пусты, fail-open в полный путь — ок; если частично заполнены криво — early clarify с **другими** подписями, чем поздний clarify после арбитра → клиент видит «разницу путей», вопреки §1.A «клиент не видит разницы». Нужен замок/снимок: opts early ≡ opts late на золотом корпусе clarify.

## 4. Вердикт и правки v1 → v2

### Вердикт: **ДОРАБОТАТЬ** (к стоп-точке владельца — нет)

План можно принимать как **каркас направления** (cap отвергнут, SAMPLES=1 запрещён, периметр чист, порядок A→B→C→D разумен). Как **исполняемый контракт до стоп-точки** — нет, пока не закрыты противоречие L67 и UX A+B.

### Список правок v1 → v2

1. **§1.A:** заменить условие на «**то же** условие неоднозначности, что даёт текущий clarify (ссылка на код/PLAN_ANSWER_CONTRACT); без новых эвристик»; метрика приёмки: 0 новых clarify на бывших L-match; opts early ≡ opts late.  
2. **§1.A↔B:** порядок исходов — готовый clarify/answer побеждает deadline; deadline только режет продолжение работы.  
3. **§1.C:** таблица callers keep/cut (включая `resolve_near` / оси / head); явный «entity-head на полный пул обязателен»; замер «эталон в голове» на L-корпусе.  
4. **§0 ↔ §2:** согласовать L67 — после каждого ослабления **или** честные контрольные точки (A; конец C; конец D) + снять ложное «для каждого», если оставляют один прогон; замки ≠ L.  
5. **§1.B / §4:** инвариант `ASK_DEADLINE_SEC < ASK_TIMEOUT` (+ gateway); правка только тройкой; не полагаться на default 300 в коде.  
6. **§1.B:** дописать pending / decision_id / SQL / «фаза = …» (S4 A4).  
7. **§3:** критерии STOP всего пакета (A5) + per-item revert.  
8. **§4 или новый §5:** явно вне скоупа — flash↔pro, 30k/агентный промпт, Q1–Q3, такт/B/вектора.  
9. **§0.2 / D:** либо усилить stability до A2, либо пометить «ослабленный замер, риск разброса ниже порога S4» для решения владельца.  
10. **Одна таблица** эффектов × классов W4 × доказательство — перед стоп-точкой.
