## Вердикт

1. **После генерации поля почти не «сливаются» с новым ответом:** первый проход пишет только в **пустые** `aliases`; **коллизионный** проход **перезаписывает** все три поля целиком; reask (выкл. по умолчанию) **дописывает** только токены aliases. Версий/истории по сущности **нет** — откат = ручной MERGE из bak/snap.
2. **Вне генератора** в репо нет юнита/SQL, который UPDATE'ит эти поля. Живые правки боя — **ручные операции** (С2 из `alias_okna_c1`, перенос из `alias_okna_c5` 28.08 — `HOW_NOT_TO §3.99`).
3. **Потери по конвейеру:** обрезка `[:900]` в parse; `str_split(..., ',')` ломает фразы со скобками (**30** строк nef с `(…,…)`); паспорт режет `wiki_body` до **1500**; `not_enough_for` в паспорт идёт напрямую из таблицы, а не из frontmatter.
4. **Копии не синхронны:** battle 258 ≠ c1 (21 field-diff + 1 orphan) ≠ c5 (все 258 пересечений различаются). `wiki_pages` — VIEW, синхронен на чтении с joinable 255.
5. **Рестарт:** частичный словарь — норма при убийстве mid-run; пустышки `mark_skip` блокируют переспрос на `RETRY_H` (6 ч).

## 1. Жизненный цикл после генерации

### 1.1. Политики MERGE (три разных правила)

| Путь | Файл:строки | Когда MATCHED | Поля |
|---|---|---|---|
| Первый проход / reask→боковая | `wiki_alias_merge_entity.sql:12–17` | **только если** `coalesce(t.aliases,'') = ''` | aliases, best_used_for, not_enough_for, seen_at=now() |
| Добор величин | `wiki_alias_merge_measures.sql:11–12` | только пустые measure.aliases | aliases measure, seen_at |
| Коллизии | `wiki_alias_collision_merge.sql:11–13` | **всегда** | **полная перезапись** aliases + best + nef + seen_at |
| Reask confirmed | `wiki_alias_reask_merge_confirmed.sql:14–21` | слияние CSV: не дублировать / дописать `, ` | **только aliases**; best/nef не трогает |

Итог: **непустая** строка первого прохода **не обновляется** новым ответом той же политики. Обновить best/nef у живой строки штатно может только **коллизионный** круг (перезапись) или ручной SQL.

### 1.2. `seen_at`

- Ставится при INSERT пустышки (`wiki_alias_mark_skip.sql:3–4`), при успешном MERGE, при collision, при reask-append.
- Селект первого прохода **пропускает** сущность, если aliases непуст **или** `seen_at > now() - RETRY_H` (`wiki_alias_select_entity_batch.sql:7–9`, default `RETRY_H=6` в `wiki_alias.sh:49`).
- Reask (если `WIKI_ALIAS_REASK_EVERY>0`) берёт stale по `seen_at < now() - REASK_STALE_DAYS` (`wiki_alias_reask_select_entity_batch.sql:16`); по умолчанию **выкл** (`REASK_EVERY=0`, `wiki_alias.sh:64`).

## 5. Рестарт-безопасность

| Сценарий | Состояние таблицы | Следующий прогон |
|---|---|---|
| Убийство **до** MERGE пачки | пачка не записана (tmp под `trap rm`) | те же сущности снова в select |
| Убийство **после** успешного MERGE части пачек | **частично новое** (заполнены только прошедшие пачки) | идемпотентно добирает пустых (`wiki_alias.sh:18`, `:128`) |
| Осечка модели → `mark_skip` | INSERT пустых aliases/best/nef + seen_at | **не** берётся `RETRY_H` часов (`select_entity_batch.sql:7–9`) |
| Убийство на **collision** после MERGE слова | поля соседей **уже перезаписаны**; probe уже отмечен до вызова модели (`wiki_alias.sh:285–289`) | слово не переспрашивается; откат полей — только из bak |
| `TimeoutStartSec` раньше infinity | исторический риск «наполовину собранный словарь» | закрыт в юните: `TimeoutStartSec=infinity` (`1c-wiki-alias@.service:44–50`) |
| Транзакция на весь прогон | **нет** — каждый MERGE отдельный psql | середина прогона = валидное частичное состояние |

**Вывод:** упавший на середине генератор оставляет **смесь** старых непустых, новых непустых и (при skip) пустышек с свежим `seen_at`. Это не «all-or-nothing». Бой okna сейчас почти полный (258/258 aliases, 257/258 nef), но следы добора/ручных правок видны по `seen_at`.

## Открытые дыры (не чинить в этом аудите)

1. Нет посущностной истории → откат «одной строки» = ручной SQL из snap.
2. Collision **молча затирает** лучшие aliases при разведении.
3. `str_split` по запятой бьёт nef/best с перечислениями в скобках (30/13 строк).
4. Бой разошёлся с c1 (21 поле) и полностью с c5 — snaps не «горячий бэкап», а археология.
5. Орфан-алиасы и сущность без nef живут в боевой таблице без страницы вики.
