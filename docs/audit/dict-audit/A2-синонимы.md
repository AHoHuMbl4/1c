Классификация 1031 фразы (эвристика по склейке с `src_table` и стемам title):

| класс | N | доля | смысл |

**~28%** (A+B) — почти бесполезны для различения при уже известном label (дублируют имя).

Примеры A: `Импорт ТМЦ`, `Книга Покупок`.  
Примеры C полезные: `catalog_контрагенты` → клиенты/поставщики/Покупатели; `informationregister_ценыноменклатуры` → прайс-лист.

## 7. Системные дефекты (5)

1. **Мета-синонимы как массовые коллизии.**  
   `справочник`/`список`/`типы`/`документ`/`реестр` сидят у десятков сущностей → BM25/list_has_any по aliases не различает класс. Пример: «список»×28.

2. **Чужой предметный якорь на документах (склад/клиент/закупка).**  
   При живом `catalog_местахранения` («склады») документы тащат «приход на склад», «выдача со склада»; ввод в эксплуатацию — «закупка». Судья получает меню нерелевантных лидеров на размытых вопросах.

3. **Дыры обиходной лексики у истинных носителей.**  
   Нет «деньги», «наличие/запас», «заказчик», «сбыт», ед.ч. «цена»; у `document_реализациятмц` нет «продажи/отгрузка»; у `document_поступлениетмц` нет «закупка/приход».

4. **~28% бюджета aliases съедают title-split/морфология имени.**  
   При лимите длины поля (~84 символа median, max 256) полезные ролевые слова вытесняются повтором label.

5. **Стемминг не закрывает все формы, на которые модель всё равно опирается.**  
   `прайс-лист` → `праис`; `деньги`≠`денег`; при этом словарь почти не кладёт нормализованные одиночные стемы — только фразы модели. Коллизионный круг (`wiki_alias` pass-2) не вычищает мета-слова (по коду A1: обиходные общие слова **оставляют** намеренно).
