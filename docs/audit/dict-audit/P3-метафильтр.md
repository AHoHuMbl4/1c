## Вердикт

Нужен **код-фильтр после парсинга** ответа модели: выкидывать из `aliases`
сущности слова, которые называют **класс объекта платформы 1С**, а не предмет.
Словарь — конечный (~22 леммы, ru+en формы), одинаков для любой базы (п.0 TARGET /
девиз универсальности). Точка расширения — уже существующий
`filter_entity_aliases` (`wiki_alias_parse.py:87–109`); коллизионный inline-разбор
в `wiki_alias.sh:321–354` сейчас **обходит** эту функцию — его тоже надо провести
через тот же фильтр. **«тмц» не фильтровать**: это предметная аббревиатура, не
мета-класс. С кругом разведения: фильтр режет только стоп-леммы; обиходные слова,
которые круг намеренно оставляет общим (`клиент`, `склад`…), не трогает.

## 1. Критерий включения / исключения

| | Правило |
|---|---|
| **В стоп** | Слово (лемма) обозначает **класс объекта метаданных платформы** или канцелярскую оболочку «как называется любой объект этого класса» (`список`, `карточка`, `запись`). На любой конфигурации 1С смысл один и тот же. Источник истины классов — префиксы OData / `_KIND_WORD` (не имена конкретной базы). |
| **Не в стоп** | Слово предметной области или отраслевой жаргон, даже если делит десятки сущностей (`тмц`, `номенклатура`, `склад`, `реализация`). Высокая коллизия ≠ мета. |
| **Бюджет** | ≤ ~25 **лемм**; формы падежа/множ. и en-перевод — варианты одной леммы, не отдельные слоты. |
| **Сопоставление** | После `casefold` + `ё→е`: (а) весь CSV-элемент aliases == лемма/вариант; (б) внутри многословной фразы — вырезать токены-варианты, схлопнуть пробелы; пустая фраза → отброс. Стемминг боевого `search_dict_stem` **не** подключать (привязка к локали — A6). |

### 2.3. Что сознательно НЕ включать (и почему)

| Слово | Решение | Обоснование |
|---|---|---|
| **тмц** | **не фильтровать** | Предметная аббревиатура «товарно-материальные ценности». Не класс метаданных 1С (нет в `_KIND_WORD` / OData-префиксах). ×32 в A2 — потому что **в именах** этой базы много `*тмц*`, и модель тащит кусок имени в aliases; это домен базы, не платформенный ярлык. Фильтр «тмц» сломал бы вопросы вроде «записей в реализациятмц» / склейки (B2) и нарушил бы п.0 (стоп-лист по отраслевому слову = привязка к профилю базы). Критерий: *на пустой конфигурации без ТМЦ слово бессмысленно; «справочник» осмыслен всегда*. |
| номенклатура, склад, товар, позиция, клиент, реализация, поступление, импорт, счета… | не фильтровать | Домен / роль / имя сущности; коллизии лечит круг + промт v2 + verify, не мета-стоп. |
| классификатор | не в v1 | Часто часть **имени** предметного объекта (ОКВЭД и т.п.); риск ложного выреза. |
| форма / table / entity | не в v1 | Реже в aliases; «форма» ещё и отчётность. |
| план, задача, бизнес-процесс | опционально позже | Есть в `_KIND_WORD`, но в топе A2 почти не светятся; не раздувать v1. |
| накопления, сведений, бухгалтерии, расчёта | не отдельные леммы | Идут только в составе фразы с «регистр…»; достаточно вырезать токен **регистр** и/или точного матча двусловных мета-фраз (см. §4). |

## 3. Где фильтровать (как есть сейчас)

### 3.1. Уже есть: `filter_entity_aliases`

Файл: `ubuntu/serenedb/wiki_alias_parse.py`.

| Строки | Что делает |
|---:|---|
| 78–84 | `_alias_tokens` — массив или CSV → список фраз |
| **87–109** | `filter_entity_aliases` — **только** бан имён/алиасов **величин** (`quantity_names` / `quantity_aliases`); дедуп `casefold`; **мета-слов нет** |
| 196–197 | вызов из `parse_items` после разбора quantities |
| 22–23 | `_join(..., n=900)` — обрезка CSV после фильтра |

Докстринг функции (стр. 88–91) уже фиксирует инвариант: отсев **без** списков слов
конкретной базы или языка — стоп платформы этому не противоречит (конечный словарь
платформы, как `_KIND_WORD`).

### 3.2. Дыра: коллизионный круг

`wiki_alias.sh:321–354` — **отдельный** inline-parse: aliases склеиваются как есть,
**без** `filter_entity_aliases`. Значит модель на pass-2 может вернуть «справочник»
обратно даже после чистки pass-1.

Промт круга (`wiki_alias.sh:310–312`, A1 §2.2): общие **обиходные** слова оставлять
в aliases; различие — в `notEnoughFor`. Это про домен (`клиент`), не про мета.

Выбор слова круга: `wiki_alias_collision_round.sql:4–8` — полное совпадение
CSV-фразы aliases у ≥2 сущностей. Поэтому одиночные «список»/«справочник» в aliases
становятся кандидатами круга и сжигают раунды впустую (A2: круг мета не вычищает).

### 3.3. Точка встраивания (проект)

```
parse_items / collision-parse
    → _alias_tokens
    → filter_entity_aliases(..., quantity_*)   # как сейчас: бан мер
    → filter_platform_meta_aliases(...)         # НОВОЕ: стоп §2
    → _join → rows
```

- **Один** код пути для pass-1, measure-добора (entity aliases), reask и collision.
- Collision: заменить inline `j(it.get('aliases'))` на вызов той же функции
  (quantity_* пустые — мер в collision-схеме нет).
- `search_measure_alias` / `quantities[].aliases` — **не трогать** (явное ТЗ).
- `bestUsedFor` / `notEnoughFor` — **не трогать** (там «документ X» может быть
  осмысленным текстом разведения; чистка — только aliases).

```python
    # lemma -> frozenset вариантов (уже casefold, ё→е)
    "список": frozenset({"список", "списки", "list", "lists"}),
    "справочник": frozenset({"справочник", "справочники", "catalog", ...}),
    # ...
}

def filter_platform_meta_aliases(aliases, *, title=None, log=None):
    """Убрать мета-класс из aliases сущности. Не трогает quantities."""
```

Либо расширить `filter_entity_aliases(..., title=None)` вторым проходом внутри —
чтобы все вызовы не разъехались. Предпочтительнее **отдельная** функция + явный
вызов рядом: проще тест и счётчик «мета отброшено».

### 4.2. Правила отброса

1. Нормализация токена фразы: `strip`, `casefold`, `ё→е`.
2. Если **вся** CSV-фраза ∈ стоп-вариантам → отбросить фразу.
3. Если фраза из нескольких слов — удалить слова∈стоп; остаток склеить;
   пусто → отбросить; иначе оставить остаток (`"список складов"` → `"складов"`).
4. Опционально v1.1: точный матч двусловных платформенных ярлыков целиком
   (`"регистр накопления"`, `"журнал документов"`, …) из
   `_NAMED_PLATFORM_TYPE_PHRASES` — без новых доменных слов.
5. Дедуп как сейчас.

### 4.3. «Единственный синоним» / title

После шагов 2–4:

| Исход aliases | Результат |
|---|---|
| несколько фраз, мета ушла, остались доменные | оставить доменные |
| осталась ровно одна не-мета фраза | оставить её |
| всё вырезано, но был `title` во входе пачки | **подставить title** (как просит промт «title itself» — единственный безопасный якорь) |
| всё вырезано, title пуст | `[]` → пустая запись / mark_skip на следующем такте (как сейчас при пустом ответе) |
| единственный синоним **был** мета, title есть | не оставлять мета; заменить на title |

Не оставлять голое «справочник» «чтобы не пусто» — это и есть дефект A2.

`title` в `parse_items` сейчас в `filter_entity_aliases` не передаётся: взять из
`pay` (`allowed_quantities` уже итерирует pay) или из `it` ненадёжно (модель может
не вернуть title). Надёжный источник — `wiki_entity_facts.label` во входном JSON
пачки (`title` в select). Проект: прокинуть `title_by_entity` в `parse_items`.

- На пачку / прогон: счётчик `meta_alias_dropped=N` рядом с уже существующим

- Согласуется с сводкой армии, п.6 «наблюдаемость генератора».

## 5. Сочетание с коллизионным кругом

```
Pass-1 (+ meta-filter) → MERGE только в пустые aliases
        ↓
Круг: pick слово = CSV-фраза, живущая у ≥2 сущностей
        ↓
Промт: общие ОБИХОДНЫЕ слова оставить; различие → notEnoughFor
        ↓
Parse + meta-filter (+ title fallback) → collision_merge (перезапись)
```

| Риск | Как закрыт проектом |
|---|---|
| «Вырежет то, что круг свёл» (общие `клиент`/`склад`) | Стоп только §2; доменные леммы вне списка. Круг как раз про них. |
| Круг снова впишет «справочник» | Один и тот же meta-filter на collision-parse (закрыть дыру `:321–354`). |
| Круг тратит раунды на мета-слова | Pass-1 без мета → кандидат «справочник»×28 исчезает из `dup`; раунды идут на реальные омонимы. |
| Фильтр после круга сотрёт различители | Режет только стоп-токены; фразы вроде «покупатели в продажах» целы. |
| notEnoughFor ссылается на вырезанное слово | notEnoughFor не фильтруем; плюс круг пишет разведение соседей по **сущностям**, не обязан повторять стоп-слово. |
| Force-перегенерация / MERGE | На живых непустых aliases pass-1 не обновит (B1); эффект мета-фильтра на бою — через collision overwrite, reask, или `WIKI_ALIAS_FORCE` (отдельный пункт сводки). Песочница `alias_okna_c5` — правильный первый контур. |

Итог: фильтр **помогает** кругу (убирает ложные столкновения класса), а не спорит с
ним. Правило промта «everyday words that also fit siblings stay» остаётся; меняется
только состав «everyday»: мета-класс туда не входит.
