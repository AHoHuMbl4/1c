# B5 — Промты генератора словаря vs лучшие практики

Дата: 13.09.2026 (cursor, read-only).  
Код: `/srv/1c/ubuntu/serenedb/wiki_alias.sh`, `alias_infer_gateway.py`.  
Коммитов нет. Живой SELECT на окне в этой сессии не снят (SSH к `~/.ssh/id_ed25519_deploy` режет runtime floor); замер «96% разведение соседей» — из брифа армии 13.09; причинная связь выведена из **текста промта** (что просили — то и получили).

---

## Вердикт

Промты просят JSON и «соседей поимённо» в `notEnoughFor` — и **не** просят: лимит синонимов, запрет падежей/английского/жаргона, критерий «сомневаешься — не пиши», тематический «не я» (склад/цены/клиенты вне списка соседей), few-shot на русском. Следствие предсказуемо: `not_enough_for` ≈ разведение kNN-пачки; aliases тянут морфологию и общие слова → коллизии; повторный прогон не детерминирован (`temperature` нигде не зафиксирован).

**«Мердж» как LLM-промта нет.** `wiki_alias_merge_entity.sql` / `wiki_alias_merge_measures.sql` / `wiki_alias_collision_merge.sql` — чистый SQL без модели. LLM-промты: инициализация (= добор величин = reask), коллизионный круг, day-basis forks.

## 2. Разбор по критериям

| Критерий | Инициализация (:182) | Коллизия (:312) |
|---|---|---|
| **Few-shot** | Один абстрактный пример на **английском** (counterparty → buyers/suppliers). Нет русских эталонов «хорошо/плохо». | Нет примеров вообще. |
| **Строгий формат** | Да: «JSON only, no prose, no code fences» + schema. Полей-ограничений (min/max items) нет. | То же. |
| **Сколько синонимов** | **Не задано.** | **Не задано.** |
| **Какие синонимы** | «everyday words … in their question» + **title** + role words из `flows`. Термины 1С / падежи / «только стемы» — не запрещены и не ограничены. | «everyday asking-words and the title»; **общие соседям слова оставлять в aliases**. |
| **Запрет англ / жаргона / повторов имени** | Только «SAME language as its title». Англ. в примере промта сам. Повтор title **явным образом просят** («also the record title itself»). Склонения title не запрещены. | То же «SAME language»; title снова в aliases. |
| **Соседи в контексте** | **Да:** пачка по `emb <=>` (`wiki_alias_select_entity_batch.sql:14–28`); + `flows` (до 12 меток держателей ссылки). Промт: «CLOSE IN MEANING». | **Да:** все носители одного слова-алиаса. Промт: «ALL CALLED BY THE SAME WORD». |
| **«Сомневаешься — не пиши»** | **Нет.** | **Нет.** |
| **Слова-события («сколько», «продажи»)** | Aliases: слова *из* вопроса (риск служебных слов снят комментарием 05.08 / правкой 25.08 — раньше просили «natural way someone would ask»). `bestUsedFor` — **«the questions it answers»** → вопросы целиком всё ещё поощряются. `quantities`: «noun or noun with the action word» → «продажи/продали» у мер допустимы по тексту. | `bestUsedFor` — «what only this one answers» (меньше «questions», но без запрета). |
| **notEnoughFor** | Явно: назвать **sibling types from this list** и что каждый отвечает. | Явно: «the other types from this list»; различие **только** сюда, не в aliases. |

## 3. Сопоставление с известными результатами

### 3.1. `not_enough_for` ≈ 96% «разведение соседей» (бриф армии, замер 13.09)

**Недостающий элемент промта:** тематический негатив вне списка соседей пачки  
(«не отвечает на остатки / прайс / число клиентов», топики doesNotAnswer для verify).

**Что промт вместо этого делает:** п. (4) *дословно* сводит `notEnoughFor` к  
«naming the sibling types from this list». Модель честно заполняет поле списками  
kNN-соседей / одноимённых носителей. При такой инструкции доля «разведение соседей»  
~100% ожидаема; 96% — не сбой модели, а **выполнение ТЗ**.

Следствие для судьи/паспорта (`doesNotAnswer`): на размытых вопросах («сколько на складе позиций», «прайс», «сколько клиентов») паспорт продаж/номенклатуры **не несёт** маркера «не я про склад/цены», если сосед по пачке не был «МестаХранения» / «ТипыЦен». Ровно класс дефекта, ради которого армия ушла в семантический verify, а не в слово-гейт.

### 3.2. Синонимы-падежи / склейки title

**Недостающий элемент:** запрет морфологических вариантов title и «N–M **разных** обиходных основ, не склонений».

История: [замер 25.08] CHANGELOG — при «SHORT NAMES… including its own title» в словаре были title/склонения; правка на «everyday words» **не добавила** запрета падежей. Title по-прежнему обязателен → модель добивает «Контрагенты, контрагент, контрагентов…». Solr/стемм частично склеивает, но `alias_idx` без стемма (отклонён) и коллизии по сырым токенам остаются.

### 3.3. Коллизии слов (одно слово → ≥2 сущности)

**Недостающий элемент в коллизионном промте:** запрет оставлять общее слово у всех  
**или** правило «общее слово — только у канона / ни у кого».

Наоборот, `:312` говорит: *«everyday words that also fit siblings stay in aliases, and the sibling distinction goes in notEnoughFor»*. Коллизии **законсервированы намерением** (чтобы `ts_lexize('…','клиент')` не обнулялся — комментарий `:310–311`, замер okna 25.08). Разведение переносит различие в `not_enough_for`, а `alias_hits`/индекс по-прежнему тянут всех носителей «клиент». Второй проход обновляет not_enough, но **не снимает** общее слово с aliases.

## 4. temperature / детерминизм

| Слой | Факт |
|---|---|
| `alias_infer_gateway.py:48–61` | Аргументы: `--local\|--gateway`, `--model`, `--thinking`, `--json`, `--prompt`. **Нет** `temperature`, `top_p`, `seed`, `max_tokens`. |
| Канон OpenClaw | `ubuntu/openclaw/instance/openclaw.json:23–28` — у `vllm/Qwen3.8-27B` только `chat_template_kwargs.enable_thinking=false`. Поля `temperature` нет. |
| `patch_vllm_provider.py:51` | То же: thinking off, temperature не ставит. |
| `wiki_alias.sh:77–78` | Модель умолч. `vllm/Qwen3.8-27B`, thinking `off`. |
| Доки `cli/infer.md` | У `model run` нет флага temperature; sampling — из params модели / дефолта провайдера. |

**Вывод:** повторный полный прогон **мог бы дать другой словарь**, если бы MERGE перезаписывал непустые строки. На практике 1-й проход **идемпотентен** (`merge_entity`: только пустые aliases) — уже заполненные сущности не переспрашиваются, дрейф «заморожен». Дрейф проявляется на: пустышках после retry, collision-merge (полная перезапись), reask (боковая таблица → confirm), новых сущностях. Даже при `temperature=0` у ask-контура известен разброс 18/58 ([замер 04.08]); у словаря temp **даже не зафиксирован в 0**.

## 5. Дыры промтов → следствие в данных

Формат: **дыра** (чего не просили) → **следствие**.

1. **`notEnoughFor` = только siblings из пачки**  
   Цитата: «naming the sibling types from this list…».  
   → `not_enough_for` на ~96% «разведение соседей»; нет тематического «не остатки / не прайс / не клиенты» → verify/паспорт не режет нерелевантного лидера на размытых вопросах.

2. **Нет «сомневаешься — пропусти поле/токен»**  
   → модель заполняет aliases/notEnough «по догадке»; мусор и ложные разведения попадают в MERGE без сигнала неуверенности (пустота только при осечке JSON/инфры).

3. **Нет лимита и типа синонимов (N основ ≠ падежи title)**  
   Цитата: «everyday words … and also the record title itself» без верхней границы.  
   → длинные CSV aliases, доля падежей/склеек имени; шум в `alias_idx` и Solr-синонимах.

4. **Нет запрета англ / 1С-жаргона / метаданных**  
   Только «SAME language as its title»; пример промта на английском.  
   → в aliases/bestUsed могут уехать англ. роли, имена реквизитов (частично ловит `filter_entity_aliases` только для quantity-имён, не для жаргона).

5. **Коллизионный промт запрещает снимать общие слова**  
   Цитата: «everyday words that also fit siblings stay in aliases».  
   → коллизии «клиент»/«продажа» живут вечно; not_enough обновляется, а отбор по алиасу снова тащит всех.

6. **`bestUsedFor` = «the questions it answers»**  
   → канцелярит и вопросы целиком в поле судьи/паспорта; риск служебных слов вопроса (класс дефекта 05.08 для aliases, для bestUsed формально не закрыт).

7. **Few-shot слабый / на чужом языке**  
   Один en-пример ролей; нет негативных образцов («не склоняй title», «не пиши сколько»).  
   → модель копирует паттерн «навалить вариантов», а не «3–5 точных обиходных основ».

8. **Нет temperature=0 / seed в вызове**  
   → нестабильность на collision/reask/пустышках; словари двух прогонов на одной базе могут разъехаться там, где MERGE пишет.

## 6. Что уже хорошо (чтобы не чинить лишнее)

- Соседи **показываются** (векторная пачка + collision по факту слова) — это закрывает урок 30.07 (одиночные описания).  
- Явный JSON schema; имена величин только из входа (`wiki_alias_parse.canon_measure`).  
- После 05.08 aliases больше не просят «как спросить вопрос целиком».  
- Role words из `flows` — правильное направление (замер «покупателей» 28.08).  
- Отсев quantity-мусора из entity aliases — кодом, не промтом (`filter_entity_aliases`).
