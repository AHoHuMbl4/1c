# A6. Универсальность генератора словаря/вики (TARGET п.0)

Дата: 12.09.2026. Режим: **только чтение**. Коммитов нет.
Контур: `ubuntu/serenedb/wiki_alias*.sh|sql`, `wiki_build.sql`, `corpus_init.sql`,
`alias_infer_gateway.py`, вызов из `build.sh` / юнита `1c-wiki-alias@`.
Мерило: TARGET п.0 + п.9; критерий PLAN_AUTONOMY — *может ли код узнать нужное,
ничего не зная о конкретной базе?*

База разработки: okna (~258 сущностей с алиасами; C5: E≈351). Чужие вопросы не
подгонялись.

---

## 1. Контракт

| Источник | Требование |
|---|---|
| TARGET п.0 | продакшен-база заработает «из коробки» при подключении, без доработок; база разработки скрыта специально |
| TARGET п.9 | без хардкода и подстройки под конкретную базу; любая размерность |
| PLAN_AUTONOMY | никто ничего не трогает после установщика; догадка по тексту = привязка; источник истины — движок / `$metadata` / модель |

Генератор **задуман** универсальным (комментарии в `wiki_alias.sh:13-15`,
`wiki_build.sql:18-21`): имена сущностей в код не вшиты; модели велят отвечать
«на том же языке, что title»; каркас страниц вики — английский. Ниже — где
замысел расходится с умолчаниями и масштабом.

## 2. Аудит кода: привязки (файл:строка)

### 2.2. Масштаб: лимиты пачек, бюджета, CAP

| Параметр | Умолчание | Место | Эффект на чужой базе |
|---|---|---|---|
| `WIKI_ALIAS_BATCH` | 20 | `wiki_alias.sh:41` | размер JSON в модель; на пачке >~25 раньше ломался argv (`:157-159`) |
| `WIKI_ALIAS_PER_TACT` (CAP) | 100 | `build.sh:675` | за такт ≤100 сущностей |
| `WIKI_ALIAS_MAX_SEC` | 120 | `wiki_alias.sh:129` | внутри такта свежести часто режет раньше CAP |
| `WIKI_ALIAS_COLLISION_ROUNDS` | 40 | `wiki_alias.sh:293` | потолок кругов разведения |
| `WIKI_ALIAS_RETRY_H` | 6 | `wiki_alias.sh:49` | пустые ответы переспрашиваются не чаще |
| flows на сущность | `LIMIT 12` | `wiki_alias_select_entity_batch.sql:21` | обрезает список потоков-ролей |
| обрезка строк алиасов при разборе | `_join(..., n=900)` | `wiki_alias_parse.py:22-23` | хвост слов молча срезается |
| collision-пачка | `LIMIT :batch` | `wiki_alias_collision_round.sql:33` | при слове с >20 носителями — не все в одном круге |
| day-fork / branch CAP | 10 / 60 с | `wiki_alias.sh:515` | хвост развилок откладывается |

C5-формула (`docs/C5_ALIAS_PIPELINE.md:33-42`): okna E=351 → ~4 такта;
ut_test E=1502 → ~16 тактов **только** по CAP=100, без учёта бюджета 120 с и
добора мер/коллизий.

Юнит полного прогона снимает бюджет: `WIKI_ALIAS_MAX_SEC=0`
(`1c-wiki-alias@.service:39`), `TimeoutStartSec=infinity` (`:50`) — иначе на
крупной базе убивал бы словарь наполовину (замер okna 27.08, комментарий `:44-48`).

| Факт | Место |

Имён сущностей okna / УТ в SQL/Python генератора **нет** (grep по коду; упоминания
okna — только в комментариях замеров: `wiki_alias.sh:44,115,173,208,227,311,523`).

### 2.4. Что универсально сделано правильно

- Ответ модели «SAME language as its title» — `wiki_alias.sh:182`, `:312`, `:487`.
- Каркас `wiki_pages` на английском, данные — из label/aliases базы —
  `wiki_build.sql:18-21,50-78`.
- Префикс типа `Catalog_`/`Document_` не переводится — `wiki_build.sql:19-20,52`.
- Отсев мусора величин из алиасов — по данным пачки, без словаря языка —
  `wiki_alias_parse.py:87-91`.
- Столкновения алиасов — по факту дубля в таблице, не по списку слов —
  `wiki_alias.sh:273-274`, `wiki_alias_collision_round.sql:3-14`.
- Имя базы для reask-таблиц — `current_database()`, не разбор DSN —
  `wiki_alias.sh:97-101` (урок PLAN_AUTONOMY).
- `alias_infer_gateway.py` — без имён баз/языков; только транспорт и обёртка JSON.

## 3. Мысленный холодный старт: 3000 сущностей / другой язык метаданных

Допущение: чистая машина, установщик поднял витрину/корпус, классификатор и
эмбеддер ещё догоняют; словарь пуст.

### 3.1. Масштаб ~3000 бизнес-сущностей

| Шаг | Что случится |
|---|---|
| Такт свежести | `wiki_alias.sh 100` + бюджет **120 с** → за такт часто <<100 сущностей (замер: пачка 20 на vLLM ~17 мин wall при gateway-потолке; local дольше — комментарий `alias_infer_gateway.py:6-7`) |
| Полное покрытие только по CAP | `ceil(3000/100) = 30` тактов; с бюджетом 120 с — **десятки–сотни** тактов; бот отвечает по неполному словарю |
| Полный юнит `1c-wiki-alias@` | `MAX_SEC=0`, CAP=0 — дойдёт, но часы wall; без env rw — INSERT падает |
| Коллизии | на УТ-подобных базах одноимённых слов много («клиент», «сумма»); 40 кругов/такт + probe — разведение растягивается |
| `LIMIT 12` flows | у справочника с десятками документов-ссылок роли обрежутся → алиасы ролей беднее (урок okna «покупателей», комментарий `:175-180`) |
| `_join` 900 символов | сущности с длинным списком алиасов/мер — хвост молча теряется (п. 13 на стороне словаря) |

**Упадёт ли процесс?** Обычно нет: идемпотентность + «остальное следующим тактом».
**Деградация:** долгий период «бот без вики-слоя» на части сущностей — ровно класс,
ради которого вики заводили (`wiki_build.sql:5-10`).

### 3.2. Другой язык метаданных (не русский title)

| Условие | Поведение |
|---|---|
| Title на английском/украинском | промпт просит тот же язык → алиасы модели **могут** выйти верно без правки кода |
| `SEARCH_DICT_LOCALE` не задан | стемминг/токенизация **русских** правил на чужом языке (`build.sh:48`) → `ts_lexize` / solr_synonyms хуже стыкуют словоформы; поиск алиасов деградирует **молча** |
| Нет кириллицы в вопросах | сам генератор не режет алфавит; резолвер ask (вне генератора) — отдельный блокер `BOXED_BLOCKERS` §1 |
| Модель/vLLM недоступны | пачки skip + пустые строки; через `RETRY_H` — снова; при полном отказе словарь остаётся дырявым, такт зелёный (`build.sh:675` глотает ошибку) |
| Нет `openclaw` | `exit 0` — словарь **молча** не строится (`wiki_alias.sh:105`) |

### 3.3. Зависимость от emb / classify

- Пока `search_tables.emb` пуст, `emb <=> seed` даёт NULL-дистанции: пачки
  вырождаются в лексикографический порядок `src_table`, смысл «соседей» пропадает
  (`wiki_alias_select_entity_batch.sql:14`) — **деградация качества**, не crash.
- Ошибка classify «business → service» → сущность **навсегда** вне `wiki_pages` и
  вне alias (`wiki_build.sql:114`, select `:6`) — молчаливая дыра до ручного
  переспроса класса.

## 4. Автоматика из метаданных vs человек

### Автоматически (из данных / модели)

| Что | Откуда |
|---|---|
| Список сущностей, label, parent, measures | `wiki_entity_facts` ← `search_tables` + корпус (`wiki_build.sql:28-39`) |
| Класс business/service | `classify_entities.py` (модель по имени/колонкам/строкам) |
| Пачка «похожих» | вектор `search_tables.emb` |
| flows (роли) | `search_refcols` + label соседей, до 12 (`wiki_alias_select_entity_batch.sql:15-21`) |
| Текст алиасов / bestUsedFor / notEnoughFor | LLM через `alias_infer_gateway.py` |
| Сборка markdown-страниц | VIEW `wiki_pages` (SQL) |
| Столкновения слов | агрегат по `search_entity_alias` |
| Solr-синонимы | compile из боевой таблицы алиасов |

### Требует человека / env / внешнего контура

| Что | Где |
|---|---|
| `SEARCH_DICT_LOCALE` (иначе ru_RU) | `build.sh:48` |
| `/etc/1c-wiki-alias-%i.env` с rw DSN | иначе serene_ro и отказ на INSERT |
| OpenClaw + профиль undebot + модель (vLLM/DeepSeek) | `wiki_alias.sh:26-40,77,105` |
| `CSV_DIR` / права обмена | `wiki_alias.sh:112-119` |
| `EMBED_MODEL` и досчёт emb до осмысленных пачек | `build.sh:45-46` + select по emb |
| Ручной полный прогон на крупной базе | `systemctl start 1c-wiki-alias@…` (бюджет 0) |
| `WIKI_ALIAS_REASK_*` | по умолчанию выкл (`REASK_EVERY=0`, `:64`) — доучивание не стартует само на бою |
| `WIKI_ALIAS_WORD` | точечное разведение слова — ручная ручка (`:54`) |

Ручных **списков сущностей** конкретной базы в генераторе нет.

Имена везде русские (типичная 1С) — генератор кодом не привязан, но умолчание локали
совпадает с ними и **маскирует** дефект языка на этих двух базах.

## 6. Вывод: ограничения универсальности (приоритет)

| # | Ограничение | Класс | Почему |
|---|---|---|---|
| 1 | Умолчание `SEARCH_DICT_LOCALE=ru_RU.utf8` | **упадёт качество / молча** на не-русской базе | стем и solr_synonyms чужого языка; человек должен знать и задать локаль — против п.0/п.9 и PLAN_AUTONOMY |
| 2 | Бюджет 120 с + CAP 100 в такте свежести | **деградирует** на 10³ сущностей | словарь наполняется десятки тактов; бот долго без слоя вики; полный прогон — отдельный юнит + rw env |
| 3 | Нет openclaw / нет CSV_DIR / нет rw env | **промолчит** (exit 0 или отказ записи) | установщик «зелёный», словарь пуст; нарушение «никто не трогает» — нужен человек |
| 4 | Зависимость пачек от `emb` + classify | **деградирует** | без emb — слепые пачки; ошибочный `service` — сущность без вики навсегда до вмешательства |
| 5 | Жёсткие срезы `LIMIT 12` flows, `_join` 900, collision batch 20 | **деградирует** | на густых графах ссылок и длинных алиасах — потеря ролей/слов без сигнала клиенту |
| 6 | Промпт и каркас на английском + «SAME language as title» | **выживет** на чужом языке метаданных | при живой модели и верной локали словарь соберётся без правки кода |
| 7 | Имена okna/УТ не зашиты; отбор service — моделью | **выживет** как замысел | холодный старт второй русской базы не требует правки генератора — только времени и контура |
| 8 | Reask выключен (`REASK_EVERY=0`) | **деградирует** со временем | устаревшие/пустые описания на живой базе сами не лечатся без ручного env |

### Итог одной фразой

Генератор **не привязан к okna именами**, язык ответа модели берёт из title, и на
второй русской базе (UT/klient1) код «выедет» без правок — но **не «из коробки» в
смысле п.0**: русская локаль по умолчанию, ручной rw-env/OpenClaw и потолки
времени/CAP делают полный словарь на 10³–10⁴ сущностей долгой фоновой работой с
риском тихого недосбора, а не результатом одного подключения.
