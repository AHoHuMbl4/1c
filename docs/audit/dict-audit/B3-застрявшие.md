## Вердикт

1. За 30 дней **2263** исхода `no_data`+`clarify` (**53.6%** журнала), **173** уникальных `q_hash`, **168** уникальных непустых текстов. Повторы жёсткие: **43** вопроса с 20–49 повторами и **2** с 50+ держат **1609** строк (**71%** застрявших с текстом).
2. Топ — не «редкие дыры», а два кластера: **остатки/склад/позиции** (~**982** строк / 50 uniq) и **деньги-за-период** (`наторговали` / `продали` / `сделали` / `вышло` / `наотгружали`, ~**374** строк / 30 uniq).
3. Словарь **частично** может помочь классу «деньги-за-период» через `best_used_for` продаж («итог продаж за период», «Сколько продали…»), но **разговорные глаголы-события** (`наторговали`, `сделали`, `вышло`, `наотгружали`) в aliases/`best_used_for` **отсутствуют целиком (0)**.
4. Доля (по строкам, эвристика §4): словарь **виноват ≈47%**, **не при чём ≈48%**, смешанное ≈5%. Главный вклад «виноват» — **mismatch «остатки/склад»** (ведёт в справочник мест / взаимозачёты / бух. остатки, а не в остатковый регистр ТМЦ). Главный вклад «не при чём» — **clarify-меню** (гомоним/мера/период) и **meta-count** по имени регистра.
5. Требование к генератору: не только синонимы имён сущностей, а **разговорные кубы** «остатки на складе», «наторговали/сделали за период», плюс явный `doesNotAnswer` «не список складов / не книга продаж / не номенклатура-как-прайс».

### 2.2 Структурный фон (не только aliases)

Это усиливает класс `dict_stock_mismatch`, но корень — и покрытие сущностей, и тексты словаря.

## 3. Класс «деньги-за-период»

Вопросы с `(наторг|наотгруз|прода|сделал|вышл|было продаж|отгруз)`: **~245 строк** в money_* классах выше; узкий money_period = **334** строки / **25** uniq; плюс «наотгружали» и «было в прошлом месяце» в other.

### Может ли словарь помочь?

| механизм | помогает? | замер |
|---|---|---|
| aliases сущности = имя документа/регистра | слабо | люди говорят «наторговали», не «реализациятмц» |
| aliases = «продажи», «оптовые продажи» | средне | «продажи» уже у 3 сущностей; «продали» тянет 12 |
| **best_used_for** продаж | **да, потенциально** | `accumulationregister_реализациятмц`: «Каков общий итог продаж за период?» |
| buf розницы | да | `document_выручкаотреализациитмцфизлицо`: «Сколько продали физическому лицу?» |
| buf журналов опт/розница | да | «сумма оптовых/розничных продаж» |
| разговорные **наторговали / сделали / вышло / наотгружали** | **нет** | **0** в aliases и **0** в best_used_for |

**Вывод:** словарь **может** помочь классу, но только если генератор кладёт в `aliases`/`best_used_for` **глаголы-события и разговорные обороты периода**, а не только канцелярит «итоги реализации». Сейчас buf уже ближе к «продали за период», aliases — нет. При попадании в пул продаж Clarification (Реализация vs Книга продаж) — **ожидаемое** поведение одного пути, не дефект словаря.

### Контракт для генератора (короткий чеклист)

1. **Event-глаголы продаж** в aliases **или** best_used_for канона продаж: `наторговали`, `сделали`, `вышло`, `продали`, `наотгружали`, `отгрузили` + «за день/неделю/месяц».
2. **Складской куб** на остатковом источнике (не на `местахранения`): `остатки на складе`, `остатки по складам`, `сколько позиций на складе`, `нулевой остаток`.
3. **Взаимный doesNotAnswer / not_enough_for:** местахранения — «не остатки»; реализация — «не остатки на складе» (уже дыра B4); книга продаж — «не оперативные продажи».
4. **Не раздувать** aliases канцеляритом meta-count и одиночными словами `товар`/`позиция` без контекста — они дают 12–23 коллизии.
5. **Не ждать** от entity-словаря спасения SKU-имён (`петли`) и фильтров (`реально покупают`) — это другие слои.
