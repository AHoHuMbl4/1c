## Методика (2 строки)

Уникальные формулировки = нормализованный `q_text` (пробелы вместо `\n`; из дампов чата берётся последний `User:`; отброшено 4 мусорных). Для топ-100 по частоте значимые стемы (длина ≥3, без стоп/признаков вопроса) сопоставляются со стемами `aliases||best_used_for`: **0** сущностей = пробел, **1–2** = ок, **≥3** = каша.

Признаки вопроса (не сущности): `сколько/покажи/дай`, предлоги, `нас/всего/уже`, календарь (`месяц/неделя/вчера/воскресенье…`), `реально/отдельно/каждый`. Глаголы сбыта и имена регистров в 1С-склейке считались **значимыми** (спрос на смысл, а не стоп).

### Метрики по вопросам топ-100

| метрика | значение |
|---|---:|
| вопросов с ≥1 значимым словом | 99 / 100 |
| доля вопросов с непокрытым значимым словом | **65%** (65/100); по обращениям **64.9%** |
| доля вопросов со словом ≥3 сущностей | **89%** (89/100); по обращениям **88.4%** |
| и пробел, и каша в одном вопросе | 55 |
| «чистых» (есть значимые, без 0 и без ≥3) | **0** |

Каша доминирует: почти любой частый вопрос попадает в многозначный стем (`склад`, `позиц`, `остатк`, `движен`…). Пробел часто соседствует с кашей (техническое имя регистра + «движений»).

## 6. Выводы — системные пробелы словаря по реальному спросу

1. **Разговорный сбыт не в aliases.** Люди говорят «наторговали / наотгружали / вышло / сделали / продали»; словарь кормит существительными и именами документов (`реализация*`, `книгапродаж`). Стем `прода`/`продаж` ещё и **каша** (5–13 сущностей). Нужны якорные синонимы действия→носитель оборота, иначе verify/поиск уводят не туда или в меню из каши.

2. **Склеенные имена регистров как отдельный язык.** Частотный кластер `«реализациятмц»`, `«допзатратыимпорттмц»`, `«кассовыеордера»`… — cover=0 по поверхности склейки, хотя сущности в таблице есть. Словарь/поиск не склеивает human/instrument label с `src_table` без пробелов и кавычек.

3. **Доменные штучные слова вне вики.** `петел` (петли) — стабильный живой спрос, в aliases нет. Это не «общее ТМЦ», а конкретная номенклатурная тема установки; без синонима вопрос упирается в склад/позиции (каша) или в no_data.

4. **Одноимённые бытовые якоря размазаны по десяткам таблиц.** `склад` (10), `позиц` (22), `товар` (37), `номенклатур` (19), `остатк` (6), `клиент`/`покупател` (5) — при реальном спросе на остатки/клиентов словарь сам создаёт ≥3 кандидата. Это та же болезнь A2 (мета-проза + чужие документы в aliases), усиленная частотой склада/позиций в журнале.

5. **Мета-слова из шаблона генератора попадают в боевой матч.** `справочник` (31), `список` (48), `запис` (5), `движен` (8) — люди и приборы ими пользуются как оболочкой («сколько записей/движений»), а aliases тащат их почти на всё. Покрытие «есть», смысла выбора нет.

6. **Чистых попаданий в топ-100 нет (0/99).** Либо пробел разговорного/технического слова, либо каша бытового. Словарь не пуст (258, 992 стема), но **не совпадает с распределением спроса**: редкие длинные фразы описаний vs короткие частые стемы людей. Усиление вики-verify по паспортам без чистки коллизий и разговорных якорей будет спотыкаться о тех же лидеров (`склад`/`позиц`/`наторгова`).
