## 2. Мысленный прогон генератора: 258 vs N и лимиты

**258 — не потолок кода.** Это живой счёт непустых алиасов okna (`search_entity_alias`).
В `wiki_alias.sh` / SQL нет `LIMIT 258` и нет имени okna в исполняемом коде.

### 2.1. Что реально ограничивает на второй базе

| Лимит | Умолчание | Место | UT 1502 / klient arrived 1519 | Полный контур klient 9151 |
|---|---|---|---|---|
| `WIKI_ALIAS_BATCH` | 20 | `wiki_alias.sh:41` | ~76 пачек только сущностей (+ меры + коллизии) | ~458 пачек по arrived-масштабу; контур 9151 не весь попадает в wiki (service/empty) |
| CAP в такте | `WIKI_ALIAS_PER_TACT=100` | `build.sh:675` | ≥16 тактов только по CAP | десятки тактов |
| Бюджет такта | `WIKI_ALIAS_MAX_SEC=120` | `wiki_alias.sh:129` | **треснет раньше CAP**: 120 с ≪ одной пачки на медленном gateway (A6 / комментарий infer) | то же |
| Юнит полного прогона | `MAX_SEC=0`, `TimeoutStartSec=infinity` | `1c-wiki-alias@.service:39,50` | **выживет** по wall-time (потолок 7200 с снят после okna 27.08) | дойдёт за часы, не упадёт по таймауту юнита |
| Коллизии | 40 кругов | `wiki_alias.sh:293` | **деградация**: на УТ/ERP густота «клиент/сумма» выше okna; история — час кругов при стоячих 697 | ещё хуже |
| flows | `LIMIT 12` | `wiki_alias_select_entity_batch.sql:21` | у `Catalog_Партнеры` / контрагентов ссылок ≫12 → роли обрежутся | то же |
| обрезка текста алиасов | `_join(..., n=900)` | `wiki_alias_parse.py:22-23` | хвост слов **молча** срезается | то же |
| длина колонок | `VARCHAR` без длины | `wiki_alias_init.sql:3-6`, `corpus_init.sql:300-309` | имена 95–113 символов — **не треснут**; VARCHAR без лимита | не треснут |
| solr compile | из боевой таблицы | `wiki_alias.sh:528-537` | карта растёт с числом алиасов; путь через файл (не argv) | то же |

Итог по «треснет ли процесс»: **жёсткого crash на размере UT/klient-1 нет.**
Треснут ожидания «один такт / установка из коробки»: словарь наполняется долго;
в такте свежести за 120 с почти ничего не успеет.

### 2.2. Десять имён из реального материала — что сделает промпт

Промпт (`wiki_alias.sh:182`): JSON; **тот же язык, что title**; aliases = обиходные
слова вопроса + title + **ролевые** слова из `flows`; quantities — точные имена мер;
bestUsedFor / notEnoughFor с соседями пачки.

| # | Имя (как в материале) | База | Что генератор сделает | Чего не сделает |
|---|---|---|---|---|
| 1 | `catalog_партнеры` | UT (`ACCEPTANCE_UT`) | алиасы «партнёры», «клиенты»…; title в aliases | сам не отличит от контрагентов, пока 2-й проход не разведёт слово |
| 2 | `catalog_контрагенты` | UT | то же; классический дубль «клиент» (замер в комм. `:268-271`) | не зашьёт «контрагент ≠ партнёр» без коллизионного круга |
| 3 | `catalog_номенклатура` | UT | обычная пачка; меры из `nums` корпуса | не угадает бизнес-синонимы вне title/flows |
| 4 | `catalog_склады` | UT | «склад/склады»; стем `ru_RU` стыкует «складов» | на не-ru локали (см. §3) — молча хуже |
| 5 | `document_заказклиента` | UT | flows ≤12 от ссылающихся типов | роли от 13-го документа-ссылки не попадут |
| 6 | `document_реализациятоваровуслуг` | UT | пачка с «похожими» по emb (приобретение/розница) | без emb — соседи лексикографические, разведение слабее |
| 7 | `document_приобретениетоваровуслуг` | UT | много `Сумма*` → обязателен measure-проход | 9 «сумм» без алиасов мер → бот снова путает величины (ACCEPTANCE §1) |
| 8 | `Catalog_Партнеры` | klient1 arrived | то же, что п.1; `src_table` в нижнем регистре в движке | — |
| 9 | `AccumulationRegister_ВыручкаИСебестоимостьПродаж` | klient1 | по label: выручка/продажи/себестоимость; меры `СуммаВыручки`… | не выкинет внутригрупповые передачи (это знание данных, не словаря) |
| 10 | `Document_АктВыполненныхРабот` | klient1 | «акты», «услуги», «ремонт» — если модель знает по title | не отличит от реализации без notEnoughFor соседней пачки |
| 11* | `InformationRegister_МестоПозицииШтатногоРасписанияВСтруктуреПредприятия` | klient1 | длинный title → модель сжимает в обиход; entity = полное `src_table` | `_join` 900 может срезать длинный список aliases |
| 12* | длинные `*ПрисоединенныеФайлы_УдалитьСертификатыШифрования` (skipped, 109–113) | klient1 | если доедут в корпус и `cls≠service` — опишет; иначе вне вики | classify→service = **дыра без страницы** |

\*п.11–12 — запасные примеры масштаба имён, не «бизнес-ядро».

## 3. Язык метаданных второй базы vs стемминг `ru`

| База | Язык имён OData / title | Доказательство |
|---|---|---|
| ut_test | **русский** | `catalog_партнеры`, `СуммаДокумента`, вопросы ACCEPTANCE на русском |
| klient-1 | **русский** | arrived/skipped — кириллические суффиксы; KLIENT1_LIVE — рубли, СПб |
| Украинский / английский в этих следах | **не найден** | grep по KLIENT1_LIVE / completeness — пусто |

Следствие для **этих** двух баз:

- Умолчание `SEARCH_DICT_LOCALE=ru_RU.utf8` (`build.sh:48`, `wiki_alias.sh:529`)
  **совпадает** с метаданными → стемминг **не** является блокером UT/klient-1.
- Это **маскирует** дефект п.0: на базе с английскими title тот же дефолт даст
  русские правила Snowball на чужих словоформах → деградация `ts_lexize` /
  `solr_synonyms` **молча** (см. A6 §3.2, `BOXED_BLOCKERS` §2).
- Промпт «SAME language as its title» для UT/klient выдаст **русские** aliases без
  правки кода — это подтверждение универсальности **языка ответа модели**, не локали словаря.

`search_dict` основной индекс: `stemming=false` (коды/артикулы); стем только в
`search_dict_stem` / `search_dict_alias_stem` / solr pipeline (`corpus_init.sql:349-414`).

## 4. Что уже универсально (подтверждение кодом)

Имён okna/UT/klient в **исполняемом** теле генератора нет (упоминания okna — только
комментарии замеров в `wiki_alias.sh`).

| Механизм | Откуда берёт данные | Код |
|---|---|---|
| Список сущностей / label / measures | `search_tables` + корпус → VIEW `wiki_entity_facts` | `wiki_build.sql:28-39` |
| Каркас страниц | англ. шаблон + данные базы | `wiki_build.sql:18-21,48-114` |
| Тип сущности | префикс `Catalog_`/`Document_`… **не переводится** | `wiki_build.sql:19-20,52` |
| Пачка «похожих» | `search_tables.emb <=> seed`, не список тем | `wiki_alias_select_entity_batch.sql:14-28` |
| flows / роли | `search_refcols` → label соседей | тот же SQL `:15-21` |
| Язык aliases | «SAME language as its title» | `wiki_alias.sh:182` (и копии) |
| Отсев мусора величин | ban-set из **этой** пачки, без словаря языка | `wiki_alias_parse.py:87-109` |
| Коллизии | факт дубля слова в таблице, не whitelist | `wiki_alias.sh:273-274` |
| Имя reask-таблиц | `current_database()`, не разбор DSN | `wiki_alias.sh:97-101` |
| Юнит на любую базу | `%i` = имя БД движка | `1c-wiki-alias@.service:15-17,43` |

Человек/env всё ещё нужны: `SEARCH_DICT_LOCALE`, rw `/etc/1c-wiki-alias-%i.env`,
OpenClaw, emb, полный юнит на крупной базе (A6 §4).

## 5. Вывод: упадёт / деградирует / выживет

Проверено на **именах и числах** UT (доки) + klient1 (файлы) + живом okna 258;
живая `ut_test` на окне недоступна.

### Упадёт (жёсткий отказ / молчаливый ноль)

| Что | На какой базе | Почему |
|---|---|---|
| Живой прогон словаря на `ut_test` **сейчас** | ut_test | БД `not accessible` — контур выведен; это инфраструктура, не генератор |
| Словарь при отсутствии openclaw / CSV_DIR | любая | `wiki_alias.sh:105,113` → `exit 0`, словарь пуст |
| Запись без rw-env юнита | любая | serene_ro → permission denied на INSERT |
| Сущность с ошибочным `cls=service` | UT/klient (риск выше на ERP) | вне `wiki_pages` и alias-select навсегда до переклассификации |

### Деградирует (процесс жив, качество/срок — нет)

| Что | Пример имени | Механика |
|---|---|---|
| Масштаб 258→~1500 | весь arrived klient / корпус UT 1502 | CAP 100 + бюджет 120 с → недели тактов; бот без слоя вики на хвосте |
| Коллизии «клиент» | `Catalog_Партнеры` ↔ `Catalog_Контрагенты` | 40 кругов/такт + probe; на УТ уже ловили (комм. wiki_alias) |
| Обрезка flows | `Catalog_Партнеры`, `Catalog_Номенклатура` | `LIMIT 12` — роли «покупатель/поставщик» могут не доехать |
| Обрезка aliases 900 симв. | длинные ERP-имена + богатый ответ модели | `wiki_alias_parse._join` молча режет хвост |
| Слепые пачки без emb | любой холодный старт | `emb <=>` NULL → порядок по `src_table` |
| Меры «Сумма*» | `document_приобретениетоваровуслуг` | без добора measure-alias — класс дефекта ACCEPTANCE §1 |
| Локаль на **не**-русской базе | (в следах UT/klient нет) | дефолт `ru_RU` — молчаливая порча стемма |

### Выживет (без правки генератора)

| Что | Пример | Почему |
|---|---|---|
| Холодный старт русской УТ/ERP | `catalog_склады`, `Document_РеализацияТоваровУслуг` | нет хардкода имён; промпт на языке title |
| Длина `src_table` 95–113 | `…ЗависимостиДополнительныхРеквизитов`, `…УдалитьСертификатыШифрования` | `VARCHAR` без лимита |
| Полный oneshot-юнит | `systemctl start 1c-wiki-alias@…` | `TimeoutStartSec=infinity`, `MAX_SEC=0` |
| Сборка текста вики SQL | любой `src_table` из `search_tables` | `wiki_build.sql` без имён базы |
| Стем на UT/klient | «складов»↔«Склады» | метаданные русские = дефолт локали |

### Итог одной фразой

На **реальном** материале второй базы (UT ~1502 / klient arrived 1519, всё по-русски)
генератор **кодом выживет** и словарь **соберётся** без правок под имена — но
**«из коробки за один такт» не выживет**: бюджет 120 с и CAP 100 превращают 258→1500
в долгую деградацию покрытия; жёстких лимитов длины колонок и таймаута юнита на
этих именах нет. Украинских/английских метаданных во второй базе в следах **нет** —
тест языка локали этими двумя базами **не закрывается**.
