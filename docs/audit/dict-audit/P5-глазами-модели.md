Дата: 12.09.2026 (cursor, **read-only**).  
Угол: как слабая–средняя модель **поймёт** проектируемые правила, не как их читает человек.  
Коммитов нет. P1–P4 в каталоге ещё нет — опора: `wiki_alias.sh:182` / `:312`, `00-СВОДКА.md`, `B5-промты.md`, `A2`/`A4`/`A5`/`B4`.

Модель-исполнитель (канон): `vllm/Qwen3.8-27B` / OpenRouter `qwen/qwen3.8-27b`, thinking **off**, пачка JSON ~20 сущностей, ответ строго по схеме (`A5`, `B5`). Temperature в вызов **не** передаётся.

## Вердикт

27B при thinking off **честно исполняет буквальную инструкцию** и **не догадывается о цели продукта**. Старый промт просил «title itself», «siblings from this list», «everyday words» без запретов — и словарь получил мета-слова, соседские NEF и догадки (`список`, `ОТМ`, `кassa`, «выдача со склада»). Новые правила сработают только если: (а) короткие императивы + явные **запреты с антипримерами**; (б) few-shot на **языке title**; (в) дешёвая песочница из 5 сущностей **до** полного прогона. Длинные англ. абзацы с несколькими «and also» 27B сжимает в «навали варианты».

## 0. Как 27B читает промт (рабочие аксиомы)

Выведены из факта старого словаря + текста `:182`/`:312` (`B5` §3, `A5` §3.4):

1. **Приоритет у последнего явного приказа.** «SAME language as title» проигрывает английскому few-shot `buyers/suppliers`, если нет RU-антипримера.
2. **«Everyday» без верхней границы = чем больше, тем лучше.** Модель расширяет, не режет.
3. **Поле с формулой «naming X from this list» заполняется только X.** Тематический «не я» вне списка **не появится**, пока его не попросят отдельным пунктом.
4. **Нет «пропусти» → угадай.** Пустое поле модель считает провалом; пишет жаргон/аббревиатуру/канцелярит.
5. **Соседи в пачке = единственный мир различения.** Всё, чего нет в JSON входа, для NEF «не существует» — пока не дадут фиксированный список топиков-отказов.
6. **Схема JSON соблюдается лучше смысла.** Валидный JSON с мусором в aliases — успех для модели и для parse.

Следствие для v2: каждое правило — **одна короткая строка + 1 хороший / 1–2 плохих примера**, не эссе.

## 1. Ключевые правила: трактовки 27B → однозначные формулировки

Ниже для каждого правила из проекта сводки (§«Промт генератора v2»):  
**(А)** как модель скорее всего поймёт (включая неверные чтения);  
**(Б)** формулировка, которую 27B исполнит буквально;  
**(В)** мини-few-shot (язык = язык title; здесь RU-шаблон).

### 1.1. Запрет мета-слов платформы

Цель продукта: не писать в aliases `список` / `справочник` / `типы` / `виды` / `каталог` / `реестр` / `журнал` / `документ` / `регистр` (коллизии ×27–28, `A2`).

| # | Трактовка 27B | Почему всплывает |
|---|---|---|
| T1 ✓ | Не ставить эти слова **отдельными** токенами в aliases | Если в промте явный список запрещённых |
| T2 ✗ | Можно «список клиентов», «справочник складов» — это же «everyday asking» | Старое «words that appear in their question» + люди реально говорят «покажите список…» (`A3`) |
| T3 ✗ | Запрет только для catalog_; для document_ слово «документ» ок | Модель обобщает по kind из `entity`, если запрет не универсален |
| T4 ✗ | В `bestUsedFor` мета-слова можно — запрет «про aliases» | Поле не названо → обход |

**Императив (Б):**
```
aliases: только слова ДОМЕНА (кто/что в учёте). ЗАПРЕЩЕНО в aliases и bestUsedFor:
список, справочник, типы, виды, каталог, реестр, журнал, документ, регистр,
и любые фразы, где эти слова — главное («список X», «справочник Y»).
Если без мета-слова фразы нет — НЕ пиши фразу.
```

**Few-shot (В):**
```
Хорошо: ["клиенты", "покупатели", "поставщики"]
Плохо: ["список клиентов", "справочник контрагентов", "типы контрагентов"]
Плохо: ["документ реализации", "регистр продаж"]  ← мета + смысл
```

Код-фильтр после модели (сводка п.2) обязателен: 27B всё равно протащит 10–20% мета через «естественность вопроса».

### 1.2. «Слова из вопросов людей» (+ роли из flows)

Цель: обиходные основы и роли потока, не морфология title и не целые вопросы (`wiki_alias.sh` комм. 05.08 / 25.08 / 28.08).

| # | Трактовка 27B | Почему |
|---|---|---|
| T1 ✓ | Короткие существительные/роли, как в устной речи | Если есть лимит 3–6 и запрет предложений |
| T2 ✗ | Любая фраза, которой «могли бы спросить», включая «сколько …», «покажите …» | Старое «words that appear in their question» без «не целиком вопрос» |
| T3 ✗ | Склонения title = «слова из вопроса» («контрагентов», «контрагентам») | «also the record title itself» + нет запрета падежей → ~28% A+B (`A2` §4) |
| T4 ✗ | Роли = пересказ `flows` машинными именами / англ. buyers | Англ. few-shot в `:182`; нет «копируй смысл flows человеческим словом на языке title» |
| T5 ✗ | Глаголы-события («наторговали») — нельзя, это не «words for this kind of record» | Слишком узкое чтение «kind of record»; сводка как раз требует кубы событий в словарь — **если промт их не попросит явно, 27B их не даст** (`B3`: 0 глаголов) |

**Императив (Б):**
```
aliases: 3–6 РАЗНЫХ обиходных основ (не падежи одного слова).
Можно: роли из flows («покупатели» / «поставщики») на языке title.
Можно: 0–2 коротких куба события, если сущность — движение/итог
  («продажи», «отгрузка», «оплата») — СУЩЕСТВИТЕЛЬНЫЕ, не предложения.
Нельзя: целые вопросы; «сколько/у нас/покажите»; падежи title;
  латиница; аббревиатуры, которых нет в title; имена полей (только quantities).
Title: ровно ОДИН раз, как в поле title входа — без склонений рядом.
Сомневаешься, что люди так говорят — НЕ пиши (лучше меньше).
```

**Few-shot (В):**
```
Вход: title="Контрагенты", flows содержат продажи и закупки
Хорошо: ["Контрагенты", "клиенты", "покупатели", "поставщики"]
Плохо: ["Контрагенты", "контрагент", "контрагентов", "список контрагентов"]
Плохо: ["сколько клиентов", "buyers", "suppliers"]
```

Отдельно для событий (если продукт их хочет — иначе 27B снова даст 0):
```
Вход: title="Реализация ТМЦ" (документ отгрузки)
Хорошо: ["Реализация ТМЦ", "продажи", "отгрузка", "реализация"]
Плохо: ["наторговали за месяц"]  ← предложение/глагол целиком — в aliases НЕТ;
  такие кубы только если отдельное поле/правило продукта явно разрешит
```
*(Уточнение для проектировщиков P1–P4: глаголы-события из журнала (`B3`) либо отдельное поле, либо явный белый шаблон «1–2 слова-существительных события»; иначе 27B снова уйдёт в «Отчет о реализации» / «ОТМ».)*

### 1.3. Тематическое «не я» (doesNotAnswer / notEnoughFor)

Цель: не только siblings пачки, а «не остатки / не прайс / не число клиентов», даже если сосед не в батче (`B5` §3.1, `A4` §3, `B4` §4).

| # | Трактовка 27B | Почему |
|---|---|---|
| T1 ✓ | Две части: (а) топики-отказы; (б) соседи из списка | Если промт нумерует оба подпункта |
| T2 ✗ | Только «смотрите SiblingTitle» — как сейчас ~96% | Буквальное «naming the sibling types from this list» (`:182`) |
| T3 ✗ | Перечислить ВСЕ сущности базы, о которых «не я» | Нет лимита → вода / обрезка JSON (`A5` truncation) |
| T4 ✗ | Повторить bestUsedFor чужого соседа длинным абзацем | «what each of them answers» без лимита длины |
| T5 ✗ | Тематические отказы только если топик «похож» на title | Модель не ставит «не прайс» у Номенклатуры, если не дали **фиксированный чеклист топиков** |

**Императив (Б):**
```
notEnoughFor — РОВНО два блока (короткие строки, не абзацы):

A) Тематический отказ (всегда, 2–4 строки), формат:
   "не <топик человека> — это у <кто отвечает, если знаешь из пачки; иначе: другая сущность>"
   Топики проверяй по чеклисту (пиши отказ, ТОЛЬКО если ЭТА запись на топик НЕ отвечает):
   остатки/наличие на складе | прайс/текущие цены | список складов/мест |
   число клиентов/контрагентов | деньги на р/с | касса | НДС/книга продаж |
   зарплата/кадры
   Нет совпадения с чеклистом — блок A можно короче (1 строка) или пустым массивом
   только если запись узкая и чеклист нерелевантен; НЕ выдумывай топики.

B) Соседи из ЭТОЙ пачки (0–N): "не путать с <title соседа>: у того <одно короткое чем отличается>"

Запрещено: только «см. X» без топика; обещания чужих мер в bestUsedFor.
```

**Few-shot (В):**
```
Сущность: Номенклатура (карточки товаров). В пачке есть «Виды номенклатуры», нет «Цены».
Хорошо notEnoughFor:
  ["не прайс и не текущие цены — цены в отдельном регистре/документе цен",
   "не остатки на складе — остатки в регистре остатков",
   "не путать с Виды номенклатуры: там классы, не карточки товаров"]
Плохо:
  ["не Виды номенклатуры"]                          ← только сосед, без топика
  ["установка цен, характеристики, единицы"]        ← это вообще BUF-мусор
```

Критично: чеклист топиков — **универсальный** (не okna-имена). Имена «кто отвечает» — только из пачки или общая роль («регистр остатков»), без хардкода `src_table` чужой базы.

### 1.4. «Сомневаешься — не пиши»

Цель: убрать догадки (`ОТМ`, `кassa`, «локации активов», «аккамулятивный»).

| # | Трактовка 27B | Почему |
|---|---|---|
| T1 ✓ | Пропустить токен / оставить короткий список | Если разрешено «массив короче — норма» |
| T2 ✗ | Поле всё равно заполнить «чем-нибудь близким» | Страх пустого JSON-поля; нет явного «empty ok» |
| T3 ✗ | Сомнение = написать в notEnoughFor | Перенос мусора в другое поле |
| T4 ✗ | Сомнение только про quantities; aliases всегда «полные» | Правило без привязки к полям |

**Императив (Б):**
```
Правило пропуска (важнее полноты):
- Нет уверенности ≥ «люди так говорят про ЭТУ запись» → НЕ добавляй токен.
- 3 точных aliases лучше 8 сомнительных. Пустой доп. слот — ОК.
- Аббревиатура: только если она есть в title входа. Иначе — запрет.
- Латиница в RU-title пачке — запрет.
- Не изобретай жаргон склада/банка («выдача», «кassa»), если title и flows
  этого не говорят прямо.
```

**Few-shot (В):**
```
Title: "Поступление на расчетный счет"
Хорошо aliases: ["Поступление на расчетный счет", "оплата на счет", "входящий платёж"]
Плохо: ["кassa вход", "оплата от клиента"]  ← касса≠банк; «клиент» — чужой якорь каталога
Пропуск: не знаешь бытового слова → просто не пиши четвёртый пункт.
```

## 2. Дешёвая песочница: 1 пачка × 5 сущностей → живой 27B

До полного прогона: один вызов infer, ручная сверка по чеклисту ниже. **Не** L67.

### 2.1. Зачем 5, не 20

- Меньше риск truncation (`A5`: рвущийся JSON на пачке 20).
- Человек успевает построчно сверить aliases/BUF/NEF.
- Достаточно соседей, чтобы проверить блок B notEnoughFor.

### 2.2. Критерии выбора слотов (не имена okna)

Состав пачки — **роли в тесте**, сущности подставляются с живой базы по SQL/эмбеддингу так, чтобы роли закрылись:

| Слот | Роль в тесте | Критерий отбора (универсальный) | Что ловим у 27B |
|---|---|---|---|
| **K1** | Коллизия «склад» | Catalog мест хранения **или** аналог «где лежит товар» + в той же kNN/пачке документ движения ТМЦ с словом склад* в старых aliases | Мета «список складов»; «выдача/перенос на склад» у документа; NEF без «не остатки» |
| **K2** | Коллизия «клиент/оплата» | Catalog контрагентов/партнёров + документ банковского прихода (р/с) | «оплата от клиента» / латиница / касса≠банк; общее «клиент» |
| **K3** | Гомоним документ↔накопитель | Пара с одним stem в title (реализация / продажи): document + accumulationregister | «Отчет…», аббревиатуры; BUF чужого топика (склад); взаимный NEF |
| **E1** | «Пустая» / бедная карточка | Мало flows (0–1), мало/нет quantities, служебный или узкий catalog | Канцелярит («локации активов»), мета-ярлыки, выдуманные синонимы вместо пропуска |
| **N1** | Обычная «толстая» сущность | Много flows, 2+ quantities, частый title в вопросах журнала | Регрессия: роли из flows есть; нет падежей title; BUF не врёт |

Итого: **2 коллизионных якоря + 1 гомоним-пара (как два слота или K3=два entity в пятёрке)** — при пятёрке удобнее: K1, K2, K3a (doc), K3b (reg), E1 **или** заменить E1 на N1, если гомоним уже 2 слота. Рекомендуемый набор ролей: **K1, K2, K3-doc, K3-reg, N1**; слот E1 — второй прогон песочницы (ещё 5 мин), не смешивать с гомонимом в одном JSON, если хотите чистый сигнал «бедная карточка».

Минимальный компромисс одной пачки из 5:
1. носитель «склады/места»  
2. документ списания/перемещения (рядом по смыслу)  
3. catalog клиентов/контрагентов  
4. документ поступления на р/с  
5. номенклатура **или** регистр цен (проверить «не прайс» / «прайс»)

### 2.3. Ручной чеклист приёмки песочницы (pass/fail)

На каждый item ответа:

| ID | Критерий | Fail если |
|---|---|---|
| C1 | Нет мета-токенов из стоп-списка §1.1 | есть «список»/«справочник»/… |
| C2 | ≤1 вхождение title; нет падежного веера | «X, x, xов» |
| C3 | Нет латиницы (при RU title) | `kassa`, `buyers`, … |
| C4 | Нет аббревиатур вне title | `ОТМ` при title без ОТМ |
| C5 | aliases ⊆ домен; нет чужого якоря склада/клиента/кассы | «выдача со склада» у списания; «клиент» у банка |
| C6 | bestUsedFor без чужих мер/топиков | «установка цен» у номенклатуры; «склад» у отгрузки как главный вопрос |
| C7 | notEnoughFor содержит ≥1 тематический отказ из чеклиста, если сущность за топик не отвечает | только «не Sibling» |
| C8 | Сосед из пачки упомянут коротко (блок B) | пусто при явном конкуренте в пачке |
| C9 | JSON schema; все entity из входа | лишние/пропущенные entity |
| C10 | «Сомнение» = короче, не мусор | 8+ слабых синонимов |

**Стоп на полный прогон:** любой Fail на C1/C3/C4/C6/C7 в песочнице → править промт, не гонять CAP=0.

### 2.4. Как гонять (механика, без смены серверов)

Один вызов тем же `alias_infer_gateway.py` / тем же model id, thinking off; payload — ручной JSON из 5 entity в формате `wiki_alias_select_entity_batch` (поля `entity`, `title`, `quantities`, `flows`). Сверить глазами по C1–C10. Temperature по возможности зафиксировать в 0 на время пробы (сейчас не передаётся — `B5` §4; для песочницы это отдельный микро-патч вызова, не словаря).

## 3. Антипримеры: старый промт → мусор (причинно)

Чтобы v2 **не повторил** те же лазейки. Источник фактов синонимов: `A2` §3; связь с текстом промта: `B5` + `:182`/`:312`.

### 3.1. «список» (×28 сущностей)

| | |
|---|---|
| **Что в словаре** | «список позиций», «список складов», … у массы catalog_* |
| **Какой кусок старого промта** | «everyday words a person uses when asking» + люди в журнале говорят «покажите список…» (`A3`); **нет** запрета мета-слов; title/обёртка «список X» выглядит «естественно» |
| **Как 27B это прочитала** | T2 из §1.1: фраза целиком = asking-words |
| **Что должно быть в v2** | Явный бан мета-главного слова; few-shot «список клиентов» = плохо; плюс код-фильтр |
| **Ловушка повтора** | Написать «avoid generic words» без списка — 27B не знает, что `список` generic |

### 3.2. «кassa» (латиница)

| | |
|---|---|
| **Что в словаре** | у `document_поступлениенарасчетныйсчет`: `кassa вход` (+ «оплата от клиента») (`A2` #9) |
| **Какой кусок старого промта** | Только «SAME language as its title»; **нет** «no Latin in RU pack»; пример ролей в промте на **английском**; нет «сомневаешься — не пиши» |
| **Как 27B это прочитала** | «Касса» звучит рядом с деньгами → транслит/опечатка как «короткий alias»; банк≈касса по догадке |
| **Что должно быть в v2** | Запрет латиницы; запрет переноса кассового словаря на р/с; skip при сомнении |
| **Ловушка повтора** | «Prefer the language of the title» без антипримера `kassa` — слабо для 27B |

### 3.3. «ОТМ»

| | |
|---|---|
| **Что в словаре** | у `document_реализациятмц`: **ОТМ**, «Отчет о реализации» (`A2` #3) |

### 3.4. «выдача со склада»

| | |
|---|---|
| **Что в словаре** | у `document_списаниетмц` (`A2` #4); рядом «перенос на склад» у перемещения |
| **Какой кусок старого промта** | «everyday words» без запрета чужого топика; соседи в пачке = close in meaning → модель **сближает** складские документы общим якорем «склад»; notEnoughFor просят отличить siblings, но **aliases** общие слова оставлять можно (ещё жёстче в `:312`) |
| **Как 27B это прочитала** | Списание ≈ выдача материалов со склада (бытовая аналогия); слово «склад» полезно для «asking» → в aliases; конкуренция с `catalog_местахранения` не штрафуется промтом |

## 4. Рекомендуемый скелет промта для 27B (черновик под P1–P4)

Не финальный текст продукта — **форма**, которую mid-model не размазывает:

```
JSON only. No prose. No code fences.

Language: EVERY string value in the SAME language as each item's title.
Latin letters forbidden unless the title itself has them.

For EACH input item write:
1) aliases — 3 to 6 tokens. Rules:
   - domain words people say + role words from flows + title ONCE
   - FORBIDDEN meta: список, справочник, типы, виды, каталог, реестр, журнал, документ, регистр
   - FORBIDDEN: case variants of title; whole questions; invented abbreviations; field names
   - unsure → omit (short list is OK)
2) quantities — only names from input; 1–3 word human aliases each; no sentences
3) bestUsedFor — 2–4 short templates of what THIS record answers; no foreign topics
4) notEnoughFor — array of short lines:
   - topic refusals from checklist if this record does not answer them
   - plus "not <sibling title>: <one-line difference>" for siblings in THIS input

[few-shot 1 good + 2 bad on title language]

Schema: { "items": [ ... ] }
Input:
```

Длина: лучше **короче старого `:182`**. Один абзац «and also… so include…» 27B уже доказала, что исполняет выборочно.
