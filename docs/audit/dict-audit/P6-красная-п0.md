## 2. Стоп-словарь P3 и чужая предметная область

### 2.1. Вопрос: «каталог» в магазине = предмет

Да. В рознице человек говорит «каталог» про ассортимент / витрину товаров. Голый бан леммы **каталог/catalog** вырежет реальный asking-word, если title сущности «Каталог товаров» / «Product catalog», а короткий запрос — «каталог». Title-fallback (P3 §4.3) подставит длинный title, не короткое слово — **recall коротких вопросов падает**.

То же семейство риска: **документ/document**, **список/list**, **журнал/journal** — в речи людей это и класс платформы, и бытовая оболочка вопроса («покажите список…», A3).

### 2.2. Фикс-список платформы 1С — легитимен ли?

**Да, с оговоркой источника.**

| Опора | Вердикт |
|---|---|
| Конечный словарь **классов OData / `_KIND_WORD`** (`z20_ask_main_http.py:922–938`) + `_NAMED_PLATFORM_TYPE_PHRASES` (`z21_wiki_choice.py:98–121`) | **Легитимен по п.0**: это платформа 1С, одинаковая на любой конфигурации; не профиль okna |
| Топ коллизий A2 на боевом срезе okna как *источник*, какие леммы взять | Допустимо как **эвристика приоритизации** v1; не как доказательство «это мета везде» |
| Чистый фикс-список поверхностных форм без связи с `src_table` kind | Слабее: ловит доменные омонимы |

Критерий, который держит п.0 лучше «голого списка»:

1. Токен ∈ множество **локализованных ярлыков классов платформы** (значения `_KIND_WORD` + EN OData-имена + при появлении — UK/др. локали метаданных), **или**
2. Токен == `kind_word(entity)` этой строки, **или**
3. Точная двусловная платформенная фраза из `_NAMED_PLATFORM_TYPE_PHRASES`,
4. И только потом — вырезание токена-оболочки внутри фразы (`список складов` → `складов`).

Стемминг боевого `search_dict_stem` в фильтр **не** тащить (A6: локаль `ru_RU` по умолчанию — уже блокер коробки).

### 2.3. Дыры P3 относительно п.0

| Дыра | Почему |
|---|---|
| Только **ru + en** формы (§2.1–2.2) | База с укр. метаданными (`довідник`, `документ`, `журнал`, `реєстр`, `звіт`, `перелік`…) протащит мета в aliases мимо фильтра |
| Леммы **типы / виды / группы / движение** | Не чистые OData-классы; в части конфигураций — якорь имени («Типы цен», «Движение товаров»). P3 аргументирует «якорь должен быть доменным» — разумно для каши, но это **продуктовое сжатие речи**, не чистая мета-платформа |
| «тмц» не фильтровать | Верно по п.0 (отраслевое; на пустой конфигурации бессмысленно) |
| Collision-parse в обход фильтра | Не п.0, но обязательно чинить — иначе мета вернётся |
| Опора обоснований на ×28 okna | В отчёте ок; в коде константы не должны называться «из замера okna» |

**«Как фильтр узнаёт»:** не «слово часто на okna», а «слово называет класс объекта платформы 1С / является его локализованным ярлыком». Фикс-список таких ярлыков — нормальный код (как `_KIND_WORD`), **если** расширяется локалями метаданных, а не профилем одной базы.

## 3. Формат P4: миграция и потребители

### 3.1. Миграция живых строк — чужие базы

Рекомендация P4: оставить VARCHAR, сменить разделитель `, ` → ` | `; JSON-в-колонке — запасной.

| Сценарий | Потеря данных? |
|---|---|
| «Чистые» строки без `,` внутри фразы: массовый `replace(', ', ' | ')` | **Нет**, на любой базе |
| Строки с `,` внутри элемента (EN «A, B, and C»; RU со скобками как 30 nef okna) | Эвристика «скобки+запятая» с B1 **okna-калибрована** — на чужой базе даст ложный split / склейку. **Не гонять** как универсальный скрипт |
| Безопасный путь для неоднозначных | Snap (`CREATE TABLE … AS SELECT *`) → force-переген сущности после схемы §1 → не угадывать машинно |
| База, где в тексте уже есть `\|` | Редко в RU; в EN/кодах — возможно. Валидатор `pattern` + запрет в промте обязательны **до** записи |
| Меры (короткие aliases) | Обычно безопасный replace |

**Вывод:** миграция разделителя **не** теряет данные чужих баз, если неоднозначные строки не «чинят» okna-эвристикой, а переспрашивают. Числа «258 / 30 / 13» — про okna, не параметр продукта.

### 3.2. CSV → JSON в колонке: кто переварит?

Если вместо CSV положить текст вида `["a","b"]` в `aliases` / `best_used_for` / `not_enough_for` **без** смены всех читателей:

#### Ломаются (режут/ждут плоский CSV)

| Потребитель | Файл:строка | Эффект |
|---|---|---|
| Frontmatter вики | `ubuntu/serenedb/wiki_build.sql:57–64` | `str_split(..., ',')` → обломки `"["`, кавычки, ложные bullet'ы |
| Коллизии: токены aliases | `wiki_alias_collision_left.sql:5`, `wiki_alias_collision_round.sql:6` | Ложные алиасы / ложные дубли |
| Подпись = первый алиас | `entity_rank_v2.py:694` | `split_part(..., ',', 1)` → `"["` или кусок JSON |
| Топики intent | `ask/z02_intent.py:298` | `re.split(r"[,;|/]", …)` — ещё хуже на JSON |
| Обратный разбор | `wiki_alias_parse.py:78–84` `_alias_tokens` | Split по `,` внутри JSON |
| Reask append | `wiki_alias_reask_merge_confirmed.sql:15–19` | `\|\| ', '` к JSON-строке → мусор |
| Solr compile | `solr_synonyms_compile.sql:57–64` | Split/escape под CSV |
| Solr Python | `solr_synonyms_build.py:50–79`, `:114` (`escape_term` / `split_alias_csv`) | То же |

#### «Едят» VARCHAR целиком — но JSON **вредит семантике**

| Потребитель | Файл:строка | Эффект |
|---|---|---|
| Hybrid / stem | `wiki_card_hybrid.sql:76,112,130,151–153`; `entity_card_build.sql:82–91`; `z05_entity_form.py:310–311,355`; `z12_stock_balance.py:214`; `z17_aggregate_groups.py:334`; `z02_intent.py:425` | `concat_ws` / `@@` / `ts_lexize` увидят `[`, `]`, `"` как токены → шум или промах |
| Паспорт + судья | `wiki_passport.sql:9,14`; `z21_wiki_choice.py:23,660–697` | NEF уйдёт в `doesNotAnswer` сырой JSON-строкой — модель судьи прочитает, люди/отладка — хуже; не «падение», но деградация |
| Collision ILIKE | `wiki_alias_collision_left.sql:14` | Подстрока внутри JSON часто ещё находится — ложная «сведённость» возможна |

**Итог:** JSON-в-VARCHAR **не** переварят потребители без миграции всех call-site + отдельного текста для `inverted`/`@@`. Вердикт P4 «запасной, дороже» — подтверждён. Путь ` | ` требует правки того же множества split-потребителей (§ выше, блок «ломаются»), но hybrid/паспорт остаются совместимы.

### 3.3. Замечание к z02

При разделителе ` | ` текущий `re.split(r"[,;|/]", …)` (`z02_intent.py:298`) **разрежет каждый алиас по пайпу**. Поле топиков-примеров не боевой критичный путь (P4 §7), но это регресс наблюдаемости — в HOW_NOT_TO при правке, и сам split надо сузить.
