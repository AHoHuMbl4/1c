## Вердикт

Генератор — **оркестратор bash + SQL-пачки + один вызов модели на пачку** через `openclaw infer model run` (обёртка `alias_infer_gateway.py`). Модели уходят **не `$metadata` и не сырые таблицы**, а JSON из `wiki_entity_facts` + соседние `flows` по `search_refcols`. Промт просит `aliases` / `quantities` / `bestUsedFor` / `notEnoughFor`; явного «N синонимов» и `temperature` в коде генератора **нет**. `maxTokens` берётся из каталога OpenClaw модели (**8192** в каноне `ubuntu/openclaw/instance/openclaw.json`). Живой `journalctl` окна в этой сессии **не снят** (SSH к ключу `~/.ssh/id_ed25519_deploy` режет runtime floor); ниже — зафиксированные замеры из CHANGELOG/графа.

## 3. Модель и способ вызова

### 3.1. Цепочка

```
wiki_alias.sh
  → (runuser -u undebot | напрямую) python3 alias_infer_gateway.py
       --message-file MSG --model MODEL --thinking THINKING --ans --err
  → openclaw infer model run --local|--gateway --model --thinking --json --prompt TEXT
```

- Транспорт по умолчанию: **`--local`** (`alias_infer_gateway.py:23–31`; `ALIAS_INFER_TRANSPORT` / `BRANCH_ALIAS_INFER`).  
- Gateway: RPC-потолок **120 с** → на длинных пачках падал (`wiki_alias.sh:74–75`, комментарий к замеру 24.08).  
- Thinking: `WIKI_ALIAS_THINKING` умолч. **`off`** (`wiki_alias.sh:78`).  
- Модель умолч. в скрипте: **`vllm/Qwen3.8-27B`** (`wiki_alias.sh:77`).  
- Юнит: модель/DSN/batch перекрываются `/etc/1c-wiki-alias-%i.env` (сервис `:34`); в каноне агента dict — та же `vllm/Qwen3.8-27B` (`ubuntu/openclaw/instance/openclaw.json:38–42`).  
- Смоук 06.09: проводка окна на OpenRouter `qwen/qwen3.8-27b` через тот же provider id `vllm` (CHANGELOG 06.09) — **живой env окна в этой сессии не читался**.

### 3.2. temperature / max_tokens

| Параметр | В генераторе | Откуда фактически |
|---|---|---|
| temperature | **не передаётся** (`alias_infer_gateway.py:48–61` — только model/thinking/prompt) | умолчание провайдера OpenClaw / API; в каноне openclaw.json для vllm **поля temperature нет** |

### 3.3. Сколько проходов

| Проход | Условие | Цикл | Что делает |
|---|---|---|---|
| 1. Инициализация сущностей | пока есть непокрытые | `while` + `BATCH` + бюджет/`CAP` | select → промт 2.1 → parse → merge entity+measures |
| 2. Добор величин | сущность описана, measures пусты | второй `while` | тот же промт; merge **только** measures |
| 3. Коллизии | `WIKI_ALIAS_COLLISIONS=1` (умолч.) | до `WIKI_ALIAS_COLLISION_ROUNDS` (умолч. **40**) или бюджет | pick слово → probe **до** модели → промт 2.2 → collision_merge |
| 4. Reask (С5) | `REASK_EVERY>0` и tick кратен | до `REASK_CAP` | боковая таблица → confirm → merge confirmed |
| 5. Day-basis + branch | всегда в конце скрипта | batch forks / `branch_alias.sh` | подписи веток |
| 6. Solr syn | всегда | один SQL | compile из **боевой** `search_entity_alias` |

Такт сборки (`build.sh`): `./wiki_alias.sh "${WIKI_ALIAS_PER_TACT:-100}"` с бюджетом умолч. **120 с** — не полный юнит.

**Не показывают:** `$metadata`, сырой OData, суммы/счета/даты документов, полный список всех сущностей базы.

**Показывают (JSON-массив записей):**

| Поле | Откуда | Когда |
|---|---|---|
| `entity` | `wiki_entity_facts.src_table` | все entity-пачки |
| `title` | `wiki_entity_facts.label` ← `search_tables.label` | все |

Коллизия — сущности, разделяющие одно и то же слово в `aliases` (`wiki_alias_collision_round.sql`).

## 5. Ограничения (списком)

1. **BATCH** умолч. 20 (`WIKI_ALIAS_BATCH`); живой хотфикс 28.08 — BATCH=8 на окне при truncation (граф `wiki_alias_parse.py`).
2. **Бюджет времени** `WIKI_ALIAS_MAX_SEC`: умолч. скрипта 120 с; у юнита **0 = без лимита** (`1c-wiki-alias@.service:39`).
3. **CAP** аргумент `wiki_alias.sh N` (0 = все); юнит зовёт `0`.
4. **RETRY_H** умолч. 6 ч — пустая запись переспрашивается не раньше (`wiki_alias.sh:49`, select NOT EXISTS с `seen_at`).
5. **Коллизии:** макс. 40 кругов/прогон; отметка `search_alias_probe(alias, entities_fp=md5(...))` **до** вызова — осечка тоже «съедает» слово; новое множество сущностей → новый fp → снова спрос.
6. **Осечка модели (exit≠0):** пачка не валит весь прогон; `skipped++`; mark_skip пустышками; `continue` (`wiki_alias.sh:188–197`, `:246–250`).
7. **Сбой SELECT 1-го прохода:** `exit 1` (не «база кончилась») — `:148–151`.
8. **Обрезка JSON ответа:** `_salvage_items` спасает целые items; хвост переспросится (`wiki_alias_parse.py:112–176`).
9. **Права обмена:** каталог `CSV_DIR`/`/var/lib/serenedb`, chmod 644 на pay/ans/rows; chown undebot при root (`wiki_alias.sh:112–119`, `:211`).
10. **openclaw отсутствует:** шаг `exit 0` с сообщением (`:105`).
11. **Reask** по умолчанию выкл (`REASK_EVERY=0`).
12. **Day-basis:** отдельный бюджет 60 с, batch 10; инфра/биллинг — break через `branch_alias_parse --infra-check`.
13. **Solr compile fail-closed:** ненулевой exit юнита (`:536–537`).
14. **systemd:** `TimeoutStartSec=infinity` (после убийства 2h при 258/258, CHANGELOG 27.08).
15. **Gateway transport:** не использовать для длинных пачек (120 с RPC).

## 6. Схема конвейера по шагам

```
[init DDL]
    │
    ▼
┌─ while сущности без alias (или пустышка старше RETRY_H) ─────────────┐
│  select_entity_batch (seed + kNN emb, +flows)                         │
│  prompt 2.1 + pay → alias_infer_gateway → wiki_alias_parse            │
│  merge_entity (+measures) | on fail: mark_skip, skipped++             │
│  break: пусто / CAP / бюджет                                          │
└───────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ while сущности с alias, без measure-aliases ─────────────────────────┐
│  select_measure_batch → тот же prompt 2.1 → parse                     │
│  merge_measures only | on fail: mark_measure_skip                     │
└───────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ if COLLISIONS=1: while rounds < 40 ──────────────────────────────────┐
│  collision_round: pick слово → INSERT probe → pay                     │
│  prompt 2.2 → (inline parse) → collision_merge (перезапись полей)     │
│  break: нет кандидатов / бюджет                                       │
│  echo left via collision_left                                         │
└───────────────────────────────────────────────────────────────────────┘
    │
    ▼
[opt reask] → publish (stats + VACUUM REFRESH) → dayfork → branch_alias
    → solr_synonyms_compile (всегда из search_entity_alias)
```

Идемпотентность 1-го прохода: повторный прогон берёт только непокрытых / протухшие пустышки. Collision переспрашивает только неспрошенные fp или слова без упоминания в `not_enough_for`.

## 8. Замечания аудита (не правки)

1. Промт **не ограничивает** число aliases — качество/шум словаря целиком на модели + пост-фильтр величин.  
2. `temperature` в контуре генератора **не зафиксирован кодом** — дрейф провайдера возможен.  
3. Collision **перезаписывает** aliases/best/not_enough целиком; 1-й MERGE — только в пустые.  
4. Вход — метаданные корпуса (label, measures, flows), не тексты документов и не `$metadata` XML.  
5. Подгонка под конкретные вопросы gold **в коде генератора отсутствует** (соответствует TARGET п.0 на уровне этого контура).
