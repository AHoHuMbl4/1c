# Карта M1: маршрут z20 против формулы №15 (2026-09-11)

Источник: чтение кода (без правок кроме этого файла). Вход:
`ubuntu/serenedb/serene_ask.py` → `ask/_bootstrap.load_all` (зоны z01…z22, z20 последней) →
`Handler.do_POST` → `answer_checked` → `answer`.

ФОРМУЛА №15: вопрос → интерпретация из вики → вопрос в БД → варианты из вики (если >1) → выбор → ответ.
Разрешены владельцем (не снос): B-дедлайн 88 с; A-ранний clarify (ступень 4 раньше по тракту).

Обозначения вердикта: **снести** = вне формулы / молчаливый выбор; **ступень N** = нужен формуле;
**ускорение-не-снос** = защитный/инфраструктурный слой без выбора смысла; **оставить-пока** = ступень 4/5
механикой, но форма не из вики (нужна пересборка, не слепой вырез).

## (а) Эскиз минимального тракта

После сноса всего вне формулы (физическая последовательность):

1. **HTTP** `Handler.do_POST` → вопрос (+ `decision_id` если выбор).
2. **Ступень 1** — сырой текст вопроса.
3. **Ступень 2** — вики-интерпретация: `wiki_hybrid_pool` → (при необходимости LLM-разбор смысла **словами человека** из карточек/синонимов, без имён метаданных в ответ человеку) → структурированный запрос к БД.
4. **Ступень 3** — один (или узкий) SQL/агрегат по интерпретации (`aggregate` / `rows_of`).
5. **Ступень 4** — если прочтений >1: `kind=clarify` + options с **человеческими** подписями из вики (не src_table); иначе сразу 6. Сюда же разрешённый **A-ранний clarify**.
6. **Ступень 5** — `decision_id` / `seal_clarify` / `consume_decision` → повтор с trusted.
7. **Ступень 6** — `compose` + подстановка чисел + **gate** (защита цифр) → answer.
8. **B-дедлайн** — обёртка таймера вокруг 2–6; при истечении — unavailable, без нового смысла.

Не входят: `parse_intent` как отдельный судья сущности/меры; K6; rerank; fork A/B/C; arbiter×N; prefer_*/sales_canon/stock_canon; alias-veto; period/currency prefer; enough-слой; memory auto-apply; серый stock bypass.

## (в) Неясные места (ступень не зафиксирована честно)

1. **`parse_intent` vs формула**: владелец требует интерпретацию **из вики**; сейчас LLM-intent — отдельный слой без карточек. Это «ступень 2 сейчас» или однозначный снос — зависит от того, останется ли узкий слот want/period после вики. В таблице помечено как замена.
2. **Один `wiki_verify` yes → leader без меню**: по формуле при одном прочтении — сразу ответ (ок); но «одно yes» может быть ошибкой модели verify. Неясно, считать ли обязательным всегда показывать варианты при `len(pool)>1` даже с одним yes.
3. **`_wiki_clarify_collapse_answer`**: равные числа → answer. Формально «прочтения совпали», но человек не выбирал — серая зона между ступенью 4 и 6.
4. **Axis/grain (`serene_axis.decide_grain`)**: это «интерпретация» или отдельная догадка? Без вики-осей неясно.
5. **Period leader / day_basis / currency prefer**: часть «интерпретации периода» или запрещённая догадка? Формула не детализирует период.
6. **`serene_enough` (достаточность)**: уточнение слотов до/после счёта — ступень 4 или чужой слой.
7. **Паспорт ответа (`build_answer_passport`)**: видимость решений vs «ничего больше» в формуле — не запрет, но не ступень.
8. **Rank-детерминированный ответ** (`rank_deterministic_answer`, ~4994): обход compose — ступень 6 кодом или особый путь.
