## 3. РАСХОЖДЕНИЯ, РАЗВЕДЁННЫЕ ОРКЕСТРАТОРОМ (волне P оспорить можно)

1. **z09 fork_detector**: M1 «снести» vs M2/M3 «детектор прочтений = ступень 4».
   Решение: ДЕТЕКТОР и fork_labels (вики-подписи из БД) ОСТАЮТСЯ — это способ
   узнать «прочтений больше одного»; сносу подлежат только авто-исходы (A/unique/
   mute/лидеры). Меню при >1 строит единый построитель с вики-подписями.
2. **rerank**: остаётся ТОЛЬКО как техника порядка входов для LLM/verify; любое
   место, где ranked[0] становится ответом/мерой/осью без человека, — снос (Speed C
   HTTP-экономия не спорит).
3. **K6**: M1 «снести» vs M4 «оставить-ускорить». Решение: СНЕСТИ из тракта (это
   перестановщик до вики + 52с); MOL-ускорение K6 тем самым отменяется. Красной
   команде проверить падение качества wiki-pick без K6-порядка (риск: больше
   clarify — приемлемо, хуже — нет).
4. **z02 intent**: остаётся ТЕХНИКОЙ разбора (слоты периода/условий для SQL);
   убираются суждения (majority-голосование смыслов, first-of-list, exempt).
   Полная замена z02 на вики-разбор — НЕ в этом пакете (слишком большой переворот
   preds; вопрос владельцу отдельно).
