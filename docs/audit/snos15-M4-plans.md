## (в) Конфликты между планами

1. **Три разных меню:** MOL A2 *до* K6 (`MOL:29`) vs Speed A *после* fork/entity_form (`SPEED:51-52`) vs FIX 3B clarify на degraded *в хвосте verify* (`FIX:104-107`). Формула требует **одно** меню: после вики+БД, подписи из вики. A2 с формулой несовместим; Speed A совместим только после вырезания предшествующих заплаток; FIX 3B — ближайший по смыслу к ступеням 4–5.
2. **prefer_*:** MOL A2 **строит пул с prefer_*** (`MOL:24`); FIX 3A **режет prefer** post-lock, но **оставляет** до-wiki (`FIX:86`). Формула: резать все.
3. **Canon locks:** Speed A **запрещает** early-clarify при `sales_canon_locked` / `wiki_arbiter_locked` (`SPEED:58-60`) — сохраняет silent pick; FIX 3A/3C как раз вычищают обходы вокруг lock. Направление FIX — ближе к сносу; forbid Speed A консервирует антагонистов формулы.
4. **Мера:** FIX 4A включает `ASK_SALES_RANK_CANON`/`ENTITY_FORM`; Speed A явно не закрывает measure_ambiguous; формула запрещает угадывание меры. Планы Speed+FIX согласны между собой в «мера отдельно», и **оба** спорят с №15.
5. **Дедлайн:** MOL запрещает «дедлайн ≥90с» (`MOL:87`); Speed ставит 88 < 90 (`SPEED:28-29`, `:38`) — согласованы. Конфликта с формулой нет.
6. **SAMPLES=1:** MOL и Speed оба запрещают — ок.
7. **Wiki-порядок:** MOL честно фиксирует «wiki-выбор сегодня после K6» (`MOL:31-32`); Speed A уже принят на полигоне (`activeContext` автовброс: B+A в origin). Внедрение A2 поверх принятого A усугубит два меню и wiki-перехват.
8. **PTT К8/К9 vs FIX «НЕ новый выбиратель»** (`FIX:208-209`) и №15 «ничего больше» — прямой конфликт; FIX/activeContext №11 ближе к сносу, PTT К8/К9 — к наращиванию.
9. **Склад:** PTT+эпизод скорости сносят фильтры; MOL 4c ускоряет stock SQL после витрины — не конфликт, если 4c не возвращает маршрутизацию словами.

**Вывод по A2 vs меню-по-формуле:** A2 **не** совместим. Меню формулы = ступень 4 после вики и запроса; A2 = ранний перехват с другим пулом и без гарантии вики-подписей.

## (г) Неясные места (честно)

1. **Что считать «интерпретацией из вики» на ступени 2** при сегодняшнем коде: wiki_arbiter / entity cards / alias / intent LLM? Планы пишут «wiki после K6» (`MOL:31-32`); формула ставит вики **до** БД. Точная нарезка «что удалить из pre-wiki пути» в этих четырёх планах **не специфицирована** — ждут карту отклонений волны M.
2. **Однозначность:** когда lock/wiki_verify==pick — это ступень 6 без меню или скрытые прочтения? FIX 3A.2 и Speed forbid это не разводят замером.
3. **FIX 2B:** календарные формы — словарь периода или запрещённая «интерпретация не из вики»? В планах нет решения владельца после №15.
4. **Подписи меню:** `mk_opts` / fork_labels / wiki labels — Speed требует fingerprint ≡ полному clarify (`SPEED:67-68`), но не требует источник = вики. Формула требует вики; сверка кодом в планах не записана.
