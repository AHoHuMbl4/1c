Вердикты раннера (`i2_runner.py` ~214–266):

- `kind ∈ {clarify, no_data, unavailable}` → **honest_no**
- `kind ∈ {answer, figures}` + число = эталон → **match**; иначе **confident_wrong**
- нет kind / транспорт → **unresolved**

Следствие для формулы №15: **рост clarify = рост honest_no в сводке L67**. Это
ожидаемо и **не дефект**. Дефект — только если среди honest_no растёт
`no_data`/`unavailable` при живых данных **или** появляется `confident_wrong`.
Поэтому после каждой волны обязательно резать jsonl по `kind`:

```text
match / clarify / no_data / unavailable / confident_wrong / unresolved
```

а не только четвёрку L19.

**(д) Скорость:** уходит cold-lift / force_pool / wiki short-circuit lock —

**(е) Ядро:** снос bypass `z21:671-673` не должен ломать cascade; замок wiki +
