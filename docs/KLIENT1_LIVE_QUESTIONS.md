# A. Правила игры для прогона в любой день

## A1. «Сегодня» и часовой пояс
Сервер klient-1 — **UTC** (сервис ответов берёт дату из `time.strftime` → UTC), данные 1С —
**московские** (часы документов 08–18 Мск; закрытие месяца 23:59:59 / 00:00:00). Между
00:00 и 03:00 Мск «сегодня» бота отстаёт от бизнес-дня. Эталон:
`WITH today AS (SELECT timezone('Europe/Moscow', now())::date AS d)`. Прогоны — в рабочие
часы (06:00–20:00 UTC); расхождение бота в ночном окне — отдельная находка.

## A2. Свежесть: регистры отстают от документов — на klient-1 это главное
Пакеты из 1С идут редко и по сущностям: документы — дельтами (реализации — 18.08 16:23
UTC), **регистр выручки — полной выгрузкой и редко** (последний раз **17.08 20:18 UTC**,
117 130 строк). Итог на 19.08: в документах 8 проведённых реализаций за 18.08 (795 176 ₽)
и 1 акт (378 060 ₽), а в регистре выручки за 18.08 — **0 строк**. Корпус бота собран
18.08 21:07 UTC.
Правило теста: эталон «Д»-вопросов считать из **того же источника, что бот (корпус)** в тот
же момент; свежесть регистра проверять отдельно (`max(Period)` регистра против `max(Date)`
проведённых `document_реализациятоваровуслуг`). **Молчаливый 0 за вчера при проведённых
документах — дефект** (п. 13 TARGET): ожидание — «по регистру выручки N (выгрузка от …),
по документам M».

## A3. Что такое «продали» — три ловушки в одном регистре
Регистр `accumulationregister_выручкаисебестоимостьпродаж`: `СуммаВыручки` (с НДС, упр.),
`СуммаВыручкиБезНДС`, себестоимость `Стоимость`, штуки `Количество`, дата `Period`.
1. **Внутригрупповые передачи** между своими фирмами лежат в том же регистре
   (`Recorder_Type LIKE '%МеждуОрганизациями'`; в корпусе
   `refs_map['НастройкаХозяйственнойОперации'] = 'Реализация товаров в другую организацию'`,
   суммы совпадают с витриной копейка в копейку: 2 049 505 873,70 за всё время). Июль:
   внешняя **136 669 867,21**, внутригрупп 22 400 931,48, весь регистр 159 070 798,69.
   Бот, суммирующий всё, завышает «продали» на 16 % (май — 42 %).
2. **Услуги/ремонт** — `Document_АктВыполненныхРабот`, без себестоимости в регистре. В
   корпусе их отличает отсутствие `refs_map['ВидЗапасов']` (июль: 31 527 062,18 против
   актов 31 523 062,18 — разница 4 000 ₽, строка услуги в товарном документе). «Лучший
   товар» без фильтра выдаст «Ремонт с полной разборкой прибора» (июль — 24,2 млн, 1-е место).
3. **Возвраты, сторно, распределение затрат** — отрицательные и нулевые строки; возвраты
   за 2026 есть в каждом месяце.

## A4. Себестоимость считается с отставанием
`Стоимость` заполнена по **07.08** включительно, далее нули до расчёта себестоимости.
«Сколько заработали в этом месяце» — честно: прибыль за август неизвестна; за закрытый
месяц — считается.

## A5. Справочники в витрине РАЗВЁРНУТЫ по табличным частям — главная ловушка счёта
`catalog_номенклатура`: 16 471 строка = **9 030** живых позиций (3 642 ключа повторяются);
`catalog_партнеры`: 8 922 строки = **5 130** уникальных; `catalog_пользователи`: 9 дублей.
Любой `JOIN` на эти таблицы без `DISTINCT Ref_Key` умножает суммы (первая версия этого
файла имела лидеров ×2–×3 и счёты ×1,8). Без дублей: `склады`, `организации`,
`банковскиесчетаорганизаций`, `видызапасов`, `валюты`, `видыноменклатуры`.
Правило: имена брать из `(SELECT DISTINCT Ref_Key, Description FROM catalog_…)`, счёты —
`count(DISTINCT Ref_Key)`.

## A6. Организация и имена — двухходовые ссылки
В регистре нет `Организация`: брать через шапку документа-регистратора (`реализация…`,
`актвыполненныхработ`, `корректировкареализации`, `возвраттоваровотклиента` →
`Организация_Key`; покрытие 100 %). Клиент: `АналитикаУчетаПоПартнерам_Key` →
`informationregister_аналитикаучетапопартнерам` (ключ уникален) → `Партнер_Key` →
партнёры. Товар: `АналитикаУчетаНоменклатуры_Key` → `…аналитикаучетаноменклатуры` →
`Номенклатура_Key`; тип Товар/Услуга — `catalog_видыноменклатуры.ТипНоменклатуры`.
Менеджер: `Менеджер_Key` → `catalog_пользователи`.
🔴 В корпусе бота `refs_map['АналитикаУчетаПоПартнерам']` — **неразрешённый GUID**; имя
клиента в регистре выручки боту недоступно; организация по товарам угадывается из текста
`refs_map['ВидЗапасов']` («…; Организация: НОРДМЕД») лишь частично (56 строк августа без
имени, акты — без `ВидЗапасов`). Вопросы «лучший клиент» и «по одной фирме» для бота
заведомо трудны — эталон всё равно с именами из витрины.
Техника SQL: агрегировать по ключу ДО join со справочником; `today` держать внутри CTE
(`FROM a, today LEFT JOIN …` ломает привязку LEFT JOIN — проверено).

## A7. Остатки, деньги, долги, заказы — ЕСТЬ (в отличие от okna)
Остатки: `accumulationregister_товарынаскладах`, `RecordType` Receipt/Expense, ресурс
`ВНаличии`, `Period < today+1`; отрицательных остатков нет. Склад в деньгах —
`себестоимостьтоваров` (`Стоимость`). Деньги — `денежныесредствабезналичные` (44 рублёвых
счёта + 13 CNY и др.; `СуммаУпр` = рубли) и `денежныесредстваналичные` (0). Дебиторка —
`расчетысклиентамипосрокам` (`ДолгУпр`, `ДатаПлановогоПогашения`); **крупнейший «должник»
— партнёр «Наше предприятие» (внутригрупп, 18,2 млн)** — внешний долг считается без него.
Заказы — `document_заказклиента` (`Статус='КОбеспечению'`) × `informationregister_состояниязаказовклиентов`
(регистра `заказыклиентов` в витрине нет).

## A8. Будущие даты и выходные
41 строка регистра датирована вперёд (20.08, 24.08, 31.08 — закрытие): верхняя граница
`today + 1 day` обязательна. Выходные — 0 (сб 15.08, вс 16.08), но проверять SQL-ом;
**18.08 (вторник) — 0 в регистре по причине A2, не выходной.**

Шаблон внешней выручки (витрина):
```sql

SELECT round(sum(TRY_CAST(СуммаВыручки AS DECIMAL(38,10))),2)
FROM accumulationregister_выручкаисебестоимостьпродаж, today
WHERE Recorder_Type NOT LIKE '%МеждуОрганизациями'
```

```sql
SELECT round(sum(nums['СуммаВыручки']),2) FROM search_corpus, today
```

# C. Корпусные эквиваленты (как бот может это увидеть)
- внешняя выручка: `НастройкаХозяйственнойОперации <> 'Реализация товаров в другую организацию'` ✓ (сходится с витриной);
- услуги vs товары: `refs_map['ВидЗапасов'] IS NULL` ✓ (±4 000 ₽);
- организация: частично из текста `ВидЗапасов` («Организация: …»), акты — нет; клиент — **нет** (GUID); менеджер — `refs_map['Менеджер']` ✓; склад — `refs_map['Склад']` ✓;
- остатки/деньги/долги/заказы — регистры с `RecordType` есть в корпусе как строки; формула «приход − расход» — забота бота.

# D. Что менялось (честный след)
v1 (чекпойнт) считала лидеров, остатки позиций и счёты через JOIN со справочниками, а
справочники в витрине развёрнуты по табличным частям (A5): лидеры были ×2–×3 (МООКЦ
27,4 млн → 13,7; SpyGlass 30,4 млн/6 шт → 10,1/2; Ким 63 млн → 31,5; щипцы 24 шт → 8;
Семашко 6,18 млн → 2,06), счёты ×1,8 (партнёры 8 902 → 5 130; номенклатура 16 129 →
9 030). Не менялись: итоги периодов, разрез по организациям и услугам, себестоимость,
банк, долг всего/внутригрупп, заказы — они без join на развёрнутые справочники.
