# A. Правила игры для прогона в любой день

## A1. Что такое «сегодня»

Сервис ответов берёт дату из локального времени сервера okna (`time.strftime`), а
сервер живёт в **Europe/Chisinau (EEST, UTC+3)**. База же отвечает на `CURRENT_DATE`
по **UTC**. Между 00:00 и 03:00 по Кишинёву они расходятся на день.

Эталон обязан считать «сегодня» так же, как сервис:
```sql
WITH today AS (SELECT timezone('Europe/Chisinau', now())::date AS d)
```
Даты в данных (`Period`, `doc_date`) — местное кишинёвское время, границы дня —
местная полночь. Продажи идут в рабочие часы (вчера: 09:01–16:58), поэтому днём
расхождения не видно, а ночной прогон без этой поправки возьмёт не тот день.

## A2. Источник правды и источник бота

Бот отвечает по корпусу (`search_corpus`), корпус собирается из витрины
(`accumulationregister_реализациятмц` и др.) по такту. Пакет из 1С приходит каждые
~30 минут (в рабочее время), сборка корпуса — после него. Для **закрытых дней**
витрина и корпус равны копейка в копейку (сверено по всем 900 дням). Для **текущего
дня** корпус может отставать на такт: в 07:47 UTC витрина 480 104,42, корпус 462 573,08.

Решение для теста: эталон «Д»-вопросов (сегодня / эта неделя / этот месяц /
лидеры текущих периодов) считать по **корпусу**, тем же SQL, в тот же момент, что
задаётся вопрос — тогда сверяется разум бота, а не свежесть такта. Свежесть — отдельный
тест (`/health`, `freshness_lag`). Эталоны закрытых периодов можно считать откуда угодно.

## A3. Классы стабильности

- **С** (стабильно): период закрыт — вчера, позавчера, прошлая неделя, прошлый месяц,
  выходные, счёт справочников (меняется редко, но правилом).
- **Д** (движется): сегодня, эта неделя, этот месяц и их лидеры. За 15 минут проверки
  «сегодня» менялось трижды (480 104,42 → 479 710,42 → +2 строки): документы
  перепроводятся. Число нельзя зашивать, только пересчитывать в момент теста.
- Оговорка к «С»: документы **создаются заранее** с датой поставки (на 18.08 вечером
  уже лежали 247 строк с датой 19.08; сейчас 68 проведённых документов датированы
  25.08 и 28.08) — значит, могут и датироваться назад. За сутки наблюдения закрытые дни
  не менялись (17.08: 176 строк / 693 688,38 и вчера вечером, и сегодня), но правило
  одно: **эталон пересчитывается при каждом прогоне**, числа из этого файла — не эталон.

## A4. Календарь: честные нули

За 12 месяцев в базе **ни одной продажи в субботу и воскресенье** (дни с продажами:
только Mon–Fri). Отсюда зависящие от дня недели ожидания — и они следуют из SQL, а не
из календаря в коде:

| Прогон в | «вчера» | «позавчера» | «эта неделя» |
|---|---|---|---|
| понедельник | вс → **0** | сб → **0** | только сегодня |
| вторник | пн | вс → **0** | пн + сегодня |
| ср–пт | обычный день | обычный день | с понедельника |
| сб, вс | пт / сб → **0** | чт / пт | неделя целиком, сегодня 0 |

Ноль в эталоне = ожидание «честный ноль, не выдумка и не подмена дня» (например,
в понедельник на «вчера» нельзя молча выдать пятницу; можно сказать «в воскресенье
продаж не было, в пятницу — N»). Праздники Молдовы (27.08, 31.08, 25.12, 1.01, 7–8.01,
8.03, 1.05, 9.05, Пасха) дадут 0 так же — правило то же. 1-го числа месяца «этот месяц»
= только сегодня, «прошлый месяц» = только что закрытый.

## A5. Источник продаж и ловушки данных

**Регистр накопления `accumulationregister_реализациятмц`**, поле `Всего` (леи, с НДС:
ровно ×1,2 к `СуммаБезНДС`), дата `Period`, накладная `Recorder`. Корпус: `src_table =
'accumulationregister_реализациятмц'`, `nums['Всего']`, `doc_date`.

1. **Не считать по шапкам документов.** (а) Таблица документов развёрнута по строкам:
   71 429 строк = 8 266 документов. (б) **Валюта**: в августе 9 документов в EUR —
   в шапке `Всего` евро, в регистре леи по курсу (док 4190: 3 174,14 EUR ↔ 63 641,51
   леев, курс 20,05). Сумма шапок за 19.08 даёт 375 521,31 вместо 479 710,42.
2. **Возвраты в том же регистре** (`Recorder_Type = …Document_ВозвратТМЦОтПокупателя`,
   `Всего` < 0). Июль: отгружено 2 798 536,20, возвраты −31 085,22, **чистыми
   2 767 450,98**. Корпус бота суммирует всё → канон = чистыми; «отгружено» принимать,
   если бот так и сказал. За 2026 год возвраты были в каждом месяце (от −908 до −66 104),
   так что для любого прошлого месяца есть два числа.
3. **Будущие даты.** 68 проведённых документов на 25.08 (35) и 28.08 (33), 370 795,98.
   Верхняя граница `today + 1 day` обязательна: без неё «этот месяц» 3 677 021 вместо
   3 306 225,01. Когда эти даты наступят — станут обычными днями.
4. **Регистр за всё время — четыре типа регистраторов**: `РеализацияТМЦ` (основной),
   `ВозвратТМЦОтПокупателя`, `ВыручкаОтРеализацииТМЦФизЛицо` (розница 01.2023–01.2024,
   контрагент — нулевой GUID), `РеализацияТМЦЭкспорт` (09.2024–09.2025). На периоды
   2026 года влияют первые два; на «за всё время» — все.
5. **Счёт справочников** — без папок (`IsFolder`) и без помеченных на удаление
   (`DeletionMark`); в корпусе это `flags['IsFolder']`, `flags['DeletionMark']`.
6. **Имена** — румынские латиницей: `Maner` ручка, `Balama` петля, `Broasca` замок,
   `Capac` заглушка, `Piesa inchidere` запорная планка. В корпусе `refs_map['ТМЦ']` и
   `refs_map['Контрагент']` — строка «Имя / код / адрес»; сравнивать по имени-префиксу.
7. **Ничьи реальны**: за 18.08 по штукам после лидера (115) — пять позиций по 106.
   Ответ «топ-3» обязан либо назвать ничью, либо принять любые две из пяти.
8. **Остатков нет** — проверено, не предположено: регистров с признаком прихода/расхода
   четыре и все не про товар; в бухгалтерских проводках витрины нет субконто; последняя
   инвентаризация 13.08.2025. Любое «на складе N штук» — выдумка.

## B7. Неоднозначные — встречный вопрос

«как у нас дела» → период и мера; «покажи по механизмам» → продажи или остатки, период
(и «механизм» = `mecanism`); «сравни с прошлым разом» → с каким периодом. Эталон —
`clarify`; число без уточнения — угадывание. (Допустимо: «за эту неделю N, уточните,
если имели в виду другое» — ответ с явно названным допущением.)
