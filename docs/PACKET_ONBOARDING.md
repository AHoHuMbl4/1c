# Онбординг новой базы (нового бизнеса) на пакетный канал

Частый процесс: «подключить очередного клиента». Принцип: **одна база = один
комплект = один слот приёмника**. Комплект ничего не знает о конфигурации базы —
структуру сервер узнаёт из первого пакета `kind=meta` (универсальность, TARGET).

Действующие лица: рабочая сессия (claudedev) делает всё, кроме одноразовой
установки юнита; root-шаги спрятаны в юнит `1c-packet-onboard@<base>` (polkit).

## Одноразовая подготовка (владелец, один раз на сервер)

```
sudo install -m 644 /srv/1c/ubuntu/packet/systemd/1c-packet-onboard@.service /etc/systemd/system/
sudo systemctl daemon-reload
```

## Выпуск новой базы (сессия, одна команда)

```
bash /srv/1c/work/packet/onboard-base.sh <base_id>
```

`base_id` — метка слота `[a-z0-9_-]`. 🔴 Называть так, чтобы **клиент узнал свою
базу** («ромашка-ут», не «ut»): установщик показывает метку человеку в подсказке
«выбрана ли та база, для которой выдан комплект». Прогон 08.08: метка «ut» не
совпала ни с одним именем базы на стенде — отсюда установка чужой базы в чужой
слот (контур одной базы + данные другой = 404 каждой сущности).

Скрипт сам, по порядку:

1. **Комплект** — `ubuntu/packet/packet_kit.py <base>`: токен Bearer, age identity,
   клиентский сертификат mTLS (подпись нашего CA), `packet-setup.json` →
   `work/packet/kit/<base>/`. Повторный прогон = ротация токена и сертификата,
   identity сохраняется (контракт §3) — это же механизм отзыва.
2. **Слот приёмника** — `systemctl start 1c-packet-onboard@<base>` →
   `work/packet/onboard-base-root.sh` под root: identity в `/etc/1c-packet-age-<base>.key`,
   **merge** записи в `/etc/1c-packet-bases.json` (не overwrite: соседние базы не
   теряются), каталог `/var/lib/serenedb/packet-meta/<base>`. Рестарт приёмника
   НЕ нужен — `packet_server` перечитывает файл баз по mtime.
3. **Проверка** — mTLS `GET /health` через релей сертификатом новой базы.
4. **Дистрибутив** — `work/packet/dist/<base>/`: `1c-ai.exe` (общий бинарь),
   `packet-setup.json`, `client.pfx`, `ПРОЧТИМЕНЯ.txt` + zip.
5. **S3** — `installers/<base>/1c-ai-<base>.zip` (public-read), печатает ссылку
   для клиента.

## Дальше (уже не этот скрипт)

1. Клиент запускает `1c-ai.exe` из zip — установка IIS/OData + агент (см. ТЗ
   `work/installer-exe/AGENT_TZ.md`). Единственный ручной шаг клиента —
   пользователь-читатель в 1С; 🔴 в карточке обязательна галка **«Вход в
   приложение разрешён»** + «Записать и закрыть» (замер 08.08: без галки запись
   есть только в справочнике, пользователя ИБ нет — канал не поднимается).
2. Smoke `kind=meta` кладёт снимок `$metadata` в `packet-meta/<base>/`.
3. Строится витрина: `work/pipeline/build.sh` с
   `ETL_ODATA_BASE=/var/lib/serenedb/packet-meta/<base>` (контракт §9).
4. Контур агента: `packet_config <base>` (config_version растёт, агент забирает
   список сущностей следующим тактом, контракт §10).
5. Первая ПОЛНАЯ выгрузка — сама, демоном агента.

## Перевыпуск/отзыв

- Ротация: повторный `onboard-base.sh <base>` — новые токен/сертификат, старый
  комплект у клиента перестаёт работать после замены (выдать новый zip).
- Отзыв: убрать запись базы из `/etc/1c-packet-bases.json` (root) — приёмник
  перечитает файл сам.

## Ловушки (замеры, не рассуждения)

- **Один комплект на две базы нельзя**: данные смешаются в одном слоте; контур
  строится по $metadata первой приславшей базы, у второй каждая сущность 404
  (прогон 08.08, buh_test в слоте ut).
- Приёмник перечитывает `bases.json` по mtime — merge делать ТОЛЬКО атомарно
  (temp+rename, так делает onboard-base-root.sh); полупустой файл приёмник
  игнорирует (fail-stale), но база в нём отсутствующая = 401 для её пакетов.
- Новый клиентский сертификат первые ~2 минуты может отвергаться релеем, если
  его часы отстают (замечено 07.08) — не дефект комплекта.
- Smoke `kind=meta` перезаписывает снимок `$metadata` слота: если в слот `ut`
  случайно поставили другую базу, её smoke подменил снимок (замер 08.08,
  buh_test→ut). Лечится само первым meta правильной базы, но до него
  `packet_config <base>` запускать нельзя — контур посчитается по чужому снимку.
