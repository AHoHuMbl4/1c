# К4-2: уточнение вместо честного «данных нет»

Разбор класса провалов из живого замера неоднозначных вопросов на okna
([`ACCEPTANCE_AMBIGUOUS.md`](ACCEPTANCE_AMBIGUOUS.md) §8, 27.08, коммит `96b51ab`).
Итог прогона: **5/18**. Этот документ — только класс
«уточнение вместо `no_data`» (**4** случая). Код `serene_ask.py` здесь
**не меняется** (параллель с оркестратором); ниже — факты из кода и проект патча.

Контракт: [`TARGET.md`](../TARGET.md) п. **21** — порядок
«ответ → уточняющий вопрос → отказ». Уточнение уместно, только когда ответ
существует хотя бы в одном прочтении. Если данных нет ни в одном — сказать это
прямо, словами человека, и назвать, чего именно нет (п. 12/18).

## 2. Развилка clarify против no_data в коде

Файл: `ubuntu/serenedb/serene_ask.py`, функция **`answer`** (с строки **11970**).
Читался код возвратов, не имена в комментариях.

### 2.1. Ранний `no_data` по значениям из вопроса

Фрагмент `answer`, строки **12125–12135** (после `probe` / `matched_group_count`):

```python
n_groups = len(intent.get("terms") or [])
matched_groups = matched_group_count(kinds)
if n_groups > 0 and matched_groups < n_groups:
    missing = n_groups - matched_groups
    diag["unmatched_terms"] = missing
    if matched_groups == 0:
        return {"partial": cut or None, "kind": "no_data", "sources": [],
                "text": NO_DATA_TEXT or refuse_text(question),
                "diag": _diag_pack(diag, sec=round(time.time() - t0, 2),
                             reason="значения из вопроса не найдены в данных")}
```

Срабатывает **только** когда `matched_groups == 0`. Если часть групп нашлась,
а именованное значение (например «ПАНГЕЯ») — нет, путь **продолжается** с
`diag["unmatched_terms"]`, без отказа. Счётчик — `matched_group_count` (**2746**).

### 2.2. Ранний `no_data` «кандидатов нет» — после запасного наполнения

Строки **12278–12282**:

```python
if not by and not extra:
    by = tables_of("", preds)
if not by and not extra:
    return {"partial": cut or None, "kind": "no_data", ...}
```

Пока `tables_of("", preds)` (часто период / пустой match) отдаёт хоть какие-то
таблицы, отказ **не** наступает. Дальше круг кандидатов живёт за счёт этого
наполнения и поверхностей смысла/синонимов.

### 2.3. Место, откуда уходит «мусорный» clarify замера

После выбора сущности и величины, при нескольких подходящих мерах
(строки **14268–14308**):

```python
if (measure_alts and not measure_already_proven(trusted, resolved, measure_pick)
        and not diag.get("sales_measure_canon")
        and not _rank_sales):
    diag["measure_ambiguous"] = measure_alts
    ...
    opts = [{"src": src, "measure": m, "label": _caps[m], ...}
            for m in measure_alts]
    return {"partial": cut or None, "kind": "clarify",
            "text": clarify_say(question, opts, diag) or ...,
            "options": opts, "sources": [src],
            "diag": _diag_pack(diag, sec=round(time.time() - t0, 2))}
```

Именно этот возврат совпадает с живым следом №6/14/17/18: опции — **меры**
уже выбранного `src` (валюта / НДС / итого), числа вроде «8» / «189043» —
живые счёты по этой сущности, не про предмет вопроса.

Другие возвраты `kind=clarify` в том же `answer` (ось focus **12857**,
fork C **13620**, арбитр **13737**, axis grain **14398**, `ask_back` **15014**)
для этого класса замера вторичны: на экране не «какой склад / какая фирма»,
а перечень мер.

## 3. Ключевой вопрос: бот уже знает, что данных нет?

**Ответ: в момент решения «уточнить» — нет, не знает (про предмет вопроса).
Знает другое: у уже выбранного `src` несколько живых мер.**

Подтверждение по данным, посчитанным к точке **14266**:

| Уже есть | Откуда | Что это значит |
|---|---|---|
| `intent` (kind / terms / want / measure) | разбор в начале `answer` | для №17/18 terms часто пусты → ветка **12131** молчит |
| `kinds` / `matched_groups` | `probe` + `matched_group_count` | отказ только при **нуле** найденных групп; частичный промах имени только в `diag.unmatched_terms` |
| `by` / `extra` / `cands` | индекс, смысл, синонимы, запасной `tables_of("", preds)` | круг **непустой** даже без предмета («анкеты», «президент») |
| `picked` / `src` | `pick_entity` / focus / каноны | выбран **чужой** live-источник (часто курсы валют) |
| `measure_alts`, `_all_tot` | `totals_of` / `measures_of(src)` | у чужого `src` меры живые → срабатывает clarify |

К этой точке **нет** проверки вида «существует ли хотя бы одно прочтение,
отвечающее на *этот* вопрос». Есть проверка «у *этой* сущности неоднозначна
мера». Отсюда вид починки: **не перестановка двух равноправных веток
«уже знаем no_data ↔ clarify»**, а **дешёвая проба существования / поддержки
предмета до measure-clarify** (и ужесточение раннего отказа по terms).

Исключение по соседним строкам замера: №4/5/13 — ранний или последующий
`no_data` уже сработал; там отсутствие значения/номенклатуры как раз зафиксировано.

## 4. Проект патча (текст; `serene_ask.py` в этом коммите не менять)

### 4.1. Цель

Перед любым `kind=clarify` по **мерам** (возврат ~14304) и, узко, перед
уточнением сущности из «шумного» пула: если **ни одно прочтение не даёт
ответ на заданный предмет** — `no_data` + `refuse_text` (назвать, чего нет),
без опций валюты/НДС.

### 4.2. Место A — ужесточить ранний отказ по terms

**Где:** сразу после `matched_group_count`, блок **12126–12135**.

**Что:** при `n_groups > 0` и `matched_groups < n_groups` возвращать `no_data`
не только когда `matched_groups == 0`, а когда **есть хотя бы одна**
ненайденная группа значений (сейчас это только пишется в
`diag["unmatched_terms"]`).

**Почему:** groups — AND между понятиями (`probe` / `match_expr`). Имя
«ПАНГЕЯ» без совпадения при любом сигнале в других слотах не открывает путь
к чужому `src`. Это закрывает класс №6 в той конфигурации intent, где имя
попало в `terms`, а что-то ещё дало `matched_groups > 0`.

**Почему верные 5 строк прогона остаются целы:**

| № | Почему цел |
|---:|---|
| 4, 5 | Уже `no_data` при нуле совпадений имени — поведение то же или строже в ту же сторону |
| 9 | `terms` пусты / предмет не именован значением — ветка terms не срабатывает; clarify про «о чём речь» остаётся |
| 13 | Уже `no_data` (нет номенклатуры) |
| 15 | Имя/год находятся; `matched_groups` полный |

Риск: группа-значение, которую резолвер мог бы поймать позже иным путём.
Сейчас резолвер уже внутри `probe` до `matched_group_count` — повторного
окна нет. Замок: кейс «Питер→Санкт-Петербург» из комментария у **2731**
остаётся `matched` (покрытие `test_step2` / резолвер).

### 4.3. Место B — страж перед measure-clarify

**Где:** непосредственно **перед** условием `if (measure_alts and …)` (~14268),
после того как известны `src`, `intent`, `diag`, `by` / смысл.

**Что (дешёвая проба, без второго полного круга арбитра):**

Считать `src` **поддерживающим вопрос**, если выполнено хотя бы одно:

1. есть непустые `terms` и все группы matched (после места A — иначе сюда не дойдём с дырой в terms);
2. `src` входит в буквальный `by` или в `diag["by_meaning"]` / synonym hit по **роду** (`kind`), не только по периоду;
3. сработал канон, который сам указывает на предмет учёта (`sales_canon_locked`, `catalog_count_locked`, stock-balance capable).

Иначе (типичный след: `src` из запасного `tables_of("", preds)` / шума смысла,
`kind` не покрыт алиасом, terms пусты или тема вне учёта) — **не** строить
`measure_alts` clarify, а вернуть:

```text
kind=no_data
text=NO_DATA_TEXT or refuse_text(question)
diag.reason=subject_unsupported_before_measure_clarify
```

**Почему закрывает №14/17/18:** к ~14268 у них как раз «чужой live-src + measure_alts»;
проба режет clarify до опций. №6, если проскочил место A (имя не в terms) —
тот же страж: без поддержки имени/алиаса на `src` → `no_data`.

**Почему верные 5 и полезный clarify остаются:**

| Случай | Почему clarify/ответ жив |
|---|---|
| №9 «На какую сумму?» | Это не measure_alts валюты; либо другой путь clarify, либо канон/род «сумма» с поддержкой. Страж B смотрит только ветку `measure_alts` без proven measure |
| Продажи / остатки с живым родом | `by_meaning` / alias / sales_canon → support=true |
| Честный measure-clarify («рубли или штуки») на **верной** сущности | `src` в `by` или meaning по kind → support=true; опции мер остаются |
| №15 выручка 2022 | Идёт в answer/figures, не в эту ветку |

Без правок промта: ветвление кодом + `refuse_text` как сейчас.

### 4.4. Место C (второй заход) — запасное наполнение кандидатов

**Где:** **12278** `by = tables_of("", preds)`.

**Идея:** не наполнять весь периодный пул, когда нет ни буквального, ни
смыслового сигнала по роду/значениям и вопрос не «только период + известный
род продаж». Иначе тема вне учёта всегда находит «курсы валют».

Включать после замка на месте B: иначе легко задеть date-only вопросы,
которые сегодня опираются на смысл+kind. В К4-2 достаточно A+B.

### 4.5. Порядок внедрения

1. Замок (§5) — красный на фикстурах до патча.
2. Место A → прогон замка + `test_step2`.
3. Место B → тот же замок + дымовой `/ask` на okna по четырём вопросам + регрессия №9/13/15.
4. Выкат только после зелёного замка; `serene_ask.py` меняет отдельный поток.

## 9. Снайпер: порог длины убран, источник починен (патч 3.4, 27.08)

Снайпер коммита справедливо остановил первую редакцию: слабый резолв
ловился порогом `len(rval) < max(3, len(orig)//2)` в пути правильности
(`terms_substantively_matched`) — числовая пара, подобранная под кейс
«ПАНГЕЯ»→«П». Источник мусора нашёлся в самой гардe резолвера:
