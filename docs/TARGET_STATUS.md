# Статус по контракту: что на какой стадии

Спутник [`TARGET.md`](../TARGET.md). Тот говорит, **чем продукт обязан быть**; этот —
**где мы по каждому пункту сейчас**. Менять `TARGET.md` нельзя; этот файл живой.

**Обновлено: 2026-07-31.** Правило стадий — как в п. 11 контракта: «готово»
ставится только по замеру на живых данных, не по рассуждению.

Стадии: 🟢 **готово** (проверено замером) · 🟡 **частично** (работает, но не по полному
критерию) · 🔴 **не начато** · ⚪ **по контракту — последним**.

## Что мешает закрыть жёлтые и красные

Почти всё оставшееся упирается во **внешнее**, а не в нашу работу:

- **п. 9** — вторая конфигурация ПРОЙДЕНА (УТ 11.4.9, 28.07): работает без правок кода,
  найдено и починено 5 дефектов, невидимых на одной базе. Остался **другой язык** —
  англоязычную конфигурацию 1С достать сложно.
- **п. 15** (приёмка из базы клиента) — набор вопросов должен строиться из самой базы;
  по слову владельца делаем в конце.
- **п. 16** (модели внутрь контура) — **решение владельца** о периметре, не техника.
- **п. 3/10** (любые ошибки запрещены) упираются в **п. 15**: чтобы доказать «без
  ошибок», нужен большой набор из самой базы и прогон независимыми агентами.
- **п. 14, 1, 11** — инсталлятор и финальная приёмка, по контракту делаются последними.

Из того, что двигается **без внешнего**, крупного не осталось: п. 13, 17, 18, 21 закрыты
в эту сессию. Дальше нужна вторая база или слово владельца по 15/16.
