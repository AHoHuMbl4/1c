## §1. Свежесть до конца (фронт А — в работе сейчас)

- **А1.** Corpus-ф2: частичная потеря 3 регистров (23–29 строк каждый) —
  диагноз по каждому (orphan-строки vs дефект анти-соединения), починка,
  такт зелёный ЦЕЛИКОМ (все шаги 0–8). Сторож не ослаблять.
- **А2.** Контроль после зелёного: `build_state` свежая дата, `/health`
  показывает свежесть, **замер лага** «изменение в 1С → ответ бота» живой
  пробой (п. 17, число — владельцу).
- **А3.** Wiki-выгрузка едет тактом: после зелёного такта `wiki_pages` растёт,
  `entities/` в хранилище бота свежей датой (было 254 / заморожено 24.08).
- **А4.** Самодиагностика протухания: если такт красный дольше порога — это
  ВИДНО клиенту в каждом ответе (приписка старения). Проверить, что механизм
  реально доходит до ответа; если нет — короткая правка. Уверенный ответ по
  протухшим данным — запрещён (п. 18).

## §2. Паспорт-слой wiki → выбор сущности (фронт Б)

Три коротких шага, данные уже есть:

- **Б1. Карточка сущности.** Короткая выжимка собирается В БАЗЕ (SQL такта,
  штатно, п. 20): имя + описание из `wiki_pages` + оси и меры из метаданных
  (`search_refcols` — уже считает К9). 1–2 предложения + структурные поля.
  Эмбеддинг — `ai_embed` (штатный). Непокрытые wiki сущности (819−254) —
  карточка из структуры без описания; до наполнения wiki такие кандидаты
  честно слабее, а не скрыты.
- **Б2. Кандидаты по карточкам.** Вопрос → эмбеддинг → штатный kNN по
  карточкам → топ-5. Объём в модель фиксирован (5 карточек), от размера базы
  не зависит (п. 19 цел).
- **Б3. Выбор с исходом «ни один».** Модель выбирает из карточек СРАВНИМОЙ
  формы; разделяемость топ-2 — числом; близко → переспрос (исход B), валидация
  лидера осями (К9). Исход «ни один не подходит» обязан существовать — иначе
  получим «лучшего из плохих» (сегодняшние уверенно неверные).

Приёмка фронтa Б: склад-класс обе формулировки → живой эталон; клиентский
gold-набор (67); вторая база klient-1; замки на каждый шаг.

**Контрольные вопросы (top-5, cosine distance):**

| Вопрос | Верная сущность (ожидание) | Место в top-5 |
|---|---|---|
| сколько на складе позиций всего | регистр остатков / складская операция | **>5** — top line-items «номенклатура», не balance |

на нерелевантных вопросах. Следующий шаг Б3 — выбор модели с исходом «ни один».
