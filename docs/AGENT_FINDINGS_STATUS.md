## ⚠️ Регресс, найденный 27.07: починка была и потерялась

`serene_search_build.py:185-196` разбирает вывод `psql` через `--csv` + `csv.reader`,
и в его докстроке дословно записано, зачем: «в комментарии или адресе доставки бывает
перевод строки — при построчном разборе колонки съезжают, ключом становится обрывок
текста, **а короткая строка роняет сервис**».

`serene_ask.py:119` написан позже и делает **ровно это**:
`[l.split("\x1f") for l in p.stdout.split("\n") if l != ""]`.

Как потерялось: когда чинили стену argv (1713 сущностей → `OSError`), перешли на подачу
SQL через stdin `-f -` и вместе с ней взяли `-F "\x1f"` вместо `--csv`. Две починки не
сложились — вторая затёрла первую.

**[замер] 27.07, воспроизведено дословно тем же кодом:**

| | |
|---|---|
| строк корпуса с переводом строки внутри `doc` | **3 991 из 97 965 (4,07 %)** |
| строк вернула база | 40 |
| строк получил разбор | **799** |
| из них битых (меньше 6 полей) | **759** |
| обращение к полю `r[5]` | **`IndexError: list index out of range`** |

Лечение — сложить обе починки, они не противоречат друг другу:
`["psql", DSN, "-tA", "--csv", "-f", "-"]` и `csv.reader`, как в сборщике.
