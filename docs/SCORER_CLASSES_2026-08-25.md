## 4. Классы провалов (одинаково для обоих контуров)

Девять FAIL разложены в **6 классов**. Класс — общая причина, не пересказ вопроса.
Цитаты ответа — с боевого `/ask` (диагностический повтор после скорера; `kind` и
смысл совпали с прогоном). Лечение **не делалось**.

### Сводка классов

| Класс | N | Виден клиенту | Слой лечения |
|---|---:|---|---|
| **K1. Rank: не та мера / не тот src** | **2** | да (другое число или другой лидер) | детектор |
| **K2. Rank: axis-clarify по полям меры вместо top-N** | **1** | да (уточнение вместо ответа) | детектор |

Самый крупный по числу вопросов — **ничья K1 / K5 / K6 (по 2)**. По смыслу «что
чинить одним заходом» крупнейший **кластер** — **rank-путь (K1+K2+K3 = 4 вопроса)**.

---

### K1. Rank: не та мера / не тот src (2) — ✅ закрыт 25.08

**Суть:** лидер/ось «товар» или «клиент» узнаны, но агрегат идёт по другой мере или
другому `src_table`, чем эталон корпуса.

1. **«какого товара больше всего продали за всё время?»**  
   Эталон: ТМЦ + **Количество** → `356715 Piesa inchidere toc HG VEKA…`.  
   Ответ: `«Balama Rollenband Dr.Hahn…»: 3 271 771.26 лей · … · Всего · Номенклатура · rank`.  
   Диагноз: rank по **Всего (деньги)**, не по количеству.

2. **«какой клиент больше всех купил в этом месяце?»**  
   Эталон (регистр накопления): `DYNAMIC SELLING…` / **1 537 150,47**.  
   Ответ: `«DYNAMIC SELLING GROUP SRL … ap. 89»: 1 543 357.32 лей · … · Реализация ТМЦ (документ) · Всего`.  
   Диагноз: имя лидера то же семейство, число с **документа**, не с регистра эталона;
   скорер — `число не сошлось`.

---

### K2. Rank: axis-clarify по полям меры вместо top-N (1) — ✅ закрыт 25.08

**«дай топ-3 клиента по деньгам за этот месяц»**  
Ответ `kind=clarify`: «итого? / курс? / НДС? / оплата карточкой? / долг клиента?» по
`document_реализациятмц`, без оси Контрагент и без top-3.  
Клиенту виден лишний вопрос вместо ранга.

---

### K3. Период понят иначе (1) — ✅ закрыт 25.08

**«кто из клиентов молодец за прошлую неделю, три лучших»**  
Эталон: top-3 за **прошлую** календарную неделю (лидер `DYNAMIC SELLING…`).  
Ответ: один клиент `VEFASISTEM-COMPANIE…` за окно **`2026-08-24..2026-08-25`** (не
прошлая неделя; не top-3). Скорер: `имя не найдено`.

---

### K4. Compare: форма не собрана (1)

**«эта неделя лучше прошлой или хуже?»**  
Эталон: diff сумм продаж двух окон ≈ **−792 128,74**.  
Ответ: `«Основной договор / 0000000001»: 728 · … · Договоры · rank` — count/rank по
договору, не сравнение двух сумм. Число эталона в тексте нет.

---

### K5. Ответ в atoms есть, наружу отказ (2) — ✅ закрыт 25.08 (atom наружу; K5b gold — хвост compare)

Молчаливая потеря: число уже посчитано в атомах/`proof_status=computed`, клиент
получает clarify/figures без этого числа (п. 13 TARGET).

1. **«сколько документов реализации за декабрь 2025?»**  
   В `ask_journal` за прогон: atom `count exact_value=307` по «Реализация ТМЦ»,
   `outcome=clarify`. Текст клиенту — clarify по «партиям бланков» / «наборам
   фурнитуры». Эталон **307**.

2. **«в этом месяце продали больше, чем в прошлом?»**  
   Журнал: atom `compare exact_value=1755883.45`, `outcome=figures`. Текст:
   «Проверенный ответ на этот вопрос сейчас дать невозможно.»  
   Эталон diff MTD ≈ **1 049 991,33** (даже при совпадении формы число сейчас другое —
   отдельный хвост внутри compare; наружу всё равно отказ).

---

### K6. Не та сущность (2)

1. **«сколько позиций совсем не продаётся в этом месяце?»**  
   Эталон: `|номенклатура| − |DISTINCT ТМЦ в продажах месяца|` = **1891**.  
   Ответ: clarify на `accumulationregister_книгапродаж` («Книга продаж — итоги
   исходящего НДС…»). Формула «не продаётся» не собрана.

2. **«сколько клиентов реально покупают?»**  
   Эталон: DISTINCT контрагент в продажах за 12 мес = **141**.  
   Ответ: рассуждение по **карточкам** `catalog_контрагенты` («Всего в выборке 353…»),
   `kind=clarify`, без count distinct по продажам.
