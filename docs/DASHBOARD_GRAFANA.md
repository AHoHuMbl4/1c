# Дашборды в веб-интерфейсе: Grafana

Задача (владелец, 18.08): в веб-интерфейсе — отдельное окно с дашбордами.
У ответа в чате — кнопка «добавить в дашборд»; у каждого графика на странице —
настройка визуала (как показывать) и периодичности обновления данных.

Решение владельца 18.08: **Grafana**. Этот документ — итог пробного стенда
и целевая архитектура.

## §1. Пробный стенд 18.08 — что доказано замером

Стенд: `work/grafana-stand/setup-grafana-stand.sh` (один скрипт, идемпотентен,
два прогона подряд зелёные). Grafana OSS **13.2.0**, userspace, без systemd,
`127.0.0.1:3001`, живёт в `/dev/shm` (см. ловушку про квоту).

| Шаг | Результат |
|---|---|
| Запуск из tarball без root | работает, `grafana server --homepath … --config …` |
| Datasource SereneDB (`postgres`, `127.0.0.1:7890`, роль `serene_ro`) | создан через API, запросы ходят |
| Запрос по живой витрине okna (`accumulationregister_реализацияуслуг_recordtype`) | 6 точек «сумма по дням» через `/api/ds/query` |
| Создание дашборда с панелью | `POST /api/dashboards/db` → 200, uid `stand-from-chat` |
| Добавление панели в СУЩЕСТВУЮЩИЙ дашборд (модель кнопки «добавить») | GET → append → POST → version 2, 2 панели |
| Смена визуала | это поле `panel.type` (`timeseries`/`stat`/…), меняется тем же API |
| Встраивание iframe | `allow_embedding=true`; `/d-solo/<uid>?panelId=N` — одиночная панель |
| Сквозной вход: JWT в заголовке `X-JWT-Assertion` (RS256, свой ключ) | `auto_sign_up` создал пользователя, `/api/user` отдаёт его (`authLabels: ["JWT"]`), дашборд 200 |
| Полная цепочка: браузер несёт только cookie, прокси подставляет заголовок | по cookie `gf_jwt` → `/api/user` тот же логин, дашборд 200; без cookie — 401 (прокси-заменитель на python, Caddy-снипет в §3) |
| `url_login` (`?auth_token=` в ссылке) | логинит **только первый запрос**: сессионная кука не ставится, SPA уходит на `/login` (см. ловушку 6) |

### Ловушки (все пойманы замером, не чтением)

1. 🔴 **SereneDB отдаёт все колонки как VARCHAR.** `date_trunc('day', "Period")`
   падает: `No function matches … date_trunc(STRING_LITERAL, VARCHAR)`;
   `sum("Сумма")` — `sum(VARCHAR)`. Лечится явными кастами:
   `"Period"::timestamp`, `"Сумма"::DECIMAL`. **Генератор SQL панелей обязан
   ставить касты всегда** — типы известны на стороне ask (классификация
   колонок корпуса), отдельной разведки не нужно.
   Доки: `sql/functions/timestamp#date_trunc`, `sql/data_types/typecasting`.
2. **API мутаций — по uid, не по числовому id**: `PUT /api/datasources/<id>`
   отдаёт 404, рабочий путь `/api/datasources/uid/<uid>` (Grafana 12+).
   `GET /api/datasources/name/<name>` тоже убран — искать в списке.
3. **`/api/health` отвечает раньше, чем монтируются остальные маршруты**:
   `GET /api/datasources` сразу после старта — 404 пару секунд. Ждать ретраем.
4. **`X-Frame-Options: deny` по умолчанию** — без `allow_embedding=true`
   панель в iframe не вставить.
5. **Квота /srv/1c ~700 МБ свободно** [замер: dd 700M ОК, 1000M EDQUOT],
   распакованная Grafana — 1,3 ГБ. Стенд поэтому в `/dev/shm`; для прода
   на серверах квоты нет, но в репозиторий бинарь не кладём.
6. 🔴 **Сквозной вход — только через заголовок на каждый запрос, не через
   `url_login`.** `?auth_token=` аутентифицирует первый запрос, но
   сессионной куки не ставит — SPA после загрузки уходит на `/login`
   [замер 18.08]. Поэтому вход держит прокси: браузер несёт cookie, Caddy
   копирует её в заголовок `X-JWT-Assertion`. И **`header_name` обязан
   быть задан явно**: с пустым `header_name` JWT-клиент не включается
   вовсе и `url_login` молча не работает [замер 18.08].

## §2. Целевая архитектура

```
чат Open WebUI ──Action «в дашборд»──▶ адаптер ──▶ Grafana API ──▶ SereneDB (serene_ro)
     ▲                                   │              ▲
     └────── ссылка/iframe ◀──── страница дашбордов ◀───┘
```

Вход на страницу дашбордов (решение владельца 18.08: **та же авторизация,
что в чате, без второго логина**):

```
браузер ──1. клик «Дашборды»──▶ адаптер /dash/enter
                                 │ 2. проверяет сессию OWUI (её cookie/token),
                                 │    mint JWT (RS256, TTL ~минуты), sub/email = пользователь чата
                                 │ 3. Set-Cookie gf_jwt + 302 на /dash/d/<uid>
браузер ──cookie gf_jwt──▶ Caddy (тот же домен, что OWUI)
                                 │ header_up X-JWT-Assertion = cookie gf_jwt
                                 ▼
                            Grafana [auth.jwt] ── вход без формы, тот же логин
```

Снипет Caddy (⚠️ синтаксис на стенде не замерян — caddy локально нет,
проверить на фронте; семантика цепочки замерена прокси-заменителем, §1):

```
handle_path /dash/* {
    reverse_proxy 127.0.0.1:3001 {
        header_up X-JWT-Assertion {http.request.cookie.gf_jwt}
    }
}
```

Ключи: пара RSA, публичный — в `[auth.jwt] key_file` у Grafana, приватный —
у адаптера (`/etc`, 640). Роль в Grafana — claim `role` (Viewer/Editor) или
умолчание Viewer. Гость без cookie получает 401 [замер §1].

- **Кнопка** — штатный механизм Open WebUI *Action functions* (кнопка под
  сообщением, вызов нашего HTTP-обработчика). Отдельных кастомных страниц
  в OWUI нет (open-webui/discussions#7603) — страница дашбордов живёт рядом.
- **Адаптер** (новый маленький сервис или расширение ask): принимает от
  кнопки спецификацию ответа и делает GET→append→POST панели в Grafana.
  Это и есть «добавить в дашборд» — доказано стендом.
- **SQL панели строится детерминированно** из посчитанного ответа: у
  `serene_ask` есть `agg.scope` (источник, условие, период) и величина —
  из них собирается `SELECT … GROUP BY` с кастами (ловушка 1). Никакого
  NL→SQL для дашбордов: числа считает база, модель запрос не пишет
  (п. 19 TARGET.md; схема в модель не уходит никогда).
- **Периодичность обновления**: в Grafana автообновление — на уровень
  ДАШБОРДА (поле `refresh`), у панелей только min interval
  (grafana/discussions#36965 — запросу много лет, не сделано).
  Варианты: **(а)** у каждого своего дашборда свой интервал — приемлемо,
  если «страница графиков» = один дашборд с одним интервалом;
  **(б)** своя тонкая страница, которая встраивает панели через
  `/d-solo?panelId=N` и перезагружает каждый iframe по СВОЕМУ таймеру —
  per-chart периодичность при Grafana как движке рендера. Решение — за
  первым живым контуром, начать с (а).
