У ответа в чате — кнопка «добавить в дашборд»; у каждого графика на странице —
настройка визуала (как показывать) и периодичности обновления данных.

## §1. Пробный стенд 18.08 — что доказано замером

Стенд: `work/grafana-stand/setup-grafana-stand.sh` (один скрипт, идемпотентен,
два прогона подряд зелёные). Grafana OSS **13.2.0**, userspace, без systemd,
`127.0.0.1:3001`, живёт в `/dev/shm` (см. ловушку про квоту).

### Ловушки (все пойманы замером, не чтением)

1. 🔴 **SereneDB отдаёт все колонки как VARCHAR.** `date_trunc('day', "Period")`
   падает: `No function matches … date_trunc(STRING_LITERAL, VARCHAR)`;
   `sum("Сумма")` — `sum(VARCHAR)`. Лечится явными кастами:
   `"Period"::timestamp`, `"Сумма"::DECIMAL`. **Генератор SQL панелей обязан
   ставить касты всегда** — типы известны на стороне ask (классификация
   колонок корпуса), отдельной разведки не нужно.
   Доки: `sql/functions/timestamp#date_trunc`, `sql/data_types/typecasting`.
2. **API мутаций — по uid, не по числовому id**: `PUT /api/datasources/<id>`
   отдаёт 404, рабочий путь `/api/datasources/uid/<uid>` (Grafana 12+).
   `GET /api/datasources/name/<name>` тоже убран — искать в списке.
3. **`/api/health` отвечает раньше, чем монтируются остальные маршруты**:
   `GET /api/datasources` сразу после старта — 404 пару секунд. Ждать ретраем.
4. **`X-Frame-Options: deny` по умолчанию** — без `allow_embedding=true`
   панель в iframe не вставить.
5. **Квота /srv/1c ~700 МБ свободно** [замер: dd 700M ОК, 1000M EDQUOT],
   распакованная Grafana — 1,3 ГБ. Стенд поэтому в `/dev/shm`; для прода
   на серверах квоты нет, но в репозиторий бинарь не кладём.
6. 🔴 **Сквозной вход — только через заголовок на каждый запрос, не через
   `url_login`.** `?auth_token=` аутентифицирует первый запрос, но
   сессионной куки не ставит — SPA после загрузки уходит на `/login`
   [замер 18.08]. Поэтому вход держит прокси: браузер несёт cookie, Caddy
   копирует её в заголовок `X-JWT-Assertion`. И **`header_name` обязан
   быть задан явно**: с пустым `header_name` JWT-клиент не включается
   вовсе и `url_login` молча не работает [замер 18.08].
7. **Голый `pyjwt` не умеет RS256** — `KeyError: 'RS256'` на первом же
   обращении; ставить `pyjwt[crypto]` [замер 18.08, выкат okna].
8. 🔴 **Grafana 13 с `serve_from_sub_path=true` ждёт подпуть В запросе**:
   со срезанным префиксом (Caddy `handle_path`) отвечает 301 на себя же —
   петля редиректов. Проксировать надо `handle` БЕЗ срезания
   [замер 18.08, выкат okna].
9. **`information_schema.columns` в SereneDB пуст** (а `\d` падает на
   `pg_partition_ancestors`) — колонки смотреть через `pg_attribute`
   [замер 18.08].
10. **venv OWUI недоступен другому пользователю** (`/home/webui` закрыт,
    `status=203/EXEC Permission denied`) — адаптеру свой venv
    `/opt/1c-grafana/venv` [замер 18.08, выкат okna].
11. 🔴 **Имя базы у postgres-datasource Grafana 13 живёт в `jsonData.database`,
    а не в поле верхнего уровня `database`.** Создание datasource через API с
    одним верхним полем проходит (200, uid выдан), probe `select version()`
    из установщика **тоже проходит** — а панели дают `No data` с ошибкой
    «You do not currently have a default database configured for this data
    source» [замер 19.08, живой okna: `json_data` в базе Grafana —
    `{"postgresVersion":1500,"sslmode":"disable"}`, имени базы нет].
    Итог: **probe установщика не доказывает, что панели заработают** —
    он ходит другим путём. Приёмка выката — открытый дашборд с данными.
12. 🔴 **Grafana 13 держит дашборды в unified storage** (таблица `resource`,
    `resource='dashboards'`, значение — k8s-подобный объект с `spec`), а
    таблица `dashboard` при этом **пуста** [замер 19.08]. Выгрузка дашбордов
    из базы (`grafana/export-dashboards.py`) читает `resource`.
13. **Тип postgres-datasource Grafana 13 отдаёт плагином.** Создаётся он как
    `"type": "postgres"`, а `GET /api/datasources` возвращает
    `grafana-postgresql-datasource` [замер 19.08]. Код, который ищет datasource
    по типу, обязан знать оба имени (`panel_from_scope.PG_TYPES`), иначе
    «в Grafana нет postgres-datasource» на живом инстансе, где он есть.
14. **Битый запрос панели отдаёт HTTP 400 у `/api/ds/query`**, а сообщение
    базы лежит в теле ответа [замер 19.08: панель с несуществующей колонкой
    роняла приёмку исключением вместо находки]. Инструмент обязан читать тело
    и показывать ошибку по панели, а не падать. SereneDB в такой ошибке сама
    перечисляет годные колонки (`Candidate bindings: …`) — это и есть подсказка.

## §2. Целевая архитектура

```
чат Open WebUI ──Action «в дашборд»──▶ адаптер ──▶ Grafana API ──▶ SereneDB (serene_ro)
     ▲                                   │              ▲
     └────── ссылка/iframe ◀──── страница дашбордов ◀───┘
```

Вход на страницу дашбордов (решение владельца 18.08: **та же авторизация,
что в чате, без второго логина**):

```
браузер ──1. клик «Дашборды»──▶ адаптер /dash/enter
                                 │ 2. проверяет сессию OWUI (её cookie/token),
                                 │    mint JWT (RS256, TTL ~минуты), sub/email = пользователь чата
                                 │ 3. Set-Cookie gf_jwt + 302 на /dash/d/<uid>
браузер ──cookie gf_jwt──▶ Caddy (тот же домен, что OWUI)
                                 │ header_up X-JWT-Assertion = cookie gf_jwt
                                 ▼
                            Grafana [auth.jwt] ── вход без формы, тот же логин
```

Снипет Caddy (⚠️ синтаксис на стенде не замерян — caddy локально нет,
проверить на фронте; семантика цепочки замерена прокси-заменителем, §1):

```
handle_path /dash/* {
    reverse_proxy 127.0.0.1:3001 {
        header_up X-JWT-Assertion {http.request.cookie.gf_jwt}
    }
}
```

Ключи: пара RSA, публичный — в `[auth.jwt] key_file` у Grafana, приватный —
у адаптера (`/etc`, 640). Роль в Grafana — claim `role` (Viewer/Editor) или
умолчание Viewer. Гость без cookie получает 401 [замер §1].

- **Кнопка** — штатный механизм Open WebUI *Action functions* (кнопка под
  сообщением, вызов нашего HTTP-обработчика). Отдельных кастомных страниц
  в OWUI нет (open-webui/discussions#7603) — страница дашбордов живёт рядом.

### §2.1. Кнопка «добавить в дашборд»: что сделано и чего не хватает (19.08)

```
кнопка (owui-functions/add_to_dashboard.py)
   │ берёт metadata.ask_scope сообщения, НИЧЕГО не сочиняя
   ▼
POST /dash/add  (dash_adapter.py, сессия чата проверяется у самого OWUI)
   │ panel_from_scope.build_sql — SQL собирается ДЕТЕРМИНИРОВАННО из scope,
   │ касты обязательны; проверка запроса ДО закрепления
   ▼
панель в личном дашборде пользователя  ask-<sha1(id)[:12]> «Панели — <имя>»
```

Готово и замерено 19.08: сборщик (11/11 offline-замков), проверка запроса до
закрепления (битая ось получает отказ с перечнем годных колонок от самой
SereneDB), ручка `/dash/add` на фронте (без сессии чата — 401, чужой путь —
404), живое создание панелей на боевой Grafana (день — 900 строк, разрез по
оси — 1 строка, обе через `/api/ds/query`), уборка самопроверочного дашборда.

🔴 **Не хватает одного — источника спецификации.** `agg.scope` (источник,
условие, величина, ось) живёт в `diag` ответа `serene_ask` и до чата **не
доходит**: `mcp_ask` отдаёт модели текст, а `diag` не читает вовсе — так
задумано, внутренние имена таблиц модели не показываются. Фронт добыть его
сам не может: с фронта открыт только `:18801` (чат), `:8091` закрыт ufw
[замер 19.08].

### §2.2. Стык бэкенда: спецификация счёта наружу — ГОТОВ (19.08, фикс period_col/алиасы панели)

**Выбран путь B (через SereneDB).** Обоснование: путь A (`sha256→scope` через
`:18801`) невозможен без кастомных HTTP-ручек у OpenClaw-плагина (он их не
умеет), а `:8091` закрыт ufw с фронта. Путь B использует уже открытый relay
`:7890` (SereneDB) и существующий datasource Grafana на фронте — ни портов, ни
ufw, ни новых сервисов.

**Как работает:**

```
serene_ask.py (ответ kind=answer/figures с diag["счёт"])
   │ _persist_ask_scope: sha256(text) + spec → INSERT ask_scope
   │ (роль serene_resolver, через _resolver_psql)
   ▼
таблица ask_scope (answer_sha256 PK, spec VARCHAR, created_at TIMESTAMP)
   │ GRANT SELECT → serene_ro
   ▼
dash_adapter.py (POST /dash/scope {"answer_sha256": "…"})
   │ SELECT spec через Grafana /api/ds/query → relay → SereneDB
   │ → 200 спецификация | 404
   ▼
add_to_dashboard.py (кнопка OWUI)
   │ sha256(текст ответа) → POST /dash/scope → spec
   │ → POST /dash/add → панель в Grafana
```

Модель спецификацию не видит: `diag` до неё не доходит вовсе (`mcp_ask.py`
его не читает), scope идёт мимо неё через SereneDB.

**Таблица** — `ask_scope_table.sql` (от `postgres`, resolver не имеет прав
`CREATE TABLE`). На каждом контуре создаётся один раз при установке.

**Кнопка** — вычисляет `sha256(текст ответа)`, запрашивает scope у
`/dash/scope`, передаёт в `/dash/add`. Нет scope — «закреплять нечего»,
без догадок (п. 12).

**Что отдаётся** — ровно `diag["счёт"]` без служебных чисел; для SQL панели backend экспонирует величину/ось под алиасами.

| поле | откуда | зачем |
|---|---|---|
| `src` | `scope.src` + подзапрос для алиасов | FROM панели (таблица или скобочный подзапрос) |
| `where` | `scope.where` + `folder_pred` | то же условие, что ушло в базу; пусто — допустимо |
| `measure` | алиас панели (`__ask_value`) | колонка величины: `sum("<measure>"::DECIMAL)` |
| `axis` | алиас панели (`__ask_axis`) | разрез; нет — панель по дням |
| `period_col` | `doc_date` | ось времени |
| `title` | вопрос [:120] | заголовок; служебных имён нет |

Чего НЕ делается: подмешивание в текст ответа (утечка протокола),
отдача модели, правила в промте.
- **Адаптер** (новый маленький сервис или расширение ask): принимает от
  кнопки спецификацию ответа и делает GET→append→POST панели в Grafana.
  Это и есть «добавить в дашборд» — доказано стендом.
- **SQL панели строится детерминированно** из посчитанного ответа: у
  `serene_ask` есть `agg.scope` (источник, условие, период) и величина —
  из них собирается `SELECT … GROUP BY` с кастами (ловушка 1). Никакого
  NL→SQL для дашбордов: числа считает база, модель запрос не пишет
  (п. 19 TARGET.md; схема в модель не уходит никогда).
- **Периодичность обновления**: в Grafana автообновление — на уровень
  ДАШБОРДА (поле `refresh`), у панелей только min interval
  (grafana/discussions#36965 — запросу много лет, не сделано).
  Варианты: **(а)** у каждого своего дашборда свой интервал — приемлемо,
  если «страница графиков» = один дашборд с одним интервалом;
  **(б)** своя тонкая страница, которая встраивает панели через
  `/d-solo?panelId=N` и перезагружает каждый iframe по СВОЕМУ таймеру —
  per-chart периодичность при Grafana как движке рендера. Решение — за
  первым живым контуром, начать с (а).
