## 🔴 Как подключаться к базе — от этого зависит, что вам разрешено

Строка подключения **не одна**, и роль решает, пройдёт ли запись:

```bash

psql 'host=127.0.0.1 port=7890 user=postgres dbname=postgres'

# ТОЛЬКО ЧТЕНИЕ — роль serene_ro, ей CREATE запрещён
psql 'host=127.0.0.1 port=7890 user=serene_ro dbname=postgres'
```

```bash

  md5sum /srv/1c/ubuntu/serenedb/$f /opt/1c-mcp-reports/$f
done
```

## Как связаны репозиторий и рабочий код

Сейчас это **две разные копии**: репозиторий правится на машине разработки, файлы
копируются на сервер в `/opt/1c-mcp-reports/` через `scp`.

Когда Claude Code работает **на сервере**, этот шаг лишний и вреден — легко забыть
скопировать и отлаживать старый код. Два варианта:

**Вариант А, простой.** Клон в `/srv/1c`, после правки копировать в `/opt/1c-mcp-reports/`:
```bash
cp /srv/1c/ubuntu/serenedb/<файл>.py /opt/1c-mcp-reports/
```
Плюс: ничего не меняется в устройстве. Минус: тот же риск рассинхронизации.

**Вариант Б, чище.** Сделать `/opt/1c-mcp-reports` клоном репозитория, тогда правка
сразу боевая. Требует переноса файлов, которых нет в репозитории — проверить перед этим,
что там нет ничего лишнего.

**Решение за владельцем.** По умолчанию — вариант А, он не меняет ничего.

# 5. Установлено твёрдо — не перепроверять

- **«Корпус = представление» — путь закрыт.** Индекс поверх `VIEW` заморожен на момент
  создания. Корпус остаётся таблицей.
- **Механизм сборки текста — `UNPIVOT` + `COLUMNS(*)`.** Быстрее остальных у всех трёх
  ревизоров и единственный обращается с пустыми значениями как боевой код.
- **`sha1()` движка побайтово совпадает с `hashlib.sha1`** — разовый пересчёт
  эмбеддингов не потребуется, если состав полей тот же.
- **`pg_class.reltuples` негоден как детектор изменений** — правка поля не меняет
  `count(*)`.
- **Журнала изменений в движке нет** — только сравнение отпечатков.
- **Вектор `ivf` заблокирован снаружи.** Порог 6 000 строк воспроизводим, все четыре
  наших обхода отвергнуты замером, вопросы у разработчиков SereneDB. Продукт этим
  **не блокируется**: перебор даёт 280-322 мс с полной точностью.

## ✅ Ночная сборка индекса — ПОЧИНЕНА 27.07 вечером

Ниже оставлен разбор причины: он объясняет, почему нельзя менять порядок строк в юните
обратно, и почему та же ошибка легко повторится в соседнем месте.

**Что сделано:** в `1c-serene-index.service` файлы окружения переставлены —
`-/etc/1c-mcp-reports.env` идёт **первым** (он нужен только ради `DEEPSEEK_API_KEY`),
роль задаёт `/etc/1c-serene-sync.env` **последним**. Правка есть и в репозитории
(`ubuntu/systemd/1c-serene-index.service`), и в `/etc/systemd/system/`.

**[проверено]** `1c-serene-index` был в состоянии `failed`. В журнале:

```
ERROR: permission denied for schema public
```

Причина — порядок файлов окружения в юните:
```
EnvironmentFile=/etc/1c-serene-sync.env      # SERENEDB_DSN ... user=postgres
EnvironmentFile=-/etc/1c-mcp-reports.env     # SERENEDB_DSN ... user=serene_ro
```
В systemd **побеждает последний**, то есть в сборку попадает read-only роль `serene_ro`,
и создание таблицы падает.

**Значение:** индекс существует только потому, что сборку запускали руками. По
расписанию он не пересобирался **ни разу**. То есть свежесть данных сейчас не «медленная»,
а **отсутствует**.

# 7. Ловушки — читать до того, как трогать базу

- 🔴 **Опыты с `ivf` — только на отдельном `--server_directory`.** Сборка не прерывается
  ничем, кроме рестарта движка: `pg_cancel_backend` возвращает успех и не делает ничего,
  `SET memory_limit` игнорируется. Незавершённая работа уходит в **WAL** и проигрывается
  при каждом старте — движок уходит в петлю OOM-рестартов и сам не выходит. Так уже
  положили инстанс на три часа.
- 🔴 **Никакого `VACUUM (REFRESH_TABLE)` на корпусе.** На таблице с вектором это дало
  34 ГБ и смерть движка. Только `REFRESH_INDEX`.
- **Ссылка определяется по форме значения, а не по имени колонки.** GUID лежат в 88
  колонках с суффиксом `_Key` **и в 26 без него, включая `Контрагент`**. Критерий по
  имени молча потерял бы разрешение контрагента.
- **`<=>` — расстояние, `cosine_similarity` — похожесть.** Перепутать значит вывернуть
  выдачу наизнанку. Порог `min_cos = 0.70` в резолвере сравнивается с похожестью.
- **`pgrep -f` находит сам себя**, а `pgrep | head -1` возвращает не тот процесс.
  Выбирать по наибольшему RSS.
- **Каталог движка не хранит состав индекса** — `duckdb_indexes().sql` отдаёт
  `USING inverted ()` при любом составе. Поэтому желаемый DDL хранится своим отпечатком
  в таблице `search_meta`.

# 8. Как проверить, что ничего не сломано

После **каждой** правки:

```bash
bash /opt/1c-mcp-reports/golden.sh
```

Восемь вопросов, все должны вернуть `answer`. Эталон:
контрагентов **13**; ИНН **7701012342**; за год **12 326 000**;
декабрь **2 456 400** на **6 документов**; крупнейшая продажа **1 629 700**.

Инварианты:
```sql
SELECT count(*) FROM search_corpus;                    -- 97 965
SELECT count(DISTINCT src_table) FROM search_corpus;   -- 226
SELECT index_name FROM duckdb_indexes();               -- search_idx
```

Вопросы приёмки лежат в `ubuntu/serenedb/golden-questions.txt` — **это тестовые данные
под наш стенд, а не часть продукта**. На другой базе файл будет другим; по п. 15
`TARGET.md` набор должен строиться из самой базы клиента при установке.
