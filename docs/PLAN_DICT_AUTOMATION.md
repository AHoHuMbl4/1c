## 2. Целевая схема (что уходит в пайплайн)

**Один режим вместо ручных env-танцев.** `WIKI_ALIAS_MODE`:
- `tick` (обычный такт, как сейчас): добор пустых + collision до потолка;
- `cycle` (полный пересбор, раз в N тактов или по слову владельца):
  init-проход → collision ДО НУЛЯ (итеративный потолок, без ручного
  поднятия ROUNDS) → promote (снапшот с датой-суффиксом автоматически) →
  migrate_sep → solr compile → A3-отчёт. Всё внутри ОДНОГО запуска юнита,
  env трогает только человек при смене режима (п.0: без слов базы).

**Самозащита памяти разведения.** Прогон, не давший «разведено сущностей ≥1»
на спрошенное слово, помечает probe-строку результатом (ok/failed); при
смене версии генератора юнит сам чистит отметки failed (замена Р5) —
«спрашивалось сломанным кодом» ≠ «разведено». Источник чистки — не время
и не человек, а факт результата.

**Прогресс и здоровье.** Каждые N минут в журнал: сколько слов/пачек
сделано, осталось, средняя скорость; при K минут без прогресса — стоп с
ошибкой в журнал (не молча) — замена Р6.

**Авто-отчёт качества.** После init-фазы юнит сам печатает в журнал:
строк, пустоты по полям, счётчик событийных форм по классам записей
(детектор — общий морфологический список, без слов базы; числа — в
журнал и CHANGELOG-факт). Замена Р7.

**Deploy полон.** FILES deploy_wiki_alias.sh += wiki_alias_promote.sql,
wiki_alias_migrate_sep.sql (Р8), md5-контроль уже есть.

**Снапшот-суффикс** = дата запуска фазы (Р1/Р9): внутри cycle-режима.

## 3. Шаги внедрения (порядок, критерии приёмки)

🔴 **Решение владельца 15.09: полный cycle-прогон НЕ выполняем** (сутки
карты — нельзя). Приёмка всех шагов — точечными проверками: 1 вызов модели
на сложный момент, остальное — замки и чтение диффа. Токены не жжём,
задач на часы не ставим.

1. `cycle`-режим в wiki_alias.sh: последовательность фаз одним прогоном,
   ROUNDS-итератор («пока осталось>0, потолок +40, максимум BUDGET»).
   Приёмка: замок на фазовую последовательность + точечный прогон
   cycle с малым LIMIT/MAX_SEC (1–3 слова проходят init→collision→promote);
   полный cycle не гоняем.
2. Прогресс-репорт + стоп-при-тишине. Приёмка: искусственная пауза модели
   (стоп vllm) → юнит останавливается с ошибкой < 2·K минут.
3. probe с результатом + авто-чистка failed при смене версии генератора.
   Приёмка: инъекция битого прогона → отметки чистятся сами, слова
   возвращаются в кандидаты.
4. Авто-отчёт качества init-фазы. Приёмка: числа совпадают с ручным
   замером оркестратора (±детерминизм детектора).
5. Deploy-список + снапшот-суффикс. Приёмка: deploy md5 полный; promote
   из cycle сам ставит дату.
6. Красная ×3 на каждый дифф; замки test_wiki_alias_* расширить под
   новые механизмы (ассерты на фазовую последовательность, ROUNDS-итератор,
   probe-результат).
7. Мерный сайт на «1 задача = 1 вызов» (Р11): aliases/best/nef мер раздельно,
   лимиты, канон ' \| '; приёмка — те же замки, что для сущностей, плюс
   точечная проба: 1 мера через новые промты (не полная регенерация — её
   отдельным словом владельца, если понадобится).

Ограничение по п.0/п.19: никаких слов/имён конкретной базы в коде — все
переключатели режимные, детекторы морфологические, снапшоты по датам.

## 4. Не автоматизируется (внешний периметр)

- GPU-переключение 27B ↔ эмбеддер+реранкер — владелец (одна карта).
- Полный пересбор (cycle) — по слову владельца или редкому расписанию:
  дорого по карте; обычная свежесть — tick-режимом (уже есть).
