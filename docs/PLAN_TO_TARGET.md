## 1. Потоки и что в них можно делать одновременно

Пять потоков. Внутри потока — строго по порядку, между потоками —
одновременно, с одной оговоркой ниже.

| Поток | О чём | Правит | Кто ведёт |
|---|---|---|---|
| **И** | Измерение: наборы, замеры, статус | документы, `ab_scorer.py`, gold-наборы | оркестратор + агент |
| **С** | Словарь и данные поиска | `wiki_alias*`, `*_load.sql`, `build.sh` | агент + прогон оркестратором |
| **К** | Классы неверных ответов | **`serene_ask.py`** | агенты, по одному за раз |
| **В** | Ворота Ф6: флаги в бой | env боевых юнитов, документы | оркестратор |
| **Э** | Эксплуатация и недостающие замеры | документы, юниты, `*.sh` | агенты |

🔴 **Оговорка о параллельности.** `ubuntu/serenedb/serene_ask.py` — один файл на
15 851 строку. Два агента, правящие его одновременно, затирают друг друга —
это уже случалось. Поэтому:

- в потоке **К** одновременно работает **ровно один** агент;
- потоки **И, С, В, Э** идут параллельно с **К** и между собой, потому что
  правят другие файлы;
- если задача из другого потока всё же требует правки `serene_ask.py`, она
  ждёт освобождения потока К.

Проверять пересечение до запуска — по карте зон `docs/CODE_MAP_ASK.md`
(20 зон, якоря, замок `test_code_map.py`). Две задачи в разных зонах —
всё равно один файл, всё равно очередь.

## 3. Порядок запуска

**Сразу и одновременно:** И1, И2, С1, С4, Э1, Э5 и один агент в потоке К (К1).

**После И2** становится известен объём К4 — и только тогда можно назвать срок.

**После С1 → С2**, и если оба K6 сходятся — это самый дешёвый прирост
качества из всех оставшихся.

**После С2 и К1 → В2** (ворота в бой), затем И3 (детерминированность на
боевом контуре).

**Последними** — п. 11 (финальная приёмка) и п. 15 (база клиента).

## 4. Чем доказывается «сделано»

Одинаково для каждой задачи:

- живой замер с числом, а не чтение кода;
- прогон замков с числами PASS/FAIL;
- полный скорер + `check_deploy_gate` перед любым выкатом в бой;
- запись в `CHANGELOG.md` с меткой `[замер]` / `[код]` / `[решение]`;
- обновление `docs/TARGET_STATUS.md`, если сдвинулась стадия пункта.

Задача без своего числа считается незаконченной, каким бы зелёным ни
выглядел код.
