# Сетевая схема продукта

Сетевое устройство системы на одной схеме: публичные точки, Hetzner Cloud network, vSwitch, LXD-контейнеры, RU↔EU туннель и потоки данных между компонентами.

🔴 **Источник фактов — замеры 22.08.** IP, порты и маршруты не догаданы, а сняты на живых хостах. Схема действительна до следующего переключения инфраструктуры; процедуры подключения нового сервера приведены, чтобы повторить её без поиска.

## 3. vSwitch 4003 — подключение нового выделенного сервера

Используется vSwitch **#84994**, VLAN **4003**, subnet **10.3.1.0/24**. Шлюз — 10.3.1.1 (на ICMP не отвечает, это норма).

### Пошагово

1. В **Hetzner Robot** → vSwitch #84994 → кнопка **«Add servers»** добавить сервер.
   🔴 Без членства в vSwitch кадры уходят в никуда: ARP без ответа, RX=0 [замер 22.08].
2. На сервере создать VLAN-интерфейс и persist через netplan:
   ```yaml
   # /etc/netplan/02-vswitch.yaml
   network:
     version: 2
     ethernets:
       eno1: {}
     vlans:
       eno1.4003:
         id: 4003
         link: eno1
         mtu: 1400
         addresses:
           - 10.3.1.XX/24
         routes:
           - to: 10.3.0.0/16
             via: 10.3.1.1
         nameservers:
           addresses: [213.133.98.98, 213.133.99.99]
   ```
3. `netplan apply`; проверить: `ip addr show eno1.4003`, `ip route | grep 10.3.0.0/16`, `ping 10.3.0.4`.
4. MTU 1400 — обязательно: туннель/инкапсуляция Hetzner Cloud network режет большие фреймы.

## 4. Туннель RU↔EU

### Замеры (89.23.101.22 ↔ 2.28.54.129) [замер 22.08]

| Вариант | Задержка | Скорость RU→EU | Скорость EU→RU | Примечание |
|---|---|---|---|---|
| **WireGuard UDP 51820** | ~44 мс | ~192 Mbps | ~240 Mbps | **Выбран основным** |
| ssh -w (tun поверх TCP 22) | — | ~120 Mbps | ~70 Mbps | Запасной; требует `PermitTunnel` |
| GRE/IPIP | — | проходят | проходят | Запасные на случай блокировки UDP |

### Открытые направления

* TCP 22/80/443/1194/51820/46000 и UDP 500/1194/4500/51820/46000 открыты в обе стороны [замер 22.08].*

## 6. Правила

- **1С — только читаем.** Доступ к OData только GET; запись физически запрещена двумя слоями (пользователь `ai_reader` + OData-шлюз).
- **Секреты только в `/etc/*.env`.** Никаких ключей, паролей и токенов в git, документах и аргументах командной строки.
- **Inbound только через форварды владельца.** Публичный SSH на gpu-1c разведён по портам 2201/2202; прямого доступа к LXC из интернета нет.
- **Эмбеддеры внутри vSwitch.** Прод-трафик эмбеддингов идёт через `10.3.1.11:8000` / `10.3.1.12:8002`, а не через публичные адреса.
- **RU↔EU — WireGuard UDP 51820.** Запасные варианты (ssh -w, GRE/IPIP) держатся на случай изменения политики провайдера.
- **Hetzner Cloud network 10.3.0.0/16** — магистраль EU; vSwitch 4003 соединяет с ней выделенные серверы Robot.

## 7. Старая схема (история до конца приёмки переезда)

Старая okna (`167.233.249.110`) держала весь контур сама: SereneDB 26.07.3 `:7890`, `ask` `:8091`, `packet-server` `:6090`, `openclaw gateway` `18800/18801`, `lan-relay` `10.3.0.4:7890` (`enp7s0` — cloud network). klient-1 — аналогично на `10.1.1.7` в LAN клиента. Схема оставлена как историческая; боевой трафик переключается на новые контейнеры gpu-1c.
