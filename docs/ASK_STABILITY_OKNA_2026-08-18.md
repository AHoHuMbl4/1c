## Кандидаты корневой причины

### 1. Модель (Qwen3.8-27B)

| За | Против |
|---|---|
| 17.08 DeepSeek pro держал те же golden (оркестратор) | **kind/text/числа 100% стабильны** на 5 прогонах — это не «случайность модели» |
| `clarify` вместо ответа при однозначном atom 349 (B8-02) — типичный промах LLM-маршрутизации | Систематика одинакова на каждом run: модель не «угадывает по-разному» |
| | B8-05 **5/5** — модель способна отдать верное число в этом контуре |

**Вердикт:** **против** как причины *нестабильности*; **за** как один из слоёв
*систематической* ошибки (clarify/no_data/неверная сущность). A/B с DeepSeek —
**не выполнялся** (по заданию модель не переключали); рекомендуется оркестратору.

### 2. Детектор развилок / outcome B

| За | Против |
|---|---|
| B8-01/B8-04: стабильно неполный набор B-пар при `fork_outcome=B` | `fork_outcome` и число пар в **text** не меняются между прогонами |
| B8-06: стабильный выбор регистра «книга продаж» вместо `реализациятмц` | Хэш состава `fork.atoms` **меняется** каждый run (5 вариантов), но **отбор в ответ не влияет** |
| B8-02: pool 16 веток, atom 349 посчитан, но маршрут в clarify | |

**Вердикт:** **за** — главный корень **содержательных** провалов B8-01/04/06;
outcome B / post-fork routing отрезает нужные ветки или entity.

### 3. Словарь развилок (коммит `74c56a2`, «замок»)

| За | Против |
|---|---|
| | Подписи в ответах **идентичны** 5/5; нет «плавающих» label между прогонами |
| | B8-05 **5/5** — словарь для «книга продаж» работает |

**Вердикт:** **против** — не объясняет ни нестабильность, ни большинство провалов.

### 4. Память выбора (shadow / apply)

| За | Против |
|---|---|
| `ASK_MEMORY_APPLY=1` в env | Во **всех 30** ответах: `diag.memory.mode=shadow`, `applied=null` |
| | Нет расхождения между прогонами из-за памяти |

**Вердикт:** **против** — на golden-линейке память **не участвует**; не источник
расхождения B7↔зонд и не источник «нестабильности».

## Корневая причина (числа)

1. **Нестабильности как класса нет:** 30/30 прогонов — тот же `kind`, тот же
   текст, те же видимые числа внутри вопроса.
2. **Систематический дефект step4/outcome B + маршрутизация модели:**
   - продажи-сумма: **1/3** эталонных сумм стабильно (B8-01), **1/3** count (B8-04);
   - контрагенты: база **349/349** в diag, пользователю **0/5**;
   - банки Казань: **0/5** `no_data`;
   - реализация ТМЦ docs: **74 407** vs **77 381** стабильно.
3. **Qwen на okna сейчас: 1/6 golden × 5/5**, не **6/6 × 5/5**.
