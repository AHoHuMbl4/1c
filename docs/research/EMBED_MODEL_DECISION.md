# Выбор эмбеддера: вердикт по итогам армий бенчмарков (10.09)

Вопрос владельца: «можно ли поставить эмбеддинг меньше 4B от Qwen (или квантованный),
чтобы пересчёт шёл быстрее, при условии что качество поиска НЕ упадёт?»

Армия: 4 независимые линзы (семейство Qwen3 / квантизация / RU-альтернативы /
практика 0.6B). Отчёты: `EMBED_QWEN3_FAMILY.md`, `EMBED_QUANT_EFFECT.md`,
`EMBED_ALTERNATIVES_RU.md`, `EMBED_QWEN3_06B_PRACTICE.md` (все — с URL источников).
Все сошлись в одну сторону.

## Вердикт

**НЕТ — переходить на меньшую модель нельзя: качество падает именно там, где
терять нельзя — на русском retrieval. Остающейся моделью остаётся
Qwen3-Embedding-4B (bf16); ускорение досчёта делается параллельностью того же 4B,
а не сменой модели.**

## Почему это решение окончательное для текущего продукта

1. Поиск — ядро продукта (TARGET: «не врёт», ответ по данным). Русский retrieval
   −9 nDCG@10 — это не «чуть хуже», это другой класс: у 0.6B на живом корпусе
   в 6 раз больше провальных вопросов.
2. Квантование решает память, а не скорость GPU: на нашем стеке выигрыша нет,
   потеря retrieval есть (−1.14% на int4). Отпадает.
3. Смена модели = обязательный полный пересчёт 1.67M векторов (пространства
   несовместимы) — разовая цена без выгоды по качеству.
4. 4B→8B тоже не нужен: +1.13 пункта при ×2 VRAM — не наш критерий, мы не ищем
   «ещё точнее любой ценой», нам запрещено терять текущую точность.

## Что ускоряет досчёт без потери качества (штатно по EMBED_BULK_HOWTO)

- параллельность: 3 потока на карту (карта насыщается на 3), линейно по картам;
- полосы по длине строк (уже в скрипте, a5a5c94: 8.6 → 150-230 строк/с);
- одна копия сервиса на карту (две копии бесполезны — замер HOWTO §4);
- bf16 + батчи (литература: 2.9-3.9× против неоптимального прогона).

## Оговорка и путь, если вопрос вернётся

Прямых замеров 0.6B vs 4B на НАШЕМ корпусе 1С нет и в открытом доступе быть не
может. Если когда-нибудь понадобится малая модель (например, дешёвые
малоресурсные инсталляции «коробки», п.0 TARGET) — путь один: поднять 0.6B рядом
(TEI, `/v1/embeddings`, dim 1024 совместим), прогнать НАШ gold-набор (L-метрика:
recall@10/nDCG@10, не косинус) против 4B на одних и тех же вопросах, и принять
решение только по этому замеру. Без золотого прогона смена модели запрещена.
