## 1. Резюме владельцу

Сейчас продукт — живой стенд, не товар на полке. Сентябрьский замер L19 (канон MARKET; поправка: README со старой «меньше половины» не использовать): **35 верных / 28 честных «нет данных или уточните» / 3 уверенно неверных** из 67. Пока есть уверенная ложь — в рынок с деньгами нельзя: только дружеские прогоны на знакомых базах. Сейчас: не продавать; чинить ложь; демо только знакомым.

**Выручка и готовность платить (WTP) сегодня = 0.** Нет LOI, нет платного пилота, нет цитаты «готов платить X». Таблицы чека ниже — арифметика себестоимости под желаемый сегмент, не замер рынка.

Стоит ли пилить дорогой продукт?

**Да** — если остаётесь в дорогом сегменте: подписка порядка **80–120 тыс. ₽/мес** (пол **50 тыс.** — только железо у клиента и низкие часы сопровождения). Всё это `[гипотеза, не прайс]` до слепого A/B и первого платящего. Железо у клиента; сопровождение не больше нескольких часов на клиента в месяц.

**Нет** — если цель «догнать чат за семьсот рублей»: там экономика людей и видеокарты структурно проиграна. Критик согласен по цене, спорит про готовность рынка платить средний чек (десятки–сотня тысяч в месяц).

Как показать преимущество перед семьюстами рублями? Не ценой и не слоганом. Демо: пятнадцать вопросов директора на **их** базе, рядом наша система и дешёвая обёртка, сверка каждой цифры с отчётом 1С или независимым SQL, запись на видео. Выигрываете там, где вопроса нет в готовом отчёте, цена ошибки высокая, нужна честная «нет данных», данные не в чужом облаке. Сравнение «наш чек vs 700 ₽» в рекламе запрещено — другой сегмент.

Кто покупатель `[гипотеза, не замер продаж]`: собственник или финдир торговой/производственной компании на УТ или КА, примерно 30–200 человек, продажи·склад·деньги. Рядом — компании среднего размера с запретом облака. Не наша война: микробизнес и облачный 1С:Фреш, «как ChatGPT за три тысячи», запись в 1С, чистый ЗУП.

**Первые 90 дней после готовности продукта** (не от сегодня; «готово» = M2=0 на согласованном наборе + путь к чужой базе, см. §8):

- Цель до закрытого слепого A/B: **пилоты + доказанное преимущество** (Demo-15 с нулём уверенной лжи, видео, scorecard). Не KPI «выручка».
- Цель «1 платящий» — **только после ворот E5** (слепой A/B) и стабильного нуля уверенных ложных; ориентир, не обещание регулярной выручки за квартал: **1 платящий или 2 пилота с датой решения**.
- До готовности канал не открываем; список ~15 тёплых контактов можно копить. Тёплые демо → 1–2 (или до 1–3 по каналам 1С) дружественных франчайзи как рефереры → контент со сверкой. Холодные звонки/письма незнакомым, Infostart как карточка товара и реселл через партнёров — рано.

**Когда остановиться**

- Через ~90 дней после «готово к продаже»: нет одновременно (1) преимущества на чужой базе, (2) демо без уверенной лжи, (3) живого бота после ребута. Установку «за день» считать стопом **масштаба канала** (когда дойдём до инсталлятора), не стопом всей линии — иначе конфликт с TARGET п.14 «инсталлятор в конце».
- Раньше: уверенная ложь не уходит к нулю; слепое сравнение с плагин+MCP+Claude не даёт заметного плюса.
- Инвестор: нет аппетита к ещё 2–3 кварталам инженерии без выручки; нет второго человека по инструкции запуска → заморозить и искать покупателя прав на технологию.

**Решение сейчас:** (а) не продавать; (б) не ронять гипотетический якорь ниже ~80 тыс. «ради SMB»; (в) сначала нуль уверенной лжи, чужая база, ребут — деньги после слепого A/B. Инженерный порядок: дожать пакет корпуса (полная B: merge/mode → flip) → план фиксов → независимая приёмка → ребут без рук → только потом инсталлятор.

**Понедельник (действие владельца, без кодов):** одна страница фактов — откуда 35/67, ребут pass/fail, burn ₽/мес, сколько людей поднимают контур; да/нет на 2–3 квартала без выручки; если да — одно имя тёплого кандидата на будущий Demo-15 (демо не раньше нуля лжи на срезе).

## 2. Экономика

*Источники: экономист (sp3); сверка с критиком (sp5); чек/пилот — рыночный канон §3.3. Все чеки — `[гипотеза, не прайс]` до доказательства.*

### 2.1. Себестоимость контура `[оценка]`

| Статья | Порядок величины | Комментарий |
|---|---|---|
| Сервер Ubuntu + 1×GPU (эмбеддер) | Разовые затраты на железо (CAPEX) ~600 тыс. ₽; амортизация ~17 тыс./мес | Железо у клиента → в нашем расходе (P&L) ≈ 0 |
| Аренда GPU 24/7 (если hosted у нас) | ~27–55 тыс./мес | Убивает чек ≤50 тыс. |
| Токены внешнего LLM (типичная нагрузка ядра) | ~0,4–6 тыс./мес | Копейки vs люди |
| Сопровождение зрелый / ранний `[гипотеза]` | ~5–10 / ~20–40 тыс./мес | Часы инженера — главная чувствительность |
| **Итого on-prem у клиента, зрелый** | **~12–15 тыс./мес** | Unit-себестоимость **без** оклада FTE; оклад — в §2.3 |
| **Итого hosted у нас, зрелый** | **~50–75 тыс./мес** | |

*Вывод одной строкой:* при железе у клиента зрелый контур дешёвый (~12–15 тыс.); hosted без доплаты за GPU съедает mid-чек.

Loaded-стоимость 1 инженера ~380 тыс. ₽/мес `[оценка]`. Порог «15–20 тыс. подписки» из канона — зона войны с SaaS (дешёвая полка / малый бизнес) — **не садится**, если GPU на нас.

### 2.2. Модели монетизации `[гипотеза, не прайс; после доказательства качества]`

| Модель | Чек `[гипотеза]` | Вердикт |
|---|---|---|
| **A. Подписка on-prem** (ПО + удалённое сопровождение; железо клиента) | 50–170 тыс./мес; якорь 80–120 | **Победитель** на ядре 30–200 |
| **B. Hosted у нас** | Пол ≥80 тыс. + доплата GPU **или** ≥100–150; 80k hosted хрупко (~17 клиентов на оклад, тонкая маржа) | Только upsell |
| **C. Лицензия + % поддержки** | Разово 0,8–2 млн + 15–25%/год | Дополнение для mid с запретом SaaS |

*Вывод:* первые 5–10 клиентов — инвестиция; устойчивый P&L после ранних — после ~10–15 платящих при падении часов (инсталлятор + runbook).

### 2.3. Безубыточность (покрытие зарплаты инженера) `[оценка]`

Допущение маржи: on-prem ≈ цена − ~13 тыс.; hosted ≈ цена − ~58 тыс. (из итогов §2.1).

| Цена подписки, ₽/мес `[гипотеза]` | Клиентов → 1 инж. (on-prem) | Hosted |
|---:|---:|---|
| 50 000 | ~10 | Не покрывает |
| 80 000 | ~6 | ~17 (хрупко / не цель) |
| 100 000 | ~4 | ~9 |
| 170 000 | ~2–3 | ~3–4 |

*Вывод:* зарплату инженера закрывают ~4–6 on-prem при 80–100 тыс.; это **не** то же самое, что «оправдано» в §2.6 (~10–15 на устойчивый P&L).

### 2.4. Полная стоимость 12 мес. у клиента: мы vs ~700 ₽/мес `[оценка]`

Клиент ~50 чел., УТ; наш якорь `[гипотеза]`: пилот 250 тыс. + железо ~600 тыс. + подписка 100×12 = **~2,05 млн** в год 1.  
У дешёвой обёртки (~700 ₽): **~15–40 тыс.** в год.  
Разница ~2 млн ≈ **~167 тыс./мес**.

Развести два порога `[гипотеза]`:

1. **Ниже ~50 тыс./мес** ожидаемого ущерба ошибок обёртки (или разовой ошибки ≥50–200 тыс. раз в 1–2 мес) — клиент рационально берёт SaaS.  
2. **Закрыть дельту год 1** — ожидать ущерб **≥~170 тыс./мес** (или ≥~2 млн/год) **или** жёсткий запрет облака (тогда сравнение не с 700 ₽, а с заказной внедренкой).

*Вывод:* без кейса «обёртка стоила N» аргумент TCO — сказка; с запретом облака сравнение другое.

### 2.5. Спор экономиста и критика

| | Экономист (sp3) | Критик (sp5) |
|---|---|---|
| «Пилить дорогое?» | Да как mid on-prem | «Дорогое» без доказанной цены ошибки и готовности платить (WTP) — фантазия; склейка «МСП-цикл + mid-чек» фатальна |
| Себестоимость (COGS) | Посчитан таблицей `[оценка]` | После появления таблицы атака сместилась: без кейса ошибки / WTP mid-чек не защищён; SMB-полка враждебна — согласен |
| Когда оправдано | Чек ≥80к, GPU у клиента, ≤4 ч/мес, запас ≥10–15 клиентов, 0 ложных | Согласен по направлению; добавляет: без кейса «бот спас N» mid-чек не защищён |

*Вывод:* считать себестоимость можно; продавать mid-чек без WTP и кейса ошибки — нельзя.

### 2.6. Вердикт «при каких числах оправдано»

**Оправдано, если одновременно:**

- якорь подписки ≥80 тыс. `[гипотеза]` (пол 50 — только on-prem + дисциплина часов);
- GPU платит клиент (или доплата hosted);
- сопровождение ≤4 ч/клиент·мес;
- **BE зарплаты** ~4–6 при 80–100к; **устойчивый P&L** после ранних — ~10–15 на инженера;
- ущерб обёртки закрывает дельту год 1 (≥~170 тыс./мес или запрет облака); порог «~50 тыс./мес» — лишь «не брать 700₽», не окупаемость нашего TCO;
- коммерция только после 0 уверенных ложных **и** закрытого слепого A/B (ворота E5→E6).

**Не оправдано:** рынок платит только &lt;20 тыс. при доказанном качестве; hosted без доплаты при ≤50 тыс.; вечно ≥10–12 ч на клиента; есть WTP на «чат», но нет преимущества на чужой базе; через ~90 дней после «готово» нет связки качество+демо+ребут — kill линии (установка — kill канала).

*Пока не доказано качество — не спорить о цене; якорь 80–120 `[гипотеза]` держать.*

## 3. Как продавать: выход на рынок и каналы 1С

*Источники: маркетолог (sp1) + спец по 1С-каналам (sp6); канон §3.3. До готовности (§8) канал не открываем.*

### 3.1. Воронка (тёплый старт) `[гипотеза конверсий — sp1]`

Источник → квалификация → согласие на демо на базе → **Demo-15** (15 вопросов на их базе, запись + scorecard) → **дружеский** пилот 4–8 нед → (после E5) коммерческий пилот / подписка → реферал.

Ориентир: из 20 тёплых заявок/квартал → ~1–2 пилота → **0,5–1,5 платящих** после ворот денег. Цель Q1 после готовности: **пилоты + доказательство**; «1 paid» — только после слепого A/B, иначе 2 пилота с датой решения — не KPI инвестора по ARR.

### 3.2. Демо-движок «15 вопросов на их базе»

1. Клиент (или фасилитатор) пишет 15 вопросов «как утром» + ловушки.  
2. Read-only доступ; наша система + конкурент **без подгонки**.  
3. Съёмка; после каждого ответа — сверка с 1С/SQL в кадре.  
4. Порог «демо прошло» (как у критерия «демо 10+5», K2): ≥9/10 верных или честный clarify; **0** уверенных ложных; ловушки → уточнение/отказ.  
5. Упаковка: cut 3–5 мин + scorecard; **не вырезать** отказы.

*Вывод:* Demo-15 — прокси качества и контент; **не** замена слепому A/B (K1) и **не** разрешение брать деньги.

### 3.3. Путь первых 5 клиентов (sp6)

| # | Откуда | Сколько из первых 5 `[ориентир]` |
|---|---|---|
| 1 | Личная сеть / знакомые УТ·КА | 2–3 |
| 2 | 1–2 (до 1–3) дружественных франчайзи-реферера | 1–2 |
| 3 | Intro из кейса №1 | 1 |
| 4 | Infostart / конфы / холод | **0 как план** |

*Вывод:* квартал 0 без выручки = доказательство на знакомых; реселл — после инсталлятора; до того только реферал. Имени первого покупателя в документе нет — честно «списка нет», копить контакты.

### 3.4. Первые 90 дней после готовности (сжато)

*Легенда:* wrong = уверенно неверное; Demo-15 = демо 15 вопросов; mid SQL = сверка независимым SQL.

| Недели | Фокус | Успех `[гипотеза]` |
|---|---|---|
| 1–2 | 1–2 Demo-15 + список 15 контактов / 5 франчайзи | ≥1 видео+scorecard с 0 wrong |
| 3–4 | Показ scorecard франчайзи; пост в своём Telegram | ≥2 партнёра **посмотрели** запись (не «пришлют клиента» до 0 wrong на записи) |
| 5–6 | Тёплые исходящие; 2–3 демо; черновик Habr | ≥1 «хочу **дружеский** пилот» |
| 7–8 | Первый **дружеский** пилот (коммерческий чек — **запрещён** до стабильного 0 wrong **и** E5) | Пилот live; 0 wrong на срезе |
| 9–10 | Второй контур; нарезка видео партнёрам; при закрытом E5 — путь к коммерческому | 2 пилота или 1+ mid SQL |
| 11–12 | Сверка с порогами; paid **только если** E5 закрыт | ≥1 paid **или** 2 пилота с датой решения |

*Вывод:* деньги в 90 дней — после A/B; иначе успех = пилоты. Тревога: 0 paid при 2+ сильных демо с 0 wrong **и** закрытом A/B → проблема оффера/чека. Любой уверенный wrong → **стоп продаж**, назад в разработку. В оффере пилота явно: «ставим мы; коробка ≤1 день — после этапа инсталлятора».

### 3.5. Сообщения по ролям (одно предложение)

| Роль | Фраза |
|---|---|
| Собственник | Спросите бота на своей 1С то, чего нет в избранном — за полминуты цифра как в учёте, не оценка нейросети. |
| Финдир | Ad-hoc по продажам/складу/деньгам без ожидания 1С-ника и без проекта BI; считает база, число сверяется кодом. |
| ИТ | Read-only рядом с 1С; без записи в ERP; отказ/уточнение вместо догадки; пока для тестов LLM может быть снаружи — mid с ИБ только после нулевого исходящего трафика чувствительных фактов. |

### 3.6. Анти-маркетинг

Война цен с ~700 ₽; слоганы «ИИ-магия / GPT для 1С»; продажи до 0 уверенных ложных и до слепого A/B; Infostart как основной товар (.cfe); ложь про on-prem LLM при текущем DeepSeek наружу; холод «для всех на 1С»; реселл до инсталлятора; демо только на типовой демо-базе; прятать честные отказы; война с Напарником (помощник разработчика 1С) за разработчиков.

### 3.7. Противоречия маркетолога и каналов 1С

| Тема | Маркетолог (sp1) | Каналы 1С (sp6) | Как читать |
|---|---|---|---|
| Оффер франчайзи | 10–15% первого года / фикс за пилот `[гипотеза]` | 10–20% **или** фикс 50–150 тыс. за пилот; при реселле 30–50% `[гипотеза]` | **Ещё не решаем** одну цифру; до первого реферала — диапазон гипотез в PDF |
| Habr / Telegram | Дом контента после Demo-15 | TG дёшево и шумно | Контент **только** со scorecard/SQL |
| «Совместимо!» / прайс 1С | Не в фокусе 90 дней | Год 2–3; mid может ультиматум | Не обещать «от 1С»; сертификация — после 2–3 кейсов |
| Цикл mid 200+ | В воронке как P1 | 3–9 мес., ИБ/NDA/комитет | Не путать с 90-дневной целью МСП |

*Вывод:* канал года 1 = тёплые прямые + 1–3 франчайзи-реферера; Infostart — репутация, не primary revenue.

## 4. Бренд

*Источник: бренд-стратег (sp2). Выбор имени — после проверки ТЗ/домена; до продажи не блокирует. Имена/слоганы — не приоритет, пока нет платящего.*

| Элемент | Формулировка |
|---|---|
| Обещание | «Цифры из учёта — без догадок.» — **цель контракта / не статус стенда** |
| Shortlist имён `[проверить занятость]` | **Учётник** → **Спроси учёт** → **Как в базе** |
| Отклонить | «Сверка» (занято); «Счетовод» (консалтинг) |
| Три слогана | «Цифры из 1С. Считает база; модель — формулировка.» (формулировку «не из нейросети» — только после K6 / нулевого egress) · «Большая база — тот же вопрос.» (**после** L20 / приёмки из метаданных клиента) · «Лучше спросить, чем угадать.» |
| Tone of voice | Сухой учётный; числа впереди; без «магии ИИ»; честный статус стенд→пилот→прод |

**Честно про 3 неверных из 67.** Не говорить «без ошибок» как факт стенда. Можно: цель контракта — ноль уверенных ложных; сейчас стенд; на демо — ваши вопросы + сверка. Если спросили про 3/67: «Да, это блокер продажи; до нуля на согласованном срезе с чеком не идём.» Отказы/уточнения — фича контракта (п.12), не баг; параллельно закрывать ложные отказы при наличии данных (п.21). Не цитировать клиенту «ошибки запрещены» (п.10), пока wrong &gt; 0 — противник использует как оружие.

## 5. Продукт и метрики

*Источник: продактолог (sp4); пороги — канон K1/K2/K5/K8/K10 и L19.*

### 5.1. Ядро ценности

Ad-hoc цифра из живой 1С — **цель** типичной задержки p50 ≤30 с (метрика M4), не замер сегодня; как в учёте, не «оценка модели»; не знает — спросит или откажет. Три работы: спросить вне избранного отчёта; проверить «что в базе» перед решением; спросить с телефона без прав записи.

**Святое:** гейт чисел + модель не считает; отказ/уточнение вместо догадки; ответ при наличии данных; без хардкода + приёмка из их метаданных; read-only; видимая полнота/свежесть.  
**Лишнее в первой продаже:** обещание инсталлятора «за день», реселл, запись в 1С, BI-замена, смена эмбеддера как фича покупателю.

### 5.2. Метрики с порогами (предложение для пилота)

*Легенда:* Match = верный; Wrong = уверенно неверное; L20 = следующая независимая приёмка / чужая база. Колонка «Ещё продукт» = стенд/R&D, **не оффер**. Продажа только при 0 wrong.

| # | Метрика | Ещё продукт (R&D) | Можно продавать |
|---|---|---|---|
| M1 Match | ≥70% на пути к чужой приёмке (L20); сейчас ~52% (35/67) | ≥90% на клиентском наборе **или** ≥ конкурента +15 п.п. |
| M2 Wrong | ≤1 на набор на стенде → путь к 0 | **0** уверенных ложных |
| M3 Качество отказов | Wrong среди non-match ↓; ложные отказы разобраны | Системных ложных отказов → 0 |
| M4 Latency | типичная (p50) ≤30 с; почти худшая (p95) ≤90 с | + честный статус при сбое |
| M5 WAU спрашивающих | ≥3 чемпиона в пилоте (еженедельно активные) | ≥5 после продажи |
| M6 Вопросов/user·нед | ≥3 у чемпиона | ≥5 у ядра ролей |
| M7 Доля «не из отчётов» | ≥40% в пилоте | ≥50% |

*Вывод:* до пилота смотреть только **0 уверенных ошибок + ребут**. Остальное — на пилоте. Свежесть — явный флаг (TARGET п.17: фиксированного срока нет).

### 5.3. Валидация пилотом

1. 15 вопросов с **их** базы (10 директорских + 5 ловушек).  
2. Эталон SQL/1С **до** показа ответа.  
3. Разметка match / clarify / no / wrong. Kill: любой уверенный wrong или &lt;9/10 на директорских.  
4. Pass → **дружеский** пилот 4–8 нед (**не** коммерческий 150–400 тыс. до стабильного 0 wrong **и** слепого A/B). Далее — операционализация п.15 TARGET на пилоте (агентский прогон ⊂ п.15, не равен всей установке).

### 5.4. Топ-5 фич после зелёной приёмки

1. Клиентский приёмочный контур (генератор вопросов + дашборд match/wrong).  
2. Онбординг «умею спросить про…» на сущностях их метаданных.  
3. След цифры в ответе + флаг неполноты/свежести.  
4. История и «повтори / уточни период».  
5. Алерты по 3–5 сохранённым вопросам чемпиона (не BI).

*Вывод:* полная B + фиксы + L20 двигают продажу; инсталлятор позже; пробел — петля ценности человеку, не только L-прогон.

## 7. Инвестиционный взгляд

*Источник: инвестор (sp8); kill — канон §6.2 + правка ворот sp8. Два слоя kill — не лазейка: продуктовый без установки; канал — с установкой.*

### 7.1. Вердикт

**Сейчас — не покупка продукта, а опцион на технологию с воротами.**

| Вариант | Когда |
|---|---|
| **(а) Вкладываться в доведение** | Есть тёплый чемпион-покупатель; аппетит к 2–3 кварталам без регулярной выручки; bus-factor ≥2 или найм ≤60 дн.; дисциплина «не продавать до 0 ложных»; гипотеза чека совместима с себестоимостью |
| **(б) Заморозить / искать покупателя IP** | Нет аппетита к разработке без выручки; команда 1–2; владелец хочет кэш-аут; SI с каналом дешевле доведёт установку/прод |
| **(в) Убить** | ~90 дней после «готово» без преимущества∧демо∧ребут; раньше — wrong не →0 / нет плюса vs MCP; вендор без pivot; культура «перепроверь» + чек не выше SaaS; нет денег до коробки |

*Вопрос владельцу:* какой исход при текущем аппетите к 2–3 кварталам без выручки?

### 7.2. Staged-план с воротами `[ориентир]` — порядок согласован с §8

Порядок доказательств **один:** ребут до внешнего пилота; слепой A/B до **коммерческого** пилота (дружеский пилот — раньше A/B, без денег).

| Этап | Доказываем | Дальше / стоп |
|---|---|---|
| S0 Факты | Burn (сжигание ₽/мес), ETA до вехи, команда, baseline конкурента | Нет цифр → не (а) |
| S1 Качество P0 | Wrong →0 на согласованном наборе | Wrong &gt;0 без плана за 30 дн. → стоп коммерции |
| S2 Чужая база / L20 | Независимая приёмка | Нет переноса → (б) или убить |
| S3 Ребут | Бот сам после reboot | Не закрыт → запрет внешнего пилота с обязательством доступности (SLA) |
| S4 Дружеский пилот | Demo 10+5 на базе клиента | Провал → назад в S1 |
| S5 Слепой A/B | Vs плагин+MCP+Claude, N≥50, +15 п.п., 0 галлюц. чисел | Провал порога → kill досрочно |
| S6 Монетизация | 1–3 платных пилота → подписка | Нет оплаты → (б) |
| S7 Инсталлятор | ≤1 день до первого верного ответа | Без него — нет реселла |
| S8 Mid+ пакет | 0 чувствительного egress; 2-й инженер | ИБ-veto без этого → не mid-чек |

**Kill:** за ~90 дней после L20 обязательны преимущество на чужой базе ∧ демо без лжи ∧ ребут. Установку «за день» — kill **масштаба канала** (после решения масштабировать), не kill линии (иначе конфликт с п.14).

### 7.3. Красные флаги (топ-5)

1. Контракт «ошибки запрещены» vs 3 wrong / 67.  
2. Time-to-value на порядки хуже обёртки.  
3. Бот не переживает ребут как прод.  
4. Заменители густые при «пустом» пересечении — пустота ≠ спрос.  
5. Сложность контура + малоизвестный SereneDB + временный egress + bus-factor ≈1–2.

**Два часа:** V1 (60–90 дней **от сегодня**, sp8) — факты burn/ETA + 0 wrong на наборе + тест ребута. Отдельно: kill коммерции — ~90 дней **после готовности** (после L20), не от сегодня. Не смешивать часы.

## 8. Единый план

«Готово к продаже» = после L20/пути к независимому набору + **M2=0 на согласованном наборе** (не «траектория»). Детали инженерии — `activeContext`; здесь — решения владельца.

| Этап | Что делаем (одной фразой) | Дальше / стоп | Не делаем |
|---|---|---|---|
| **E0 Сейчас** | Дожать полную B: merge/mode → flip/6a0; бэкап эмбеддингов перед рискованными сменами (писатели 1∥3-A уже выкатаны) | Зелёный такт / стабильный корпус; стоп — массовая смена текста без бэкапа emb | Продажи; реселл; смена эмбеддера «ради фичи» |
| **E1 Качество** | План фиксов; wrong→0 на согласованном наборе | M2=0; стоп — wrong не закрывается ~30 дн. | Outbound; коммерческий пилот; Infostart-SKU |
| **E2 L20 / чужая база** | Независимая приёмка из метаданных клиента | Перенос без подгонки; стоп — нет преимущества | Прайс mid как факт |
| **E3 Ребут** | Бот жив после reboot | Pass; стоп — fail при ожидании uptime | Внешний пилот с SLA |
| **E4 Дружеские пилоты** | Demo-15 на тёплых; 1–3 франчайзи-реферера | ≥1 артефакт 0 wrong; wrong на пилоте → E1 | Реселл; война цен; «on-prem LLM уже»; **деньги** |
| **E5 Доказательство рынка** | Слепой A/B vs MCP+Claude на чужой базе | +15 п.п. и 0 галлюц. **или** честный провал → упростить / (б)/(в) | Enterprise без чемпиона |
| **E6 Коммерческий пилот** | 150–400 тыс. `[гипотеза]` за 4–8 нед **после** E5 и стабильного 0 wrong | Оплата / подписка; нет оплаты при сильном демо → пересмотр оффера, не демпинг | Реселл-сеть; прайс на Infostart |
| **E7 Инсталлятор** | TARGET п.14; ≤1 день до первого верного ответа | Pass установки | Обещать «за день» раньше |
| **E8 Масштаб канала** | Реселл с 1 франчайзи | Экономика партнёра; стоп — партнёр на бесплатном Linux/SereneDB | Холодный Директ; 50 партнёров сразу |
| **E9 Mid+** | On-prem LLM; 0 egress; 2-й инженер | ИБ не veto | Mid-чек без пакета периметра |

*Вывод:* порядок = качество → чужая база → ребут → дружеские пилоты → **A/B → деньги** → инсталлятор → канал → mid+.

**Сводный kill (без лазейки «удобный слой»):**

- **Линия продукта (~90 дней после «готово»):** нет преимущества на чужой базе **или** демо со лжью **или** мёртвый ребут → упростить / сменить категорию.  
- **Масштаб канала:** нет установки «за день» после решения масштабировать → стоп реселла (не всей линии).  
- **Ранний стоп:** wrong не →0; нет тёплого buyer и burn/ETA; bus-factor 1 без плана найма → не открывать полный путь (а).
