|---|---|---|---|---|

| На какую сумму продали вчера? | **16,2 с** | answer | 2 | развилка 1,4 с; сущность 2,4 с; **гейт 10,4 с** |
| Дай топ-3 товара за прошлый месяц | **18,4 с** | clarify | 4 | развилка 2,9 с; исходы 2,9 с; **GAP wall−шаги = 12,3 с** |

На **clarify** после последнего `шаг` остаётся **12–23 с**, не попавших в

обвязка `seal_clarify` / опции (в коде после возврата из веток без отдельного
`шаг`).

### 3.2. Cold vs warm (один и тот же уникальный вопрос)

| | wall | LLM calls | «разбор» в шагах |
|---|---|---|---|
| **cold** (nonce в тексте) | **21,9 с** | **5** | 0 мс (см. артефакт ниже) |
| **warm** (тот же текст) | **11,8 с** | **2** | 0 мс |

Разница **~10 с** и **+3 LLM-вызова** = цена холодного `parse_intent`
(мультисэмплинг до отрыва `INTENT_LEAD`, по умолчанию до 5). Изолят intent×5
= 19,9 с; живой отрыв раньше даёт ~10 с — согласуется.

**Артефакт следа:** на измеренном контуре кумулятив «разбор вопроса» часто
**0 мс**, хотя cold платит секунды за intent. В дереве `t0` стоит *до*
`parse_intent` (`serene_ask.py` ~11977); либо туннель смотрит на сборку, где
порядок другой, либо часть времени intent уходит вне `шаги`. Для аудита
используем **wall − сумма видимых шагов** и **счётчик `diag.tokens.calls`**,
а не только первую строку шагов.

## 5. Почему ожидание «должно быть быстро» ломается

1. **Вектор — один короткий шаг**, не весь ответ. После кандидатов пайплайн
   всё ещё: развилка → (часто) LLM выбора → счёт → LLM прозы → гейт →
   (иногда) retry / clarify LLM.
2. **Детерминизм входа куплен мультисэмплингом** (`INTENT_SAMPLES`/`LEAD`,
   замер 04.08: 18/58 расхождений при одном вызове). Это сознательная цена
   п. 3, не баг поиска.
3. **Compose на answer** тянет большой контекст (тысячи prompt tokens) —
   секунды генерации; retry удваивает.
4. **Clarify** дописывает LLM *после* последних `шаги` — в следе «дырка».
5. **Мемо разбора** делает повторные прогоны быстрее и **маскирует** cold
   стоимость в скорерах/ручных повторах одной и той же фразы.

## 6. Что это не значит (границы аудита)

- Не утверждается, что IVF/RRF «не нужны» — они уже почти не видны на фоне LLM.
- Не предлагается выключить мультисэмплинг или гейт — это контракт (п. 3, 10, 21).
- Локальный ask на этой машине (`:8091` hang, `:8098` = `/tmp/serene_ask_v8.py`)
  для боя не репрезентативен; цифры — с туннеля okna.
- Полный прогон gold × N для p50/p90 латентности не снимался — достаточно
  для диагноза «где», не для SLA-таблицы.

## 7. Если позже чинить скорость (не в этой работе)

Имеет смысл мерить/трогать **только** после явного слова, в порядке рычагов:

1. Дописать `шаг` вокруг cold `parse_intent` и `clarify_text`, чтобы след = wall.
2. Смотреть, можно ли раньше обрывать intent при стабильном отрыве (уже есть
   LEAD) и не раздувать prompt compose.
3. Развилка: меньше лишних счётов / один SQL (как Ф6.1), не «ускорить вектор».
4. Не ждать выигрыша от embed/rerank — они уже <0,2 с.
