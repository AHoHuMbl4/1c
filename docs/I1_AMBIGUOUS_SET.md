## 1. Одна команда

На сервере okna (нужны локальный `psql` к корпусу и `/ask`):

```bash
cd /tmp/i1-ambiguous   # или каталог с ab_scorer.py + ab-ambiguous-okna.tsv
export ASK_URL=http://127.0.0.1:8092/ask   # стейджинг-кандидат; бой — :8091
# ASK_TOKEN и PGPASSWORD — из /etc/1c-serene-ask.env и /etc/1c-mcp-reports.env
# (грузить построчно: env со пробелами ломается при `. file`)
export AB_DSN='host=127.0.0.1 port=7890 user=serene_ro dbname=postgres'
AB_AMBIGUOUS=okna python3 ab_scorer.py
```

Выбор набора: `AB_AMBIGUOUS=okna` → `ubuntu/serenedb/ab-ambiguous-okna.tsv`.
`AB_GOLD_FILE` перекрывает. Вместе с `AB_CONTOUR`/`AB_PROBE` приоритет у ambiguous.
Отметки `.golden-*` / `.probe-*` **не** ставит (это приёмка, не smoke-гейт).

## 2. Что намерено

| | |
|---|---|
| Вопросов | **18**, те же 6 видов, что в [`ACCEPTANCE_AMBIGUOUS.md`](ACCEPTANCE_AMBIGUOUS.md) |
| Режимы | только `clarify` и `kind` — **вид** ответа и ось уточнения |
| Не меряем | величину числа (`digits`/`name` нет — сверять текст/цифру = подгонка) |
| Эталон clarify | игла оси в `options` (человеческая формулировка, не имя метаданных) |
| Эталон kind | SQL → `truth()`: `SELECT 0` → `no_data`; ненулевой → `answer` |

Новых режимов скорера нет: хватает `clarify` + `kind`.

## 3. Чем отличается от замера 5/18 (27.08)

Ручной прогон 27.08 (`ACCEPTANCE_AMBIGUOUS.md` §8) гонял **ut_test-набор**
`ab-acceptance-ambiguous.tsv` на корпусе okna и судил по таблице вручную.
Штатный набор okna учитывает **факты корпуса** (тот же §8.2):

| № | Вопрос (срез) | ut_test / ручной TSV | okna `ab-ambiguous-okna.tsv` |
|---|---|---|---|
| 4–6 | Алмаз / Сатурн / ПАНГЕЯ | `clarify` (в ut два «Алмаз») | `kind` / `SELECT 0` — совпадений **0** |
| 12 | на всех складах вместе | игла «склад» | игла «товар» (предмет не назван) |
| 15 | выручка за 2022 | `kind` / `SELECT 0` (вне корпуса ut) | `kind` + SQL выручки 2022 → ожидание **answer** |
| 7 | закупили товаров | игла «сумм» | игла «руб» (ось рубли/штуки) |
| 16 | как у нас дела? | пустая игла (любой clarify) | игла «продаж» (ось темы) |

Поэтому **N/18 штатного набора ≠ прямой повтор 5/18**: состав ожиданий сдвинут
под okna. Сравнивать с 5/18 можно по **классам дефектов** (догадка периода/меры,
мусорный clarify, отказ вместо уточнения), а не побитово по номерам.

Базовый ручной итог 27.08 на боевом `:8091`: **5/18**. Свежий прогон штатным
набором — в §4 (после замера).
