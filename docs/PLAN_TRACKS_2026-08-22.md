### Политика порядка хостов (решение 22.08, вопрос владельца «один сервер или одновременно»)

1. **Источник истины один — git HEAD.** На сервере лежит только развёрнутое из HEAD;
   контроль — md5 в env-map после каждого шага. md5 боя ≠ HEAD = дефект, а не «версия
   сервера».
2. **Порядок всегда dev → okna → klient-1** (от дешёвого к дорогому). Одновременно —
   только шаги, идентичные и безопасные на всех (строчка в env, документы).
3. **Различия баз живут только в /etc/1c-*.env и в данных самой базы** — никогда в коде
   и никогда в процедуре. Два сервера идут ОДНОЙ процедурой с разными env — это и есть
   проверка универсальности и заготовка copy-paste для новых подключений.
4. Каждый шаг пишется в RUNBOOK параметризованно («<база>», «<порт>»), не «для окна так».
5. После каждого шага — env-map обеих баз одной таблицей; рассинхрон = дефект дня.

Применение к фазам: Ф1 — только dev. Ф2 (движок): dev → okna → klient-1, окно останова
и откат на каждом; klient-1 последним (хрупкий: клин 22.08 повторился, диск). Ф4
