## 3. Архитектура промтов («1 задача = 1 вызов», решение владельца 14.09)

| Правило | Источник |

| Каждый промт несёт ТОЛЬКО правила своего поля | там же |

## 5. Правила полей и валидатор (исполнение — кодом, не надеждой)

| Правило | Источник |
|---|---|
| aliases: 3–10 (init) / ≥2 (collision), каждый 1–3 слова; баны: метки платформы, варианты одного стема, латиница при нелатинском title, слова-вопросы отдельно, quantity-имена | канон; wiki_alias_parse.py |
| bestUsedFor: 2–4 шаблона; запрет «скобка+запятая» внутри строки | канон; parse (hard-fail) |
| notEnoughFor: НИКАКИХ запятых и скобок (CSV ' | ') — запятая = hard-fail поля = ретраи | канон; parse; §3.123 |
| Событийный триггер — единая фраза во всех промтах: `flows OR movement / money-total / event totals, not a bare headcount/Count alone`; осевые слова и ранговые шаблоны — только записям-событиям | wiki_alias.sh (после 24e6fca, замок ассертит) |

## 6. Пределы модели — что она срезала (замерено)

| Факт | Источник |
|---|---|
| Обрезка JSON: пачка 20 + богатые quantities — JSON рвётся, salvage спасает часть | A5 §3.3; wiki_alias_parse._salvage_items |
| Плотный промт = выборочное исполнение: INIT-A с 8 вложенными правилами — осевые слова легли на 16 событий из ~сотни, на целевой паре продаж модель их выбросила (замер 20.09) | CHANGELOG 2026-09-20 (1)-(2); черновик cycle_20260919 |
| «Expecting value: line 1 column 1» + retry-карусель = пустой ответ: либо stopReason=length (лечить maxTokens), либо пустой стрим инстанса под параллельной нагрузкой (ретраится само) | HOW_NOT_TO §3.123 |
| Дискреционные правила («1–3 на усмотрение») модель выполняет непостоянно на сложных записях — замерено, учитывать при написании правил (предпочитать обязательный минимум) | замер 20.09 (там же) |

| Правило | Источник |
