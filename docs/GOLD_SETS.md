## 4. Пересечения (нормализованный текст вопроса)

Норма: lower, `ё→е`, обрезка пунктуации/кавычек, сжатие пробелов.

| Пара | Точных | Почти (Jaccard ≥ 0,75) | Заметки |
|---|---:|---:|---|
| gold-okna ∩ probe-okna | **7** | 0 | probe — подмножество; 8-й probe «сколько товара на складе?» вне gold-okna |
| gold-okna ∩ ambiguous | **1** | **1** | точное: «как у нас дела?»; почти: «петель…складе» ≈ «Сколько осталось на складе?» |
| probe-okna ∩ ambiguous | **1** | **1** | «сколько товара на складе?»; то же почти про склад |
| ambiguous ∩ ACCEPTANCE_UT | **5** | 0 | **намеренно** (док Э3): №27/28/44-класс и др. |
| ACCEPTANCE_UT ∩ любой рабочий `ab-*` / golden | **0** | 0 | заморозка чиста относительно рабочих |
| gold ∩ golden-questions | **0** | — | разные базы |

**Итого пар с точным пересечением: 4** (7+1+1+5 вхождений вопросов).

## 5. Правило пользования (проверяемое)

1. **Приёмочный набор** (`ACCEPTANCE_UT.md`) **не открывают при отладке** ответа на конкретный провал: не правят эталон/формулировку «под код», не выкидывают вопрос из прогона.
2. Прогон приёмки — **только целиком** (или фиксированным диапазоном пачек прибора, без выборочного «подкрутить один» и объявить успех).
3. Провал на приёмке → чинят **код** (или заводят вопрос в **рабочий** набор), эталон приёмки не подгоняют.
4. Перед добавлением вопроса в **рабочий** набор — проверка: той же формулировки нет в приёмочном.
5. `ab-gold-okna.tsv` / probe / calendar / smoke — место для воспроизведения и регрессии правок.

### Чем держится механически

Офлайн-замок [`ubuntu/serenedb/test_gold_sets_split.py`](../ubuntu/serenedb/test_gold_sets_split.py):

- читает приёмочный `ACCEPTANCE_UT.md` и рабочие TSV/txt из реестра;
- падает, если нормализованный вопрос из приёмки есть в любом рабочем наборе;
- сверяет, что роли в этом файле и в замке совпадают (пути существуют, числа вопросов ≥ ожидаемых минимумов).

`ab-acceptance-ambiguous.tsv` в «рабочие» замка **не входит** (это не набор правок) и в «замороженную приёмку И4» тоже **не входит**, пока в нём есть пересечения с рабочим okna — иначе замок красный без права чистить наборы в этой задаче. После снятия пересечений ambiguous↔working его можно добавить во вторую приёмочную полку отдельным шагом.
