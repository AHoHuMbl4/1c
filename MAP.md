## 1. Что делает продукт

Бот отвечает на вопросы по данным 1С. Цепочка:

```
1С (Windows, IIS, OData только на чтение)
  └─ шлюз :6011 — режет всё, кроме GET
      └─ витрина в SereneDB — таблицы 1С как есть
          └─ ПОДГОТОВКА + СБОРКА (внутри движка, SQL): корпус, величины, ссылки, векторы
              └─ индекс `search_idx` (инвертированный, BM25)
                  └─ сервис ответов :8091 — ищет индексом, считает базой, формулирует моделью
                      └─ бот OpenClaw в Telegram
```

**Главный принцип** (п. 20 `TARGET.md`): данные лежат в SereneDB — работа с ними делается
**внутри** SereneDB. Своим кодом остаётся только то, чего у движка нет.

## 2. Файлы, которые работают

### Сборка данных — `ubuntu/serenedb/`, всё на SQL, питона нет

Такт **не ночной**: система обязана отражать изменения в 1С не позднее 20 минут
(п. 17 `TARGET.md`, подтверждено владельцем 28.07). Отсюда замок от наложения запусков,
докатка прерванного прогона и цена такта по числу изменений, а не по размеру базы.

| Файл | Что делает |
|---|---|
| `build.sh` | **точка входа такта.** Связывает шаги, держит замок, создаёт и удаляет секреты |
| `corpus_init.sql` | развёртывание с нуля: таблицы, словарь, индекс, **права**. Идемпотентно |
| `corpus_precheck.sql` | проверки ДО такта: индекс, права, наличие источников, живость эмбеддера и размерность. Снимает отпечаток «как было» |
| `corpus_build.sql` | подготовка + сборка корпуса: читает `$metadata` из 1С, классифицирует колонки, находит имена объектов, карту ссылок, даты, величины строки, собирает текст и отпечаток |
| `corpus_merge.sql` | перенос собранного в боевой корпус по отпечатку + публикация индекса |
| `corpus_postcheck.sql` | проверки ПОСЛЕ такта: сверка с отпечатком «как было». Его код возврата — код всей сборки |
| `resolver_build.sql` | значения измерений для резолвера, инкрементально, одним `MERGE` |
| `embed_missing.sh` | досчёт векторов штатной `ai_embed`: пачки по строкам И по символам, докатка прерванного, перенос по деловому ключу |

### Ответы — `ubuntu/serenedb/serene_ask.py`

Единственный большой файл своего кода в контуре ответа. Что в нём важно:
поиск штатными функциями движка (`ts_*`, `bm25`, `lm_dirichlet`), выбор сущности
**реранкером**, выбор величины **по вопросу**, гейт чисел по ролям, честный отказ и
уточнение, вторая попытка при отказе.

### Проверка

| Файл | Что делает |
|---|---|
| `golden.sh` + `golden-questions.txt` | приёмочный набор, 8 вопросов, гоняется после КАЖДОЙ правки |
| `ab_scorer.py` | второй набор: 8 вопросов, истина считается независимым SQL по источнику |

### Выведено из контура, не трогать

`serene_search_build.py` — прежняя питоновская сборка. 🔴 **Запускать нельзя**: при
нынешнем составе корпуса она сносит таблицу и индекс (авария 28.07).
`serene_report.py`, `mcp_reports.py` — инструмент `report_1c`, решено вывести.
`build_resolver_index.py` — прежняя сборка резолвера, заменена на `resolver_build.sql`.

## 4. Где что живёт на сервере

| Что | Где |
|---|---|
| репозиторий | `/srv/1c` — работаем здесь |
| боевой код | `/opt/1c-mcp-reports/` — копия файлов; после правки копировать туда |
| исходники движка | `/srv/serenedb-src` — без них агент `serenedb-native` слеп |
| секреты | `/etc/*.env`, права 600, в git не входят |
| данные движка | `/var/lib/serenedb` |

**Подключение к базе:** запись — `psql 'host=127.0.0.1 port=7890 user=postgres dbname=postgres'`;
только чтение — роль `serene_ro`. Перепутать = получить `permission denied` и решить,
что нашёл дефект.
