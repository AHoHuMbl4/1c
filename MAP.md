## 1. Что делает продукт

Бот отвечает на вопросы по данным 1С. Цепочка:

```
1С (Windows, IIS, OData только на чтение)
  └─ шлюз :6011 — режет всё, кроме GET
      └─ витрина в SereneDB — таблицы 1С как есть
          └─ ПОДГОТОВКА + СБОРКА (внутри движка, SQL): корпус, величины, ссылки, векторы
              └─ индекс `search_idx` (инвертированный, BM25)
                  └─ сервис ответов :8091 — ищет индексом, считает базой, формулирует моделью
                      └─ бот OpenClaw в Telegram
```

**Главный принцип** (п. 20 `TARGET.md`): данные лежат в SereneDB — работа с ними делается
**внутри** SereneDB. Своим кодом остаётся только то, чего у движка нет.

## 2. Файлы, которые работают

### Сборка данных — `ubuntu/serenedb/`, всё на SQL, питона нет

Такт **не ночной**: система обязана отражать изменения в 1С не позднее 20 минут
(п. 17 `TARGET.md`, подтверждено владельцем 28.07). Отсюда замок от наложения запусков,
докатка прерванного прогона и цена такта по числу изменений, а не по размеру базы.

| Файл | Что делает |
|---|---|
| `pipeline.sh` | **точка входа конвейера**: синк-дельта → сборка. Один атомарный такт |
| `serene_sync.py` | синк витрины из 1С: **дельта по `DataVersion`**, перепись схемы раз в час |
| `poc_load_entity.py` | загрузка сущности: полная и **`load_entity_delta`** (только изменения) |
| `build.sh` | сборка поискового слоя. Связывает шаги, держит замок, создаёт/удаляет секреты |
| `corpus_init.sql` | развёртывание с нуля: таблицы, словарь, индекс, **права**. Идемпотентно |
| `corpus_precheck.sql` | проверки ДО такта: индекс, права, источники, живость эмбеддера. Отпечаток «как было» |
| `corpus_build.sql` | сборка корпуса: `$metadata`, классификация колонок, имена, ссылки, даты, величины, метки сущностей (`search_tables`) |
| `corpus_merge.sql` | перенос в боевой корпус по отпечатку + публикация индекса |
| `corpus_postcheck.sql` | проверки ПОСЛЕ такта: сверка с отпечатком. Код возврата — код сборки |
| `coverage_build.sql` | **перепись полноты** (п. 13): 1С → витрина → корпус → индекс → вектор + причина |
| `resolver_build.sql` | значения измерений для резолвера, инкрементально, одним `MERGE` |
| `embed_missing.sh` | досчёт векторов `ai_embed`: пачки по строкам И символам, докатка, перенос по ключу, `ROWS_WHERE` для очерёдности |
| `classify_entities.py` | разметка сущностей моделью: о чём спрашивают / служебное. Кэш в `search_entity_class`, задаёт **очерёдность** векторизации, ничего не выбрасывает |
| `deploy.sh` | раскладка кода в рабочий каталог, атомарной подменой. Убирает ручной шаг «скопировать в `/opt`» |
| `embed_all.sh` | **только досчёт векторов**, без пересборки корпуса. Для продолжения после обрыва и при первой заливке крупной базы |

Контракт `/ask` для фронта — [`docs/API_ASK.md`](docs/API_ASK.md): адреса, `kind`,
уточнение кнопками, и два ограничения, которые надо знать до начала (loopback без CORS,
токен нельзя класть в браузер).

Проверка «не сломали ли первую базу» — [`docs/REGRESSION_BASE1.md`](docs/REGRESSION_BASE1.md):
там сведено, какой правкой и каким замером это доказано.

Юниты systemd — в `ubuntu/systemd/` (`1c-serene-pipeline.service/.timer`, `1c-serene-index.service`).

### Ответы — `ubuntu/serenedb/serene_ask.py`

Единственный большой файл своего кода в контуре ответа. Что важно: поиск штатными
функциями (`ts_*`, `bm25`, `<=>`), выбор сущности **реранкером**, величину — **по вопросу**
(базовая предпочтительнее уточнённой), **калькулятор** (числа ставит код, не модель),
**резолвер** (слово → значение через отдельную роль), связка **уточнение → выбор `focus`
→ ответ**, честный **503 при сбоях**, видимое старение данных.

### Проверка

| Файл | Что делает |
|---|---|
| `golden.sh` + `golden-questions.txt` | приёмочный набор, 8 вопросов, гоняется после КАЖДОЙ правки |
| `ab_scorer.py` | второй набор: 8 вопросов, истина считается независимым SQL по источнику |

### Выведено из контура, не трогать

`serene_search_build.py` — прежняя питоновская сборка. 🔴 **Запускать нельзя**: при
нынешнем составе корпуса она сносит таблицу и индекс (авария 28.07).
`serene_report.py`, `mcp_reports.py` — инструмент `report_1c`, решено вывести.
`build_resolver_index.py` — прежняя сборка резолвера, заменена на `resolver_build.sql`.

## 4. Где что живёт на сервере

| Что | Где |
|---|---|
| репозиторий | `/srv/1c` — работаем здесь |
| боевой код | `/opt/1c-mcp-reports/` — копия файлов; после правки копировать туда |
| исходники движка | `/srv/serenedb-src` — без них агент `serenedb-native` слеп |
| секреты | `/etc/*.env`, права 600, в git не входят |
| данные движка | `/var/lib/serenedb` |

**Подключение к базе:** запись — `psql 'host=127.0.0.1 port=7890 user=postgres dbname=postgres'`;
только чтение — роль `serene_ro`. Перепутать = получить `permission denied` и решить,
что нашёл дефект.

**Стадии по каждому пункту контракта — [`docs/TARGET_STATUS.md`](docs/TARGET_STATUS.md).**

**Свежесть по готовности:** конвейер `1c-serene-pipeline` (синк-дельта → сборка → повтор
через `OnUnitInactiveSec`), такт ~6 мин. Синк тянет из 1С **только изменения** по
`DataVersion`. «Ночного» нет. Старые таймеры `sync`/`index` отключены, юнит `index` — на
`build.sh` (не на снёсший корпус `serene_search_build.py`).

**Что дальше:** крупного без внешнего не осталось. Упирается во вторую конфигурацию 1С
(п. 9, 15), решение владельца о периметре (п. 16) и инсталлятор последним (п. 14).
Мелкое: дельта регистров (сократит такт), кнопки уточнения в боте (бэкенд готов).

```
1С (OData) ──синк-дельта (serene_sync + poc_load_entity)──► витрина (таблицы 1С)
```
