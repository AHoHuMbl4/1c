# ПАМЯТКА линии «ОДИН ПУТЬ + ПРАВИЛЬНЫЕ ОТВЕТЫ» (активная; компакт 19.09)

## 🔴 ЧИТАТЬ ПЕРВЫМ, ПЕРЕД ЛЮБЫМ ДЕЙСТВИЕМ — уроки, стоившие дня работы

Эти правила выучены живыми деньгами этой сессии. Они ЗДЕСЬ, а не в HOW_NOT_TO,
потому что туда ты не смотришь. Перед каждым шагом сверься с этим списком:

1. **«Готово» = полный L67 прогнан и зелёный.** Не 6 вопросов, не замки, не смоук.
   Замки зелёные + точечные пробы OK ≠ система ок (доказано 19.09: замки 24/24
   зелёные, а L67 живой показал картину). Полный набор — ДО доклада владельцу.
2. **Правильность важнее формы.** Эксперимент «1 запрос = 1 вызов без пачек»
   (решение владельца) убил СРАВНЕНИЕ кандидатов: близнецы-регистры получали
   одинаковые «да»/оценки → меню вместо ответов → L67 1-2/25. Откат на пачки
   выполнен (FALLBACK1, 0912ee6). Сравнение кандидатов — только в одном вызове.
3. **Не измеряй новым инструментом и не хвались числом, пока не проверил, что
   инструмент гоняет ТО, что ты выкатил** (L67-прогон взял старую копию скорера
   из /tmp — результат «2/25» был старым скорером без кликов).
4. **Скорер должен вести себя как человек**: кликать меню по совпадению подписи с
   вопросом, до 4 хопов, вердикты по TARGET п.12/п.21 (OK/WRONG/honest_no/
   refusal_with_data). Первый-пункт-вслепую даёт ложные WRONG.
5. **Правки файлов канона/скриптов — проверять grep'ом сразу после правки**
   (NameError в heredoc молча съел правку канона).
6. **Промежуточные состояния не дожимать** — если направление отменено, коммить
   только финал (владелец: «зачем дожимать то, что не нужно»).
7. **Зависание сервиса :8091 под длительной нагрузкой** — symptom: LISTEN есть,
   ответа нет, рестарт лечит. Сторож: /tmp/run_l67_watch.sh (рестартует при
   2 подряд no-answer). Причина НЕ найдена — если повторится, диагностировать
   (кандидаты: накопление соединений, дедлок в параллельных паспортах).

## 🔴 ТРИ ОПОРЫ — держать в голове всю сессию

### 1. TARGET.md (контракт, 21 пункт, менять нельзя)
- **п.0**: база разработки ≠ прод; прод скрыт специально — работает из коробки на
  чужой базе БЕЗ правки. Никаких списков слов/имён базы в коде, порогов под базу,
  подгонки под известные вопросы. Проверка каждой механики: «что знает движок/
  $metadata/модель — спроси у них, не разбирай текст».
- **п.10**: ошибочные ответы запрещены (числовые и смысловые).
- **п.12**: отказ и уточнение — НЕ ошибка; догадка — ошибка. Несколько прочтений →
  меню; «продали» = 4 регистра-близнеца → меню канонично.
- **п.19**: модель НЕ считает и НЕ ищет — только смысл (разбор, сопоставление,
  формулировка); числа всегда из SQL; контекст в модель ограничен и не растёт
  с базой.
- **п.20**: своих скриптов для базы нет — всё внутри SereneDB штатным.
- **п.21**: ответ → уточняющий вопрос → честный отказ; отказ при живых данных =
  дефект; после уточнения ответ ОБЯЗАН доехать.

### 2. КОНТРАКТ «ОДИН ПУТЬ» (приказ владельца 12.09, действует всегда)
вопрос → интерпретация из вики (z21) → запрос в базу → варианты с описаниями из
вики (если прочтений больше одного) → выбор → ответ. Ничего больше. Вторых
выбирателей сущности нет; выбор сущности — только wiki-каскад (пул → pick →
verify); семейства/перестановщики — снесены (СНОС-15). Текущая реализация:
пачковый pick+verify (FALLBACK1 — сравнение в одном вызове, см. урок 2) + C-волны
(ТОЧКА 1 rescue-проход полного пула при смерти каскада; ТОЧКА 2 concepts перед
отказом «значения не найдены»; spans z06; гард z14; журнал unknown_* — корм
шага 7 пайплайна). Канон всех решений: .claude/state/design-c.md §2 (читать
перед правками z21/z20 — там история решений владельца с атрибуцией).

### 3. ПРАВИЛА РАБОТЫ С АГЕНТАМИ (оркестратор Kimi → исполнители cursor-agent)
- Исполнители — ТОЛЬКО свежие процессы `cursor-agent -p "$(cat промт.md)" --force
  --model auto --output-format stream-json | tee лог` фоном; 1 задача = 1 процесс;
  резюмировать сессии запрещено. Полный регламент: docs/ORCHESTRATION_CURSOR.md
  (§9 — ловушки: промт только из файла; без pkill по подстрокам; python только
  heredoc; git add точными путями).
- **Красная ×3** свежих проверяющих на каждый дифф до ACCEPT ×3; промт красной
  обновлять под НОВЫЙ контекст (устаревшее «== HEAD» стоило круга); вердикты
  извлекать из stream-json (последняя assistant-запись с «ВЕРДИКТ»).
- Промты самодостаточны: цель с критерием-числом, точные файлы, что НЕ трогать.
  Ложный блок check-prompt-rules на .md/строках → правка python-heredoc (правило 7)
  с отметкой в коммите.
- Мои (оркестратора) обязанности: замеры, приёмка, коммиты. Вера сводке
  исполнителя запрещена — проверять git diff/замками.
- Git: add и commit РАЗНЫМИ вызовами; коммит пат-спеком (`git commit -- файлы`);
  выкат — ОТДЕЛЬНОЙ командой после пуша (гейт: выкат только из коммиченного
  дерева); «Числа:/Доки:» в сообщении; граф тем же коммитом (MCP дописывает файл
  с задержкой — после add_observations делать `git add` ЗАНОВО и проверять
  `git diff --cached` перед commit; гонка ловилась трижды 19.09).
