Решение владельца 2026-07-26, дословно: «report_1c не нужен тогда. он нужен потом в
конце после ответа. можно доделать запрос и подтянуть данные и на них построить графики».

**Порядок:** ask_1c отвечает (поиск по индексу → выбрана сущность, известны условия
отбора, итог посчитан в базе) → если нужна картинка, КОД дописывает группировку к уже
известному отбору (src_table + match + предикаты + amount/doc_date) и выполняет в базе
→ единицы строк → render_chart.

**Запрос достраивается кодом, а не сочиняется моделью по схеме.** В модель для графика
не уходит ничего. Это следствие замера: get_schema() = 464 292 символа (~155k токенов)
на каждый вопрос, с живыми значениями клиента; на базе x100 — ~15 млн токенов, то есть
путь не масштабируется в принципе.

Сделать: убрать report_1c из mcp.servers.*.toolFilter.include, погасить NL→SQL-путь
(get_schema, генерация SQL моделью), добавить в ask_1c шаг «доделать запрос → график».
render_chart из serene_report.py переиспользуется как есть.

[[feedback-data-placement-is-owner-decision]].
