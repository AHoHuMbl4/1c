**Решение владельца 28.07.2026:** «нужен просто калькулятор для чисел, а не сложные
системы». Пересмотру не подлежит.

Модель не пишет посчитанных чисел. Она оставляет места (`{total}`, `{count}`, `{max}`,
`{min}`, `{avg}`, `{date_min}`, `{date_max}`, при нескольких величинах `{total:ИМЯ}`), а
код ставит туда посчитанное базой.

**Почему так, а не проверкой.** Прежде неверное число было возможно и лишь отлавливалось
гейтом. Всякая проверка ошибается в обе стороны: за один день 28.07 она уронила ВЕРНЫЕ
ответы дважды — на функции ранжирования и склеив «36, 4» в несуществующее 36.4. При
подстановке неверное число невозможно по устройству.

**Граница:** посчитанное по нескольким строкам — место; прочитанное из одной строки
(номер документа, ИНН, дата записи) — цитата, её модель пишет сама, её проверяет гейт.

**Чего нельзя:** заполнять место, которому нечего подставить. Ноль — такое же неверное
число, как любое другое ([замер]: «Общая сумма — 0 руб.» при настоящих 2 088 800).

Связано: [[project-clarify-as-buttons-plus-free-text]] — тот же принцип, запрет держится
кодом, а не просьбой в промте.
