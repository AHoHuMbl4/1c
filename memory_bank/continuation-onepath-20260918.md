# ПЛАН: «Один путь — без ловушек до и после» (единый фронт тракта)

Заказ владельца 18.09 (после прогона 67 вопросов: wrong 0, но 6/67 — отказ при живых
данных). Приказ: НИКАКИХ отдельных механизмов «до» или «после» — один общий путь для
каждого вопроса; инструмент — доп-запрос в LLM («где что», как арбитр этой сессии).
Исполнение — армия агентов (cursor-agent + красная ×3 на каждый дифф), как в волне
слоёв 2/3. Этот план — ТОЛЬКО план; работа по слову владельца после компакта.

## 0. Принцип (канон будущей design-c)

Вопрос живёт одним трактом: разбор → КАНДИДАТЫ (поиск без молчаливых срезов) →
LLM-резолвер «где что» (там, где детерминированный слой не уверен) → меню с
дайджестами при >1 прочтении / guard живости / ответ. Умирает вопрос только честно:
данных нет И ЛЛМ-резолвер подтвердил, что кандидатов нет. Любое место, где вопрос
умирает ДО меню/ответа при живых кандидатах или данных, — дефект тракта, не «чужая
очередь». Запрещено чинить классы отказов точечными механизмами — только через
общий тракт.

## 1. Волны (каждая = cursor-agent + красная ×3, до ACCEPT ×3)

- **C-канон (дизайн design-c.md + красная ×3 на дизайн)**: карта ВСЕХ мест тракта,
  где вопрос может умереть до меню/ответа (по коду: bm25-топ-3 в entity-поиске z06;
  пороги среза кандидатов; словарное покрытие слов; склеенные/разделённые имена;
  всё, что отдаёт no_data при непустом пуле кандидатов). Каждое место получает один
  из двух исходов: (а) кандидат проходит в общий тракт; (б) пул уходит в
  LLM-резолвер. Третьего («тихий отказ») нет. Красная проверяет именно
  одноканальность: не появился ли новый «выбиратель»/обход.
- **C1. LLM-резолвер «где что» — единая точка тракта** (по образцу llm_option_
  highlight из D4: дешёвая модель, ≤800 мс, fail-soft — меню/отказ не блокирует;
  вход: вопрос + кандидаты с их данными/подписями, без сырых имён машин, п.16;
  выход: ранжирование/выбор кандидата или «кандидатов нет»). Встраивается ОДИН раз
  в общий тракт — до меню мер/сущностей, — а не в каждую ловушку отдельно.
- **C2. Поиск без молчаливых срезов**: bm25-топ-3 и пороги кандидатов не убивают
  вопрос: слабый/неоднозначный топ → полный пул кандидатов в LLM-резолвер → меню
  с дайджестами. «сколько у нас вообще клиентов» (эталон 361) — приёмка класса.
- **C3. Незнакомое слово → не отказ**: слово вне словаря → LLM-резолвер подбирает
  кандидатов мер/сущностей по описаниям/алиасам словаря → меню с дайджестами;
  незнакомое слово пишется в журнал (корм шага 7 словарной линии — соседям, без
  правки словаря руками). Приёмка: «наторговали» ×2, «наотгружали», «вышло»
  (эталоны 357 393,03 / 0,00 / 661 458,38 / 2 083 550,46).
- **C4. Единая нормализация имён на входе**: склеенное/разделённое имя
  («РеализацияТМЦ» ↔ «Реализация ТМЦ») — одна норм-функция в одной точке входа
  entity-поиска (класс уже есть — _homonym_norm из D2; поднять на вход z06).
  Приёмка: «Сколько движений в регистре реализации ТМЦ?» (эталон 80 173).
- **C5. Замки + приёмка**: замок «один путь»: на фикстурах всех 6 вопросов —
  вопрос доходит до меню/ответа, no_data только при пустом пуле ПОСЛЕ
  LLM-резолвера; регресс 67-вопросного прогона (wrong 0; отказы только честные);
  живые пробы на окне; p95 фронта (резолвер ≤800 мс, меню всегда уходит).

## 2. Приёмка числами (по прогону владельца)

6/67 отказов при живых данных → 0: каждый из шести либо отвечает эталоном, либо
даёт меню с дайджестами, где человек видит своё (и выбор пишется в журнал →
следующий такт словаря умнеет). wrong остаётся 0. Доля меню может вырасти — только
за счёт прежних глухих отказов.

## 3. Что НЕ делаем

- Не правим словарь руками и не хардкодим слова/имена (п.0/п.9) — незнакомое слово
  это сигнал журнала, а не список в коде.
- Не строим отдельных механизмов под классы (гейт по теме, выбиратель по слову) —
  HOW_NOT_TO §1.49/§1.51: только общий тракт.
- Промты-правила не пишем (проверяет гейт); LLM-резолвер — механизм в коде, как
  арбитр D4.

## 4. Старт

По слову владельца после компакта: круг-1 красной на дизайн design-c.md, далее
C1→C5 армией агентов. Правила оркестратора неизменны (ORCHESTRATION_CURSOR; add и
commit разными вызовами; apply-скрипты при ложном блоке хука).
